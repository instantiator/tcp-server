Our tests are currently run with supporting scripts eg. `scripts/run-e2e-tests.sh` that manage docker containers and setup the system for testing.

It might be worthwhile shifting these capabilities into the test code itself. This will mean being able to manage docker containers and docker compose from the tests.

It looks as if the `testcontainers` library can orchestrate docker containers from jest.

```bash
npm install --save-dev testcontainers
```

It looks promising. Gemini is pretty confident that it can handle `Dockerfile` and `docker-compose.yml` files, and gives some examples:

```ts
import { GenericContainer, StartedTestContainer } from 'testcontainers';
import { createClient } from 'redis';

describe('Redis Integration Test', () => {
  let container: StartedTestContainer;
  let redisClient: ReturnType<typeof createClient>;

  // 1. Spin up the container before tests run
  beforeAll(async () => {
    container = await new GenericContainer('redis:7-alpine')
      .withExposedPorts(6379)
      .start();

    // Get the dynamically assigned host and port
    const host = container.getHost();
    const port = container.getMappedPort(6379);

    redisClient = createClient({ url: `redis://${host}:${port}` });
    await redisClient.connect();
  }, 30000); // Docker pull/startup might take a moment the first time

  // 2. Tear down the container when tests finish
  afterAll(async () => {
    if (redisClient) await redisClient.disconnect();
    if (container) await container.stop();
  });

  it('should write and read data successfully', async () => {
    await redisClient.set('framework', 'Jest');
    const value = await redisClient.get('framework');

    expect(value).toBe('Jest');
  });
});
```

```ts
import { GenericContainer, StartedTestContainer } from 'testcontainers';
import path from 'path';

describe('Custom Dockerfile Test', () => {
  let container: StartedTestContainer;

  beforeAll(async () => {
    // Path to the directory containing your Dockerfile
    const contextPath = path.resolve(__dirname, '../relative/path/to/app');

    container = await GenericContainer.fromDockerfile(contextPath).build(); // Compiles the image locally

    container = await container.withExposedPorts(8080).start();
  }, 60000); // Give it extra time to build the image on the first run

  afterAll(async () => {
    if (container) await container.stop();
  });

  it('should be up and running', () => {
    expect(container.getId()).toBeDefined();
  });
});
```

```ts
import {
  DockerComposeEnvironment,
  StartedDockerComposeEnvironment,
} from 'testcontainers';
import path from 'path';

describe('Docker Compose Stack Test', () => {
  let environment: StartedDockerComposeEnvironment;

  beforeAll(async () => {
    const composeFilePath = path.resolve(__dirname, '../');
    const composeFile = 'docker-compose.yml';

    environment = await new DockerComposeEnvironment(
      composeFilePath,
      composeFile,
    )
      .withUpTimeout(60000) // Timeout for the environment to stabilize
      .up();
  }, 90000);

  afterAll(async () => {
    if (environment) await environment.down();
  });

  it('should talk to a specific service in the compose stack', async () => {
    // Grab a specific container out of the running stack by its service name
    const dbContainer = environment.getContainer('postgres-db-1');

    const mappedPort = dbContainer.getMappedPort(5432);
    expect(mappedPort).toBeGreaterThan(0);
  });
});
```

It also made these recommendations:

- `withUpTimeout`: Docker Compose environments can take a little while to network everything together. Always increase your Jest timeout (`beforeAll(..., 90000)`) and use `.withUpTimeout()` to prevent premature test failures.
- Environment Variables: You can override your compose environment variables on the fly inside Jest using .`withEnvironment({ KEY: "value" })` before calling `.up()`.
