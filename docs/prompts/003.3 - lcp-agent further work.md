## MCP tool integration

### Agent loop wiring
- Wire MCP client in `AgentLoopService.buildGraph` — replace the stub `END` edge with a conditional edge to a `tools` node once MCP servers exist
- The `tools` node calls each tool returned in `tool_calls` from the LLM response via the MCP client

### Shared company storage MCP server
- MinIO-backed read/write/list tools for files shared across agents within a company
- Per ADR-007. Enables agents to read/write files as part of their task.

### Knowledge base MCP server
- pgvector-backed `search_knowledge(query)` and `store_knowledge(content)` tools
- Per ADR-006. Requires an embedding pipeline (see Memory section below).

### Episodic memory MCP server
- pgvector-backed `remember(fact)` and `recall(query)` tools scoped per agent/role
- Per ADR-006.

### Decision logging MCP server
- `log_decision(reasoning, decision)` tool that writes to `audit_event` with `eventType: decision`
- Per ADR-008. Enables structured decision trails beyond free-form LLM output.

## Agent loop sophistication

### Per-role resource limits
- `MAX_ITERATIONS` and `TIMEOUT_MS` are currently hard-coded in `AgentLoopService`
- Move to `LcpRole.runConfig` JSONB column with per-role overrides and sensible defaults

### Smarter output validation
- MVP retries once with a generic continuation prompt
- Future: structured expected-output schema on `LcpRole`; validate against it; targeted retry prompt listing what is missing

### Concurrency and rate limiting
- No per-provider rate-limit awareness in the MVP
- Future: token-bucket or queue throttle per `LlmConfig.provider` to avoid 429s from OpenAI

### Multi-step task plans
- Agents currently run a single-thread conversation
- Future: agents maintain a structured plan (task → steps → sub-steps) that they can modify and the loop tracks

### Cross-role conversations
- One agent can initiate a consultation with another role (e.g. a planner spawns an analyst)
- Per ADR-010. Requires the `agent-results` queue and a reply-to mechanism.

### Human-in-the-loop pause
- Agents can pause awaiting user input; lcp-server exposes a `POST /api/agent/:id/reply` endpoint
- Per ADR-012.

## Observability

### Queue and thread observability ADR needed
- BullMQ queue depth, active worker count, per-thread latency, and stalled-job detection are not monitored
- Prepare an ADR for queue + thread observability before scaling beyond a single lcp-agent instance
- Suggested tooling: BullMQ's built-in metrics + a Grafana dashboard; stalled-job check via BullMQ's `checkStalledJobs`

### Live audit stream
- Expose `GET /api/agent/:id/events` as an SSE endpoint streaming rows from `audit_event` as they arrive
- Per ADR-008.

### MinIO audit export
- At the end of each agent run, export the full `audit_event` sequence for that run to MinIO as a JSONL file
- Per ADR-008. Enables offline analysis and replay.

## Orchestration

### `agent-results` queue
- lcp-agent publishes job completion/failure back to lcp-server via a `agent-results` BullMQ queue
- Allows lcp-server to react to agent outcomes without polling the DB

### Full lifecycle
- Extend `AgentStatus` to: `created → planning → in_progress → reviewing → completed / failed / cancelled`
- Per ADR-010.

### Planner role integration
- A `Planner` role that receives a high-level goal and produces a structured task plan
- Other roles execute individual steps; planner reviews and adapts
- Per ADR-010.
