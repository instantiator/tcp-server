# Plan: Dev CLI (`lcp-cli`) + API additions

## Context

The user wants a TypeScript CLI tool (`lcp-cli`) that talks to an LCP server's REST API, shares
types with the monorepo, and supports the verbs: `get-token`, `list-companies`, `list-roles`,
`set-company`, `set-role`, and `chat`. Several new API endpoints are required on `lcp-server` to
support listing, token retrieval, synchronous chat, and agent cleanup. Script docs also need path
updates following the move of `start-dev.sh` / `stop-dev.sh` into `scripts/dev/`.

**Decisions (from Q&A):**
- **Chat delivery**: synchronous — `lcp-server` calls LangGraph inline, holds HTTP connection
- **`get-token`**: server-side proxy — new `POST /api/auth/token` keeps OIDC client secret on server
- **`list-roles`**: CLI assembles result; needs new `GET /api/company` list endpoint, reuses
  existing `GET /api/company/:id/roles`
- **CLI structure**: standalone TypeScript binary under `apps/lcp-cli/` (not NestJS), `commander`
  for arg parsing

## Part 1 — New `lcp-server` endpoints

### 1a. `GET /api/company` — list all companies

- **File**: `apps/lcp-server/src/api/api.company.controller.ts`
- Add handler `@Get()` before the existing `@Get(':id')` handler
- Returns `LcpCompany[]`; delegates to `db.listCompanies()` (new `DbService` method)
- JWT guarded (already at controller level)

### 1b. `PUT /api/role/:id` — update role (currently missing)

- **File**: `apps/lcp-server/src/api/api.role.controller.ts`
- Add handler `@Put(':id')` accepting `Partial<LcpRole>`, returns updated `LcpRole`
- Delegates to a new `db.updateRole(id, partial)` method (mirrors existing `db.setCompany`)
- JWT guarded

### 1c. `DELETE /api/agent/:id` — delete agent

- **File**: `apps/lcp-server/src/api/api.agent.controller.ts`
- Physical delete via `db.deleteAgent(id)`; TypeORM cascade handles `AuditEvent` rows
- Returns 204 No Content; throws `NotFoundException` when agent not found
- JWT guarded

### 1d. `POST /api/auth/token` — OIDC token proxy

- **New file**: `apps/lcp-server/src/auth/auth-token.controller.ts`
- **New file**: `apps/lcp-server/src/auth/auth-token.service.ts`
- **NOT** guarded by `JwtAuthGuard` — it produces tokens
- Body: `{ username: string; password: string }`
- Service fetches token endpoint from OIDC discovery (`OIDC_ISSUER_URL/.well-known/openid-configuration`);
  caches the discovery doc in memory (single fetch per service lifetime)
- POSTs to `token_endpoint` with `grant_type=password`, `client_id` (`OIDC_CLIENT_ID`),
  `client_secret` (`OIDC_CLIENT_SECRET`), `username`, `password`
- Returns `{ access_token: string; token_type: string; expires_in: number }` (forward from OIDC)
- On OIDC error: throw `UnauthorizedException` with a safe message (never expose raw OIDC errors)
- Register `AuthTokenController` + `AuthTokenService` in `app.module.ts`

### 1e. `POST /api/agent/chat/start` — create a chat-mode agent (no BullMQ)

- **File**: `apps/lcp-server/src/api/api.agent.controller.ts`
- Body: `{ companyId: string; roleId: string }`
- Creates `LcpAgent` record with `initialPrompt = ""`, status `Idle`, no BullMQ dispatch
- Writes an `AuditEvent` of type `StateChange` with payload `{ newStatus: 'idle', reason: 'chat session created' }`
- Returns the new agent; used by CLI to obtain `agent.id` before the chat loop
- JWT guarded

### 1f. `POST /api/agent/:id/message` — synchronous chat message

- **File**: `apps/lcp-server/src/api/api.agent.controller.ts`
- Body: `{ message: string }`
- Delegates to new `ChatService.sendMessage(agentId, message)`
- Returns `{ response: string }`
- JWT guarded

**ChatService** (`apps/lcp-server/src/api/chat.service.ts`):

- Loads agent + role + LLM config (same DB lookup chain as `AgentLoopService`)
- Sets agent `status = Running`; on completion sets `status = Idle`
- Builds a LangGraph `StateGraph` (same pattern as `buildGraph` in lcp-agent) using
  `PostgresSaver.fromConnString(DATABASE_URL)`
- First message detection: `agent.threadId === null` → prepend `SystemMessage(renderedSystemPrompt)`
  before the `HumanMessage(message)`, then set `agent.threadId = agent.id`
- Subsequent messages: just `[HumanMessage(message)]` — LangGraph checkpoint has history
- Writes an `AuditEvent(LlmRequest)` before invoking the graph
- Invokes `graph.invoke(state, { configurable: { thread_id: agent.id } })`  
  (invoke not streamEvents — we only need the final message for MVP)
- Extracts last AI message content string
- Writes an `AuditEvent(LlmResponse)` with the response content
- Returns the response string
- On error: writes `AuditEvent(StateChange, { newStatus: 'failed', reason })`, sets
  `status = Failed`, rethrows as `InternalServerErrorException`
- The LangGraph packages (`@langchain/langgraph`, `@langchain/langgraph-checkpoint-postgres`,
  `@langchain/core`, `@langchain/openai`) are already root-level dependencies (used by lcp-agent);
  `buildChatModel` from `apps/lcp-agent/src/llm/llm-factory.ts` should be moved to
  `libs/lcp-shared/src/llm/llm-factory.ts` so both apps can use it without duplication

> **Note on `buildChatModel` move**: This is the only shared code needed. Moving it avoids
> copy-paste and keeps lcp-shared as the home for cross-app utilities.

## Part 2 — `apps/lcp-cli/` standalone CLI

### Files

```
apps/lcp-cli/
  src/
    main.ts                   # commander program, global opts, verb registration
    commands/
      get-token.ts
      list-companies.ts
      list-roles.ts
      set-company.ts
      set-role.ts
      chat.ts
    lib/
      api.ts                  # fetch wrapper (base URL + Authorization header)
      auth.ts                 # token resolution + masked password prompt
      types.ts                # DeepPartial<T> type alias
  tsconfig.app.json
```

### Global options (all verbs)

| Flag | Alias | Default | Description |
|------|-------|---------|-------------|
| `--lcp-server <url>` | `-s` | `http://localhost:3000` | Base URL |
| `--access-token <token>` | `-t` | — | Explicit token |
| `--access-token-env-var <var>` | `-e` | — | Env var holding token |
| `--username <user>` | `-u` | — | OIDC username (triggers `get-token`) |
| `--password <pass>` | `-p` | — | OIDC password (omit to prompt interactively) |

Token resolution order in `auth.ts`: `-t` → `-e` → `-u`/`-p` (prompt if `-p` absent, mask chars).  
Interactive password prompt: `readline` with `_writeToOutput` override that echoes `*` per char.

### `DeepPartial<T>` in `lib/types.ts`

```typescript
export type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P];
};
```

No extra dependency — TypeORM's `DeepPartial` is available in server code but the CLI doesn't use TypeORM.

### Verb: `get-token`

- Requires `-u`; prompts for password if `-p` absent
- `POST /api/auth/token` with `{ username, password }`
- stdout: the `access_token` string (nothing else)
- stderr: warning on failure

### Verb: `list-companies`

- `GET /api/company`
- stdout: JSON array `{ id, name }[]` (project `id` + `name` from full entity)

### Verb: `list-roles [--company-id <uuid>]`

- If `--company-id` provided: one call `GET /api/company/:id/roles`, wrap in array
  `[{ id: company.id, name: company.name, roles }]`  
  (need `GET /api/company/:companyId` to get company name — that endpoint already exists)
- If not provided: `GET /api/company` → for each company `GET /api/company/:id/roles` (N+1)
- stdout: `{ id, name, roles: { id, name }[] }[]`

### Verb: `set-company [-i <json>]`

- Reads JSON from `-i` flag or stdin
- Input typed as `DeepPartial<LcpCompany>`
- If input has `id`: `PUT /api/company/:id`
- If not: `POST /api/company` (requires `slug`, `name`)
- stdout: updated/created company JSON

### Verb: `set-role [-c <companyId>] [-i <json>]`

- Reads JSON from `-i` flag or stdin
- Input typed as `DeepPartial<LcpRole>`
- If input has `id`: `PUT /api/role/:id`
- If not: `POST /api/role` (requires `companyId` — use `-c` flag if not in input JSON)
- stdout: updated/created role JSON

### Verb: `chat -r <roleId> [-q <query>]`

**Single-query mode** (`-q` provided):
1. Obtain token
2. `POST /api/agent/chat/start` → get `agentId`
3. `POST /api/agent/:id/message` with `{ message: query }`
4. stdout: response string; stderr: status indicators
5. `DELETE /api/agent/:id`
6. Exit

**Interactive mode** (no `-q`):
1. Obtain token
2. `POST /api/agent/chat/start` → get `agentId`; print agent ID to stderr
3. Enter `readline` loop:
   - Print `> ` prompt to stderr; read line from stdin
   - If line is `exit` / `quit` or empty input on EOF: break
   - `POST /api/agent/:id/message`; print response to stdout
4. On SIGINT (Ctrl+C): break loop
5. `DELETE /api/agent/:id` (in `finally`)
6. Exit

**Conversation history**: LangGraph's `PostgresSaver` checkpoints the full message history
server-side per `thread_id = agent.id`. The CLI displays history only for the current session
(in-memory buffer if needed for display; not re-fetched from server). Users can resume a prior
conversation by using the agent ID with `POST /api/agent/:id/message` directly — but that's outside
the CLI MVP.

## Part 4 — `scripts/dev/lcp-cli.sh`

Pass-through script with optional forced rebuild:
```bash
#!/usr/bin/env bash
# lcp-cli.sh — wrapper to run the lcp-cli binary
# Usage: ./scripts/dev/lcp-cli.sh [--rebuild] [lcp-cli options]

REBUILD=false
if [ "$1" = "--rebuild" ]; then
  REBUILD=true
  shift
fi

ROOT="$(git rev-parse --show-toplevel)"
DIST="$ROOT/dist/apps/lcp-cli/main.js"

# Build if dist is missing or --rebuild was passed
if [ "$REBUILD" = "true" ] || [ ! -f "$DIST" ]; then
  echo "[lcp-cli] Building lcp-cli..." >&2
  npm --prefix "$ROOT" run build:lcp-cli
fi

exec node "$DIST" "$@"
```
