# 005.2 — Context Management Plan

This document records the implementation plan agreed in session 005. See
[005.1 - context management planning.md](005.1%20-%20context%20management%20planning.md)
for the original planning prompt.

## Features implemented

### 1. Cancelling in-flight prompts

**CLI (`apps/lcp-cli/src/commands/chat.ts`):**

- Two-stage SIGINT handler: first Ctrl+C aborts the in-flight request and re-shows the prompt; second Ctrl+C (when idle) cleans up the agent and exits.
- `sendMessage()` creates an `AbortController`, stores it in `currentAbort`, and passes the signal to `apiRequest`. On `AbortError`, returns `null` so the loop continues without exiting.
- `apiRequest` in `apps/lcp-cli/src/lib/api.ts` accepts an optional `signal` in `ApiOptions` and forwards it to `fetch`.
- SSE observer connects after 3 seconds of silence to display compaction progress.
- `compactionReport` displayed after each response when present.

**Server (`apps/lcp-server`):**

- `ChatService.sendMessage()` accepts an optional `AbortSignal`. When the graph throws `AbortError`, the agent is returned to `Idle` (not `Failed`) and a `StateChange` audit event is written with reason `'cancelled by user'`.
- `AgentController.sendMessage()` creates an `AbortController`, hooks `req.socket.on('close')`, and passes the signal to `ChatService`.

Optional `number` field added to `LlmConfig` interface. JSONB — no migration required. Defaults to `8192` when absent.

### 5. Context management services

New directory: `apps/lcp-server/src/context/`

| File                             | Purpose                                                                                                     |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `context-budget.service.ts`      | Token counting (tiktoken), budget thresholds (80%/60%), pct helper                                          |
| `context-compactor.service.ts`   | Tier-1 `trimHistory` (trimMessages, no LLM); Tier-2 `summariseMessage` / `compactSection` (parallel LLM)    |
| `incoming-data-guard.service.ts` | Pre-check incoming data; compact before inclusion if over budget                                            |
| `context-manager.service.ts`     | Orchestrator: parallel budget check + incoming guard; Tier-1 then Tier-2 compaction; SSE events; audit logs |
| `context.module.ts`              | NestJS module exporting all four services                                                                   |

**Key decisions:**

- `trimMessages` + tiktoken (Tier 1) handles the common case with no LLM cost.
- LangGraph `getState`/`updateState` + `RemoveMessage` applies compaction to the checkpoint.
- Parallel `Promise.all` for multiple oversized messages (Tier 2).
- `// TODO` marks the drop-messages/essential-info anchoring intervention point.

### 6. SSE events

`AgentEventService` (`apps/lcp-server/src/events/agent-event.service.ts`): in-memory RxJS `Subject` per agent, completes on agent deletion or module teardown.

`GET /api/agent/:id/events` SSE endpoint added to `AgentController` using NestJS `@Sse()` decorator + `rxjs/operators/map`.

### 7. Response extension

`ChatMessageResponse` gains optional `compactionReport?: CompactionReport`. `CompactionReport` (in `context/context.types.ts`) includes `strategies`, `activities`, `duration`, `before`, and `after` snapshots.

### 8. Stub LLM service

`docker/stub-llm/server.js` — pure Node.js HTTP stub (no npm dependencies). Responds to `POST /v1/chat/completions` with a configurable canned response. Control endpoint `POST /stub/config` allows per-test response override.

Added to `docker-compose.yml` under profile `integration` (port `3002`). `scripts/run-integration-tests.sh` starts it and exports `STUB_LLM_URL`.
