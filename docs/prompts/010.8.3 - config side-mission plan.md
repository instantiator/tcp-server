# Configuration Side-Mission Plan

Corrects and consolidates the configuration approach before returning to 010.8.1. Builds on [010.8.2](./010.8.2%20-%20config%20side-mission%20planning.md) and supersedes parts of [010.8.1](./010.8.1%20-%20configuration%20implementation.md).

## Summary

1. Remove `.env.defaults` — all fallback defaults live in `defaults.ts` (code), one place only
2. Rename internal URL variables to `INTERNAL_URL_*` (Docker-internal network only)
3. Add `EXPOSE_PORT_*` variables for localhost port mapping — each independently configurable, with formula-based defaults
4. Rename `POSTGRES_PASSWORD` → `DB_PASSWORD`, add `DB_NAME` (default: `lcp`)
5. Unify `OIDC_ISSUER_URL` as the single OIDC variable — derives external URL from `EXPOSE_PORT_ZITADEL` when not set
6. Host-facing URLs (`DATABASE_URL`, `REDIS_URL`, `MINIO_ENDPOINT`) are **derived** from `EXPOSE_PORT_*` and `DB_*` — not stored in `.env.*`
7. Update `docker-compose.yml`, scripts, schemas, and the setup wizard
8. Update affected documentation

## Key Design Decisions

### Derived URLs, not stored URLs

Tests, `lcp-cli`, and other non-Docker usage need `DATABASE_URL`, `REDIS_URL`, `MINIO_ENDPOINT` on the host. Rather than storing these in `.env.*` files, they are **derived at runtime** from the `EXPOSE_PORT_*` and `DB_*` variables:

```
DATABASE_URL = postgres://${DB_USER}:${DB_PASSWORD}@localhost:${EXPOSE_PORT_DB}/${DB_NAME}
REDIS_URL    = redis://localhost:${EXPOSE_PORT_REDIS}    (if Redis is exposed)
MINIO_ENDPOINT = http://localhost:${EXPOSE_PORT_MINIO}
```

This derivation happens in:

- `start-deployment.sh` — exports derived URLs before starting Docker Compose
- `testcontainers-env.ts` / `api-setup.ts` — derives URLs for test containers
- Any script that needs host-facing URLs

### OIDC unification

`OIDC_ISSUER_URL` is the single variable for OIDC. Resolution:

1. If `OIDC_ISSUER_URL` is set in `.env.*` → use it (external OIDC provider)
2. If not set → derive from Zitadel: `http://localhost:${EXPOSE_PORT_ZITADEL}`
3. Docker Compose uses `INTERNAL_URL_OIDC_ISSUER` (always `http://zitadel:8080`) for container-to-container calls

The app code reads `OIDC_ISSUER_URL` for external-facing calls and `OIDC_INTERNAL_ISSUER_URL` (mapped from `INTERNAL_URL_OIDC_ISSUER`) for internal calls. The app code does not change — only the variable naming in `.env.*` and docker-compose.yml changes.

### Port configuration

Each `EXPOSE_PORT_*` is independently configurable in `.env.*`. The setup wizard asks for the API port and generates the others using offsets. If a port is already in use at startup, the system fails with a clear error.

Default offsets from `EXPOSE_PORT_API`:

- `EXPOSE_PORT_DB` = API + 2432 (default: 5432)
- `EXPOSE_PORT_MINIO` = API + 6000 (default: 9000)
- `EXPOSE_PORT_ZITADEL` = API + 5080 (default: 8080)

## Coding Standards (Mandatory Throughout)

All code written in this plan **must** comply with these standards from `dev-environment/guidance/`:

### Non-negotiable rules (from `AGENTS.md`)

1. Less is more: concise, readable code and simple interfaces. No unrequested abstractions.
2. Comments state intent, not mechanics. Comment classes, functions, and consts; skip trivial ones.
3. Zero compiler errors and warnings; zero linter errors and warnings.
4. Never cast to `any` (or equivalent type escapes), especially in test mocks.
5. Never store secrets in the code base.
6. Only change code you have been asked to change; ask permission otherwise.

### Applied standards

- **TypeScript**: strict mode, no `any`, TSDoc on exported symbols (`dev-environment/guidance/languages/typescript.md`)
- **Bash**: `set -euo pipefail`, bash 3.2 target, quote all expansions, shellcheck clean (`dev-environment/guidance/languages/bash.md`)
- **Testing**: test intent not lines, describe blocks for intent, test data factories (`dev-environment/guidance/testing/units.md`)
- **Slop scan**: `npx aislop scan` must pass (score ≥ 50, zero errors)
- **After every change**: run `dev-environment/scripts/check.sh` and fix what it reports
- **When done**: apply judgment items from `dev-environment/guidance/process/after-coding.md`

### Unit 2.1: Add port-in-use check to startup scripts

**Status**: ✅ Complete

Create `scripts/lib/check-ports.sh`:

```bash
# Checks that EXPOSE_PORT_* ports are available.
# Exits with error if any port is already in use.
check_exposed_ports() {
  local ports=("$EXPOSE_PORT_API" "$EXPOSE_PORT_DB" "$EXPOSE_PORT_MINIO" "$EXPOSE_PORT_ZITADEL")
  for port in "${ports[@]}"; do
    if lsof -i :"$port" -sTCP:LISTEN >/dev/null 2>&1; then
      echo "Error: port $port is already in use." >&2
      echo "Check which process is using it: lsof -i :$port" >&2
      exit 1
    fi
  done
}
```

Integrate into `start-deployment.sh` before `docker compose up`.

Write behavior:

```typescript
function writeVar(
  lines: string[],
  existing: Map<string, string>,
  defaults: Map<string, string>,
  key: string,
  defaultValue: string,
  alwaysWrite = false,
): void {
  const value = existing.get(key) ?? defaultValue;
  const defaultVal = defaults.get(key);

  if (!alwaysWrite && value === defaultVal) {
    lines.push(`# ${key}=${value}`);
  } else {
    lines.push(`${key}=${value}`);
  }
}
```

## Rollback Plan

If issues arise during implementation:

1. **Phase 1 issues**: Revert `docker-compose.yml` changes, restore `.env.defaults`
2. **Phase 2 issues**: Remove `EXPOSE_PORT_*` from docker-compose, use hardcoded ports
3. **Phase 3 issues**: Revert wizard to previous version (git checkout)
4. **Phase 4 issues**: Documentation can be corrected post-merge

All changes are backwards-compatible at the application code level — variable renames only affect configuration files and Docker Compose interpolation, not application `config.get()` calls.
