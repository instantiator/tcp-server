# 007.4 — Launch Script Consolidation Implementation Plan

## Problem

1. **Double-build in CI**: The `api-test` job ran `docker/build-push-action` (with GHA layer
   cache) then `run-api-tests.sh` called `$DC build` again, discarding the cached layers.
2. **Keycloak setup duplicated**: An identical ~40-line `kcadm` block existed in
   `start-dev.sh`, `run-api-tests.sh`, and `run-smoke-tests.sh`. `start-dev.sh` had a richer
   version (`serviceAccountsEnabled=true` + realm-admin grant) that the test scripts were
   missing.
3. **Smoke tests absent from CI**: The `/swagger` smoke tests added in 007.2 never ran in CI.
4. **Test runners managed their own Docker lifecycle**: `run-api-tests.sh` and
   `run-smoke-tests.sh` started Docker stacks internally, making CI control difficult.

## Solution

### New script: `scripts/start-deployment.sh`

Single entry point for launching any named LCP stack:

```
start-deployment.sh --project <name> --env-file <path> [--rebuild]
```

- `--project` and `--env-file` required; all credentials read from env file.
- Auth profile auto-detected: if `KEYCLOAK_ADMIN_PASSWORD` is non-empty → `--profile auth` +
  full `kcadm` setup (realm, confidential client with `serviceAccountsEnabled` + `realm-admin`,
  test user from `TEST_USERNAME`/`TEST_PASSWORD`).
- Waits for: keycloak (if auth), lcp-server, lcp-agent, lcp-mcp-storage, lcp-mcp-memory,
  lcp-mcp-interactions.

### Modified scripts

| Script                       | Change                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------ |
| `scripts/dev/start-dev.sh`   | Thin wrapper — resolves env file, then `exec start-deployment.sh --project lcp-dev`              |
| `scripts/run-api-tests.sh`   | Pure test runner; local Docker mode removed; defaults to `http://localhost:3000`                 |
| `scripts/run-smoke-tests.sh` | Same treatment as `run-api-tests.sh`                                                             |
| `scripts/run-all-tests.sh`   | Auto-starts `lcp-all` via `start-deployment.sh` if stack not already running; tears down on exit |

### Env file additions

`.env.example` and `.env.testing` now include:

```
KEYCLOAK_REALM=lcp
TEST_USERNAME=test
TEST_PASSWORD=test
```

(`KEYCLOAK_ADMIN_PASSWORD=admin` was already in both files.)

### CI changes (`.github/workflows/ci.yml`)

`api-test` job renamed to `API & smoke tests`. After building images with
`build-push-action`, the job now:

1. `./scripts/start-deployment.sh --project lcp-api --env-file .env.testing`
2. `./scripts/run-api-tests.sh --base-url http://localhost:3000`
3. `./scripts/run-smoke-tests.sh --base-url http://localhost:3000`
4. `docker compose -p lcp-api --profile auth down -v` (cleanup, always runs)

Both suites share one build and one stack. Smoke test results published via
`dorny/test-reporter` to `test-results/smoke.xml`.

## Scripts not changed

- `scripts/dev/stop-dev.sh` — teardown only, already knows `lcp-dev`
- `scripts/run-integration-tests.sh` — no auth profile, manages its own `lcp-integration` stack
- `scripts/run-e2e-tests.sh` — same, `lcp-e2e` stack, no Keycloak
