## Model changes

### Shortcodes for tasks

Tasks ought to be given a shortcode on creation, eg. `000`, `001`, `002`, etc. to help distinguish them with a shorter string than the full prompt. (Task prompts could get quite large.)

The index for the shortcode (`1`, `2`, etc.) should be unique and increment automatically per company, starting at `0`. This is then padded to 3 digits (unless the number requires more digits, in which case it can be longer.)

## Shortcodes for assignments

Similarly, assignments need a shortcode. This is derived from the task shortcode, their index in the task's plan, and their mode (and so could be predictable) - although QA assignments are interesting because they are not in the plan.

Proposed examples:

- `000-000-plan` (task 0, assignment 0, ie. the planning task)
- `000-001-implement` (task 0, assignment 1, an implementation asignment)
- `000-001-qa` (task 0, assignment 1, a QA asignment)

## Company pane

## Task pane

### Assignment lists

It'd be good to separate the incomplete assignments from the completed/failed assignments in the list of the task pane.

At the moment, they're listed as: `<index-in-list>. <role> <status> "<prompt>"`
Let's adjust to: `<index-in-entire-plan>. <role> (<status>) "<prompt>"`

I've wrapped status in brackets, and `index-in-entire-plan` means that, for instance, when the planning assignment completes, it goes to the end of the list but retains its index. (And I think its index should be `0`, ie. assignments _keep_ their index from the plan, even when rendered out of order.)

Let's also add a heading for each set of assignments:

```
Assignments
Incomplete
  2. <role> (<status>) "<prompt>"
  3. <role> (<status>) "<prompt>"

Complete
  0. <role> (<status>) "<prompt>"
  1. <role> (<status>) "<prompt>"
```
