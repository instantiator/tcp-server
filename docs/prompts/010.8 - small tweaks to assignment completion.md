## assignment completion

I've seen agents iterate once or twice trying to complete assignments.

`working-file-path` and `inline-text` don't seem to work nicely for them - and they intuitively seem to choose `file` and `text` for these types.

1. Do we state acceptable values for `type` when describing the use of the assignment completion tool?
2. Let's switch to `file` and `text` (and update all supporting text used to tell the LLM how to use the tool)
   - Can we also modify the tool to accept synomyms, such as `working-file`, `inline-text`, `path`, `filename`

## assignment QA

The assure assignment tool accepts values of `accept` and `reject`. I saw an agent at least once submit `Accept` and have to go round again.

In the case where a value is from an enum or a union type of string literals, or can only be specific values, do we _always_ tell the agent exactly what the acceptable values should be? Do we also indicate to the LLM ahead of time what the acceptable values are? (ie, in the tool description?)

Let's either:

1. add a short note in the prompt for every mode stating that tool calls are case sensitive, or
2. modify tool calls to accept case variants for required strings

What do you think is best? Although this came up in a QA assignment, it should really apply to all modes and tool calls.
