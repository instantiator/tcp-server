# 005.01 — Generated API client

Create a plan to generate typed API definitions from tcp-server's OpenAPI description, and write the small runtime layer that calls it.

> **Follows:** [ADR-021](../../ADRs/ADR-021-web-ui-framework-and-architecture.md) (client generation, caching), [ADR-014](../../ADRs/ADR-014-swagger-endpoints.md) (the OpenAPI source), [ADR-024](../../ADRs/ADR-024-browser-oidc-client-and-token-handling.md) (tokens, 401 policy), [ADR-029](../../ADRs/ADR-029-spa-hosting-and-runtime-configuration.md) (the API address)
> **Needs first:** 004.01 (OIDC client), 002.04 (backend API enablement)

## Model allocation

**The plan must open with a short section allocating work between models.**

- **Opus drives the implementation** and reviews everything before it lands.
- Opus may delegate parts of the work to sub-agents, choosing the most appropriate model for each part.
- Name the parts where **Sonnet** is a good fit — mechanical, well-specified, repetitive or high-volume work — to keep costs down.
- Keep judgement-heavy work with Opus: architecture, security, accessibility behaviour, and anything where an ADR leaves a choice open.

Good Sonnet candidates here: the generation script, the CI drift check, and the per-endpoint query hooks once the conventions are set. Opus should own the fetch wrapper, the error shape, and the query-key convention — the last one is easy to get wrong in a way that only shows up much later.

## Goal

The API description is generated from tcp-server's code and changes whenever a controller does. Generating types from it means the client and server can't silently disagree.

## Requirements

- TypeScript types generated from tcp-server's OpenAPI description.
- The generated types are **committed**, so a contributor can type-check without a running server.
- **CI fails if the committed types are stale**, so drift is caught rather than discovered.
- A small hand-written runtime layer that: attaches the bearer token, turns errors into one predictable shape, and applies the shared 401 policy.
- TanStack Query is the only cache. No second copy of server data anywhere.
- A consistent convention for query keys.

## Implementation notes

- Use `openapi-typescript` for **types only**, with the runtime layer hand-written. A full client generator would produce callable methods that don't know about the shared 401 policy, the token source, or the event-stream invalidation contract — each would need wrapping, leaving two layers to maintain.
- The same runtime concerns are needed by the event stream reader (005.02), so build the wrapper to serve both rather than duplicating them.
- The generated types join `schemas/schema.json` and `docs/licenses.md` as never-edit-by-hand artefacts. Regenerate; don't patch.
- The drift check needs the description, which needs a running tcp-server. Either boot one in CI for that step, or commit a copy of the description alongside the types and diff that. **Decide this explicitly** — it's the one genuinely open question here.
- The API address is always `/api` thanks to the same-origin proxy ([ADR-029](../../ADRs/ADR-029-spa-hosting-and-runtime-configuration.md)). It isn't a runtime setting.
- **Query-key conventions must be settled now, not later.** Live events invalidate by key (005.02), so an inconsistent scheme shows up as events updating some views and not others — a bug that looks like a streaming fault and isn't.
- Get the token at call time from the auth context; never capture it.

## Testing

- Tests for the fetch wrapper: the token is attached, errors are normalised, and a 401 goes through the shared policy.
- A test that the wrapper requests a fresh token per call rather than reusing a captured one.
- Tests for the error shape across the range tcp-server actually returns — 400, 401, 403, 404, 409, 500 — not just the happy path.
- **Verify the drift check works**: change the API description, confirm CI fails; regenerate, confirm it passes.
- Tests for the query-key convention, so an inconsistent key is caught here rather than in a view.
- Confirm nothing in the frontend imports the server-only `@tcp/shared` export.

## Quality gates

- `./dev-environment/scripts/check.sh` passes; fix what it reports.
- Zero lint errors and zero warnings. No `any` casts — including in the boundary between generated types and the runtime layer, which is where they usually creep in.
- The generated artefact is committed and its regeneration command documented.
- The drift check runs in CI, not only locally.
