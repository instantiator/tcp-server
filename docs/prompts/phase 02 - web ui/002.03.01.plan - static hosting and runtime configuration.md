# 002.03.01 — Static hosting and runtime configuration plan

## Context

The web app compiles to a static bundle that must run in several environments
without rebuilding, and nothing in the stack serves it. Three accepted ADRs
converge here: [ADR-029](../../ADRs/ADR-029-spa-hosting-and-runtime-configuration.md)
(one nginx image serving assets and reverse-proxying `/api`, plus a generated
`config.js`), [ADR-025](../../ADRs/ADR-025-browser-event-stream-consumption.md)
(HTTP/2 required, because five-plus simultaneous streams is an ordinary working
state and HTTP/1.1 caps a browser at six per origin), and
[ADR-024](../../ADRs/ADR-024-browser-oidc-client-and-token-handling.md) (redirect
URLs derived from the app's real address).

Today the browser tier drives `vite preview` started by Playwright's own
`webServer` block, which 002.02 marked for deletion here. After this prompt the
deployment serves the app, the tier drives the deployment, and the six-stream
ceiling is provably gone before 005.02 writes the first stream client.

### The decision the ADR didn't confront

**Browsers only negotiate HTTP/2 over TLS.** No browser implements cleartext
h2c, and Vite's dev server cannot do HTTP/2 at all (it dropped spdy; `server.https`
is HTTP/1.1 over TLS). ADR-029 offers "enable HTTP/2 on the Vite dev server" as
an option — that option does not exist.

So, confirmed with the user:

- nginx listens **HTTPS-only** on `EXPOSE_PORT_WEB`, with `http2 on`. The
  entrypoint generates a self-signed `localhost` certificate at startup unless
  one is mounted at `/etc/nginx/certs`. **mkcert is the documented path to a
  trusted certificate** and gets a step-by-step section in `docs/web-client.md`.
- The dev loop runs **the same nginx image in front of `vite dev`**, via a
  `docker-compose.dev-web.yml` overlay mirroring the existing
  `docker-compose.dev-ports.yml`. Dev gets HTTPS+h2, the same `/api` path as
  deployment, and keeps HMR (Chrome falls back to a separate HTTP/1.1
  connection for the WebSocket, since nginx doesn't implement RFC 8441).

This needs an ADR-029 amendment recording that HTTP/2 forced TLS at the edge and
that the "HTTP/2 on the Vite dev server" option was struck as impossible.

### Ports

| Variable              | dev  | testing | What listens                                                   |
| --------------------- | ---- | ------- | -------------------------------------------------------------- |
| `EXPOSE_PORT_WEB`     | 5173 | 5174    | nginx, HTTPS + h2 — the address people and tests use           |
| `EXPOSE_PORT_WEB_DEV` | 4173 | —       | `vite dev`, HTTP/1.1, reached only by nginx in the dev overlay |

5173 was already reserved for the web app in `.env.example`; 4173 was `vite
preview`'s port and is freed by deleting the `webServer` block. Only
`EXPOSE_PORT_WEB` goes into `check-ports.sh` — `EXPOSE_PORT_WEB_DEV` is a host
process the deployment doesn't publish, and pre-flighting it would fail whenever
a dev server is legitimately already running.

## Work

### 1. nginx configuration and entrypoint — `docker/nginx/`

Three new files. The `nginx:alpine` image runs every `/docker-entrypoint.d/*.sh`
in name order before starting nginx, so no custom `ENTRYPOINT` is needed.

**`docker/nginx/10-tcp-init.sh`** (one script, three jobs — cert, `config.js`,
conf selection):

- If `/etc/nginx/certs/tls.crt` is absent, generate a self-signed pair into it:
  `openssl req -x509 -newkey rsa:2048 -nodes -days 3650 -subj /CN=localhost
-addext subjectAltName=DNS:localhost,IP:127.0.0.1`. A mounted cert always wins.
- Write `/usr/share/nginx/html/config.js` from `OIDC_ISSUER_URL` and
  `OIDC_CLIENT_ID` — exactly ADR-029's shape:
  `window.__TCP_CONFIG__ = { oidcIssuerUrl: '…', oidcClientId: '…' };`
  Fail loudly (non-zero exit) if either is empty: a container that boots with an
  empty issuer produces an auth failure three prompts later with no clue why.
- Select the conf: `envsubst '$WEB_UPSTREAM' < /etc/nginx/tcp/proxy.conf.template
  > /etc/nginx/conf.d/default.conf`when`WEB_UPSTREAM`is non-empty, else copy`static.conf.template`. Explicit `envsubst`with a single-variable allowlist —
**not** the image's built-in template pass, whose unfiltered substitution would
eat`$uri`, `$host` and friends if a matching env var ever appears.

**`docker/nginx/static.conf.template`** — deployment mode:

```nginx
server {
  listen 443 ssl;
  http2 on;
  ssl_certificate     /etc/nginx/certs/tls.crt;
  ssl_certificate_key /etc/nginx/certs/tls.key;
  root /usr/share/nginx/html;

  # Never cached: a config.js from a previous environment points the app at the
  # wrong identity provider, and the failure gives no hint of its own cause.
  location = /config.js { add_header Cache-Control "no-store" always; }

  # Content-hashed by Vite, so the name changes whenever the bytes do.
  location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable" always; }

  location /api/ {
    proxy_pass http://tcp-server:3000;
    proxy_http_version 1.1;
    # SSE dies behind a buffering proxy — nginx would hold each event until the
    # buffer filled, which for a live view is indistinguishable from a hang.
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 24h;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # Deep links: React Router owns any path that isn't a file and isn't /api.
  location / { try_files $uri $uri/ /index.html; }
}
```

Controllers already carry an `api/` route prefix (`@Controller('api/company')`
and friends), so `proxy_pass` takes no trailing slash and no path rewrite.

**`docker/nginx/proxy.conf.template`** — dev mode: identical `listen`, TLS,
`config.js` and `/api/` blocks, but `location /` becomes
`proxy_pass ${WEB_UPSTREAM};` with `proxy_http_version 1.1;`,
`proxy_set_header Upgrade $http_upgrade;` and `proxy_set_header Connection
"upgrade";` so Vite's HMR WebSocket survives the hop. No `try_files` — Vite
serves its own fallback.

`shellcheck` must pass on the init script.

### 2. Dockerfile — a `web-builder` stage and a `tcp-web` stage

The existing `builder` stage runs `npm run build:apps`, which is
`--workspace apps/backend` only — **the frontend bundle is not built in any
current image**. Add, at the end of [Dockerfile](../../../Dockerfile):

```dockerfile
# The shared `builder` runs build:apps, which is backend-only. The web bundle
# is built in its own stage so the six Node images don't pay for it.
FROM builder AS web-builder
RUN npm run build --workspace apps/frontend/tcp-frontend

FROM nginx:1.29-alpine AS tcp-web
RUN apk add --no-cache openssl
COPY --from=web-builder /app/apps/frontend/tcp-frontend/dist /usr/share/nginx/html
COPY docker/nginx/static.conf.template docker/nginx/proxy.conf.template /etc/nginx/tcp/
COPY docker/nginx/10-tcp-init.sh /docker-entrypoint.d/
RUN chmod +x /docker-entrypoint.d/10-tcp-init.sh
EXPOSE 443
```

No `node_modules`, no Node runtime — ADR-029's stated shape.

### 3. Compose service and dev overlay

[docker-compose.yml](../../../docker-compose.yml), after `tcp-server`:

```yaml
tcp-web:
  build: { context: ., dockerfile: Dockerfile, target: tcp-web }
  image: tcp-web:latest
  restart: unless-stopped
  environment:
    OIDC_ISSUER_URL: ${OIDC_ISSUER_URL:-http://localhost:${EXPOSE_PORT_ZITADEL:-8080}}
    OIDC_CLIENT_ID: ${OIDC_CLIENT_ID}
  depends_on:
    tcp-server: { condition: service_healthy }
  ports:
    - '${EXPOSE_PORT_WEB:-5173}:443'
  healthcheck:
    # busybox wget; the cert is self-signed by default, so skip verification.
    test:
      [
        'CMD-SHELL',
        'wget --no-check-certificate -qO- https://localhost/config.js || exit 1',
      ]
    interval: 10s
    timeout: 5s
    retries: 5
```

`OIDC_CLIENT_ID` is the public browser client. Until 004.01 registers a
dedicated PKCE application it takes the same value the rest of the stack uses;
note that in the service comment so 004.01 finds it.

New [docker-compose.dev-web.yml](../../../docker-compose.dev-web.yml), header comment
modelled on `docker-compose.dev-ports.yml`:

```yaml
services:
  tcp-web:
    environment:
      WEB_UPSTREAM: http://host.docker.internal:${EXPOSE_PORT_WEB_DEV:-4173}
    extra_hosts:
      - 'host.docker.internal:host-gateway' # no-op on Docker Desktop, required on Linux
```

`start-deployment.sh` gains a `--dev-web` flag that appends this file to
`COMPOSE_FILES`, exactly as `--dev-ports` does.

New `test/browser/hosting.spec.ts`:

1. **HTTP/2 is negotiated, asserted not assumed.** In-page,
   `performance.getEntriesByType('resource')` and the navigation entry both
   report `nextHopProtocol === 'h2'` — for a static asset _and_ for a request
   through `/api`.
2. **Multiplexing, not six connections.** Fire eight concurrent requests, then
   assert every entry is `h2` and that exactly one entry shows a real TCP
   connect (`connectEnd > connectStart`) — the rest reused it. This is the
   property that removes the ceiling, and it is provable today.
   _The prompt asks for a >6 simultaneous **event stream** test. That needs
   long-lived authenticated SSE connections, and there is no browser auth until
   004.x and no stream client until 005.02 — eight instant 401s prove nothing.
   The multiplexing assertion above is the real content of that test; the
   end-to-end version belongs in 005.02 and is recorded as a follow-up there._
3. **Cache headers differ.** `/config.js` → `no-store`; a hashed
   `/assets/*.js` → `immutable`.
4. **Deep link on a fresh load.** `page.goto('/company/does-not-exist')` returns
   200 and the app shell, not 404 — a full navigation, not in-app routing.
5. **`/api` reaches tcp-server.** A request through `/api` returns a tcp-server
   response (401 from a guarded route is a valid proof of reach; assert the body
   or a Nest-shaped error, not merely the status).
6. **`config.js` defines `window.__TCP_CONFIG__`** with a non-empty issuer.

Port pre-flight is covered by a shell check, not Playwright: bind
`EXPOSE_PORT_WEB` and assert `check_exposed_ports` exits non-zero naming it.

## Risks

- **HMR through nginx over h2** — Chrome should open a separate HTTP/1.1
  connection for the WebSocket, since nginx doesn't implement RFC 8441. If it
  doesn't, the fallback is `server.hmr.clientPort`/`protocol` pointing HMR
  straight at 4173, bypassing the proxy. Verify at step 7 before building on it.
- **`host.docker.internal` on CI Linux runners** — `extra_hosts: host-gateway`
  covers it, but the dev overlay isn't used in CI anyway.
- **The self-signed warning is a first-run papercut.** mkcert removes it; the
  documentation has to make that a two-minute path or people will not do it.

## As implemented

Delivered as planned, with four things the plan did not foresee.

- **Vite had to be told to listen on all interfaces.** `--dev-web` returned 502
  on every request: Vite binds to loopback by default, and
  `host.docker.internal` arrives on the host's bridge interface, not on
  `127.0.0.1`. `server.host: true` in `vite.config.ts` fixes it. That opens the
  development port to the local network — Vite's own `allowedHosts` still
  refuses any request whose `Host` header isn't localhost, which is the
  mitigation, but the port is open and the comment says so.
- **The deep-link test asserts the document, not a rendering.** The plan had it
  assert a visible `<h1>`. Only `/` has a route until 003.02, so nothing renders
  at `/company/…` — the assertion would have been testing that prompt's work.
  It now asserts 200, `text/html`, `#root` present, and `config.js` having run,
  which is exactly what nginx's fallback is responsible for.
- **Resource timings are not readable straight after `await fetch(…)`.** That
  await resolves on headers; the timing entry is queued when the entry
  completes. Reading immediately found nothing and reported "HTTP/2 is off".
  `timeConcurrentFetches` in `hosting.spec.ts` drains each body and then polls
  until every entry appears.
- **`.env.dev` is gitignored**, so its `EXPOSE_PORT_WEB` / `EXPOSE_PORT_WEB_DEV`
  additions are local-only. `.env.example` carries them for anyone starting fresh.

Verified against a live stack: HTTP/2 negotiated (`curl` reports `2`, and the
browser's own `nextHopProtocol` reports `h2` for both an asset and `/api`),
`config.js` `no-store` against a hashed asset's `immutable`, a deep link at 200,
`/api/company` returning tcp-server's JSON 401 rather than an nginx page, and
the port pre-flight refusing a collision on 5173. The `--dev-web` loop was
confirmed end to end in a real browser: page over `h2`, HMR socket open at
`wss://localhost:5173/?token=…` on its own HTTP/1.1 connection, app rendering.
All 7 browser tests pass.

### Model allocation in hindsight

Sonnet took §2–§7 in two batches and needed no corrective round on either. The
two allocations that were wrong were both Opus's own: the deep-link assertion
and the resource-timing race were written into the plan as if settled, and both
only surfaced against a running deployment. Nothing there was a model-choice
error — it was specifying test assertions ahead of seeing the system run.
