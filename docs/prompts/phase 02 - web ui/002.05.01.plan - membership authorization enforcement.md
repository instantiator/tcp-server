# 002.05.01 — Membership authorization enforcement plan

## Context

tcp-server authenticates but does not authorize. `JwtAuthGuard` proves _who_ the caller is; nothing checks what they may do. Any token the identity provider will issue reaches every company in the system — its tasks, knowledge, agents, storage and conversations — read and write.

That was survivable while `tcp-cli` was the only client: the operator already held the credentials and the intent to administer the system. A browser client with a **public** OIDC application (ADR-024) removes that accident of exposure. ADR-011's phase-02 amendment records this as a **release gate**: it does not block local MVP development, it does block any deployment reachable beyond localhost.

Confirmed against the code before planning:

- The gate seam from 002.04 exists exactly as the prompt describes: `getCurrentUserIdentifiers` ([current-user.ts](../../../apps/backend/apps/tcp-server/src/auth/current-user.ts#L20-L37)) returns `sub` + `email` deduplicated and possibly empty; `CompanyDbService.list(identifiers?)` treats `undefined` as unscoped and `[]` as member-of-nothing ([company-db.service.ts:155-167](../../../apps/backend/apps/tcp-server/src/db/company-db.service.ts#L155-L167)); `wantsAll` is parsed in `listCompanies` ([api.company.controller.ts:95](../../../apps/backend/apps/tcp-server/src/api/api.company.controller.ts#L95)).
- **`?all=true` has two callers today**: `tcp-cli list-companies` ([company.action.ts:30](../../../apps/backend/apps/tcp-cli/src/lib/crud/company.action.ts#L30)) and the api tier's `ApiHelper` ([ApiHelper.ts:135](../../../apps/backend/test/api/helpers/ApiHelper.ts#L135)). Both must keep working, which is what forces the admin decision below.
- **Every company-bearing entity carries `companyId`** — `TcpTask`, `TcpAgent`, `TcpAssignment`, `TcpRole`, `Conversation`, `CompanyUser` — so indirect resolution is a single lookup per route, never a join chain.
- **Storage keys are company-prefixed**: `{companySlug}/knowledge/...`, `{companySlug}/tasks/...` ([storage-keys.ts](../../../apps/backend/apps/tcp-server/src/storage/storage-keys.ts)). The first path segment is the company slug — that is the handle for `/api/storage`.
- `AuthModule` currently holds only `PassportModule` + `JwtStrategy`; it registers no repositories. It will need `TypeOrmModule.forFeature([...])`.
- `libs/tcp-shared/src/auth/internal-api-key.guard.ts` is the house pattern for a guard: constructor reads config, `canActivate` throws `UnauthorizedException`/`ForbiddenException`.
- `LOCAL_ONLY_ENV_KEYS` is a **secrets** list. The new admin variable is not a secret, so it does not join that list — `start-deployment.sh` still writes it to the `.local` override because the ids it names are regenerated per bootstrap.

### Four decisions taken with the user before planning

1. **Membership only, not permission flags.** The prompt's Requirements ask for ADR-011's flags to be enforced, but `CompanyUser` has no permission columns — only `memberType: creator|owner|member`. Adding them means a migration, defaults, and an admin surface with no UI to drive it. This prompt enforces **membership**; the flag system stays deferred in ADR-011 and is carried forward into `010.01` (which already flags itself as permission-relevant).
2. **`?all=true` and the system routes are gated on a configured admin allow-list** — `TCP_ADMIN_IDENTIFIERS`, comma-separated `sub`s or emails, **default empty so nobody is an admin**. `start-deployment.sh` already knows the bootstrapped human and machine user ids and writes them to the `.local` override, so local dev, `tcp-cli` and the api tier keep working; a real deployment must name its admins explicitly.
3. **Declarative guard, deny by default.** A `@CompanyScope(...)` decorator on every guarded route, or an explicit `@NoCompanyScope('reason')` / `@AdminOnly()`. A guarded route carrying none of them is refused at request time _and_ fails a route-audit test — a route added later cannot silently open.
4. **403 everywhere.** `403 Forbidden — not a member of company <id>`, consistently. It confirms an id exists; that goes in the unresolved notes rather than being traded for a 404 that makes a permissions bug look like a missing record.

No database migration. Every change is a guard, a decorator, configuration, tests or documentation.

### 2. Scope decorators (Opus)

New `apps/backend/apps/tcp-server/src/auth/company-scope.decorator.ts`:

```ts
/** Where a request carries the handle a company is resolved from. */
export type ScopeSource = 'param' | 'query' | 'body';

/** What that handle names — the entity whose `companyId` answers the question. */
export type ScopeVia =
  | 'company' // UUID or slug, resolved via DbService.getCompany
  | 'task'
  | 'agent'
  | 'assignment'
  | 'role'
  | 'conversation' // by slug
  | 'storagePath'; // first path segment is the company slug

export interface CompanyScopeSpec {
  from: ScopeSource;
  key: string;
  via: ScopeVia;
}
```

- `@CompanyScope(...specs: CompanyScopeSpec[])` — sets `COMPANY_SCOPE` metadata. Multiple specs mean "first one present on the request wins" (`GET /api/agent` accepts `companyId`, `roleId` or `assignmentId`).
- `@CompanyScope.missing(message)` is **not** a thing; instead `@CompanyScopeRequired(message)` sets `COMPANY_SCOPE_MISSING_MESSAGE`, used when no spec resolves, so the existing 400 wording on the list routes survives verbatim.
- `@NoCompanyScope(reason: string)` — sets `NO_COMPANY_SCOPE` metadata to the reason string. The reason is mandatory and is printed by the route-audit spec, so an exemption has to be argued in the source.
- `@AdminOnly()` — sets `ADMIN_ONLY` metadata.

### 3. `CompanyResolutionService` (Opus)

New `apps/backend/apps/tcp-server/src/auth/company-resolution.service.ts`. One method:

```ts
/**
 * Resolves the company a request targets, or `null` when the request carries
 * no handle at all. Throws `NotFoundException` when a handle is present but
 * names nothing — a request for a company that doesn't exist is a 404, not a
 * membership failure.
 */
async resolve(req: Request, specs: CompanyScopeSpec[]): Promise<UUID | null>
```

Per `via`:

| `via`          | Lookup                                                                                                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `company`      | `DbService.getCompany(handle)` — already accepts UUID **or** slug; returns `company.id`                                                                                                                         |
| `task`         | task repository `findOneBy({ id })` → `companyId`                                                                                                                                                               |
| `agent`        | `DbService.getAgent(id)` → `companyId`                                                                                                                                                                          |
| `assignment`   | assignment repository → `companyId`                                                                                                                                                                             |
| `role`         | `DbService.getRole(id)` → `companyId`                                                                                                                                                                           |
| `conversation` | conversation repository `findOneBy({ slug })` → `companyId`                                                                                                                                                     |
| `storagePath`  | first `/`-separated segment is the company slug → `DbService.getCompany(slug)`. A segment containing `*` or `?` resolves to `null` (see §5 — the validation route treats that as admin-only, never as unscoped) |

Reads `req.params`, `req.query` and `req.body` by `key`; a non-string value is treated as absent.

### 4. Membership service and guard (Opus)

New `apps/backend/apps/tcp-server/src/auth/membership.service.ts`:

```ts
/** True when any of the caller's identifiers has a CompanyUser row in this company. */
async isMember(identifiers: string[], companyId: UUID): Promise<boolean>
```

`identifiers` empty → `false` without a query (`In([])` must never be reached — the same trap `CompanyDbService.list` documents). Query: `companyUserRepo.findOne({ where: { companyId, identifier: In(identifiers) } })`. **Both `sub` and email are in `identifiers`** — this is the failure the prompt calls a data-shape bug, not a permissions bug.

```ts
/** True when any identifier appears in TCP_ADMIN_IDENTIFIERS. */
isAdmin(identifiers: string[]): boolean
```

Parses the config value once in the constructor: split on `,`, trim, drop empties. Empty list → nobody is an admin.

New `apps/backend/apps/tcp-server/src/auth/company-membership.guard.ts` — `canActivate`:

1. `identifiers = getCurrentUserIdentifiers(req)`.
2. Read metadata via `Reflector.getAllAndOverride` (handler then class).
3. `@AdminOnly()` → allow iff `isAdmin`, else `403 Forbidden — administrator access required`.
4. `@NoCompanyScope(reason)` → allow (authentication alone is the control; the reason documents why).
5. `@CompanyScope(...)` → resolve. `null` and a `@CompanyScopeRequired` message → `400` with that message. `null` and no message → `403`. Resolved → `isAdmin || isMember` else `403 Forbidden — not a member of company <id>`.
6. **No metadata at all → throw.** `500` with a message naming the handler: `CompanyMembershipGuard: <Controller>.<handler> declares no company scope`. Fail closed and fail loud; §6 catches it before it ever ships.

Wire `AuthModule` to provide and export `MembershipService`, `CompanyResolutionService`, `CompanyMembershipGuard`, importing `DbModule` and `TypeOrmModule.forFeature([CompanyUser, TcpTask, TcpAssignment, Conversation])`.
