# 002.02.01 — Testing infrastructure plan

## Context

002.01 scaffolded the frontend workspace and, with it, most of the unit/component
tier: Vitest, Testing Library, jsdom and four working test files already exist at
[apps/frontend/tcp-frontend/](../../../apps/frontend/tcp-frontend/). What is missing is
everything that makes the accessibility rules from
[ADR-026](../../ADRs/ADR-026-web-ui-accessibility-and-component-library.md) and
[ADR-027](../../ADRs/ADR-027-screen-reader-strategy.md) enforceable rather than
aspirational, and the sixth tier
[ADR-028](../../ADRs/ADR-028-frontend-testing-strategy.md) calls for:

- No axe assertion in component tests — jsx-a11y lints at edit time, nothing checks the rendered DOM.
- No announcement testing. ADR-027 makes coalescing and "never word by word" an automated gate, and `@guidepup/virtual-screen-reader`'s Jest-oriented docs are unproven under Vitest.
- No browser tier: no Playwright, no `run-browser-tests.sh`, no CI job.
- Vitest emits nothing into `test-results/`, so the frontend is invisible to CI reporting while all five Jest tiers report JUnit XML.

The outcome: every later prompt in phase 02 has somewhere to put its tests, and
the accessibility bar fails the build rather than a review.

## Model allocation

Opus drives and reviews everything before it lands.

**Sonnet** — mechanical, fully specified by this plan:

- Vitest JUnit reporter wiring and the frontend `package.json` scripts.
- `scripts/run-browser-tests.sh`, copied from `scripts/run-api-tests.sh`.
- The `run-all-tests.sh` step and the CI `browser-test` job (both have four existing examples to copy).
- `docs/testing.md` and `docs/index.md` updates.

**Opus** — where an ADR leaves a choice open:

- The `@guidepup/virtual-screen-reader` compatibility spike and its fallback.
- The browser tier's black-box boundary and the `webServer` escape hatch below.
- The axe helper's rule configuration in jsdom.

## Decisions taken

**Browser tier target.** Nothing serves the SPA until 002.03 adds the nginx
service. `run-browser-tests.sh` still takes `--base-url` and provisions nothing;
the Playwright config carries a `webServer` block with `reuseExistingServer: true`,
so it starts `vite preview` only when nothing already answers on that URL. It goes
inert the moment 002.03's web service exists, and is marked for deletion there.

**Chromium only.** One binary to install and cache. Firefox and WebKit projects
are written into the config but commented out, for 009.01 to enable when there
are six real journeys to justify the CI minutes.

**axe-core directly, not `vitest-axe`.** `vitest-axe` is 0.1.0, last released
against Vitest 0.x, and drags in `chalk`, `lodash-es` and a stale
`dom-accessibility-api`. A ten-line helper over `axe-core` (already a transitive
dep of `@axe-core/playwright`) does the same job.

## Work

### 1. Component-tier accessibility — `src/test-support/axe.ts`

New dev deps in the frontend workspace: `axe-core`.

```ts
/** Fails with the violated rule ids rather than an opaque boolean. */
export const expectNoA11yViolations = async (container: HTMLElement) => {
  const { violations } = await axe.run(container, {
    // jsdom has no layout engine and no canvas, so contrast is unmeasurable
    // here. The browser tier's @axe-core/playwright scan covers it for real.
    rules: { 'color-contrast': { enabled: false } },
  });
  expect(violations.map((v) => `${v.id} (${v.nodes.length})`)).toEqual([]);
};
```

Apply it to the existing tests in [src/App.test.tsx](../../../apps/frontend/tcp-frontend/src/App.test.tsx)
and [src/theme/ThemeProvider.test.tsx](../../../apps/frontend/tcp-frontend/src/theme/ThemeProvider.test.tsx)
— that is what proves it runs and what sets the pattern for 003.\*.

### 2. Announcement testing — the spike

New dev dep: `@guidepup/virtual-screen-reader` (0.32.1, MIT; depends only on
`@testing-library/dom`, `@testing-library/user-event`, `dom-accessibility-api`
and `html-aria` — no Jest, which is the encouraging sign).

Write `src/test-support/screen-reader.test.tsx`: a throwaway live-region
component defined in the test file (the real announcer is 003.03's), driven
through `virtual.start({ container: document.body })`, asserting
`spokenPhraseLog()` contains exactly one coalesced phrase after fake timers
advance past a throttle interval — the shape ADR-027 §Detail specifies.

Watch for `virtual.start()` and Vitest fake timers fighting: the simulator
polls the DOM via MutationObserver, so advance timers with
`vi.advanceTimersByTimeAsync` and flush microtasks between dispatch and
assertion. **Confirm before relying on it.**

_If the spike fails:_ fall back to Layer 1 only (assert on the live region's
`textContent`), record the finding as an amendment to ADR-027 — it currently
asserts the port "should" work — and note it in `docs/testing.md`. Do not
paper over it with a skipped test.

### 3. Vitest JUnit output

In [vite.config.ts](../../../apps/frontend/tcp-frontend/vite.config.ts)'s `test` block:

```ts
reporters: ['default', 'junit'],
outputFile: { junit: '../../../test-results/frontend.xml' },
```

Matching the five Jest configs' `outputDirectory: "<rootDir>/../../test-results"`.
The frontend already rides the unit tier — root `npm test` fans out to
`--workspaces`, so `run-unit-tests.sh` runs it today with no change.

### 4. The browser tier

New dev deps in the frontend workspace only: `@playwright/test`, `@axe-core/playwright`.

- `apps/frontend/tcp-frontend/playwright.config.ts` — chromium project, `reporter: [['list'], ['junit', { outputFile: '../../../test-results/browser.xml' }]]`, `baseURL` from `process.env.TCP_WEB_URL`, and the `webServer` escape hatch carrying a `ponytail:` comment naming 002.03 as its removal point.
- `apps/frontend/tcp-frontend/test/browser/tsconfig.json` — extends the workspace tsconfig, `"types": ["node"]`, no DOM-only assumptions. Needed because the workspace `tsconfig.json` is browser-only (`"types": []`) and only includes `src/**/*`. eslint's `projectService: true` discovers it automatically. Add it as a third `tsc --noemit -p …` in the workspace `typecheck` script.
- `test/browser/app-shell.spec.ts` — the one proving journey: load the app, query the `h1` by role and accessible name, and run `new AxeBuilder({ page }).analyze()` with zero violations. Deliberately thin; 009.01 owns the six real journeys.
- `scripts/run-browser-tests.sh` — copied from [scripts/run-api-tests.sh](../../../scripts/run-api-tests.sh): `--base-url` (default `http://localhost:${EXPOSE_PORT_WEB:-5173}`, read from the env file the way `run-all-tests.sh` derives `EXPOSE_PORT_API`), `-- <playwright options>` passthrough, `usage()` in the same house style. It also runs `npx playwright install chromium` when the binary is absent, so the download stays opt-in for contributors who never invoke this script.

Wire-up: root `package.json` gains `"test:browser": "npm run test:browser --workspace apps/frontend/tcp-frontend"` (matching `test:api`/`test:smoke`); `.gitignore` gains `playwright-report/`.

## Verification

Infrastructure that has never failed is unproven, so each check is a deliberate break:

1. **Each tier fails when it should.** A failing assertion added to (a) a Vitest component test, (b) the Playwright spec — confirm each fails its own script _and_ `run-all-tests.sh`, then remove.
2. **axe actually fires.** Add an unlabelled `<img>` to a rendered component; confirm the component test fails naming `image-alt`. Remove.
3. **The screen reader mechanism works.** `spokenPhraseLog()` returns the coalesced phrase, and does _not_ contain per-token entries. This is the spike's pass condition.
4. **The browser tier is black-box.** Run `./scripts/run-browser-tests.sh --base-url http://localhost:4173` against a separately-started `vite preview`, and confirm Playwright reuses it rather than starting a second server.
5. **CI reporting.** Confirm `test-results/frontend.xml` and `test-results/browser.xml` both exist after a local run and parse as JUnit; confirm both reporter steps appear in the CI run on the PR branch.
6. **The whole gate.** `./dev-environment/scripts/check.sh`, `npm run shellcheck`, then `./scripts/run-all-tests.sh` — zero lint errors, zero warnings, no `any` in test mocks.

Commit to `p02/002_monorepo-restructuring`; the user opens the PR into `phase-02`.

## As implemented

**The spike passed.** `@guidepup/virtual-screen-reader` 0.32.1 works under Vitest 4 and jsdom with no Jest present, and is stable over repeated runs — so the fallback to live-region assertions alone was not needed. It did contradict ADR-027's snippet in three ways, all now recorded as an [ADR-027 amendment](../../ADRs/ADR-027-screen-reader-strategy.md#amendment-as-implemented-00202): `spokenPhraseLog()` is a Promise, `start()` seeds the log with a `'document'` phrase that must be cleared, and phrases carry a politeness prefix (`'polite: …'`) — which turns out to be an improvement, since the per-surface politeness column becomes assertable in the same expression as the wording. Fake timers need `shouldAdvanceTime: true`, or the simulator's own awaits never settle.

Four departures from the plan:

- **The launcher defaults to `http://localhost:4173`, not `EXPOSE_PORT_WEB`.** 4173 is `vite preview`'s port, which is what actually serves the app at this stage; `EXPOSE_PORT_WEB` (5173) belongs to a service 002.03 has yet to build. Pointing the default at a port nothing listens on would have made the tier fail out of the box. 002.03 moves the default when the service exists.
- **`test/browser/tsconfig.json` is standalone rather than extending the workspace config.** The workspace `tsconfig.json` describes a browser bundle — `"types": []`, no Node — so extending it means overriding most of what it sets. It is named `tsconfig.json` (not folded into `tsconfig.node.json`) because eslint's `projectService` discovers projects by that filename, and typed rules must keep working on the specs. `playwright.config.ts` joined `tsconfig.node.json`, and like `vite.config.ts` was eslint-ignored for the same reason. **Superseded:** see the note below.
- **Playwright artefacts go to `test-results/browser-artifacts/`**, via an explicit `outputDir`. The default would have been `apps/frontend/tcp-frontend/test-results/`, which the repo-root-anchored `/test-results` gitignore entry does not cover, and which CI would not have uploaded.
- **`retries: 0`, including in CI.** The plan did not specify one, and Playwright's `--init` default of 1-in-CI was written in and then removed: 009.01 requires a suite reliable without retries, and a retried test reports green while staying untrustworthy. `trace: 'retain-on-failure'` follows from it — with no second attempt, the only run has to be diagnosable.

Verified: axe fires (an unlabelled `<img>` fails a component test naming `image-alt`); a failing Vitest test exits `run-unit-tests.sh` non-zero through `npm test --workspaces`, which was the propagation worth checking; a failing Playwright test exits `run-browser-tests.sh` non-zero and lands a `<failure>` in `browser.xml` plus a screenshot in the artefact directory; and Playwright reuses an already-running `vite preview` rather than starting a second one (1.6s against 7.5s cold), which is the black-box behaviour 002.03 depends on.

## Follow-up: the TypeScript projects were rearranged (2026-08-04)

Opening `playwright.config.ts` in an editor reported `process` as undefined, while `npm run typecheck` passed. Editors resolve a file by walking up to the nearest file _named_ `tsconfig.json` and ignore every other name — so `tsconfig.node.json` typechecked those files on the command line while the IDE fell back to a default project with no `types` at all.

The fix an editor suggests — add `"node"` to the browser project's `types` — is the one to avoid: it makes `process`, `Buffer` and `fs` typecheck inside `src/`, dissolving the boundary ADR-022 exists to hold. Confirmed by probe, not assumed.

Project references are the documented answer and are not usable here: a referenced project must be `composite`, `composite` requires a closed file list, and the browser project reaches across the workspace into `@tcp/shared`'s _sources_ rather than its built types. `tsc --build` fails with TS6307 on every shared model.

So each project now sits in the directory it governs, and no project is named anything but `tsconfig.json`:

| Project                      | Governs                                                          |
| ---------------------------- | ---------------------------------------------------------------- |
| `tsconfig.json`              | `vite.config.ts`, `playwright.config.ts` — the Node-side tooling |
| `src/tsconfig.json`          | the browser bundle, still `"types": []`                          |
| `test/browser/tsconfig.json` | the Playwright specs                                             |

`tsconfig.node.json` is gone. A bonus: with the tooling configs now in a project `projectService` can discover, both are linted in full with typed rules instead of being eslint-ignored.
