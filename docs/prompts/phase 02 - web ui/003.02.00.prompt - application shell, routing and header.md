## Goal

Everything after this prompt renders inside this shell. Getting the routing, the header and the navigation accessibility right once means later views inherit them.

## Requirements

- A route table covering the MVP's pages, with URLs that can be deep-linked, refreshed and shared.
- **A catch-all route.** Carried forward from 002.03: nginx already falls back to `index.html` for any path that isn't a file and isn't `/api`, so a deep link always returns the app document with a 200. That is the server half. Until this prompt adds a route table with a not-found route, an unknown path loads the shell and renders **nothing** — a blank page, not a 404. `hosting.spec.ts`'s deep-link test asserts only the document, deliberately, because the rendering half is this prompt's.
- A distinction between public routes (the landing page) and protected ones (everything else).
- **Protected routes work against a replaceable session abstraction.** The real sign-in arrives in 004; this prompt must not wait for it, and must not hardcode assumptions about how sessions work.
- **The theme control already exists — adopt it, don't rebuild it.** Carried forward from 003.01: `ThemeControl` (`src/theme/ThemeControl.tsx`) ships with the landing page as two React Aria radio groups, palette and colour mode, and was written to be reused here. It has its own tests. The landing page stays header-free, so it keeps rendering its own copy.
- **`main` currently lives inside `LandingPage`.** Carried forward from 003.01: when the shell owns the layout there must still be exactly one `main` on the page — either the shell provides it and `LandingPage` drops it, or the landing page renders outside the shell. Two `main` elements is an axe violation, and `LandingPage.test.tsx`'s accessibility assertion will not catch it, because it only scans the page in isolation.
- A header on every page except the landing page, containing:
  - a placeholder for a logo
  - an account menu offering: my profile, my company memberships, and sign out
- A breadcrumb component, used first by the company view (006.01).
- **Navigation is accessible**: moving between pages must not leave a screen reader user stranded.

## Implementation notes

- On route change, move focus to the main heading and announce the page title. The main heading must be programmatically focusable for this to work.
- Focus is managed at exactly four points across the whole app ([ADR-027](../../ADRs/ADR-027-screen-reader-strategy.md)); route change is one of them. Don't add others here.
- Provide a skip link so keyboard users can bypass the header.
- The account menu uses the standard menu-button pattern from React Aria Components — don't hand-roll it. The pattern already handles keyboard interaction and screen reader semantics.
- **Give the menu its own rules in `src/styles/base.css`.** Carried forward from 003.01: React Aria ships no styling whatsoever, so the menu button, popover and menu items will render as invisible or unreadable until that file carries token-valued defaults for them — the same reason the radio indicator and focus ring had to be added there for the theme control. Component stylesheets still ship with empty rule bodies; `base.css` is the one place the library's own defaults live.
- The menu items open dialogs built in 008.06 and trigger sign-out built in 004.03. Wire them to placeholders here; the point is the shell, not the destinations.
- The session abstraction should be trivially mockable, because every later component test renders inside this shell.

## Testing

- Component tests for the header, querying by role and accessible name, including the account menu's keyboard interaction.
- A test that a protected route redirects when there's no session, and renders when there is — using the mock session, not real auth.
- **The landing page's `h1` is one of the focus targets.** Carried forward from 003.01: making it programmatically focusable must not change its accessible name or its level — `LandingPage.test.tsx` asserts the page's whole heading outline (`[[1, app.title], [2, …], [2, …]]`) and fails if either moves.
- **A test that focus moves to the main heading on route change**, and that the page title is announced. Use `@guidepup/virtual-screen-reader`'s `spokenPhraseLog()` for the announcement, per [ADR-027](../../ADRs/ADR-027-screen-reader-strategy.md).
- A test that the skip link works by keyboard.
- Accessibility assertions on the shell and header, with no violations.
- A test that a deep link renders the right page directly, not only via in-app navigation.

## Quality gates

- `./dev-environment/scripts/check.sh` passes; fix what it reports.
- Zero lint errors and zero warnings, including `jsx-a11y`. No `any` casts.
- No hardcoded user-facing strings, and no literal values in stylesheets.
- Mocking stops at the network boundary: mock the session and API client, not React Router or the query cache.
