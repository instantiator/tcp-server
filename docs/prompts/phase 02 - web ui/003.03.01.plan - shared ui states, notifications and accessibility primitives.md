# 003.03.01 — Shared UI states, notifications and accessibility primitives plan

## Context

[ADR-027](docs/ADRs/ADR-027-screen-reader-strategy.md) is policy with no implementation. This prompt turns it into infrastructure, and it has to land before any live-updating view: retrofitting an announcer means unpicking every component that grew its own live region.

Today `App.tsx` renders one `<p role="status" className="visually-hidden">` above `<Routes>`, fed by `useRouteChange()`, carrying the page title on navigation. That is the whole of the application's announcement machinery. This prompt replaces it with a single application-level announcer that coalesces and throttles, and ships the loading, error, empty and notification components every later view will reuse.

### Confirmed against the code before planning

- **`@react-aria/live-announcer@3.5.1`** (Apache-2.0, published 2026-05-28) is a published one-line re-export of `react-aria/private/live-announcer/LiveAnnouncer`. Its `react-aria: ^3.48.0` dependency dedupes onto the `3.51.0` that `react-aria-components@1.20.0` already pins, so installing it adds a manifest and no implementation. `announce` is **not** on `react-aria-components`' index, and its exports map has `"./private/*": null`, blocking the subpath through it.
- **What `announce()` does**, read from `node_modules/react-aria/dist/private/live-announcer/LiveAnnouncer.mjs`: builds a `<div data-live-announcer="true">` on the _first_ call containing two `role="log" aria-relevant="additions"` children (`aria-live="assertive"` and `"polite"`), `document.body.prepend`s it, then appends the message as a **new child `<div>` per call** — so repeated identical text re-announces. Outside a test environment the first message waits 100ms for the region to attach. `assertiveness` **defaults to `'assertive'`**. Message nodes self-remove after 7000ms; an empty message skips that timer. It is vanilla DOM with no React lifecycle, so `StrictMode` cannot double-invoke it.
- **`@guidepup/virtual-screen-reader`** reports `role="log"` regions the same way it reports `role="status"` — no "added in the same batch" suppression — so the `'polite: …'` prefix convention from ADR-027's amendment and `App.test.tsx`'s existing assertion both survive.
- `react-refresh/only-export-components` is an **error** in this workspace: a context object must live in a different file from its provider (`ThemeProvider.tsx`/`useTheme.ts`). The announcer sidesteps this by being a module singleton with no context at all.
- React Aria's `className` **replaces** the default class; call sites repeat it (`className="react-aria-Button error-state__retry"`).
- `strings.ts` has **no interpolation**. `t(key)` takes a key and nothing else.
- **This prompt adds no new `--tcp-*` token and touches no theme file.** A step that thinks it needs one is a stop-and-report.

### Decisions taken with the user before planning

1. **Take `announce()` via the shim package**, not the `private` subpath and not a hand-rolled pair of regions. It honours ADR-026's stated rationale and keeps Adobe's real-AT testing. The shim's nature goes into unresolved notes with a revisit condition.
2. **One `Notification` component, no plumbing.** `durableHref`/`durableLabel` are _required_ props, so WCAG 2.2.3 "No Timing" is enforced by the compiler rather than by a reviewer remembering it. No queue, no provider, no container, no timer — where notifications sit is 007.01's layout decision.
3. **`ErrorState` uses `role="group"` plus an assertive announcement, not `role="alert"`.** `role="alert"` is a per-component live region, which is exactly what ADR-027 forbids; three failed lists would mount three of them. Going through the announcer also means two errors in one tick coalesce into one assertive phrase. Deliberate deviation, confirmed in 001.02's manual pass.

### Out of scope

Any consumer of these components — 006.01 and 007.01 own the first ones. No browser-tier coverage: no announcing surface is reachable signed out (the not-found page is still the only shell-bearing route a browser can reach), so a browser assertion would prove nothing. No new tokens, no theme edits.

### 1. `strings.ts` — interpolation and the new keys (Opus)

`t` gains an optional params argument. Every existing `t('key')` call site is untouched.

```ts
/** Values interpolated into a string's `{placeholder}` slots. */
export type StringParams = Readonly<Record<string, string | number>>;

export const t = (key: StringKey, params?: StringParams): string =>
  params === undefined
    ? strings[key]
    : strings[key].replace(/\{(\w+)\}/g, (placeholder, name: string) =>
        name in params ? String(params[name]) : placeholder,
      );
```

An unmatched placeholder is **left in place**, so a missing value shows up in the output instead of silently producing "Tasks: added". The doc comment states that this is the whole of the interpolation this application has — no pluralisation, no formatting, no nesting — and that phase 03 still replaces this module rather than every call site, because `t(key, params)` is the signature real libraries offer too.

New keys:

```ts
'announce.separator': ', ',
'announce.routeChange': '{title}',
'announce.tasksAdded': 'Tasks: {count} added',
'announce.tasksCompleted': '{count} completed',

'state.loading': 'Loading {label}…',
'state.error.label': 'Error',
'state.error.announcement': 'Error: {message}',
'state.error.retry': 'Try again',

'notification.label': 'Notification',
'notification.dismiss': 'Dismiss',
```

Wordings are deliberately count-agnostic (`'Tasks: {count} added'`, never `'{count} tasks added'`) because `t` has no plural rules. The two `announce.tasks*` keys exist so the ADR-027 gate asserts the ADR's own example phrase rather than a synthetic one; 007.01 owns the final wording.

### 2. `src/announce/announcer.ts` (Opus)

```ts
import { announce as speak, clearAnnouncer } from '@react-aria/live-announcer';
import { t, type StringKey, type StringParams } from '../strings';

export type Politeness = 'polite' | 'assertive';

/** ADR-027's starting point: "~10 seconds, tuned during the manual pass." */
export const ANNOUNCE_THROTTLE_MS = 10_000;
/** For announcements that must not wait: a route change, a failure. */
export const ANNOUNCE_IMMEDIATE_MS = 0;
/** ADR-027: a wait shorter than this is not worth mentioning. */
export const ANNOUNCE_LOADING_MIN_MS = 1_000;

export interface Announcement {
  /** Changes sharing a channel coalesce into one phrase. One surface, one channel. */
  readonly channel: string;
  /** What changed — never the whole new state. Repeats within a window are counted. */
  readonly change: StringKey;
  /** Values for `change`'s slots. `{count}` is supplied by the announcer. */
  readonly params?: StringParams;
  /** Defaults to `polite`. */
  readonly politeness?: Politeness;
  /**
   * How long to accumulate before speaking. Defaults to ANNOUNCE_THROTTLE_MS
   * when polite and ANNOUNCE_IMMEDIATE_MS when assertive. Taken from the
   * announcement that *opens* a window; later ones do not shorten it.
   */
  readonly throttleMs?: number;
}

export const announce = (announcement: Announcement): void => {
  /* … */
};

/** Test-only. Drops every pending announcement and empties both regions. */
export const resetAnnouncer = (): void => {
  /* … */
};
```

**Buffer:** `Map<bufferKey, { politeness, counts: Map<countKey, { change, params, count }>, timer }>`, where `bufferKey = \`${politeness}:${channel}\``and`countKey = \`${change}:${JSON.stringify(params)}\``.

**Flush:**

```ts
const phrase = [...buffered.counts.values()]
  .map(({ change, params, count }) => t(change, { ...params, count }))
  .join(t('announce.separator'));
speak(phrase, buffered.politeness);
```

Counting by key rather than joining pre-built strings is the thing that makes a burst produce _one clause_: fifty `tasksAdded` calls become `t('announce.tasksAdded', { count: 50 })` → `"Tasks: 50 added"`. Joining strings would give `"Tasks: 1 added, Tasks: 1 added, …"` — one announcement, still a flood, and a naive length assertion would pass it. Two added plus one completed gives ADR-027's own example: `"Tasks: 2 added, 1 completed"`.

**Priming, at module scope after the imports:**

```ts
// Creates both live regions now, empty. A region that appears at the same
// moment as its content is announced by nothing (ADR-027); react-aria delays
// its *first* message by 100ms for exactly that reason, and priming means no
// real announcement ever depends on that delay. The clear removes the empty
// node the priming call appended — an empty message skips react-aria's own
// removal timer, so it would otherwise stay in the log forever.
speak('', 'polite');
clearAnnouncer();
```

Three facts the doc comment must state, because callers depend on all three: **the announcer counts repeats and does not de-duplicate** (two identical calls mean two things happened, so `StrictMode` protection is the _caller's_ job — guard on the value that changed, not on whether the effect has run); a channel's interval is set by the announcement that opens the window; and **no component may render a live region**.

No React context and no provider. ADR-027 asks for "a single application-level announcer", and a module singleton is that more literally than a provider is: it matches react-aria's own model, gives `announce` a stable identity so it never pollutes an `exhaustive-deps` array, and requires no change to `main.tsx` or `render-app.tsx`. There is therefore **no `useAnnouncer()` hook** — components import `announce` directly.

Each check has a distinct failure mode; run them in order.

1. `npm run typecheck -w tcp-frontend` — every existing `t('key')` call site still compiles unchanged.
2. `npm test -w tcp-frontend` — all tiers green, zero lint errors and warnings.

4. **Break the priming deliberately**: remove the module-scope `speak('', 'polite')` and confirm the "announces nothing on import" test still passes but nothing else regresses — this proves the priming is silent rather than load-bearing for the assertions. Restore it.
5. **Grep for stray live regions**: `rg 'aria-live|role="(status|alert|log)"' apps/frontend/tcp-frontend/src` returns only `announcer.ts`'s doc comment and the test queries.

## Risks

- **The announcer is a module singleton, so test isolation is manual.** §6's `afterEach(resetAnnouncer)` is the only thing standing between this and cross-test bleed that presents as a flake in an unrelated file.
- **`announce()` behaves differently under test.** It skips its 100ms first-message delay when `IS_REACT_ACT_ENVIRONMENT` is set, which Testing Library sets. Priming at import removes the difference, but a test that runs _before_ any React render still exercises a different path from the browser — which is exactly the 003.02 failure mode, in a new place.
- **Counting by `JSON.stringify(params)`** makes key ordering significant. Two call sites passing the same params in different orders would count as different changes. Acceptable while every call site is a literal; note it in the doc comment.
- **`role="group"` on `ErrorState` is unconventional** and may read poorly on a real screen reader. 001.02's manual pass is the check, and reverting to `role="alert"` would mean reopening the one-announcer rule.

## As implemented

Everything the prompt asked for landed. Six things differed from the plan.

### `clearAnnouncer`'s type says its argument is required; its runtime says otherwise

The published `.d.ts` declares `clearAnnouncer(assertiveness: Assertiveness)`, while the implementation clears **both** regions when the argument is omitted. `clearAnnouncer()` therefore fails the typecheck, and the announcer calls it once per politeness instead. Worth knowing before writing the call rather than after.

### `useLoadingAnnouncement`'s value-guard was dead code, and the test that "proved" it proved nothing

The plan specified a `useRef` keyed on `loading`, matching `useRouteChange`. Removing it failed **no test** — including the one named "announces once under StrictMode, not twice". `StrictMode` only double-invokes on mount, and on mount no wait has started, so every mount invocation falls out at `if (loading) return` or at the elapsed-time check regardless.

The hook was rewritten to hold only `startedAt`, so every remaining line is load-bearing, and each was then verified by deletion: removing `if (loading) return` fails 2 tests, removing the elapsed check fails 4, removing the timestamp update fails 1. Two tests were added to get there — one that the wait is measured from when it _started_ rather than from mount.

The StrictMode test was kept, with its comment rewritten to say what it actually gates: a future implementation that grows run-count state. It is a regression gate, not a proof of today's code.

### A polite `Notification` waited ten seconds to announce "on appearance"

Caught by a failing test, and a real behaviour bug rather than a test bug. The default throttle is for channels that _accumulate_; a notification is one discrete event that has already happened. It now announces on the immediate window, which still folds several arriving in the same tick into one phrase.

### The route-change announcement is browser-testable after all

The plan ruled out browser coverage on the grounds that no announcing surface is reachable signed out. That was wrong: the not-found page's "Go to the landing page" link is a real route change. Two tests were added to `test/browser/app-shell.spec.ts` — that the announcer's two regions exist and are empty on load, and that navigating lands the page title in the polite one.

This matters more than it looks. react-aria delays its **first** announcement by 100ms in a real browser so the regions have attached, and skips that delay entirely under test — so the announcer's priming, which exists to make the two environments agree, had no test in the environment it was written for. The 001.02 carry-forward was narrowed accordingly.

### `strings.ts` needed one key the plan missed

`notification.announcement` (`'{message}'`). `Announcement.change` is a `StringKey`, so a component announcing a caller-supplied message still needs a key to carry it.

### The burst gate was proven by breaking it

Setting `ANNOUNCE_THROTTLE_MS` to `0` fails exactly one test — the burst test — and nothing else. The constant was restored. A gate that has never failed is unproven, and this one is the reason ADR-027 exists.
