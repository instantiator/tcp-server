## Context

The repo is one npm package. `apps/frontend/tcp-frontend` (arriving in 002.01) cannot share the root tooling — `eslint.config.mjs` sets `sourceType: 'commonjs'` + `globals.node`, and `tsconfig.json` targets Node with decorators on. It also must not resolve `@tcp/shared`'s barrel, which re-exports TypeORM entities, BullMQ, ioredis and MinIO helpers.

[ADR-022](docs/ADRs/ADR-022-monorepo-workspace-structure.md) chose npm workspaces with three members. This change is that migration and nothing else: **a move, not a rewrite.** Every command, script, hook and test that works today works identically afterwards.

### Layout decisions (confirmed with the user; ADR-022 left them open)

- **`apps/backend/apps/<name>/`** — nested. Keeps `nest-cli.json`'s seven project roots, every `tsconfig.app.json`'s `extends "../../tsconfig.json"`, and the `dist/apps/<name>` output shape unchanged.
- **`test/` moves wholesale to `apps/backend/test/`** — all 30 spec files' `../../../apps/tcp-<app>/src/...` imports then resolve unchanged. Zero edits to spec bodies.
- **`libs/tcp-shared/src/client.ts` is types + `WireEvent` only.** The ADR-025 move of `parseWireEvents`/`wire-parse.ts` out of `tcp-cli` is deferred to 005.02, where the SSE client actually needs it.

### Target tree

```text
package.json              # workspaces, cross-cutting scripts, lockfile
tsconfig.base.json        # NEW — shared compilerOptions (see below)
eslint.config.mjs         # stays: one lint entry point, workspace-scoped blocks
Dockerfile                # widened copy layer only
scripts/                  # unchanged location; setup-wizard stays here
apps/
  backend/                # workspace 1
    package.json  nest-cli.json  tsconfig.json
    apps/tcp-{server,agent,cli,mcp-storage,mcp-memory,mcp-interactions,mcp-tasks}/
    test/                 # e2e integration api smoke support + 4 jest configs
    dist/apps/<name>/     # build output lands here
  frontend/tcp-frontend/  # workspace 2 — manifest + configs only
  tcp-stub-llm/           # unchanged, out of scope
libs/tcp-shared/          # workspace 3 — gains package.json + src/client.ts
```

## Implementation

### 1. Moves (`git mv` — keeps history and makes the diff reviewable)

- `apps/tcp-{server,agent,cli,mcp-storage,mcp-memory,mcp-interactions,mcp-tasks}` → `apps/backend/apps/`
- `test/` → `apps/backend/test/`
- `nest-cli.json`, `tsconfig.json` → `apps/backend/`
- `tsconfig.build.json` — grep for references first; nest monorepo mode uses per-project `tsConfigPath`, so it is very likely vestigial. **Delete if unreferenced**, otherwise move alongside.

### 2. Root `tsconfig.base.json` (new)

Moving `tsconfig.json` into `apps/backend/` would leave `libs/tcp-shared/tsconfig.lib.json` extending `../../apps/backend/tsconfig.json` — a library depending on an app's config. Instead:

- `tsconfig.base.json` at the repo root holds today's `compilerOptions` verbatim, **minus** the `paths` block.
- `apps/backend/tsconfig.json` = `{ "extends": "../../tsconfig.base.json", "compilerOptions": { "paths": { "@tcp/shared": ["../../libs/tcp-shared/src/index.ts"], "@tcp/shared/*": ["../../libs/tcp-shared/src/*"] } } }`
- `libs/tcp-shared/tsconfig.lib.json` and `scripts/setup-wizard/tsconfig.json` extend `tsconfig.base.json` too.
- It is deliberately **not** named `tsconfig.json`, so the frontend never inherits Node/decorator settings by proximity.

### 3. Per-app tsconfigs — the only edit is the `libs` reach

In each of the seven `apps/backend/apps/<name>/tsconfig.app.json`:

- `extends: "../../tsconfig.json"` — **unchanged** (now resolves to `apps/backend/tsconfig.json`)
- `outDir: "../../dist/apps/<name>"` — **unchanged** (now `apps/backend/dist/apps/<name>`)
- `paths` — `../../libs/tcp-shared/…` → `../../../../libs/tcp-shared/…`

`apps/backend/apps/tcp-{server,agent}/tsconfig.json`'s `"rootDir": "../.."` now means `apps/backend` — correct, leave it.

`apps/backend/test/tsconfig.json`: `extends` → `../tsconfig.json`; `paths` → `../../../libs/tcp-shared/…`; the `include` reach into `../apps/tcp-server/src/api/turndown-plugin-gfm.d.ts` is **unchanged**.

### 4. `libs/tcp-shared/package.json` (new)

```jsonc
{
  "name": "@tcp/shared",
  "private": true,
  "version": "0.0.1",
  "exports": {
    ".": "./src/index.ts",
    "./client": "./src/client.ts",
  },
}
```

No `dependencies` — npm workspaces hoist the backend's into the root `node_modules`, and adding a duplicated list here would be a second thing to keep in sync. No build step (ADR-022).

### 5. `libs/tcp-shared/src/client.ts` (new)

```ts
export type {
  WireEvent,
  AuditWireEvent,
  StreamDelta,
  TaskChangeSummary,
  AssignmentChangeSummary,
} from './events/wire-events';
export {
  buildTaskChangeSummary,
  buildAssignmentChangeSummary,
  agentEventsChannel,
  taskEventsChannel,
  companyEventsChannel,
} from './events/wire-events';
export type {} from /* DTO model types */ './models';
```

Two properties Opus must verify, not assume:

- **`export type` is erased at emit**, so no decorator or TypeORM import survives. [wire-events.ts](libs/tcp-shared/src/events/wire-events.ts) already uses `import type` exclusively for its model references — its value exports (`buildTaskChangeSummary` etc.) are pure functions, safe to re-export as values.
- **`./models` value exports are not re-exported** — `libs/tcp-shared/src/models/index.ts` re-exports classes carrying `@Entity`/`@Column`. Only named `export type` entries, never `export type *`.

### 6. `apps/backend/package.json` (new)

Takes **all** current `dependencies`, `devDependencies` and `overrides`, plus the app-specific scripts:

```text
build (build:apps), build:apps, build:tcp-cli, start, start:dev, start:debug,
start:prod, start:tcp-cli, typecheck, test, test:e2e, test:integration,
test:api, test:smoke, test:watch, test:cov, test:debug
```

The jest unit config moves here from the root `package.json`, with:

- `roots`: `<rootDir>/apps`, `<rootDir>/test/support`, `<rootDir>/../../libs/tcp-shared`, `<rootDir>/../../scripts/setup-wizard`
- `testPathIgnorePatterns`: `<rootDir>/../../apps/tcp-stub-llm/`
- `moduleNameMapper`: `<rootDir>/../../libs/tcp-shared/src/…`
- `transform.tsconfig`: `<rootDir>/tsconfig.json`
- `setupFilesAfterEach`: `<rootDir>/test/unit-test-setup.ts`
- `coverageDirectory` and the `jest-junit` `outputDirectory` → `<rootDir>/../../test-results` and `../../coverage`, **so CI's `test-results/unit.xml` paths and the existing `.gitignore` entries stay untouched.**

`typecheck` becomes the nine `-p` paths rebased onto the workspace (`apps/tcp-server/tsconfig.json` … `test/tsconfig.json`), with `libs/tcp-shared/tsconfig.json` moving to the root script (§7).

### 7. Root `package.json` (shrinks)

```jsonc
"workspaces": ["apps/backend", "apps/frontend/tcp-frontend", "libs/tcp-shared"]
```

**Every root script `check.sh`, both git hooks, the five `run-*.sh` wrappers and CI call today must keep working from the root.** Delegating scripts, not deletions:

| Script                                                                   | Becomes                                                                                           |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `build`                                                                  | `npm run build --workspaces --if-present && npm run schema:generate && npm run licenses:generate` |
| `build:apps`                                                             | `npm run build:apps --workspace apps/backend`                                                     |
| `typecheck`                                                              | `npm run typecheck --workspaces --if-present && tsc --noemit -p libs/tcp-shared/tsconfig.json`    |
| `test`                                                                   | `npm test --workspaces --if-present`                                                              |
| `test:e2e` / `:integration` / `:api` / `:smoke`                          | `npm run <same> --workspace apps/backend`                                                         |
| `start` / `start:dev` / `start:prod` / `start:tcp-cli` / `build:tcp-cli` | `--workspace apps/backend`                                                                        |

Genuinely cross-cutting, stay verbatim at the root: `lint`, `lint:check`, `format`, `shellcheck`, `licenses:generate`, `hooks:install`, `setup`, `setup:build`.

Rebased at the root: `schema:generate` (`libs/…` path is unchanged), and the three `migration:*` commands → `-d apps/backend/apps/tcp-server/src/data-source.ts`.

Root `devDependencies` keep only what root scripts need — `prettier`, the eslint stack (`eslint`, `typescript-eslint`, `@eslint/js`, `eslint-config-prettier`, `eslint-plugin-prettier`, `eslint-plugin-jsonc`, `globals`), `typescript`, `ts-json-schema-generator`, `license-report`. Note: `setup` invokes `tsx`, which is **not declared anywhere today** — it resolves transitively. Leave that as-is; fixing it is out of scope.

### 8. `apps/backend/apps/tcp-server/src/data-source.ts`

Its globs are **cwd-relative, not `__dirname`-relative**, and `migration:*` runs from the repo root:

```ts
entities: ['libs/tcp-shared/src/models/*.model.ts'],              // unchanged
migrations: ['apps/backend/apps/tcp-server/src/migrations/*.ts'], // rebased
```

### 9. `apps/frontend/tcp-frontend/` (manifest + configs only)

- `package.json` — `{ "name": "tcp-frontend", "private": true }` with `typecheck` and `test:import-boundary` scripts. No framework deps; 002.01 scaffolds.
- `tsconfig.json` — browser lib/target, **no `@tcp/shared` alias**, only `"@tcp/shared/client": ["../../../libs/tcp-shared/src/client.ts"]`. Enforcement layer 1.

### 10. Enforcement (three layers, two buildable now)

1. **tsconfig** — no bare `@tcp/shared` path, as above.
2. **eslint** — add a `files: ['apps/frontend/**/*.{ts,tsx}']` block to the root `eslint.config.mjs` with `no-restricted-imports` naming `@tcp/shared/client` as the replacement, plus `globals.browser` and `sourceType: 'module'` for that scope. Keeping one root config (rather than splitting per workspace now) keeps `npm run lint:check` and its cache as the single lint entry point; 002.01 splits it when React/TSX/JSX parsing actually diverges.
3. **Vite** — deferred to 002.01; there is no bundler yet.

**The runnable check** (prompt requires more than a comment) — a committed fixture plus a script asserting eslint rejects it:

```text
apps/frontend/tcp-frontend/test/fixtures/server-import-must-fail.ts
  import '@tcp/shared';
```

```jsonc
"test:import-boundary": "! eslint test/fixtures/server-import-must-fail.ts"
```

Exclude the fixture from the frontend `tsconfig.json`'s `include`, and add it to `.prettierignore` so the formatter does not touch it. Wire `test:import-boundary` into the frontend's `test` script so `npm test --workspaces` picks it up.

### 11. Dockerfile

Widen the cached copy layer in **both** `builder` and `prod-deps`:

```dockerfile
COPY package*.json ./
COPY apps/backend/package.json ./apps/backend/
COPY apps/frontend/tcp-frontend/package.json ./apps/frontend/tcp-frontend/
COPY libs/tcp-shared/package.json ./libs/tcp-shared/
RUN --mount=type=cache,target=/root/.npm npm ci
```

Six runtime stages: `COPY --from=builder /app/dist/apps/<name>` → `/app/apps/backend/dist/apps/<name>`. Nothing else changes — one `npm ci`, `builder`/`prod-deps` still shared across every target. `docker-compose.yml` needs no edit (`context: .`, `target:` names unchanged).

## Verification

Run in this order; each stage gates the next.

1. **Install** — `npm ci` at the root. Confirm it runs **once** and creates `node_modules/@tcp/shared` as a symlink to `libs/tcp-shared`.
2. **Gate** — `./dev-environment/scripts/check.sh`. Exercises the root delegating scripts (`format` → `lint:check` → `typecheck` → `build` → `test` → shellcheck → aislop) end to end. Zero lint errors **and zero warnings**; aislop must stay at or above `failBelow: 74`.
3. **Enforcement** — `npm run test:import-boundary --workspace apps/frontend/tcp-frontend` exits 0 (i.e. eslint rejected the fixture). Then delete the `import '@tcp/shared'` line from the fixture and confirm the script now **fails** — proving the check is not vacuously green. Restore.
4. **Full suite** — `./scripts/run-all-tests.sh`. This is the primary evidence the move broke nothing.
5. **Each tier individually**, since path changes hit them differently: `./scripts/run-unit-tests.sh`, `run-integration-tests.sh`, `run-e2e-tests.sh`, then `run-api-tests.sh` / `run-smoke-tests.sh` against a stack from `start-deployment.sh`. Confirm each writes its junit XML to the repo-root `test-results/`.
6. **Docker** — `docker buildx bake -f docker-compose.yml tcp-server tcp-agent tcp-mcp-storage tcp-mcp-memory tcp-mcp-interactions tcp-mcp-tasks`. All six images produced; check the build log shows **one** `npm ci` in `builder` and one in `prod-deps`, not one per workspace. Then `./tcp-cli.sh --rebuild --help` to confirm the CLI dist path.
7. **pre-push guard fires** — on a scratch branch, add a throwaway `@Column` to a model in `libs/tcp-shared/src/models/`, commit without a migration, run `bash scripts/hooks/pre-push`. It **must** exit 1 naming that file. Revert the branch. This is the single check whose failure mode is silence.
8. **CI** — every job green, including the bake step.

- Converging the ten `tsconfig` path declarations and four jest mappers onto workspace resolution (ADR-022 calls this optional follow-up).
- Any frontend framework, build tooling or Vite config (002.01).
