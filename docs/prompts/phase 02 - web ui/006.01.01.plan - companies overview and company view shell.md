# 006.01 — Companies overview and company view shell

## Context

Signing in works, the shell renders, the generated API client and the SSE client
exist — and the two pages behind `RequireSession` are still placeholders that
render one `h1` each. This prompt builds the first real signed-in surface: the
list of companies the user belongs to (with live statistics), and the tabbed
frame every company view will sit inside.

`DEFAULT_SIGNED_IN_PATH` is already `/companies`, so this is literally where
every signed-in user lands. For a new user with no memberships the empty state
**is** the whole application, which is why the prompt treats it as first-class.

### The finding that widened this: the generated client is mostly opaque

Planning turned up something worse than a missing DTO. `apps/frontend/tcp-frontend/src/api/schema.d.ts`
types **eight entity schemas as `Record<string, never>`** — `TcpCompany`,
`TcpRole`, `TcpTask`, `TcpAgent`, `TcpAssignment`, `CompanyUser`,
`Conversation`, `AuditEvent` — across **29 operations**. Every hook in
`src/api/queries.ts` except `useCompanies` therefore returns a value with no
properties. They are not merely untyped; they are typed as provably empty, so
reading `.name` off one is a compile error rather than an `any`.

**Why it happens.** The `@nestjs/swagger` CLI plugin is enabled for `tcp-server`
(`apps/backend/nest-cli.json`). It is a TypeScript transformer that synthesises
`@ApiProperty()` metadata by reading the AST — and it only visits files matching
its `dtoFileNameSuffix`, which defaults to `['.dto.ts', '.entity.ts']`. The
entities live in `libs/tcp-shared/src/models/*.model.ts`, matching neither. Nest
still _registers_ each class as a named schema (the controller return types name
them), but with zero properties. TypeScript types are erased at runtime, so
nothing else can recover them. `GET /api/company` is the one usable route only
because 002.04 hand-wrote `CompanyListItemDto` in a `.dto.ts` file.

`GET /api/company/{id}` is a slightly different case: it returns
`Promise<TcpCompany | null>` and has no `@ApiOkResponse`, so Nest emits an
**inline** `Record<string, never>` rather than a `$ref` — it needs an explicit
annotation whatever else changes.

You asked to fix all of them here, and this plan does. Two things worth saying
plainly before it starts:

- **It is 005.01's territory, not 006.01's.** Only `TcpCompany` blocks this
  prompt. The other seven block 007.01 and 008.x, which cannot render an agent,
  task, enquiry or role from a type with no fields. Fixing them now is cheaper
  than fixing them under a feature deadline, and it is one regeneration rather
  than four.
- **`schema.d.ts` will churn heavily** — it is a generated artefact and CI's
  `api-test` job diffs it, so the churn is expected and gated. The diff is not
  reviewable line by line; Step 1's verification is a property check, not a read.

## Step 1 — Make the OpenAPI description honest (Opus)

**No duplication, and no symlinks.** Two mechanisms do it, and the second is the
one that stops the first being actively dangerous.

### 1a — Tell the plugin where the models are (one config line)

In `apps/backend/nest-cli.json`, change `tcp-server`'s plugin entry from the
bare string to the object form:

```json
"plugins": [
  { "name": "@nestjs/swagger", "options": { "dtoFileNameSuffix": [".dto.ts", ".model.ts"] } }
]
```

**Verified, not assumed.** `node_modules/@nestjs/swagger/dist/plugin/compiler-plugin.js`
applies its transformer to _every_ source file in the program and routes each
one by `isFilenameMatched(options.dtoFileNameSuffix, sf.fileName)`, which is
`patterns.some((p) => filename.includes(p))` — a plain substring test, not a
true suffix or a glob. `.model.ts` therefore matches
`libs/tcp-shared/src/models/*.model.ts` whether the path resolves through
`tsconfig`'s `paths` mapping or through the `node_modules/@tcp/shared` symlink.
And the models genuinely are in the program: `webpack.config.js` allowlists
`/^@tcp\/shared(\/.*)?$/` out of `nodeExternals` precisely so the lib is bundled
**from source**, so ts-loader compiles those files and the transformer sees them.

The plugin only emits a static `_OPENAPI_METADATA_FACTORY()` returning a plain
object — **it adds no `@nestjs/swagger` import**, so nothing new reaches the
browser through `@tcp/shared/client`. Confirm with the frontend's
`npm run test:import-boundary`, which is the gate that would catch it.

**Do not** add `@ApiProperty` decorators inside `libs/tcp-shared/src/models/`:
that _would_ put a `@nestjs/swagger` import in a package the browser imports
from. And **do not** symlink `.model.ts` files to `.dto.ts` names — the
substring match means it would technically work, and it would give every entity
two module identities in the program, registering each TypeORM entity twice and
breaking `instanceof`. It is duplication with extra failure modes.

### 1b — `OmitType`, because the model is not the wire shape

This is the part that matters, and it is why 1a alone is not enough.

The models declare their TypeORM relations **required**: `TcpAgent.company!`,
`.role!`, `.assignment!`; `TcpRole.company!`; `TcpTask.company!`;
`TcpAssignment.company!`, `.role!`; `AuditEvent.company!`. But **no relation is
`eager`** (nothing in `libs/tcp-shared/src/models/` sets it) and `relations:` is
used in exactly two places in the whole server —
`api/chat.service.ts:81` and `api/system-drain.service.ts:170` — neither on an
API read path. **Every API response therefore returns relation properties
absent**, with only the FK `*Id` columns populated.

So 1a on its own generates a schema asserting that `TcpAgent.company` is a
required `TcpCompany` object. The frontend would typecheck `agent.company.name`
and crash at runtime — a schema that lies in the dangerous direction, which is
worse than the empty one it replaces.

The fix derives the response shape from the model rather than restating it, in
the controller layer where it belongs. In
`apps/backend/apps/tcp-server/src/api/dto/`:

```ts
import { OmitType } from '@nestjs/swagger';
import { TcpAgent } from '@tcp/shared';

/** {@link TcpAgent} as it appears on the wire: no relation is ever loaded on an
 *  API read path, so the FK columns are the whole of what a caller gets. */
export class AgentResponseDto extends OmitType(TcpAgent, [
  'company',
  'role',
  'assignment',
] as const) {}
```

`OmitType` copies the source class's Swagger metadata — **zero duplication**,
and the `*Id` fields (which _are_ on the wire) are kept. One such class per
entity that has relations, attached with `@ApiOkResponse({ type: X, isArray: … })`.

Entities and the properties to omit:

| Entity          | Omit                                                                       |
| --------------- | -------------------------------------------------------------------------- |
| `TcpAgent`      | `company`, `role`, `assignment`                                            |
| `TcpRole`       | `company`                                                                  |
| `TcpTask`       | `company`, `plannerRole`                                                   |
| `TcpAssignment` | `company`, `role`, `task`, `agent`, `targetAssignment`, `parentAssignment` |
| `TcpCompany`    | `plannerRole`                                                              |
| `AuditEvent`    | `company`, `agent`                                                         |
| `Conversation`  | none found — confirm before assuming                                       |
| `CompanyUser`   | none found — confirm before assuming                                       |

**Confirm each omission against a real response body** rather than against this
table: `curl` the route on a running deployment and diff its keys against the
generated `required` list. If a relation _is_ present on the wire somewhere,
keep it and say so in the DTO's comment.

### 1c — The nullable-return routes

The plugin cannot resolve a union return type to a `$ref`, which is why
`getCompany` (`Promise<TcpCompany | null>`) emits an **inline** empty object
rather than a named one. Annotate those explicitly:

- `api.company.controller.ts` — `getCompany` needs
  `@ApiOkResponse({ type: CompanyResponseDto })`.
- Sweep every controller under `apps/backend/apps/tcp-server/src/` for a
  declared return of `| null` or `| undefined` and annotate each the same way.

### Verification, in order

1. Start the deployment and run `npm run api:generate` (it reads
   `GET /swagger-json` from a live server — there is no source-only path).
2. `grep -c 'Record<string, never>;' apps/frontend/tcp-frontend/src/api/schema.d.ts`
   — exactly **2** survivors, `webhooks` and `$defs`, which are
   openapi-typescript's own boilerplate. None of the eight entity schemas may
   remain.
3. `grep -n '"application/json": Record<string, never>' schema.d.ts` must be
   empty — that is the inline case 1c closes.
4. For each of `company`, `role`, `task`, `agent`, `conversation` and
   `assignment`: `curl` the list route on the running deployment and check that
   every property the schema marks `required` is present in the body. **This is
   the check that catches an overstatement**, and no test in the repo does it.
5. `./dev-environment/scripts/check.sh` — the newly-real types may surface
   genuine mismatches in `src/api/queries.ts` or `src/events/cache.ts`. Fix
   them; do not cast.

**Fallback**, only if 1a's regenerated output still shows empty entity schemas:
report before improvising. Hand-written DTOs are the last resort, not the plan.

**Boundary:** no behavioural change to any handler. Documentation metadata,
`nest-cli.json`, derived DTO classes, and the regenerated `schema.d.ts` only.

## Step 2 — `useLoadingAnnouncement` gains a "nothing to announce" case (Opus)

`src/announce/useLoadingAnnouncement.ts` announces on the falling edge of
`loading`, whatever the outcome. A failed query also leaves `isPending`, so
today a failure would announce **both** `ErrorState`'s assertive message and a
polite "loaded" — two announcements for one event, one of them false.

Widen the parameter to `Announcement | null` and skip when it is `null`:

```ts
export const useLoadingAnnouncement = (
  loading: boolean,
  completion: Announcement | null,
): void => { … if (latest.current === null) return; announce(latest.current); }
```

Callers then pass `error === null ? { … } : null`. The ref already holds the
current render's value, so the falling edge reads the outcome correctly.

003.03 explicitly invited this: _"The shapes are therefore guesses about what
006.01 and 007.01 will want. If either is wrong, changing it there is the right
response."_ Add a test to `useLoadingAnnouncement.test.tsx` asserting silence
when `completion` is `null`, using the existing `virtual.spokenPhraseLog()`
pattern.

## Step 4 — `CompaniesPage` (Sonnet)

Replace `src/pages/CompaniesPage/CompaniesPage.tsx`. Add
`src/pages/CompaniesPage/CompaniesPage.css`. Rewrite `CompaniesPage.test.tsx`.

### The data

`useCompanies()` from `src/api/queries.ts` — **no arguments**. Passing
`{ all: true }` is administrator-only since 002.05 and returns `403` to
everyone else.

### Structure

```tsx
export const CompaniesPage = () => {
  useDocumentTitle(t('page.companies.title'));
  const { data, isPending, error, refetch } = useCompanies();

  useLoadingAnnouncement(
    isPending,
    error === null
      ? { channel: 'companies', change: 'announce.companiesLoaded' }
      : null,
  );

  return (
    <>
      <h1>{t('page.companies.title')}</h1>
      {/* ADR-027 marks the region whose content is loading as busy.
          `LoadingState` deliberately does not, because it does not know how
          much of the page it stands in for — this element does. */}
      <div className="companies-page__list" aria-busy={isPending}>
        …
      </div>
    </>
  );
};
```

Inside the region, in this order:

- `isPending` → `<LoadingState label={t('companies.loading')} />`
- `error !== null` → `<ErrorState message={…} channel="companies" onRetry={() => { void refetch(); }} />`
- `data.length === 0` → the empty state
- otherwise → the list

### The error message

```ts
const message =
  error instanceof ApiError && error.status === 403
    ? t('companies.error.forbidden')
    : t('companies.error.failed');
```

`ApiError` is from `src/api/errors.ts`. A `403` here is a refusal, **not** an
empty state — the user is being told no, not told there is nothing. Comment
that distinction at the branch.

### The empty state

```tsx
<EmptyState heading={t('companies.empty.heading')} headingLevel={2}>
  <p>{t('companies.empty.body')}</p>
</EmptyState>
```

`headingLevel={2}` is the default, and is passed **explicitly** because the page
owns its outline: this sits directly under the page's single `h1`, so `2` is the
next level and writing it down records the decision rather than inheriting it.

### The list and its statistics

A `<ul>` of `<li>`, each containing a react-router `<Link to={`/company/${c.id}`}>`
naming the company, then its three figures as a `<dl>` of `<dt>`/`<dd>` pairs:

| Figure                              | Source                                                              |
| ----------------------------------- | ------------------------------------------------------------------- |
| `t('companies.stat.activeAgents')`  | `c.stats.activeAgents`                                              |
| `t('companies.stat.activeTasks')`   | sum of `c.stats.tasksByStatus[s]` for `s` in `ACTIVE_TASK_STATUSES` |
| `t('companies.stat.openEnquiries')` | `c.stats.openEnquiries`                                             |

Declare the constant in this module:

```ts
// The non-terminal task statuses. `tasksByStatus` is zero-filled by the server
// (002.04), so a missing key is a bug rather than an absent count — read it
// directly and let a `NaN` show rather than defaulting it away.
const ACTIVE_TASK_STATUSES = [
  'ready',
  'planning',
  'in-progress',
  'finalising',
] as const;
```

Do not render the full seven-status breakdown — that is 007.01's tasks list.

Key each `<li>` on `c.id`.

### The stylesheet

`CompaniesPage.css`, copying `LandingPage.css` exactly: the ADR-026 header
comment, then empty rule bodies for `.companies-page__list`,
`.companies-page__company`, `.companies-page__stats`. No colour, spacing or

### Tests

`CompaniesPage.test.tsx`, rendered inside `QueryClientProvider` (with
`retry: false`) and `MemoryRouter`, mocking **fetch**, not the hook, not the

4. Loading: assert `getByRole('progressbar')` and `aria-busy="true"` on the region.
5. Error (500): the failure message, and pressing "Try again" issues a second request.
6. `403`: `t('companies.error.forbidden')` is shown and **no empty state** is rendered.
7. Empty (`[]`): the empty heading, and the body mentions `tcp-cli` —

8. `document.title` is `t('page.companies.title')`.

## Step 5 — `CompanyPage` (Sonnet writes, Opus reviews)

Replace `src/pages/CompanyPage/CompanyPage.tsx`. Add `CompanyPage.css`. Rewrite
`CompanyPage.test.tsx`.

### Where the company comes from

After Step 1, `GET /api/company/{id}` is properly typed and `useCompany(id)`
is usable. **Use it**, plus `useCompanies()`'s cache is irrelevant here — one
route, one request:

```tsx
const { companyId } = useParams();
const {
  data: company,
  isPending,
  error,
  refetch,
} = useCompany(companyId ?? '');
```

If Step 1 took its fallback and `TcpCompany` is still opaque, stop and report
before writing this page — do not work around it with a cast.

### The title, and why it matters

```tsx
useDocumentTitle(company?.name ?? t('page.company.title'));
```

`useDocumentTitle` uses `useLayoutEffect`, so on a cache hit the title is
correct before `useRouteChange`'s effect reads it. On a cold load the route
change announces "Company" and the completion announcement then names the
company — which is the right sequence, and worth an inline comment so nobody
"fixes" it later.

```tsx
useLoadingAnnouncement(
  isPending,
  company !== undefined
    ? {
        channel: 'company',
        change: 'announce.companyLoaded',
        params: { name: company.name },
      }
    : null,
);
```

### Structure

```tsx
<>
  <Breadcrumbs
    items={[
      { label: t('page.companies.title'), to: '/companies' },
      { label: company?.name ?? t('page.company.title') },
    ]}
  />
  <h1>{company?.name ?? t('page.company.title')}</h1>
  {streamError !== null && (
    <ErrorState message={t('company.stream.failed')} channel="company-stream" />
  )}
  <div className="company-page__body" aria-busy={isPending}>
    …loading / error / unavailable / tabs…
  </div>
</>
```

The last `Crumb` omits `to`, which is what marks it `aria-current="page"` —
`Breadcrumbs` takes `readonly Crumb[]` and needs nothing else.

The stream error sits **outside** the busy region: the live connection failing
is not the page failing to load, and it must not be replaced by the spinner.
`useEventStream` already returns it and 005.02 left it deliberately unrendered
for this prompt:

```tsx
const { error: streamError } = useEventStream(
  companyId ? streamUrls.company(companyId) : null,
);
```

Keep that call exactly as it is today — do not open a second connection.

`company === undefined` after a settled, non-erroring query → an `EmptyState`
with `company.unavailable.*` and a react-router `Link` back to `/companies`.

### The tabs

Inline in `CompanyPage.tsx` — one tab list is a dozen lines and a separate file
would be a directory for it. Use `react-aria-components`:

```tsx
{
  /*
   * One tab, deliberately (ADR-020). This looks like over-building and is the
   * opposite: the alternative is a single-view layout that has to be dismantled
   * and rebuilt as tabs when the configuration view lands (002.01) — in a release
   * that also has to get that view right. The tab component is small; the
   * retrofit is not. Do not "simplify" this away.
   */
}
<Tabs className="react-aria-Tabs company-page__tabs">
  <TabList aria-label={t('company.tabs.label')} className="react-aria-TabList">
    <Tab id="activity" className="react-aria-Tab">
      {t('company.tab.activity')}
    </Tab>
  </TabList>
  <TabPanel id="activity" className="react-aria-TabPanel">
    {/* 007.01 renders the live activity view here. */}
  </TabPanel>
</Tabs>;
```

Every `className` repeats React Aria's own default class name, because passing
`className` **replaces** the default rather than composing with it — the trap
`ThemeControl.tsx` and `Header.tsx` both document.

**React Aria's `RouterProvider` is not adopted, and this is the deliberate
decision 003.02 asked for.** `Tabs` renders `role="tab"` buttons, not links, so
nothing here brings React Aria's `Link` into the application; the company rows
and the breadcrumb both use react-router's `Link`. There remains exactly one
link mechanism. Record this reasoning in the component's doc comment — it is
the answer to a question a later prompt will otherwise re-ask.

### The stylesheet

`CompanyPage.css`, same convention: header comment, empty bodies for

4. **Tab keyboard behaviour**, even with one tab: tabbing into the tab list

## Step 6 — `.react-aria-Tab*` rules in `base.css` (Sonnet)

`src/styles/base.css` is the one place React Aria's unstyled defaults are given
values. It has no tab rules, so a selected tab would be indistinguishable from
an unselected one and a focused tab would have no ring — the same failure the
account menu hit in 003.01.

Add, using **only** existing `--tcp-*` tokens and matching the file's existing
comment style:

- `.react-aria-TabList` — layout hooks only.
- `.react-aria-Tab` — padding from `--tcp-space-*`, `cursor: pointer`.
- `.react-aria-Tab[data-selected]` — a visible selected state that is **not
  colour alone** (WCAG 1.4.1): a border or underline using `--tcp-color-accent`
  and `--tcp-border-width`.
- `.react-aria-Tab[data-focus-visible]` — the focus ring, copying
