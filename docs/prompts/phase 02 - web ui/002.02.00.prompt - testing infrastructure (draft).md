# 002.02 — Testing infrastructure

Create a plan to set up the frontend's test tiers: Vitest and Testing Library for units and components, and Playwright as a new browser tier alongside the repo's existing five.

> **Follows:** [ADR-028](../../ADRs/ADR-028-frontend-testing-strategy.md) (testing strategy), [ADR-026](../../ADRs/ADR-026-web-ui-accessibility-and-component-library.md) (audit tooling), [ADR-027](../../ADRs/ADR-027-screen-reader-strategy.md) (announcement testing), [ADR-016](../../ADRs/ADR-016-test-infrastructure-orchestration.md) (existing tier orchestration)
> **Needs first:** 002.01 (application infrastructure)

## Model allocation

**The plan must open with a short section allocating work between models.**

- **Opus drives the implementation** and reviews everything before it lands.
- Opus may delegate parts of the work to sub-agents, choosing the most appropriate model for each part.
- Name the parts where **Sonnet** is a good fit — mechanical, well-specified, repetitive or high-volume work — to keep costs down.
- Keep judgement-heavy work with Opus: architecture, security, accessibility behaviour, and anything where an ADR leaves a choice open.

Good Sonnet candidates here: the runner configuration, the launcher script modelled on `run-api-tests.sh`, and the CI job wiring. Opus should own the `@guidepup/virtual-screen-reader` compatibility spike and the browser tier's black-box boundary.

## Goal

Give every later prompt somewhere to put its tests, and make the accessibility rules from ADR-026 and ADR-027 enforceable rather than aspirational.

## Requirements

- **Unit and component tests** run under Vitest with Testing Library, in the frontend workspace only. The backend keeps Jest and its five tiers exactly as they are.
- **A sixth test tier for browser tests**, using Playwright, with its own launcher script matching the naming of the existing five.
- Accessibility checks run automatically at two levels: as a lint rule while editing, and as an assertion inside component and browser tests.
- Screen reader announcements are testable without a browser or a real screen reader.
- Test output reaches CI in the same format as the existing tiers, so reporting needs no special case.
- Running the whole suite stays a single command.

## Implementation notes

- The browser tier follows the **api/smoke** pattern, not the integration/e2e one: it drives a deployment someone else already started, provisions nothing itself, and takes its base URL as input. `scripts/run-api-tests.sh` is the model to copy.
- It runs against a deployment started by `scripts/start-deployment.sh` with `tcp-stub-llm`, so agent responses are scripted and repeatable.
- `@guidepup/virtual-screen-reader` provides announcement testing — it simulates a screen reader against jsdom, with no OS-level software involved. Its documentation is written against Jest; **confirm it works under Vitest before relying on it**, rather than assuming.
- Both runners emit JUnit XML into `test-results/`.
- Playwright's browser binaries are large. Scope them to the frontend workspace so contributors who never touch the frontend don't pay the install, and cache them in CI or every run pays a download.
- Add the new tier to `scripts/run-all-tests.sh` and to CI as its own job.

## Testing

The deliverable here _is_ testing infrastructure, so verification means proving each tier actually works and actually fails when it should:

- A deliberately failing test in each tier, confirmed to fail the build, then removed or fixed.
- A component test that queries by role and accessible name, and asserts no accessibility violations.
- An announcement test using `@guidepup/virtual-screen-reader`, asserting on `spokenPhraseLog()` — proving the mechanism works before feature prompts depend on it.
- One browser journey end to end (sign-in can wait for 004; use whatever is reachable at this point), proving the tier can drive a real deployment.
- Confirm CI reports results from the new tiers, and that `run-all-tests.sh` includes them.

## Quality gates

- `./dev-environment/scripts/check.sh` passes; fix what it reports.
- Zero lint errors and zero warnings. No `any` casts, especially in test mocks.
- The full suite passes via `./scripts/run-all-tests.sh`.
- Document the new tier in `docs/testing.md`, including how to run it and what it needs running first.
