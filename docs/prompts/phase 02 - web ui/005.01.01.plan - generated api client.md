# 005.01 — Generated API client

## Context

The web UI has no way to call tcp-server. `main.tsx` mounts a `QueryClientProvider` that
nothing queries, `src/auth/access-token.ts` and `src/auth/unauthorized.ts` have no callers,
and the only `fetch(` in the whole frontend is in a browser test that pulls static assets.
This prompt closes that: typed definitions generated from tcp-server's OpenAPI description,
a small runtime layer that attaches the token and normalises errors, and the query-key
convention that 005.02's event-driven invalidation will depend on.

The last item is the one that must be right now. Live events invalidate by key, so a key
scheme that disagrees with the event payload shows up much later as "some views update and
some don't" — a bug that reads as a streaming fault and isn't.

### Confirmed against the code before planning

- **`GET /swagger-json` is the source.** `SwaggerModule.setup('swagger', …)` in
  `apps/backend/apps/tcp-server/src/main.ts`; there is **no `setGlobalPrefix`**, and each
  controller declares its own `api/…` path. So the generated paths already read
  `/api/company`, and the client's `baseUrl` is `''`, not `'/api'`.
- **No global exception filter.** Errors come back in NestJS's default shape,
  `{ statusCode, message, error }`, where `message` is a `string` — or a `string[]` when
  `ValidationPipe` rejects a body. Both must normalise.
- **CI already boots tcp-server.** The `api-test` job runs
  `./scripts/start-deployment.sh --project tcp-api --env-file .env.testing --dev-ports`
  and exports `API_BASE_URL` from `.env.testing`. The drift check is one step inside that
  job, not a new boot.
- **The wire event's entity discriminator takes five values** — `company`, `agent`, `task`,
  `assignment`, `enquiry` (grepped from `payload.entity` across `apps/backend/apps/tcp-server/src`).
  `enquiry` is what the `/api/conversation` endpoints are called on the event side.
- **`.prettierignore` already has a "Generated artefacts" block** (`docs/licenses.md`,
  `schemas/schema.json`). The generated types join it, or `format:check` fights the generator.
- **The frontend's `@tcp/shared` boundary is enforced three ways** (eslint
  `no-restricted-imports`, `src/tsconfig.json` paths, and a Vite `resolveId` plugin) and
  proven by `npm run test:import-boundary`. Nothing new is needed — the generated schema is
  the contract, so `src/api/**` imports no shared types at all.

### Decisions taken with the user before planning

1. **`openapi-fetch` (0.17.0, MIT, one dependency) sits between the generated types and our
   middleware.** ADR-021 says "hand-written fetch wrapper"; the hand-written part is still
   ours — token, error shape, 401 policy — but the path/param/response conditional types
   are not worth re-deriving, and they are exactly where the "no `any` at the boundary" gate
   breaks. This needs an ADR-021 amendment (step 9).
2. **The drift check reuses the `api-test` CI job.** One committed artefact
   (`src/api/schema.d.ts`), regenerated from the live server and diffed. No committed
   `openapi.json` — a second artefact with no consumer is a second thing to keep in step.
   This resolves ADR-021's "can be decided at implementation".
3. **Hooks for the whole read surface**, not one proof hook.

### Out of scope

- Mutations. Every `POST`/`PUT`/`PATCH`/`DELETE` is left to the prompt that needs it; the
  client and error shape they will use are built here.
- Streams. `@Sse` routes belong to 005.02.
- Rendering. No `strings.ts` entries, no error UI — `ApiError` carries the server's message
  for diagnosis, and the view decides what a user sees.
- Excluded from "the read surface", deliberately: the two knowledge `GET …/{filename}` routes
  and `GET /api/storage` (binary downloads, not cacheable JSON), `GET /api/system/shutdown`
  (admin-only, no web UI surface), and every `internal/*` controller (API-key auth, not
  browser-reachable).

### 3. The error shape (Opus)

**New file:** `src/api/errors.ts`.

```ts
/**
 * Every failed API call, in one shape.
 *
 * A class rather than a plain object because TanStack Query types `error` as
 * `Error`: an object thrown from a query function loses `instanceof` narrowing
 * at every call site and shows as `{}` in devtools.
 *
 * `message` is tcp-server's, for diagnosis. It is not a user-facing string —
 * views map `status` to their own `t()` key (ADR-021).
 */
export class ApiError extends Error {
  constructor(
    readonly status: number,
    message: string,
    readonly body: unknown,
  ) {
    super(message);
    this.name = 'ApiError';
  }
}
```

Plus two constructors:

- `apiError(response: Response, body: unknown): ApiError` — reads NestJS's default shape.
  `body.message` as a `string` is the message; as a `string[]` (what `ValidationPipe`
  returns) it joins with `'; '`; anything else falls back to `response.statusText`, and
  an empty `statusText` falls back to `` `HTTP ${status}` ``. `body` is stored whatever it is.
- `networkError(cause: unknown): ApiError` — status `0`, message from the caught error.
  A rejected `fetch` (offline, DNS, CORS) never reaches a status code, and a view that
  switches on status needs one value to mean "the request never landed".

**Done:** `src/api/errors.test.ts` (step 7b) passes.
**Boundary:** `body` is `unknown` and stays `unknown` — do not type it as a NestJS error
DTO, and do not narrow it with a cast. Do not import from `@tcp/shared` or `@tcp/shared/client`.

### 4. The client and its middleware (Opus)

**New file:** `src/api/client.ts`.

```ts
import createClient from 'openapi-fetch';
import { getAccessToken } from '../auth/access-token';
import { handleUnauthorized } from '../auth/unauthorized';
import type { paths } from './schema';
import { ApiError, apiError, networkError } from './errors';

/**
 * `baseUrl` is empty, not `/api`. Every tcp-server controller declares its own
 * `api/…` path and there is no global prefix, so the generated paths already
 * carry it. The app is served from the same origin as the API (ADR-029), so a
 * relative path is the whole story and there is no runtime setting.
 */
export const api = createClient<paths>({ baseUrl: '' });

api.use({
  async onRequest({ request }) {
    // Read at the moment of the request, never captured. A held token keeps
    // going out after the user signs in again (ADR-024); `null` means the user
    // is signed out or expired, and the right move is to send no header and
    // let the 401 below route to the one policy.
    const token = await getAccessToken();
    if (token !== null) request.headers.set('Authorization', `Bearer ${token}`);
    return request;
  },
  onResponse({ response }) {
    // Not awaited: `handleUnauthorized()` is a full-page redirect, not a renew
    // that returns something to retry with (ADR-024 amendment (a)). It is
    // already deduplicated, so concurrent 401s need no debounce here.
    if (response.status === 401) void handleUnauthorized();
    return response;
  },
});
```

Then the one helper every hook goes through:

```ts
/** Turns openapi-fetch's `{ data, error }` result into a value or an {@link ApiError}. */
export const unwrap = async <T>(
  call: Promise<{ data?: T; error?: unknown; response: Response }>,
): Promise<T> => { … };
```

- Success (`response.ok` and `data !== undefined`) returns `data`.
- Otherwise throws `apiError(response, error)`. **The body is taken from openapi-fetch's
  `error`, never re-read from the `Response`** — openapi-fetch has already consumed the
  stream, and `response.json()` here throws a misleading "body already read".
- A rejection from the `await` (network failure) is caught and rethrown as `networkError(cause)`.
- A 401 still throws. The middleware started the navigation; the query must settle rather
  than hang while the page unloads.

**On typing `unwrap`:** openapi-fetch's `FetchResponse` is a discriminated union with
`data?: never` / `error?: never` branches. If `T` does not infer cleanly from it, type the
parameter against openapi-fetch's exported `FetchResponse` generic — **do not reach for a
cast or `any`.** If neither works, stop and report.

**Done:** `src/api/client.test.ts` (step 7a) passes.
**Boundary:** do not read the response body inside `onResponse` — the middleware runs before
openapi-fetch parses it, and consuming it there breaks every call. Do not add retry,
refresh-token or backoff logic; do not build a second token source or 401 path.

### 5. The query-key convention (Opus)

**New file:** `src/api/query-keys.ts`.

The rule, and it is the reason this step is Opus's:

> A key is `[entity, scope, …discriminators]`. **`entity` is the string tcp-server puts in
> `payload.entity`**, not the name of the route. That lets 005.02 invalidate everything
> about an entity kind with a one-element prefix, and it is why
> `GET /api/conversation` keys on `'enquiry'`.

```ts
/**
 * The five `payload.entity` values tcp-server publishes (ADR-025). A query key
 * beginning with one of these can be invalidated by a live event; anything else
 * is refetched only by its own hook.
 */
export const EVENT_ENTITIES = [
  'company',
  'agent',
  'task',
  'assignment',
  'enquiry',
] as const;

/** Key prefixes with no event behind them — nothing streams a role or a member list. */
export const STATIC_ENTITIES = ['role', 'company-user', 'knowledge'] as const;
```

Then one `queryKeys` object, every builder returning `as const`:

| Hook data                                 | Key                                                         |
| ----------------------------------------- | ----------------------------------------------------------- |
| `GET /api/company`                        | `['company', 'list', params]`                               |
| `GET /api/company/{id}`                   | `['company', 'detail', id]`                                 |
| `GET /api/agent`                          | `['agent', 'list', params]`                                 |
| `GET /api/agent/{id}`                     | `['agent', 'detail', id]`                                   |
| `GET /api/agent/{id}/history`             | `['agent', 'history', id]`                                  |
| `GET /api/task`                           | `['task', 'list', params]`                                  |
| `GET /api/task/{id}`                      | `['task', 'detail', id]`                                    |
| `GET /api/task/{id}/history`              | `['task', 'history', id]`                                   |
| `GET /api/assignment`                     | `['assignment', 'list', params]`                            |
| `GET /api/assignment/{id}`                | `['assignment', 'detail', id]`                              |
| `GET /api/conversation`                   | `['enquiry', 'list', params]`                               |
| `GET /api/conversation/{slug}`            | `['enquiry', 'detail', slug]`                               |
| `GET /api/company/{id}/roles`             | `['role', 'list', { companyId }]`                           |
| `GET /api/company/{id}/roles/by-slug/{s}` | `['role', 'detail', { companyId, slug }]`                   |
| `GET /api/role/{id}`                      | `['role', 'detail', id]`                                    |
| `GET /api/company/{id}/users`             | `['company-user', 'list', { companyId }]`                   |
| `GET /api/role/{id}/knowledge`            | `['knowledge', 'list', { scope: 'role', roleId }]`          |
| `GET /api/role/{id}/knowledge/status`     | `['knowledge', 'status', { scope: 'role', roleId }]`        |
| `GET /api/role/{id}/knowledge/query`      | `['knowledge', 'search', { scope: 'role', roleId, query }]` |
| `GET /api/company/{id}/knowledge`         | `['knowledge', 'list', { scope: 'company', companyId }]`    |
| `GET /api/company/{id}/knowledge/status`  | `['knowledge', 'status', { scope: 'company', companyId }]`  |

`scope` is the union `'list' | 'detail' | 'history' | 'status' | 'search'`. Params objects
go in as-is; TanStack's hash sorts object keys and drops `undefined`, so `{ all: undefined }`
and `{}` are the same key and no normalisation is needed.

**Done:** `src/api/query-keys.test.ts` (step 7b) passes.
**Boundary:** do not add a route-name-to-entity translation table — the convention exists so
005.02 needs no such thing. Do not add a key for anything this plan lists as out of scope.

## Risks

- **`baseUrl: ''` is the easy thing to get wrong.** `'/api'` looks more correct and produces
  `/api/api/company`. The comment in `client.ts` and the manual check above both name it.
- **The generated file and the formatter will fight** if `.prettierignore` is missed in step
  2 — and the symptom appears in CI as a drift failure, not a formatting one, which sends
  the reader to the wrong place. Step 2's done-condition checks it directly.
- **This deviates from ADR-021's literal wording** by adding `openapi-fetch`. The ADR's
  concern was a _generator_ producing callable methods ignorant of the 401 policy and token
  source; openapi-fetch emits nothing and its middleware hook is precisely where that policy
  goes. Step 9 records it as an amendment rather than leaving the ADR reading as though the
  wrapper were built from scratch.
- **21 hooks is a lot of surface for endpoints no view has been designed against.** The
  mitigation is that they are all the same three lines and none carries options; if 006.01
  finds a hook's signature wrong, changing it is cheap because nothing consumes it yet.
- **Drift feedback is slow** — it lands after the ~6 minute Docker bake in `api-test`. The
  alternative was a second committed artefact and a second check to keep in step. If this
  becomes a real irritant, the cheap half (types match a committed description) can be added
  later without undoing anything here.
- **`p02/004_auth` must merge first.** Branching off the wrong base gives a client whose two
  auth imports do not exist, and the failure will read as a bad import path.
