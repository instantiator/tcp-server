# 009.01 — Browser test suite for MVP journeys

Create a plan to build the end-to-end browser journeys that prove the MVP works against a real deployment.

> **Follows:** [ADR-028](../../ADRs/ADR-028-frontend-testing-strategy.md) (the six journeys, the black-box tier), [ADR-016](../../ADRs/ADR-016-test-infrastructure-orchestration.md) (tier orchestration), [ADR-026](../../ADRs/ADR-026-web-ui-accessibility-and-component-library.md) (accessibility scanning)
> **Needs first:** every MVP feature prompt (003.* – 008.*)

## Model allocation

**The plan must open with a short section allocating work between models.**

- **Opus drives the implementation** and reviews everything before it lands.
- Opus may delegate parts of the work to sub-agents, choosing the most appropriate model for each part.
- Name the parts where **Sonnet** is a good fit — mechanical, well-specified, repetitive or high-volume work — to keep costs down.
- Keep judgement-heavy work with Opus: architecture, security, accessibility behaviour, and anything where an ADR leaves a choice open.

Good Sonnet candidates here: writing the individual journeys once the harness and fixtures exist. **Opus should own the harness, the stub-llm scripting and any flake investigation** — flaky browser tests are worse than none.

## Goal

Component tests mock the network. These journeys don't: they drive a real browser against a real deployment, and they're the only thing that exercises the sign-in redirect, live event streams over a real connection, and HTTP/2 under real connection limits.

## Requirements

Six journeys covering the MVP end to end:

1. Sign in, and reach the companies overview
2. Open a company and see live activity
3. Create a task and watch it progress
4. Chat with a role and receive a streamed reply
5. Answer a user enquiry
6. Sign out, and land back on the landing page

Plus:

- Each journey scans its rendered pages for accessibility violations.
- The suite runs in CI and locally with one command.
- **The suite is reliable.** A flaky browser suite gets ignored, which is worse than not having one.

## Implementation notes

- This tier is **black-box** ([ADR-016](../../ADRs/ADR-016-test-infrastructure-orchestration.md)): it drives a deployment someone else started, provisions nothing itself, and takes its base URL as input. `scripts/run-api-tests.sh` is the model.
- The deployment is started by `scripts/start-deployment.sh` with `tcp-stub-llm`, so agent responses are scripted and repeatable rather than depending on a real model.
- **Sign-in needs a real identity provider round trip.** Zitadel is part of the deployment; work out how a test user authenticates without hardcoding credentials, following how the api tier already resolves test credentials.
- Journeys 3 and 4 depend on agents actually running and streaming. Script `tcp-stub-llm` so they complete predictably — this is where flake will come from if anywhere.
- **Wait on real conditions, not timeouts.** Wait for an element or a state, never a fixed sleep. Live-updating views make this especially important, and especially tempting to get wrong.
- Each journey should be independently runnable and not depend on another having run first.
- Consider what state each journey leaves behind, and whether the next one cares.
- Add the tier to `scripts/run-all-tests.sh` and to CI as its own job, with browser binaries cached.

## Testing

The deliverable is tests, so verification is about the suite's own trustworthiness:

- **Each journey must fail when the feature it covers is broken.** Verify by deliberately breaking something and confirming the right journey fails — a passing test that can't fail is worthless.
- Run the suite repeatedly to shake out flake before declaring it done. Intermittent failures must be fixed, not retried around.
- Confirm accessibility scanning actually runs on each page and reports violations.
- Confirm the suite works against a deployment on a non-default port, since it must not assume one.
- Confirm CI reports results the same way the existing tiers do.

## Quality gates

- `./dev-environment/scripts/check.sh` passes; fix what it reports.
- `shellcheck` passes on the launcher script.
- Zero lint errors and zero warnings. No `any` casts.
- The full suite passes via `./scripts/run-all-tests.sh`, including the new tier.
- Document the tier in `docs/testing.md`: how to run it, what must be running first, and how to debug a failure.
