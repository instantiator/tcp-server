## Goal

Where a user arrives after signing in, and the frame every company view sits in.

## Requirements

**Companies overview**

- Lists the companies the signed-in user belongs to — not every company in the system.
- **`useCompanies({ all })` and `useCompany(id)` already exist**, in `src/api/queries.ts` (005.01), keyed `['company', 'list', params]` and `['company', 'detail', id]`. Use them; don't add a second fetch path for data these already cover.
- Shows a few live statistics for each.
- The statistics are fixed and named, as 002.04 returns them: `stats.activeAgents` (agents that are idle, running or paused), `stats.tasksByStatus` (a `Record<TcpTaskStatus, number>`, **zero-filled** — every status key is present, so a missing key is a bug, not an empty count), and `stats.openEnquiries` (conversations awaiting a user reply). They arrive with the list; there is no second request.
- Selecting a company opens its view.
- **The empty state is a first-class part of this page.** For a new user with no memberships it _is_ the entire application, and it must explain what's happened and what to do about it — not just say "nothing here".
- Loading and error states throughout.
- **The four state components exist — use them, don't build more.** Carried forward from 003.03: `src/components/` holds `LoadingState` (`label`), `ErrorState` (`message`, `channel`, optional `onRetry`), `EmptyState` (`heading`, optional `headingLevel`, `children`) and `Notification`. `EmptyState` takes a heading level because the page owns its outline — pick the one that keeps this page's heading sequence unbroken rather than accepting the `2` default blindly.
- **`LoadingState` does not set `aria-busy`, deliberately.** Carried forward from 003.03: ADR-027 marks the _region_ whose content is loading as busy, and a spinner does not know how much of the page it stands in for. The region is this page's to mark.
- **Announce a completed load with `useLoadingAnnouncement(loading, completion)`**, from `src/announce/useLoadingAnnouncement.ts`. Never announce that loading started. It says nothing on a wait shorter than `ANNOUNCE_LOADING_MIN_MS`, so a fast response stays silent without the caller checking.

**Company view shell**

- A breadcrumb showing `Companies > {company}`, where `Companies` returns to the overview.
- **A tab component, showing a single tab** for the live activity view.
- **The breadcrumb component exists — use it.** Carried forward from 003.02: `src/components/Breadcrumbs/Breadcrumbs.tsx` takes `items: readonly Crumb[]`, where `Crumb` is `{ label: string; to?: string }` and the last crumb omits `to`, which is what marks it `aria-current="page"`. Nothing renders it yet; this prompt is its first consumer.
- **`CompaniesPage` and `CompanyPage` are placeholders to replace, not to add beside.** Carried forward from 003.02: both already exist under `src/pages/`, wired to `/companies` and `/company/:companyId` behind `RequireSession`, each rendering one `h1` and calling `useDocumentTitle`. Keep the paths — `test/browser/hosting.spec.ts` deep-links `/company/…`. Neither has a stylesheet yet; add one with the real markup, following the empty-rule-body convention.
- **Adding or renaming a route means editing `RETURNABLE_ROUTES` too.** Carried forward from 004.02: `src/auth/redirect-target.ts` holds a hand-maintained allow-list of the routes a user may be returned to after signing in — the open-redirect gate, so it cannot simply match the whole route table, whose catch-all matches every address. A guarded route missing from that list still works; a user sent there before signing in just arrives at `/companies` instead, silently. The same file's `DEFAULT_SIGNED_IN_PATH` is hardcoded to `/companies` and is where this prompt's real overview becomes the landing point — confirm it rather than assume it.
- **Give the company view its real title.** Carried forward from 003.02: `useDocumentTitle` takes a value rather than a route-table key precisely so this page can be titled by the company's name once it is loaded. The route-change announcement reads `document.title` back, so a page that leaves the placeholder title in place announces "Company" for every company.
- **No query hook sets `staleTime` or `refetchInterval`.** Carried forward from 005.01: freshness in this application comes from events invalidating the cache ([ADR-021](../../ADRs/ADR-021-web-ui-framework-and-architecture.md)), not from polling. A view that appears to need a poll to stay current has a missing invalidation for 005.02 to add, not a missing hook option to set here.
- **Mutation hooks are unwritten.** Carried forward from 005.01: `queries.ts` covers reads only. The client (`api`, from `src/api/client.ts`) and the error shape it throws (`ApiError`, `src/api/errors.ts`) are built — add whatever mutation this view needs alongside its own work, using them, rather than a second fetch mechanism.
- **`useEventStream(streamUrls.company(id))` already subscribes on the company route.** Carried forward from 005.02: `src/pages/CompanyPage/CompanyPage.tsx` opens this subscription already — build on it rather than opening a second connection to the same stream. Events patch the query cache through `applyEvent`, so a view that keeps its own copy of event state is exactly the mistake this design exists to prevent.
- **The hook returns an `error` that nothing renders yet.** Carried forward from 005.02: `useEventStream` surfaces a stream failure (including the `MAX_STREAMS` cap and a permanent `403`/`401` refusal) as `{ error }`, but nothing displays it today. This prompt owns giving a stream failure a visible state.

## Implementation notes

- Use `GET /api/company` — after 002.04 it returns the user's own companies by default. **Don't pass `?all=true`: since 002.05 it is restricted to the identifiers in `TCP_ADMIN_IDENTIFIERS` and returns `403` to everyone else.** A `403` anywhere in this view is a real error to surface, not an empty state — the user is not being shown "no companies", they are being refused.
- The statistics come back with the company list in one request. Don't fan out per company.
- **Build the tab component now, with one tab.** This looks like over-building and isn't: the alternative is a single-view layout that must be dismantled and rebuilt as tabs when the configuration view lands (010.01), in a release that also has to get that view right. **State this reasoning inline in the code**, or a reviewer — or a tool like ponytail — will reasonably flag it as unnecessary.
- The configuration tab is deliberately deferred ([ADR-020](../../ADRs/ADR-020-web-ui-mvp-scope.md)) because `tcp-cli` already handles company and role configuration.
- The empty state should mention that companies are created through `tcp-cli` — the MVP can't onboard a user entirely in the browser, and pretending otherwise leaves them stuck.
- Use the breadcrumb component from 003.02 and the state components from 003.03; don't build new ones.
- **Never render a live region.** Carried forward from 003.03: the announcer at `src/announce/announcer.ts` owns the only two, and asking it to speak is the only way anything gets announced. It **counts repeats rather than de-duplicating them**, so guard any announcing effect on the value that changed — never on whether the effect has run, which `StrictMode` spends on mount.
- Use React Aria Components' tab pattern rather than hand-rolling tab semantics and keyboard behaviour.

## Testing

- Component tests querying by role and accessible name.
- **A test that the overview shows only the user's companies**, not all of them.
- Tests for loading, error and empty states — the empty state deserves a real test, not an afterthought.
- A test of the tab component's keyboard behaviour, even with one tab.
- A test that the breadcrumb navigates back to the overview.
- A test that a company deep link loads directly.
- Accessibility assertions on both pages, with no violations.
- Mock at the network boundary: mock the API client, not React Router or the query cache.
- **Decide on React Aria's `RouterProvider` if its links start appearing.** Carried forward from 003.02: `Breadcrumbs` is built from `nav`/`ol`/`li` with a react-router `Link`, because React Aria's `Breadcrumb` supplies `aria-current="page"` only through React Aria's own `Link` — adopting it for one component would have meant adopting `RouterProvider` router-wide to stop those links doing full page loads. If this prompt's tab list or company rows bring React Aria links in anyway, take that decision deliberately rather than ending up with two link mechanisms.
