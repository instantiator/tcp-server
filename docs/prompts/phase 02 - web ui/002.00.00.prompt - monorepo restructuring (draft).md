# 002.00 — Monorepo restructuring

Create a plan to restructure this repository into npm workspaces, so a browser application can live alongside the existing NestJS apps without sharing their Node-only tooling.

> **Follows:** [ADR-022](../../ADRs/ADR-022-monorepo-workspace-structure.md) (workspace structure)
> **Needs first:** nothing — this is the first step in phase 02

## Model allocation

**The plan must open with a short section allocating work between models.**

- **Opus drives the implementation** and reviews everything before it lands.
- Opus may delegate parts of the work to sub-agents, choosing the most appropriate model for each part.
- Name the parts where **Sonnet** is a good fit — mechanical, well-specified, repetitive or high-volume work — to keep costs down.

Good Sonnet candidates here: the bulk path rewrites across tsconfig files, eslint globs, Jest patterns and CI paths. Opus should own the `exports` map design, the Dockerfile install layer, and verifying the pre-push guard still fires.

## Goal

Today the repository is a single npm package. A React application can't share the root tooling (it targets Node, with decorators enabled), and it must not import `@tcp/shared`'s main export, which pulls in TypeORM, Redis, BullMQ and MinIO — none of which can run in a browser.

This change makes room for the frontend, and puts each application's manifest next to the application.

## Requirements

- Three workspace members, each with its own `package.json`:
  - `apps/backend/` — the six NestJS apps and `tcp-cli`
  - `apps/frontend/tcp-frontend/` — the new web app (created empty here; scaffolded in 002.01)
  - `libs/tcp-shared/`
- `libs/tcp-shared` gains a `package.json` with an `exports` map that separates the full server-side surface from a browser-safe `./client` surface.
- The browser cannot resolve the server-only export. Enforcement is layered: no path alias for it in the frontend's TypeScript config, a lint rule naming the replacement, and the bundler failing as a last resort.
- **Everything that works today still works afterwards.** This is a move, not a rewrite — no behaviour changes.
- The Docker build keeps its single-install shape: one `npm ci` for the whole workspace, with `builder` and `prod-deps` stages still shared across every service image.

## Implementation notes

- `nest-cli.json` and the root `tsconfig.json` move to `apps/backend/`. The Nest CLI resolves `nest-cli.json` relative to the working directory.
- The root `package.json` shrinks but stays — npm workspaces require it. It keeps `workspaces`, the lockfile, and the genuinely cross-cutting scripts (`schema:generate`, `licenses:generate`, the migration commands, the hook installer).
- `tcp-shared` stays as TypeScript source consumed through the bundlers. It does **not** gain a `tsc` build step.
- The `Dockerfile`'s cached copy layer widens to copy every workspace's `package.json` before `npm ci`.
- ADR-022's Detail section lists roughly fifteen configuration surfaces that need updating. Work through them explicitly — the plan should enumerate them rather than discover them.
- **`scripts/hooks/pre-push`'s migration-drift check fails open.** Its hardcoded `apps/tcp-server/src/migrations/` path must be updated, or the guard silently stops firing and nothing reports it. Verify it still fires after the move.
- `tcp-stub-llm` is deliberately **out of scope** — it has its own TypeScript major and eslint config. Bringing it in is a separate piece of work.

## Testing

- The full existing suite must pass unchanged: `./scripts/run-all-tests.sh`. This is the main evidence that the move broke nothing.
- Verify each tier individually too, since path changes affect them differently: unit, integration, e2e, api, smoke.
- Verify the Docker build still produces every service image, and that `npm ci` still runs once rather than once per workspace.
- Add a check that the frontend workspace cannot import the server-only `@tcp/shared` export — a failing lint rule or a deliberate compile failure, not a comment.
- Confirm the pre-push migration-drift guard still fires by making a model change without a migration.

## Quality gates

- `./dev-environment/scripts/check.sh` passes; fix what it reports.
- Zero lint errors and zero warnings. No `any` casts.
- CI passes on every job, including the Docker bake step.
- Update `docs/development.md`'s source-layout section, and any doc naming the old paths.
