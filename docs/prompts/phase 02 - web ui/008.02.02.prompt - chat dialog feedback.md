## Chat dialog in UI

I tested by creating a chat through TUI with the UI open. The chat was listed, and I was able to open it.

When the dialog opens, it shows several dialog control buttons:

- "Minimise"
- "Close"
- "Close the chat with <role>"

"Minimise" and "Close" both have the same behaviour (the dialog is closed and a button is shown in a fixed position footer representing the minimised chat).

"Close the chat with <role>" closes the dialog and does not show a minimised button in the fixed position footer.

Chat events show successfully, and the input box and "Send" button also work (and are correctly disabled until the assistant has finished responding).

### Button behaviours

Please modify the button behaviours:

- "Minimise" - as currently, should close the dialog and show the minimised button
- "Close" - should destroy the dialog and complete the agent's assignment

"Close the chat with <role>" is a bit redundant - we can remove it.

**Decision, recorded after discussion:** the chat dialog can hold several open
conversations at once, which the note above didn't account for — "Close"
destroying the whole dialog would end every open conversation together, which
is a bigger action than a single button press should hide. Revised plan,
agreed 2026-08-10:

- **"Minimise"** stays exactly as it is: parks every open conversation in the
  dock, dialog unmounts.
- **The dialog-level "Close" button is removed.** It was redundant with
  Minimise anyway (both currently do the same thing — that was the bug this
  feedback opened with), and there's no "destroy everything" action left once
  completion moves to the per-conversation control below.
- **"Close the chat with `<role>`" becomes "Complete the chat with `<role>`"**,
  one per open conversation. It completes that conversation's assignment
  (status → `succeeded`, matching the existing completion path used for
  implement/consultee/finalise assignments — chat mode is currently excluded
  from that path and the guard is relaxed to admit it) and marks the
  conversation complete **in place**: the panel stays open and visible, its
  transcript stays readable, and its message input becomes permanently
  disabled rather than the panel disappearing.
- **Disabled while the agent is `running`** (mid-reply), the same way the
  message input already disables — so a turn's own completion can't land
  against an assignment that was completed out from under it.

This is a new backend capability: today nothing can mark a chat-mode
assignment complete (`assertCompletableBy` in
`assignment-completion.service.ts` explicitly rejects chat mode, and the
`TcpAssignmentMode` type documents chat as having "no completion tool"). See
the 008.02.03 plan/implementation for the endpoint this added.

## Tasks in TUI

Whilst testing, I created a task in the TUI using the task creation panel.

Having created the task, the panel did not close - so I was able to press "Submit" again (creating a second task with the same specification). No error or warning was shown.

Both tasks showed in the UI's task list (good) - suggesting they _were_ created.

Back at the active tasks list (in TUI), on attempting to enter the task panel, the error: `Cannot read properties of undefined (reading 'id')` was shown.

However, the tasks seem to be proceeding, and can be seen in the UI.

### Agents in the UI

Active agents in the UI are showing, and their full prompt shows.

In cases where the full prompt is very long, this takes up a lot of space. It would be good to be able to offer a shortened version, which can be expanded to the full version (and to allow something similar in the accessible view - ie. the shortened version is used, but the full version can be requested).

## Shutting down

I used `./tcp-cli.sh shutdown --help` believing I would see some more info and could make a decision about whether to force or not. The info was shown, but also shutdown was initiated immediately by tcp-cli.

Either I used tcp-cli wrong, or shutdown shouldn't have been initiated when the `--help` option was used. (Possibly both!)
