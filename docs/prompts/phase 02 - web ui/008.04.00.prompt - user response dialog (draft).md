## Goal

An agent that asks a question stops until someone answers. This dialog is how that happens — and it's the reason the MVP is interactive rather than read-only ([ADR-020](../../ADRs/ADR-020-web-ui-mvp-scope.md)): a UI that shows you a blocked agent but can't unblock it leaves the CLI mandatory for the one workflow that's time-sensitive.

## Requirements

- One conversation per open enquiry, showing the question and the context around it.
- The user can type and submit a response.
- Submitting a response closes the enquiry and lets the agent continue.
- Opened from the live activity view's enquiries list, showing the selected enquiry.
- A close control.
- Loading, error and empty states.

## Implementation notes

- The relevant endpoints are the conversation ones: listing open enquiries, reading one with its messages, and replying.
- Replying resumes the agent as a side effect. The reply request may return before the agent has actually resumed — the UI should reflect "sent" honestly rather than implying more than it knows.
- **Handle the already-answered case.** Someone else — or the same user in another tab, or via `tcp-cli` — may have answered between the list loading and the reply being sent. Failing clearly is fine; failing confusingly is not.
- A new enquiry is announced individually rather than folded into a summary ([ADR-027](../../ADRs/ADR-027-screen-reader-strategy.md)) — it's a request for the user to act, not background noise.
- The response field should be properly labelled and usable by keyboard, with a clear path from reading the question to answering it.
- Company timezone context comes back with the conversation; use it when showing times rather than assuming the browser's.

## Testing

- Component tests queried by role and accessible name.
- A test of the full path: open an enquiry, type a response, submit, see the result.
- **A test of the already-answered case**, confirming a clear message rather than a silent failure.
- Tests for loading, error and empty states.
- A test that the dialog is fully operable by keyboard, from reading to submitting.
- **An announcement test using `spokenPhraseLog()`** confirming a new enquiry is announced on its own.
- Accessibility assertions on the dialog, with no violations.

## Quality gates

- `./dev-environment/scripts/check.sh` passes; fix what it reports.
- Zero lint errors and zero warnings, including `jsx-a11y`. No `any` casts.
- No hardcoded user-facing strings, and no literal values in stylesheets.
