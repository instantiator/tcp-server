# 010.01 — Company configuration view

Create a plan to build the company configuration view: the second tab, covering roles, knowledge and company users.

> **Follows:** [ADR-020](../../ADRs/ADR-020-web-ui-mvp-scope.md) (which deferred all of this), [ADR-026](../../ADRs/ADR-026-web-ui-accessibility-and-component-library.md) and [ADR-027](../../ADRs/ADR-027-screen-reader-strategy.md) (accessibility)
> **Needs first:** the MVP is complete (009.03)

## Model allocation

**The plan must open with a short section allocating work between models.**

- **Opus drives the implementation** and reviews everything before it lands.
- Opus may delegate parts of the work to sub-agents, choosing the most appropriate model for each part.
- Name the parts where **Sonnet** is a good fit — mechanical, well-specified, repetitive or high-volume work — to keep costs down.
- Keep judgement-heavy work with Opus: architecture, security, accessibility behaviour, and anything where an ADR leaves a choice open.

Good Sonnet candidates: the list and form components, following the patterns the MVP already set. Opus should own file upload handling and anything touching permissions.

## Goal

> **This is post-MVP.** It's recorded here so the deferred components aren't lost, not because it's next.

[ADR-020](../../ADRs/ADR-020-web-ui-mvp-scope.md) deliberately left configuration out of the MVP: `tcp-cli` already handles company and role configuration well, and the first release focused on the thing the CLI _can't_ do — watching a company live. This prompt closes that gap, and removes the need to reach for the CLI to onboard.

## Requirements

- The second tab in the company view — the tab component was built with one tab in 006.01 precisely so this could be added without rebuilding the layout.
- **Roles**: a list, filterable by name, with a dialog per role showing its details.
- **Role knowledge**: per role, list its documents with upload, download and delete, plus the current indexing status.
- **Company knowledge**: the same for company-wide documents, plus the ability to trigger a re-index.
- **Company users**: a list, with a dialog to add or edit one.
- A way to start a chat with a role from its dialog.

## Implementation notes

- Check `tcp-cli`'s corresponding commands for the real fields and behaviours rather than guessing: role management, knowledge upload and retrieval, index status, and company user management.
- **File upload is new to this application.** Progress, failure and cancellation all need handling, and the accessible upload control is the part most likely to be got wrong.
- Uploads have server-side type restrictions. Surface them before a user picks a file, not only after a rejection.
- Indexing is asynchronous. Decide how status updates reach the user, and whether re-indexing gives feedback beyond "started".
- The API returns soft data-quality warnings on some create and update routes. Surface them.
- **Editing company users is permission-relevant.** If `002.05` (authorization enforcement) has landed, this must respect it; if it hasn't, note that this view exposes membership editing on an API that isn't yet enforcing membership.
- Reuse the MVP's dialogs, states, announcer and transcript components. Don't build parallel versions.
- Deleting knowledge is destructive — confirm first, and manage focus afterwards.

## Testing

- Component tests for every list, dialog and form, queried by role and accessible name.
- Tests for the role name filter, including no matches.
- **Upload tests**: success, rejected file type, failure mid-upload, and cancellation.
- Tests for download and delete, including the delete confirmation and where focus lands after.
- Tests for indexing status display and for triggering a re-index.
- Tests for company user create and edit, including validation errors associated with their fields.
- **A test that the tab component now works with two tabs**, including keyboard navigation between them.
- Accessibility assertions on every view, dialog and form, including error and in-progress states.
- **Announcement tests using `spokenPhraseLog()`** for anything that updates asynchronously, especially indexing status.

## Quality gates

- `./dev-environment/scripts/check.sh` passes; fix what it reports.
- Zero lint errors and zero warnings, including `jsx-a11y`. No `any` casts.
- No hardcoded user-facing strings, and no literal values in stylesheets.
- Update ADR-020 to record that the deferred scope has now landed.
- Update the documentation to reflect that browser-only onboarding is possible, if it now is.
