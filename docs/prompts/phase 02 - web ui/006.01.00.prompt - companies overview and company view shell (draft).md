# 006.01 — Companies overview and company view shell

Create a plan to build the first two signed-in pages: the list of the user's companies, and the frame the company's own views sit inside.

> **Follows:** [ADR-020](../../ADRs/ADR-020-web-ui-mvp-scope.md) (MVP scope, the tab decision), [ADR-023](../../ADRs/ADR-023-backend-api-surface-for-the-web-ui.md) (membership scoping, stats), [ADR-026](../../ADRs/ADR-026-web-ui-accessibility-and-component-library.md) (component library)
> **Needs first:** 005.01 (generated API client), 002.04 (backend API enablement), 003.03 (shared UI states)

## Model allocation

**The plan must open with a short section allocating work between models.**

- **Opus drives the implementation** and reviews everything before it lands.
- Opus may delegate parts of the work to sub-agents, choosing the most appropriate model for each part.
- Name the parts where **Sonnet** is a good fit — mechanical, well-specified, repetitive or high-volume work — to keep costs down.
- Keep judgement-heavy work with Opus: architecture, security, accessibility behaviour, and anything where an ADR leaves a choice open.

This is mostly well-specified list and layout work, and a good fit for Sonnet. Opus should review the tab component's accessibility and the empty state, which matters more than it looks.

## Goal

Where a user arrives after signing in, and the frame every company view sits in.

## Requirements

**Companies overview**

- Lists the companies the signed-in user belongs to — not every company in the system.
- Shows a few live statistics for each.
- Selecting a company opens its view.
- **The empty state is a first-class part of this page.** For a new user with no memberships it _is_ the entire application, and it must explain what's happened and what to do about it — not just say "nothing here".
- Loading and error states throughout.

**Company view shell**

- A breadcrumb showing `Companies > {company}`, where `Companies` returns to the overview.
- **A tab component, showing a single tab** for the live activity view.

## Implementation notes

- Use `GET /api/company` — after 002.04 it returns the user's own companies by default. Don't pass `?all=true`; that's for administrative callers.
- The statistics come back with the company list in one request. Don't fan out per company.
- **Build the tab component now, with one tab.** This looks like over-building and isn't: the alternative is a single-view layout that must be dismantled and rebuilt as tabs when the configuration view lands (010.01), in a release that also has to get that view right. **State this reasoning inline in the code**, or a reviewer — or a tool like ponytail — will reasonably flag it as unnecessary.
- The configuration tab is deliberately deferred ([ADR-020](../../ADRs/ADR-020-web-ui-mvp-scope.md)) because `tcp-cli` already handles company and role configuration.
- The empty state should mention that companies are created through `tcp-cli` — the MVP can't onboard a user entirely in the browser, and pretending otherwise leaves them stuck.
- Use the breadcrumb component from 003.02 and the state components from 003.03; don't build new ones.
- Use React Aria Components' tab pattern rather than hand-rolling tab semantics and keyboard behaviour.

## Testing

- Component tests querying by role and accessible name.
- **A test that the overview shows only the user's companies**, not all of them.
- Tests for loading, error and empty states — the empty state deserves a real test, not an afterthought.
- A test of the tab component's keyboard behaviour, even with one tab.
- A test that the breadcrumb navigates back to the overview.
- A test that a company deep link loads directly.
- Accessibility assertions on both pages, with no violations.
- Mock at the network boundary: mock the API client, not React Router or the query cache.

## Quality gates

- `./dev-environment/scripts/check.sh` passes; fix what it reports.
- Zero lint errors and zero warnings, including `jsx-a11y`. No `any` casts.
- No hardcoded user-facing strings, and no literal values in stylesheets.
