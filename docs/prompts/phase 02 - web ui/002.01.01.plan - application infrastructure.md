## Context

002.00 made the repo an npm workspace and left `apps/frontend/tcp-frontend` as a stub: a manifest, a `tsconfig.json`, one positive-control source file and the import-boundary fixture. Nothing builds, nothing renders.

This prompt scaffolds the application itself. Nothing user-facing ships — the landing page is 003.01. What ships is the set of seams that later prompts depend on and that are disproportionately expensive to retrofit once components exist:

- a single lookup for user-facing strings ([ADR-021](docs/ADRs/ADR-021-web-ui-framework-and-architecture.md#strings-and-theme-tokens))
- CSS custom properties instead of literal values, with two themes × two modes ([ADR-026](docs/ADRs/ADR-026-web-ui-accessibility-and-component-library.md#how-themes-work))
- a theme that is readable **before first paint**, or the page flashes the wrong one
- `eslint-plugin-jsx-a11y` as an error from the first component

It also closes ADR-022's third enforcement layer: Vite failing the build on a bare `@tcp/shared` import. That layer has never existed, and [the ADR-022 amendment](docs/ADRs/ADR-022-monorepo-workspace-structure.md#amendments-as-implemented-00200) says so explicitly.

### Decisions taken with the user

- **Strings**: `t('key')` with keys typed as `keyof typeof strings`. Phase 03 replaces the body of `t()`, not the call sites.
- **Prettier stays shared.** The root `.prettierrc` is two settings and prettier handles TSX/CSS natively; a second copy would be a thing to keep in sync for no behaviour difference. This deviates from the prompt's "own prettier configuration" on that one point — eslint and TypeScript still split per workspace as required.
- **Port wiring**: `vite.config.ts` reads `EXPOSE_PORT_WEB` from the repo-root env files, and `.env.example` gains the variable. `docker-compose.yml`, `derive-urls.sh` and `check-ports.sh` stay with 002.03, where the container exists.

### Out of scope

Playwright, axe assertions and `@guidepup/virtual-screen-reader` are 002.02. nginx, HTTP/2, the SPA fallback and `config.js` are 002.03. This prompt leaves a working `npm test` and three real tests, not a test tier.

### 2. Configuration

**`vite.config.ts`** — `@vitejs/plugin-react`; dev-server port from the repo's env convention:

```ts
// Reads .env.dev / .env.dev.local at the repo root, filtered to EXPOSE_PORT_*.
// Deliberately NOT `envDir` — that would put the repo's env files on Vite's
// own load path, and .env.dev.local holds generated OIDC credentials.
const env = loadEnv('dev', resolve(import.meta.dirname, '../../..'), 'EXPOSE_PORT_');
server: { port: Number(env.EXPOSE_PORT_WEB ?? 5173), strictPort: true }
```

`loadEnv` also picks up an exported `EXPOSE_PORT_WEB` from `process.env`, so a shell that has sourced the env file wins. Vitest config (`environment: 'jsdom'`, `setupFiles`) lives in the same file via `/// <reference types="vitest/config" />` — one config file, not two.

### 3. The theme seam

Two axes on `<html>`: `data-theme` (`default` | `high-contrast`) and `data-mode` (`light` | `dark`).

**Stylesheets** under `src/styles/`:

- `themes/default.css`, `themes/high-contrast.css` — each declares the **same** token set under `[data-theme='…'][data-mode='light']` and `[data-mode='dark']` selectors. `default` targets AA (4.5:1); `high-contrast` targets AAA (7:1).
- `base.css` — the minimal stylesheet ADR-026 says React Aria Components cannot be reviewed without: a reset, a visible `:focus-visible` ring, borders, and the `prefers-reduced-motion` block. Every colour/spacing/border value is `var(--tcp-…)`.

Opus fixes the token list before Sonnet writes the four theme blocks. Keep it small — colours, spacing scale, border width/radius, focus ring. Component stylesheets arrive empty in later prompts.

**`src/theme/storage.ts`** — the storage contract: one `localStorage` key holding `{ theme, mode }`, a `readThemeChoice()` and a `seedThemeChoice()` that reads `prefers-color-scheme` and `prefers-contrast: more`. Seeding runs once and is persisted, so the system settings set the starting point and never override a later user choice.

**`src/theme/ThemeProvider.tsx`** — context + `useTheme()` in one file. Initialises from `readThemeChoice()`, writes both attributes and `localStorage` on change.

**The pre-paint script** in `index.html` — ~8 lines, inline, ahead of the module script. It cannot import `storage.ts` (it runs before the bundle), so it **deliberately duplicates** the read-and-seed logic. Comment both sides naming the other, in the repo's comment style. The browser tier (002.02) is what would catch a divergence; Opus writes both halves in one sitting.

## Verification

Run in this order — each step's failure mode is distinct.

1. **`npm run dev`** binds the port from `EXPOSE_PORT_WEB`, not 5173-by-default. Test it: `EXPOSE_PORT_WEB=5199 npm run dev --workspace apps/frontend/tcp-frontend` must bind 5199.
2. **`npm run build --workspace apps/frontend/tcp-frontend`** succeeds, and the emitted bundle contains the value imported from `@tcp/shared/client` — proving Vite resolves a `.ts` file behind an `exports` map through a workspace symlink.
3. **ADR-022 layer 3.** Temporarily add `import '@tcp/shared'` to a source file and confirm **Vite fails the build** (not just eslint). Revert, then record the result as an ADR-022 amendment — the existing amendment says this layer "arrives with 002.01" and is currently unverified.
4. **`npm test`** from the repo root runs backend Jest _and_ frontend Vitest _and_ the import-boundary check. Three tests:
   - render `App`, query the heading by role, assert its accessible name equals `t('app.title')` — covers render, router, providers, and the strings seam in one
   - theme switch changes the applied custom properties, and the choice survives a remount
   - `t()` returns the module's value and an unknown key fails typecheck (a `// @ts-expect-error` line)
5. **Static serve.** `npm run build` then serve `dist/` with a plain file server (`npx --yes serve dist` or `python3 -m http.server`) and load `/`. Deep links will 404 — that is expected and is 002.03's SPA fallback, not a defect here.
6. **`./dev-environment/scripts/check.sh`** passes: format, lint (zero errors _and_ zero warnings, including jsx-a11y), typecheck, build, unit tests, shellcheck, aislop ≥ 74.
7. **`./scripts/run-all-tests.sh`** passes — the backend tiers must be unaffected.
8. **Hooks.** `npm run hooks:install` before relying on the pre-commit/pre-push gate; the tracked scripts are copies, not symlinks.

### Known risk to spike early

jsdom resolves custom properties declared in a stylesheet unreliably. Before writing verification step 4's theme test, spend ten minutes confirming `getComputedStyle(document.documentElement).getPropertyValue('--tcp-color-bg')` actually returns a value under Vitest's jsdom with the theme CSS imported.

If it does not, the fallback assertion is: `data-theme`/`data-mode` change on `documentElement`, the choice round-trips through `localStorage`, **and** a parity check that both theme stylesheets declare the identical token names with different values. The real computed-property check then belongs to the browser tier in 002.02. Decide this on evidence, not on hope — and say which one landed.

## As implemented

Three things this plan predicted wrongly, and one it got right for the wrong reason.

- **`eslint-plugin-jsx-a11y` is worse than "check compatibility first".** 6.10.2 declares an `eslint@^9` peer against this repo's eslint 10. npm silently installs a _second_, nested eslint 9, which then crashes against the repo's `brace-expansion@^5` override — and from a clean tree `npm ci` fails outright, so CI would have broken. Fixed with a root `overrides` entry pinning that peer (it only applies on a from-scratch resolution, so one stale nested lock entry had to be removed by hand). Verified by `npm ci` and `npm install` both producing a single eslint 10.8.0, and by a probe file confirming the plugin fires as an **error**.
- **ADR-022's layer 3 did not exist.** Vite 8 does _not_ fail on a bare `@tcp/shared` import: it externalises the Node built-ins with warnings and builds successfully, at 4.5 MB instead of 250 kB, carrying express, multer and busboy — failing later in the browser with nothing pointing back at the import. Layer 3 is now an explicit `resolveId` plugin in `vite.config.ts`, which also covers the development server. Recorded as an [ADR-022 amendment](../../ADRs/ADR-022-monorepo-workspace-structure.md#amendment-as-implemented-00201).
- **The jsdom risk did not materialise.** With Vitest's `css: true`, jsdom resolves stylesheet-declared custom properties correctly. The theme test asserts on computed `--tcp-*` values; the token-parity fallback was not needed.
- **`eslint-plugin-react-hooks` v7 ships its preset with a legacy string-array `plugins` key**, which eslint 10 rejects. Its two useful rules are wired by hand instead; the rest of the preset is React Compiler linting this application does not use.

Also differing from the plan: no theme-picker component ships (nothing user-facing does), so the theme seam is exercised through a test-only harness; `strings.ts` therefore holds one key. Contrast ratios for all 28 foreground/background pairs across the four theme blocks were computed and clear their AA/AAA targets.
