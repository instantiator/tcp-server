# 002.04.01 — Backend API enablement for the web UI plan

## Context

The API was built for `tcp-cli`: a trusted operator who already knows which company they mean. A browser has to discover what the signed-in user may see, and the live activity view renders four lists on one screen. [ADR-023](../../ADRs/ADR-023-backend-api-surface-for-the-web-ui.md) names six gaps; four are backend work and land here. This prompt is backend-only.

Confirmed against the code before planning:

- `CompanyController.listCompanies` ([api.company.controller.ts](../../../apps/backend/apps/tcp-server/src/api/api.company.controller.ts), lines 51–56) is `@Get()` with no params, delegating to `CompanyDbService.list` → `this.companyRepo.find()`. No scoping, no stats, one `@ApiOperation` and nothing else.
- `req.user` is the **raw JWT payload** ([jwt.strategy.ts](../../../apps/backend/apps/tcp-server/src/auth/jwt.strategy.ts), lines 121–123). `sub` and `email` are both there; the only helper is `getCurrentUserId` in [current-user.ts](../../../apps/backend/apps/tcp-server/src/auth/current-user.ts).
- `AuditEventPublisher.publish` gates the company channel on `entity === 'company' || entity === 'task'` ([audit-event-publisher.service.ts](../../../apps/backend/apps/tcp-server/src/events/audit-event-publisher.service.ts), lines 55–57). `primeCompanyEvents` matches it: one company signal plus each task's summary (`api.company.controller.ts`, lines 242–278).
- **There is no `enquiry` entity and no `Enquiry` model.** An enquiry is a `Conversation`, and `ConversationService` writes **no audit events at all** — so nothing about an enquiry reaches any stream today. Open enquiries are `Conversation.status === 'awaiting_user'`.
- `mode` is not a query filter on `GET /api/assignment` ([assignment.controller.ts](../../../apps/backend/apps/tcp-server/src/api/assignment.controller.ts), lines 40–69), so the documented consultations query cannot be expressed as written.
- There is **no** `audit-event-publisher.service.spec.ts` — the routing predicate has no direct unit test.

### Three points where the prompt, the ADR and the code disagreed — settled with the user

1. **Enquiries.** The prompt's Requirements say all four lists update live and its Testing section demands enquiry events on the company stream; ADR-023's decision table names only `agent` and `assignment`. **Decision: emit `entity: 'enquiry'` audit rows** at conversation open and close, widen the predicate to include them, and prime enquiry summaries. This goes one step past ADR-023 and needs an amendment there (§9).
2. **"Computed in the same query."** A literal single query needs seven correlated subqueries for the per-status task breakdown, on two DB engines. **Decision: four queries total** — one scoped company query plus three `GROUP BY companyId` aggregates — constant regardless of company count. That satisfies the test's actual intent ("rather than per company"); the deviation from the prompt's wording is deliberate and recorded in the ADR amendment.
3. **Consultations.** **Decision: add `?mode=` to `GET /api/assignment`.** Three lines plus an `@ApiQuery`. Still "no new endpoint" as ADR-023 requires, and it makes the documented consultations query real instead of aspirational.

No database migration. Every change is query, routing, documentation or configuration.

**[company-db.service.ts](../../../apps/backend/apps/tcp-server/src/db/company-db.service.ts)** — change `list()` (currently lines 147–149):

```ts
async list(identifiers?: string[]): Promise<TcpCompany[]> {
  if (!identifiers) return this.companyRepo.find();
  // An authenticated caller with neither claim is a member of nothing —
  // never a caller who sees everything. `In([])` must not be reached.
  if (identifiers.length === 0) return [];
  const rows = await this.companyUserRepo.find({ where: { identifier: In(identifiers) } });
  const ids = [...new Set(rows.map((r) => r.companyId))];
  return ids.length === 0 ? [] : this.companyRepo.find({ where: { id: In(ids) } });
}
```

Two finds rather than a join: `CompanyUser` has no `@ManyToOne` to `TcpCompany` ([CompanyUser.model.ts](../../../libs/tcp-shared/src/models/CompanyUser.model.ts), line 33), so a join needs a raw QueryBuilder for no gain.

**`api.company.controller.ts`** — replace `listCompanies`:

```ts
@ApiOperation({ summary: "List the caller's companies, with per-company statistics" })
@ApiQuery({ name: 'all', required: false, type: Boolean, description: '…' })
@ApiOkResponse({ type: CompanyListItemDto, isArray: true })
@Get()
async listCompanies(
  @Req() req: Request,
  @Query('all') all?: string,
): Promise<CompanyListItem[]> {
  // `?all` bare and `?all=true` both mean every company. Anything else is
  // the membership-scoped default — a malformed flag must never widen scope.
  const wantsAll = all === 'true' || all === '';
  const companies = await this.db.listCompanies(
    wantsAll ? undefined : getCurrentUserIdentifiers(req),
  );
  const stats = await this.stats.listStats(companies.map((c) => c.id));
  return companies.map((c) => ({ ...c, stats: stats.get(c.id) ?? emptyCompanyStats() }));
}
```

Stats are returned for both modes — the administrative view wants them too.

**`?all=true` carries no permission check.** Any authenticated caller can still use it, exactly as today. Say so in the `@ApiQuery` description and in the method's JSDoc, naming 002.05 as the prompt that gates it. Do not imply the gap is closed.

**The CORS paragraph** must say, concretely: `enableCors()` is **not** called and will not be, because `tcp-web` reverse-proxies `/api` on one origin so a browser never makes a cross-origin API call. The single deployment shape that loses the proxy is a static CDN, which needs both CORS and an API base URL added to `config.js`. If that shape is ever built, `enableCors({ origin: [<the CDN origin>], credentials: true })` goes in [main.ts](../../../apps/backend/apps/tcp-server/src/main.ts) before `app.listen`, with the allowlist derived from the same environment value that already carries the web address (`TCP_WEB_URL`). Do not add it now: an allowlist nobody exercises is an allowlist nobody maintains.
