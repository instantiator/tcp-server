## RAG

The initial prompt will be accompanied by RAG data, if there's sufficiently relevant data in the role's store.

Propose an implementation that conducts a search based on the initial prompt, against the role's RAG data, and includes results in the initial prompt.

See notes on context size management below.

The agent will also need the ability to manage the RAG data in its prompt:

- The ability (through MCP?) to submit additional requests to search RAG storage
- The ability (through MCP?) to have RAG data removed from the prompt itself, because it identifies it as irrelevant or distracting
- The ability (through MCP?) to condense RAG data in the prompt into a short summary of what's relevant from it

MCP services are discussed below.

### CLI

The `lcp-cli` will also need to be able to manage RAG data held for roles. It will need some additional verbs:

- `store-role-documents --role-id uuid --src pattern/**/path/to/knowledge-file-*.md [--overwrite]` (illustrative)
  - verifies that the documents are already in open knowledge format (ie. are markdown, have good front-matter)
  - rejects the request if not all OKF
  - adds or overwrites (if `--overwrite`) the documents to a role-specific location in shared storage
  - rebuild that role's RAG data from the content in that location, for fast search and access
- `remove-role-documents --role-id uuid --src pattern/**/path/to/knowledge-file-*.md` (illustrative)

Propose an implementation that allows a user to invoke the CLI and modify a role's RAG document store.

Does minio offer a web interface to review stored files? If so, and if trivial, add an additional verb: `--open-document-store` which prints the URL the user should visit and opens it in the system browser (if possible)

## MCP services

It's likely that the RAG interactions, as well as the shared storage, agent, and user interactions will be provided through MCP. Additionally, the company and individual roles may be granted additional access to other MCP services.

The presence of new services mean that a part of the agent's prompt will need to explain what is available, how to use these MCP services, and when to do so. Propose this portion of the system prompt in the plan.

- Some services will be provided by third parties - ie. I belive minio was selected because it offers an MCP service
- Some services will require that we create new MCP services - ie. the user / agent interactions, the RAG interactions

Propose an implementation that brings in third party services as needed, and incorporates them into docker compose or launches them through the most appropriate means (ie. maybe some are libraries that are included in `lcp-server` or `lcp-agent`, or a new application under `apps/`).

Propose an implementation of the new MCP services - again, where appropriate in the system (likely new apps under `apps/` and then incorporated into docker compose infrastructure).

All services should generate audit logs of requests and responses.
