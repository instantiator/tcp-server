## Improvements to compaction

Are there improvements we can make to compaction? Please explore how the context is assembled, and look for ways to optimise the compaction (also compacting it part-by-part to help reduce the load on the model doing the work).

At the moment, it asks for a basic summary of things. It should probably look at the context and, for parts of the context that can be modified, here are some suggestions about ways to help reduce the context size:

- attempt to preserve the initial ask, shortening it without losing too much
- attempt to reduce the RAG results to relevant parts only
- attempt to preserve the approach it has outlined to the task, as a list of short items
- attempt to preserve the current task (if one is in progress)
- attempt to preserve any planned future actions, as a list of short items
- attempt to preserve any specifics that it looks like it will use, as a list of short items
- summarise anything else relevant that it might need as succinctly as possible
- preserve relevant tool use results (only) as a list of short items (eg. '`this-file.md` written')
- remove everything covered by what was reduced/summarised above
- remove everything that seems to have already been dealt with (ie. no longer required to be able to continue: completed tasks, information no longer required, content already saved to documents that won't be needed again)

It should preserve things that shouldn't compress, eg. a draft of specific content that will be stored, essential information (eg. credentials), code (although code could be broken into smaller snippets if that would reduce the overall size)

NB. As it's a multi-part context, this may mean removing most parts of the context, and replacing them with summarised / shortened content.
