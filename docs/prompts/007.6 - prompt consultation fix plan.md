# Plan: Fix Agent Consultation Role Lookup, User Targeting, and Resume Gating

## Context

`lcp-cli.sh chat` against a role that asks another role for a consultation failed:
`interactions__request_agent_consultation` takes a `roleName` string, which
`PauseAndResumeService.pauseForConsultation` (`apps/lcp-server/src/api/pause-and-resume.service.ts:91-93`)
looks up with `roleRepo.findOne({ where: { companyId, name: roleName } })`. Role
names aren't unique within a company, so this silently picks an arbitrary match
or throws `NotFoundException`. `list_available_roles` already returns each
role's `id`, so the fix is to thread `roleId` through instead of relying on name.

While fixing this, two related gaps were confirmed during investigation:

1. `request_user_input` has no way to target specific users — it always falls
   back to `ConversationService.routeQuery()`'s keyword-matching heuristic. The
   `list_available_users` tool already returns user `id`s, so agents have no
   way to use them.
2. Neither resume path (`PauseAndResumeService.completeAgent` for
   consultations, `ConversationController.reply` for user replies) checks
   whether the agent has *other* outstanding requests before resuming — it
   resumes unconditionally as soon as any single response arrives. Decided:
   the agent should resume only once every outstanding request it raised is
   resolved, and the resume message should include every response it asked
   for, not just whichever arrived last (chosen "Aggregate all responses"
   option — requires a new `pausedAt` timestamp on `LcpAgent`).

Also decided: `docs/conversations.md` covers two genuinely different flows
(agent-to-human and agent-to-agent) and was split into two docs rather than
just renamed.

---

## Stage 1 — `LcpAgent.pausedAt` + migration

Added to `libs/lcp-shared/src/models/LcpAgent.model.ts`, mirroring the existing
`Conversation.closedAt` pattern (no explicit TypeORM date type, and no `| null`
union — TypeORM's reflect-metadata-based type inference resolves `Date | null`
to `Object`, which Postgres rejects; clearing the column at runtime uses the
`{ pausedAt: () => 'NULL' }` raw-SQL escape hatch instead):

```ts
@Column({ nullable: true })
pausedAt?: Date;
```

Migration: `apps/lcp-server/src/migrations/1782831650682-AddAgentPausedAt.ts`,
hand-written (idempotent `ADD COLUMN IF NOT EXISTS` / `DROP COLUMN IF EXISTS`)
rather than using `migration:generate` — the local dev Postgres had unrelated
schema drift (empty `typeorm_migrations` tracking table against an
already-populated schema) that caused the generated migration to include
destructive, unrelated changes (dropping pgvector embedding columns,
retyping foreign key columns). That drift is pre-existing and unrelated to
this change.

## Stage 2 — Role-id consultation fix

- `interactions-tools.service.ts` (`registerRequestAgentConsultation`): zod
  schema gained a required `roleId`; `roleName` became optional (logging
  label only).
- `internal.dto.ts` (`PauseDto`): added `roleId?: UUID` (required when
  `type === 'agent_consultation'`); `roleName` is now always optional.
- `internal.controller.ts` (`pause`): forwards `roleId`/`roleName`; response
  now also includes the resolved `roleName`.
- `pause-and-resume.service.ts` (`pauseForConsultation`): looks the role up by
  `roleRepo.findOne({ where: { id: roleId, companyId } })` instead of by name;
  returns `{ consultationId, roleName: role.name }` (the canonical name, not
  the caller's possibly-stale label); sets `pausedAt` alongside `Paused`.
- `tools.jsonc`/`prompts.jsonc`: descriptions updated to direct the LLM to
  `list_available_roles` for the id.

## Stage 3 — `request_user_input` user targeting

- `interactions-tools.service.ts` (`registerRequestUserInput`): zod schema
  gained an optional `userIds: z.array(z.uuid())`.
- `internal.dto.ts`: added `userIds?: UUID[]`.
- `pause-and-resume.service.ts` (`pauseForUserInput`): forwards `userIds`.
- `conversation.service.ts` (`create`): when `userIds` is given, validates
  each belongs to the company (`BadRequestException` if not) and uses their
  identifiers directly as `routedToIdentifiers`, bypassing `routeQuery()`.

## Stage 4 — Resume gating + multi-response aggregation

All resumes go through `AgentOrchestrationService.resumeAgent` — the single
choke point both `PauseAndResumeService.completeAgent` and
`ConversationController.reply` call into. It now:

1. Counts outstanding requests (`PendingConsultation.status === 'pending'`,
   `Conversation.status === 'awaiting_user'`) for the agent; stays paused
   (no enqueue) if any remain.
2. Otherwise collects every consultation result and user reply created since
   `agent.pausedAt`, joins them into one message, clears `pausedAt`, and
   enqueues the resume job with the aggregated message.
3. Falls back to an explicit `replyContent` param only when `pausedAt` is
   unset (non-pause-triggered resumes).

Callers (`completeAgent`, `ConversationController.reply`) no longer pass
`replyContent` themselves — aggregation reads from the DB instead, since both
callers already persisted their own result/reply before calling `resumeAgent`.

`docs/ADRs/ADR-012-human-in-the-loop.md` updated to document role-id lookup,
`userIds` targeting, and resume gating/aggregation; also corrected two
pre-existing inaccuracies found while editing that section (a stale
`POST /internal/agent/resume/:agentId` endpoint that doesn't exist, and a
`roleSlug` field that should have read `roleId`).

## Stage 5 — Tests

Added/updated unit tests in `pause-and-resume.service.spec.ts` (id-based
lookup incl. duplicate-role-name regression, `pausedAt` assertions, `userIds`
passthrough), `internal.controller.spec.ts`, `interactions-tools.service.spec.ts`,

new `pausedAt` column. Added e2e regression coverage in
`internal-conversation.e2e-spec.ts` for `POST /internal/pause`
(`agent_consultation`): the literal duplicate-role-name bug (two roles named
`analyst` in one company, consult by id, assert the correct one is targeted),
the 404-on-unknown-roleId case, and the success path.
