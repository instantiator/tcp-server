## Improved prompts

Using the `scripts/test-data/roles/chicken-assistant.json` and `scripts/test-data/roles/cat-assistant.json` roles for a quick test, I asked the cat assistant to ask the chicken assistant if it would like a worm...

This correctly initiated a simple "would you like a worm?" consultation with the chicken assistant. However, this led to the chicken assistant getting quite confused (and wasting several iterations and tokens) trying to figure out how to respond.

It made several mistakes:

- It made a typo in at least one call to the tool
- It narrated its call to the tool at least once
- It decided to write a file with its response in full

Returning a plain-text artifact for the assignment would have been sufficient, and we ought to revise our prompts to help the LLM decide which approach is best depending on the nature of the query.

NB. It did succeed in writing the file to its working directory, and I verified this by taking a look in MinIO.

Please re-word the prompts in all assignment modes to help the agents make better use of tools.

It seemed to finish with only the single planning assignment. I was able to see sometime later that it had created `chicken-food.txt`, seemingly as a working file from an orphaned assignment at path: `lcp/test-company/assignments/e93908ae-5230-487d-8d85-9da88ef00a78/working/chicken_food_preferences.md`

This assignment id does not match any other ids, so I believe it's an orphaned assignment.

My best guess at what happened:

- The planner role was `cat-assistant`
- It started, spotted that this was going to be a job for `chicken-assistant`
- It immediately short-circuited the process and consulted `chicken-assistant`
- `chicken-assistant` created the report succesfully in an orphaned assignment working directory
  - I guess it was an orphaned assignment because it was a consultation
- `chicken-assistant` completed the consultation assignment
- The planner did some other stuff, but never really created a plan or completed its assignment succesfully
- The orchestation service didn't pass or fail the task, or move it on to an in-progress state

NB. It's also possible that `chicken-assistant` _didn't_ succesfully complete the assignment, and that for some reason the failure wasn't passed back to `cat-assistant`, who therefore didn't resume or wasn't able to complete planning.

(Or perhaps a response did get back, and `cat-assistant` determined that it should not continue because `chicken-assistant` had already completed teh task?)

The task currently remains in `planning` state, as seen with:

```
./lcp-cli.sh -u test -p test get-task --task-id 08166b7b-71f6-4e17-b641-ed7a182e783c
```

Please review, and let's consider whether there are ways to improve this process and ensure it does the right thing and that all assignments run to completion or fail.

The ideal outcome:

- because `cat-assistant` understands it is planning, it doesn't consult the chicken, it creates a plan with an assignment for `chicken-assistant`
- the planning assignment completes with a plan that has a step asking the `chicken-assistant` to create the report
- the assignment is initiated, and `chicken-assistant` creates the report, its path is something like `lcp/test-company/tasks/<task-id>/assignments/<asignment-index>/working/chicken-report.txt`
- the agent completes the assignment with the `chicken-report.txt` file
- the QA step takes place afterwards, and a second `chicken-assistant` agent reviews the output (presumably giving it a pass!)
- once passed, the report is promoted to `completed/chicken-report.txt` on the assignment path
- the assignment was the last in the task, and all completed files from the assignments (just the one) are promoted to the `lcp/test-company/tasks/<task-id>/completed/` path

In fact, let's remove the consultation and file editing abilities from `plan` mode agents. This could also help to focus them towards the planning task.

It's worth understanding if we can ensure that planning completes - much as we do with other required tool calls.

Similarly, please check the passage of failures - in case a failed consultation led to the planning assignment or the task stalling overall.

Please re-word the prompts for all modes to ensure that the agents better understand what is required of them to complete their assignemnt, and revise the required tool calls if needed.
