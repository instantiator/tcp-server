# lcp-agent MVP — Implementation Plan

## Context

The LCP monorepo has working infrastructure (NestJS, PostgreSQL, Redis, MinIO, BullMQ config) but zero agent or LLM code. This plan wires the first real agent loop: a LangGraph-backed background worker that starts and resumes against a PostgreSQL checkpoint store, triggered via the lcp-server REST API.

**Deferred from the prompt (user-confirmed):**

- MCP tool access — no MCP servers exist yet; added when the first server is built
- RAG memory — pgvector is ready but no embedding pipeline; roles use static `system_prompt_template` for now

## Phase 1 — Shared entities + migration

### New entity files in `libs/lcp-shared/src/models/`

**`LcpRole.model.ts`** — role template

- `id` (UUID PK), `companyId` (FK → `lcp_company`), `name`, `description`
- `llmConfig` (JSONB: `{ provider, model, baseUrl?, apiKeyEnvVar? }`) — API keys stored only as env var names, never values
- `systemPromptTemplate` (text) — `{{name}}`, `{{description}}`, `{{date}}` placeholders
- `knowledgeDomains` (JSONB string[]) — stored unused for MVP
- `mcpServerList` (JSONB string[]) — stored unused for MVP
- Exports `LlmConfig` interface

**`LcpAgent.model.ts`** — agent instance

- `id` (UUID PK, also used as LangGraph `thread_id`), `companyId`, `roleId`
- `status` (`AgentStatus` enum: idle | running | paused | completed | failed)
- `threadId` (varchar, nullable — set on first dispatch)
- `initialPrompt` (text), `createdAt`, `updatedAt`

**`AuditEvent.model.ts`** — per ADR-008

- `id`, `timestamp` (`@CreateDateColumn()` — driver-agnostic), `companyId`, `role` (denormalized name)
- `agentId` (nullable FK → `lcp_agent`), `eventType` (`AuditEventType` enum), `payload` (JSONB)
- Composite index: `(companyId, agentId, timestamp)`

### Migration: `1750000000001-AddRoleAgentAudit.ts`

Creates `lcp_role`, `lcp_agent`, `audit_event` tables with FK constraints and index.

## Phase 2 — lcp-server additions

### DbService

Registers all four entity repos. New methods:

- `createRole` / `getRole` / `listRoles(companyId)`
- `createAgent` / `getAgent` / `updateAgentStatus(id, status, threadId?)`
- `saveAuditEvent`

### ModelCompatibilityService (`src/model-check/`)

`POST /api/model/check` — accepts `{ models: LlmConfig[] }`, returns per-model report:

```
{ provider, model, supportsTools, supportsStructuredOutput, compatible, error? }
```

Probes tool-call and structured-output support by actually calling the model; catches errors and reports unsupported.

### Controllers

- `api.role.controller.ts` — `POST /api/role`, `GET /api/role/:id`
- `api.agent.controller.ts` — `POST /api/agent/start`, `POST /api/agent/resume/:id`, `GET /api/agent/:id`
- `api.company.controller.ts` updated — `GET /api/company/:id/roles`

### AgentOrchestrationService

- `startAgent(template)` — creates `LcpAgent` (status: idle), enqueues `{ agentId, type: 'start' }` to `agent-jobs`
- `resumeAgent(agentId)` — validates status is resumable, enqueues `{ agentId, type: 'resume' }`
- BullMQ `Queue` opened in `onModuleInit`, closed in `onModuleDestroy`

## Phase 3 — lcp-agent implementation

### LLM factory (`src/llm/llm-factory.ts`)

`buildChatModel(config: LlmConfig): BaseChatModel`

- `lm-studio` → `new ChatOpenAI({ baseURL, apiKey: resolvedKey ?? 'lm-studio', model })`
- `openai` → `new ChatOpenAI({ apiKey: resolvedKey, model })`
- Unknown provider → throw

Duplicated in lcp-server `src/model-check/llm-factory.ts`. Unify into `libs/lcp-shared` once a third consumer appears.

### AgentRegistryService (`src/registry/`)

In-memory `Map<agentId, { abortController }>`. Methods: `register`, `deregister`, `isRunning`, `activeCount`.

### AgentLoopService (`src/agent/`)

Per-job lifecycle:

1. Load `LcpAgent` + `LcpRole` from DB; skip if not found
2. Create `AbortController`; set `setTimeout` → `abort('timeout')` at `TIMEOUT_MS` (60 s)
3. Register agent in `AgentRegistryService`
4. `updateStatus(Running, threadId = agentId)`
5. `PostgresSaver.fromConnString(DATABASE_URL)` + `setup()`
6. Build `StateGraph(MessagesAnnotation)` → `agentNode` (LLM invoke) → `END`; compile with checkpointer
7. Stream with `graph.streamEvents(initialState, { configurable: { thread_id }, signal })`
8. On each event: increment iteration counter; abort if `> MAX_ITERATIONS` (10); save `AuditEvent`
9. Track last `AIMessage` from `on_chat_model_end` events
10. After stream: if `signal.aborted` → status = Failed; else if empty output → one retry with continuation prompt; else status = Completed
11. `finally`: `clearTimeout`, `checkpointer.end()`, `registry.deregister`

Prompt construction: system = `renderTemplate(role.systemPromptTemplate, { name, description, date })`; user = `agent.initialPrompt`.

### AgentWorkerService (`src/worker/`)

BullMQ `Worker('agent-jobs', ...)` instantiated in `onModuleInit`. Dispatches to `AgentLoopService.run(agentId)`. Skips if `registry.isRunning(agentId)`.

### lcp-agent `AppModule`

Wires TypeORM with same 4 entities. `synchronize: false` for PostgreSQL (migrations run by lcp-server). SQLite fallback for local dev.

### Health checks

`GET /health` checks: TypeORM ping + Redis ping via `createClient({url}).connect(); client.ping()`.

## Security note

LM Studio API key is stored in `.env` (gitignored) as `LM_STUDIO_API_KEY`. The `LcpRole.llmConfig.apiKeyEnvVar` field stores only the env var name, never the key value. This applies to all providers.
