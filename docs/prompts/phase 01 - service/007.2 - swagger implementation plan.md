# 007.2 — Swagger / OpenAPI Implementation Plan

## Overview

This document records the implementation plan for [ADR-014](../ADRs/ADR-014-swagger-endpoints.md): adding
Swagger / OpenAPI documentation endpoints to all five LCP NestJS services.

## Dependencies added

| Package                     | Version   | Type       |
| --------------------------- | --------- | ---------- |
| `@nestjs/swagger`           | `^11.4.4` | production |
| `swagger-ui-express`        | `^5.0.1`  | production |
| `@types/swagger-ui-express` | latest    | dev        |

**`npm audit` findings at time of install:** 18 moderate vulnerabilities, all in Jest's dependency
chain (`js-yaml` quadratic-complexity DoS via `babel-plugin-istanbul`). These are dev-only — no
production exposure. Tracked separately; not in scope for this change.

## Stages

### Stage 1 — Install packages

```bash
npm install @nestjs/swagger@^11.4.4 swagger-ui-express@^5.0.1
npm install --save-dev @types/swagger-ui-express
```

### Stage 2 — Enable swagger CLI plugin (`nest-cli.json`)

Added `"plugins": ["@nestjs/swagger"]` to `compilerOptions` for each of the five server projects in
`nest-cli.json`. The plugin runs at TypeScript transform time and automatically extracts DTO field
types, descriptions, and validation metadata — eliminating the need for `@ApiProperty` on every field.

### Stage 3 — `SwaggerModule` in each `main.ts`

Added `SwaggerModule.createDocument` + `SwaggerModule.setup('swagger', ...)` to:

| File                                    | Port | Title                |
| --------------------------------------- | ---- | -------------------- |
| `apps/lcp-server/src/main.ts`           | 3000 | LCP Server           |
| `apps/lcp-agent/src/main.ts`            | 3001 | LCP Agent            |
| `apps/lcp-mcp-storage/src/main.ts`      | 3010 | LCP MCP Storage      |
| `apps/lcp-mcp-memory/src/main.ts`       | 3011 | LCP MCP Memory       |
| `apps/lcp-mcp-interactions/src/main.ts` | 3012 | LCP MCP Interactions |

`lcp-server` also registers bearer auth and `internal-api-key` security schemes via `DocumentBuilder`.

### Stage 4 — Controller decorators (`lcp-server`)

Added `@ApiTags`, `@ApiBearerAuth` / `@ApiSecurity`, and `@ApiOperation` to all controllers:

- `api/api.company.controller.ts` — tag: `companies`
- `api/api.role.controller.ts` — tag: `roles`
- `api/api.agent.controller.ts` — tag: `agents`
- `api/conversation.controller.ts` — tag: `conversations`
- `api/company-user.controller.ts` — tag: `company-users`
- `api/role-document.controller.ts` — tag: `role-documents`
- `api/storage-proxy.controller.ts` — tag: `storage`
- `api/api.model.controller.ts` — tag: `model`
- `api/internal.controller.ts` — tag: `internal`, security: `internal-api-key`
- `audit/audit.controller.ts` — tag: `internal`, security: `internal-api-key`

### Stage 5 — `lcp-cli open-swagger` command

New file: `apps/lcp-cli/src/commands/open-swagger.ts`

```
lcp-cli open-swagger --service <name> [--no-open]
```

`--service` is required. Accepted values: `lcp-server`, `lcp-agent`, `lcp-mcp-storage`,
`lcp-mcp-memory`, `lcp-mcp-interactions`.

URL defaults to `<SERVICE_URL_ENV_VAR>/swagger` (same env vars as smoke tests). `--no-open`
suppresses browser launch.

### Stage 6 — Smoke tests

Added one `/swagger` check per service to `test/smoke/smoke.spec.ts`, reusing the existing `get()`
helper and URL constants.

### Stage 7 — ADR-014 + docs/index.md

- Created `docs/ADRs/ADR-014-swagger-endpoints.md` (Status: Implemented)
- Added ADR-014 row to the ADR table in `docs/index.md`
