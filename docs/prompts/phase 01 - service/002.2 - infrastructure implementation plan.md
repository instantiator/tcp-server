# LCP Basic Infrastructure — Implementation Plan

**Status:** Implemented  
**Plan version:** 002.2  
**Prior planning doc:** `002.1 - basic infrastructure planning.md`

---

## Confirmed design decisions

| Decision        | Choice                                                                                      |
| --------------- | ------------------------------------------------------------------------------------------- |
| Repo structure  | NestJS monorepo (`apps/lcp-server`, `apps/lcp-agent`, `libs/lcp-shared`)                    |
| Auth            | OAuth2/OIDC — Keycloak default in Docker Compose (`--profile auth`); any OIDC IdP supported |
| MCP servers     | Child processes only — no Docker Compose containers                                         |
| User management | lcp-server thin-wraps Keycloak Admin API for create/enable/disable                          |
| DB              | PostgreSQL 16 + pgvector; better-sqlite3 in-memory for unit tests                           |
| Object storage  | MinIO                                                                                       |
| Task queue      | Redis (BullMQ — configured, workers pending)                                                |
| Node image      | `node:24-alpine` (node:22 had 1 high CVE per docker scout)                                  |

## Step 1 — NestJS monorepo restructure

Move `src/` → `apps/lcp-server/src/`, `test/` → `apps/lcp-server/test/`.

- Update `nest-cli.json` — `"monorepo": true`, three projects: `lcp-server`, `lcp-agent`, `lcp-shared`
- Add `"webpack": false` to compiler options so tsc preserves migration file structure in `dist/`
- Add `tsconfig.app.json` per app and `tsconfig.lib.json` for shared lib
- Root `tsconfig.json` — add `paths` for `@lcp/shared` → `libs/lcp-shared/src/index.ts` (no `baseUrl` — valid with `moduleResolution: nodenext`)
- Move `LcpCompany.model.ts` to `libs/lcp-shared/src/models/`; export via `libs/lcp-shared/src/index.ts`
- Stub `apps/lcp-agent/` (main.ts on port 3001, empty AppModule)
- Fix package name: `"tcp-server"` → `"lcp-server"`

**Note on `baseUrl`:** `baseUrl: "."` required for path aliases with `nodenext`. TypeScript 5.x accepts it without warning; the IDE-only warning about deprecation in TS 7.0 should not have `ignoreDeprecations: "6.0"` added (TS 5.x doesn't recognise `"6.0"` as a valid value and will error).

## Step 2 — Configuration and env validation

Install `@nestjs/config` + `joi`. Add `ConfigModule.forRoot({ validationSchema })` to both app modules. Throw on startup if any required var is absent.

**lcp-server required vars:** `DATABASE_URL`, `REDIS_URL`, `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`

**lcp-agent required vars:** `DATABASE_URL`, `REDIS_URL`, `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`

Create `.env.example` with all vars documented.

---

## Step 3 — PostgreSQL and migrations

Install `pg` + `@types/pg`.

`app.module.ts` uses `TypeOrmModule.forRootAsync` with a factory: if `DATABASE_URL` is absent or starts with `sqlite`, fall back to `better-sqlite3` in-memory with `synchronize: true`. Otherwise use `postgres` with `synchronize: false, migrationsRun: true`.

**Migration files:** `apps/lcp-server/src/migrations/`  
**TypeORM CLI datasource:** `apps/lcp-server/src/data-source.ts`

First migration (`1750000000000-InitialSchema.ts`):

1. `CREATE EXTENSION IF NOT EXISTS vector;`
2. Create `lcp_company` table

**Creating a new migration:**

```bash
DATABASE_URL=postgres://lcp:password@localhost:5432/lcp \
  npm run migration:generate -- apps/lcp-server/src/migrations/MigrationName
```

Review, then commit alongside the entity change.

## Step 5 — Docker Compose

`docker-compose.yml` — six services:

| Service    | Image                                   | Profile   |
| ---------- | --------------------------------------- | --------- |
| postgres   | pgvector/pgvector:pg16                  | (default) |
| redis      | redis:7-alpine                          | (default) |
| minio      | minio/minio                             | (default) |
| keycloak   | quay.io/keycloak/keycloak               | auth      |
| lcp-server | built from `apps/lcp-server/Dockerfile` | (default) |
| lcp-agent  | built from `apps/lcp-agent/Dockerfile`  | (default) |

All services have healthchecks. `lcp-server` and `lcp-agent` use `depends_on: condition: service_healthy` for their dependencies.

Persistent volumes: `postgres_data`, `redis_data`, `minio_data`.

**Dockerfiles:** use `node:24-alpine` (not 22 — CVE). Multi-stage: builder + runtime. Copy `dist/` and `node_modules/` from builder. `"webpack": false` means tsc output lands at `dist/apps/lcp-server/src/main.js`.

## Step 6 — Auth stub (OIDC)

Update ADR-011 from self-issued JWT to OIDC/Keycloak.

Install `passport`, `passport-jwt`, `jwks-rsa`, `@nestjs/passport`.

`apps/lcp-server/src/auth/`:

- `jwt.strategy.ts` — validates access tokens against `{OIDC_ISSUER_URL}/.well-known/jwks.json` using `passportJwtSecret`
- `jwt-auth.guard.ts` — `AuthGuard('jwt')`
- `auth.module.ts` — PassportModule + JwtStrategy

Guards not yet applied to any endpoint.

**Note:** `jwks-rsa` depends on `jose` (ESM-only). Jest's CommonJS mode fails to parse it. Fix: `moduleNameMapper` in `jest-e2e.json` replaces `jwks-rsa` with `apps/lcp-server/test/__mocks__/jwks-rsa.ts` (a stub). Unit tests never import auth modules so they're unaffected.

Create `docs/keycloak-setup.md` with realm, client, and service account setup instructions.

## Step 7 — Test structure

Four test tiers:

| Tier        | Files                                           | Config                       | External services      |
| ----------- | ----------------------------------------------- | ---------------------------- | ---------------------- |
| Unit        | `apps/*/src/**/*.spec.ts`                       | `jest` (package.json)        | None                   |
| E2E         | `apps/lcp-server/test/*.e2e-spec.ts`            | `jest-e2e.json`              | None (SQLite fallback) |
| Integration | `apps/*/test/integration/*.integration-spec.ts` | `test/jest-integration.json` | Docker Compose         |
| System      | `test/system/*.spec.ts`                         | `test/jest-system.json`      | `docker compose up`    |

Integration tests are connectivity stubs — they skip gracefully if the relevant env var isn't set.

`apps/lcp-server/test/e2e-setup.ts`: sets stub env vars with `||=` so existing e2e tests work without Docker Compose.

## Step 8b — Test runner shell scripts

`scripts/` — four scripts, all `chmod +x`, all `set -euo pipefail`:

| Script                     | What it does                                                                    |
| -------------------------- | ------------------------------------------------------------------------------- |
| `run-unit-tests.sh`        | `npm test`                                                                      |
| `run-e2e-tests.sh`         | Start postgres/redis/minio, export env vars, run `npm run test:e2e`             |
| `run-integration-tests.sh` | Start postgres/redis/minio, wait for health, run `npm run test:integration`     |
| `run-system-tests.sh`      | `docker compose up -d`, wait for `/health` endpoints, run `npm run test:system` |
