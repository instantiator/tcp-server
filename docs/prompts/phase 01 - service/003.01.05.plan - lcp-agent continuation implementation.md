# lcp-agent — Continuation Implementation (003.01.05)

Implements the plan from `003.01.04`. All phases completed and verified.

## What was implemented

### Phase 1 — Endpoint Security

Applied `@UseGuards(JwtAuthGuard)` at the class level to all four business-logic controllers:

- `api.company.controller.ts`
- `api.role.controller.ts`
- `api.agent.controller.ts`
- `api.model.controller.ts`

Health controllers on both apps remain public (intentionally unguarded).

Created `apps/lcp-server/test/helpers/test-jwt.ts` — signs HS256 JWTs with `node:crypto` using `'stub-secret'`, matching what the `jwks-rsa` mock returns to `passport-jwt`.

Updated `apps/lcp-server/test/app.e2e-spec.ts`:

- All requests include `Authorization: Bearer <jwt>`
- Added a 401 test (no token → HTTP 401)

**Critical fix**: the `jwks-rsa` mock at `apps/lcp-server/test/__mocks__/jwks-rsa.ts` had 4 parameters but `passport-jwt` calls `secretOrKeyProvider(req, rawJwtToken, done)` with 3. Fixed to 3 params — e2e went from 0/8 passing to 8/8 passing.

### Phase 2 — Agent loop integration tests

Created `apps/lcp-agent/test/integration/agent-loop.integration-spec.ts`:

- Happy path: agent runs to `Completed`, `threadId` set, `LlmResponse` audit event written
- Resume test: agent runs, paused, re-run; LangGraph restores checkpoint, same `threadId`

**Key design choices:**

- `FakeListChatModel` from `@langchain/core/utils/testing` replaces a mock HTTP server. It emits proper LangChain callbacks so `on_chat_model_end` events fire in LangGraph's `streamEvents`.
- `jest.spyOn(factory, 'buildChatModel')` intercepts the call inside `AgentLoopService` (works because TypeScript CJS compilation uses property access on the module object).
- DB cleanup uses `createQueryBuilder().delete().execute()` (not `repo.clear()`) to avoid PostgreSQL TRUNCATE FK constraint errors.
- Both `beforeEach` and `afterEach` clean the DB — `beforeEach` handles stale data from failed prior runs.

### Phase 3 — BullMQ integration test

Created `apps/lcp-agent/test/integration/agent-worker.integration-spec.ts`:

- Seeds company/role/agent, enqueues a job via `new Queue(...)`, polls until `status === Completed`
- `module.init()` starts `AgentWorkerService.onModuleInit()` which subscribes to `agent-jobs`
- Same `FakeListChatModel` spy approach

### Phase 6 — Bug fixes discovered during implementation

**`MAX_ITERATIONS` counted all `streamEvents` events, not LLM calls** (`apps/lcp-agent/src/agent/agent-loop.service.ts`):

- `streamEvents` v2 emits ~15-20 events per single LLM call (chain start/end for graph, node, model)
- `MAX_ITERATIONS = 10` fired before the first LLM response could complete
- Fix: count only `on_chat_model_start` events (one per LLM invocation)

**Integration test parallel execution** (`test/jest-integration.json`):

- Two test files sharing the same PostgreSQL DB and running in parallel caused FK violations: one file's `cleanDb()` deleted rows the other file's agent loop was actively using
- Fix: added `"maxWorkers": 1` to force sequential execution

**Authentication header missing in docs** (`docs/lcp-agent.md`):

- All `curl` examples updated to include `-H "Authorization: Bearer <token>"`
- Added Authentication section with link to `keycloak-setup.md`
