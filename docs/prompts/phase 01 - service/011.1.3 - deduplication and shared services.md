## Context

The parent prompt asks for shared code "even if it's only used twice — it's worth
it". A review pass found substantially more than twice.

`aislop` reports 11 `duplicate-block` findings, but its detector only works
_within_ a file. The larger finding is **cross-app** duplication that it cannot
see: an entire RAG retrieval method duplicated character-for-character between two
apps, a four-way copy of the MCP tool-result kit, and five hand-rolled copies of
the internal HTTP client.

## Two findings that are not refactors

> [!WARNING]
> **(G) Probable data-quality bug — handle first, as a bugfix.**
>
> `AuditClientService.record(companyId, role, agentId, eventType, payload)` is
> called with three incompatible conventions for the `role` argument:
>
> - `apps/tcp-mcp-memory/src/mcp/memory-tools.service.ts:130,175,211` passes a
>   **`roleId` UUID**
> - `apps/tcp-mcp-tasks/src/mcp/tasks-tools.service.ts:206,264,313` passes the
>   literal string **`'agent'`**
> - tcp-server (e.g. `pause-and-resume.service.ts:58` via `recordStatus`) passes a
>   **role name**, resolved as `role?.name ?? 'agent'`
>
> So tcp-mcp-memory is writing UUIDs into a column every other caller fills with a
> human-readable name. Confirm against the `AuditEvent` model, then fix it as its
> own unit **before** any shared helper papers over it. If existing rows are
> affected, raise that with the user — a backfill is a separate decision.

> [!WARNING]
> **(A) Silent RAG threshold divergence — needs a user decision.**
>
> The three copies of the retrieval query use **three different thresholds**:
> `0.7` (hardcoded in tcp-agent), `DEFAULT_RAG_THRESHOLD` (tcp-server), and `0.5`
> (hardcoded in tcp-mcp-memory). This is accident, not design. Consolidating them
> forces a single value, which **is a behaviour change** affecting retrieval
> quality. Put the choice to the user; do not pick silently.

## Unit 3 — Shared MCP tool-result kit

Create `libs/tcp-shared/src/mcp/tool-result.ts`:

| Item                     | Current copies | Locations                                                                                                     |
| ------------------------ | -------------- | ------------------------------------------------------------------------------------------------------------- |
| `interface ToolResult`   | 4              | storage:42, memory:52, interactions:18, tasks:24                                                              |
| `ok(text)` / `err(text)` | 2 verbatim     | interactions:23,27 · tasks:29,33                                                                              |
| 4xx relay                | 2              | `tasks-tools.service.ts:366-378` (`relayOrError`) · `interactions-tools.service.ts:34-45` (`relay4xxOrError`) |
| server-error extraction  | 1 divergent    | `storage-tools.service.ts:536-548` (`extractErrorMessage`) + `textResult:549-551`                             |

The two relay functions have identical bodies — a 4xx is returned as a **non-error**
result so the LLM can read the message and self-correct — with tasks' adding a
logger call and a `tool` label. `interactions-tools.service.ts:34` even carries the
comment _"Mirrors tcp-mcp-tasks' `relayOrError`"_: the duplication is known and
undocumented as debt.

Suggested surface:

```ts
export interface ToolResult {
  content: Array<{ type: 'text'; text: string }>;
}
export function ok(text: string): ToolResult;
export function err(text: string): ToolResult;
export function relay4xxOrError(
  e: unknown,
  fallback: string,
  ctx?: { tool: string; logger: Logger },
): ToolResult;
export function extractServerErrorMessage(e: unknown): string;
export function registerDescribeServer(
  server: McpServer,
  description: string,
  text: string,
): void;
```

Note that storage's error extraction is **`llmHint`-aware and the other three are
not** — adopting the richer version everywhere is arguably a latent bug fix. Call
that out rather than flattening to the weakest variant.

`registerDescribeServer` covers the 4x pattern at storage:555, memory:93,
interactions:83, tasks:120. The first three are trivially identical; **tasks' takes
an optional `agentId` and should keep its own.**

**Tests:** new spec for the shared module covering the 4xx-relay boundary (399 /
400 / 499 / 500), the `llmHint` path, and non-axios errors. Existing MCP specs must
stay green.
**Gate:** `./dev-environment/scripts/check.sh`.

## Unit 4 — Shared RAG retrieval service

The largest single block of true duplication in the repo.

- `apps/tcp-agent/src/rag/agent-rag.service.ts:45-73` (`AgentRagService.retrieve`)
- `apps/tcp-server/src/rag/rag-retrieval.service.ts:55-91` (`RagRetrievalService.retrieve`)

These are not merely similar: the SQL string, the parameter array
`[pgvector.toSql(queryVector), roleId, companyId, threshold, topK]`, the
`if (!embeddingConfig) return []` guard, the constructor dependencies
(`EmbeddingService`, `@InjectDataSource() DataSource`) and even the
`this.logger.debug(...)` line are character-identical. A third partial copy lives
at `apps/tcp-mcp-memory/src/mcp/memory-tools.service.ts:266-275`, which runs the
same query with `::uuid` casts and string formatting.

Create `libs/tcp-shared/src/rag/knowledge-retrieval.service.ts`:

```ts
@Injectable()
export class KnowledgeRetrievalService {
  constructor(
    embedding: EmbeddingService,
    @InjectDataSource() dataSource: DataSource,
  ) {}
  async retrieve(
    roleId,
    companyId,
    query,
    embeddingConfig,
    topK = 5,
    threshold = DEFAULT_RAG_THRESHOLD,
  ): Promise<RagChunk[]>;
}
```

Then: delete `RagRetrievalService`; reduce `AgentRagService` to `hasKnowledge()`
only (its lines 82–91, which are genuinely agent-specific); have memory's
`knowledgeSearch` call the shared `retrieve` and keep only its `formatResults`.
`EmbeddingService` already lives in `libs/tcp-shared/src/rag/`, so the DI wiring
exists in all three apps.

**Resolve the threshold question with the user first** (warning (A) above).

**Tests:** move/merge the existing specs for both retrievers onto the shared
service. Cover: no `embeddingConfig` → `[]`; threshold filtering; role + shared
scope both searched; `topK` honoured.
**Gate:** `./dev-environment/scripts/check.sh` + `./scripts/run-integration-tests.sh`
(this path needs real pgvector).

## Unit 6 — Shared internal API client

Highest touch count, so it goes late — after Unit 3 has landed and the MCP specs
are green.

Five copies of the `SERVER_URL` + `INTERNAL_API_KEY` config lookup, and **13**
hand-written `{ headers: { 'X-Internal-Api-Key': ... } }` literals:

- `apps/tcp-mcp-storage/src/mcp/storage-tools.service.ts:128-129`, `headers():531-533`, `fetchScope:503-509`, `post<T>:522-530`
- `apps/tcp-mcp-interactions/src/mcp/interactions-tools.service.ts:64-65`, inline axios at :154, :205, :295
- `apps/tcp-mcp-tasks/src/mcp/tasks-tools.service.ts:106-107`, inline axios at :201, :259, :308, :338
- `apps/tcp-agent/src/storage-tracking/storage-tracking-client.service.ts:21-22,:29`
- `libs/tcp-shared/src/audit/audit-client.service.ts:21-22`, headers at :39, :62, :83

Only storage bothered to factor out a `headers()` method.

Create `libs/tcp-shared/src/http/internal-api.client.ts`:

```ts
@Injectable()
export class InternalApiClient {
  constructor(config: ConfigService);
  get<T>(path: string): Promise<T>;
  post<T>(path: string, body: unknown): Promise<T>;
  postAndForget(path: string, body: unknown, context: string): void; // logs, never throws

```

`AuditClientService` then becomes a thin wrapper over `postAndForget`, dropping
~40 lines including its three duplicated `.catch(err => this.logger.warn(...))`
blocks. Each MCP tools service drops its `serverUrl`/`apiKey` fields and `headers()`.

Preserve the fire-and-forget semantics exactly: audit writes must **never** throw
into the calling path, and must still log on failure.

**Tests:** unit tests for the client (header injection, error propagation for

must stay green.
**Gate:** `./dev-environment/scripts/check.sh` + `./scripts/run-all-tests.sh`.

## Code quality requirements

Route via `AGENTS.md` → `dev-environment/guidance/index.md`; read
`process/before-coding.md` first and `process/after-coding.md` when done. State the
filename of each guidance doc you read.

- **After every unit**, run `./dev-environment/scripts/check.sh` and fix what it
  reports before starting the next. Never bypass a hook with `--no-verify`.
- Zero compiler and linter **errors and warnings**.
- Never cast to `any`, especially in test mocks — type the mock instead.
- Comments state **intent**, not mechanics; TSDoc on new shared classes, functions
  and consts; `{@link}` for type references; no decorative separator comments.
- **No unrequested abstractions.** The bar for a new shared module is real, repeated
  duplication — which every extraction above documents. If an extraction turns out
  to be thinner than described, say so and skip it rather than building the
  abstraction anyway.
- Behaviour must not change, except where this plan explicitly flags a decision
  (the audit `role` bugfix, the RAG threshold, the `llmHint` error extraction).
- Tests cover intent and edge cases, not line coverage.
- When changing a class's constructor or behaviour, grep `test/integration/` and
  `test/e2e/` by class name too, not just the owning app's `src/`.
- Full suite via `./scripts/run-all-tests.sh`; e2e via `./scripts/run-e2e-tests.sh`,
  never bare `npm run test:e2e`.
- aislop is opinionated and can disagree with these standards. Where they conflict,
  **the documented standards win** — Unit 7's rejected `entity-ref` finding is a
  worked example.
