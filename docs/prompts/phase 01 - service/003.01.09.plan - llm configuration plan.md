# LLM Configuration Plan (003.01.09)

Implements company-level LLM config inheritance, making `LcpRole.llmConfig` optional, with guards at role-creation and company-update time.

---

## What was built

### Entity changes

**`LcpCompany`** — Added `llmDefault?: LlmConfig` as a nullable JSONB column. Imported `LlmConfig` type from `LcpRole.model.ts`.

**`LcpRole`** — Changed `llmConfig!: LlmConfig` to `llmConfig?: LlmConfig` with `nullable: true` on the TypeORM column. `LcpRoleTemplate` (`Omit<LcpRole, 'id' | 'company'>`) picks up the change automatically.

### Migration

`apps/lcp-server/src/migrations/1750000000002-CompanyLlmDefault.ts`:

- `ALTER TABLE "lcp_company" ADD COLUMN "llmDefault" jsonb` (nullable, no default)
- `ALTER TABLE "lcp_role" ALTER COLUMN "llmConfig" DROP NOT NULL`

Down reverts both, back-filling nulls in `lcp_role.llmConfig` with a sentinel before restoring NOT NULL.

### Guards — `DbService`

**`createRole`:** If `template.llmConfig` is absent, load the company and throw `BadRequestException` if `company.llmDefault` is also absent.

**`setCompany`:** Merged result computed upfront. If `merged.llmDefault` is falsy and the company has an `id`, count roles with `llmConfig IS NULL`. Throw `BadRequestException` if any exist. `replace: true` path (slug-replace) is exempt — it cascade-deletes all roles first.

### Fallback — `AgentLoopService`

Added `@InjectRepository(LcpCompany) companyRepo` injection. After loading the role, resolves:

```typescript
const llmConfig =
  role.llmConfig ??
  (await this.companyRepo.findOneBy({ id: agent.companyId }))?.llmDefault;
```

If `llmConfig` is still undefined, logs an error, sets agent status to `Failed`, and returns early. Passes `llmConfig` explicitly to `runLoop()` as a new parameter (instead of reading `role.llmConfig` inside the method).

### Module wiring

`AgentWorkerModule`: added `LcpCompany` to `TypeOrmModule.forFeature([...])`.
