Let's plan a scenario simulation script for manual review, that can run against a test server. Create a new plan.

The new script should accept parameters that lcp-cli would need (username, password, baseUrl). It can probably be a shell script as it's reasonably simple.

It assumes:

- that there's a running server at the baseUrl
- that this running server has default LLM config in its .env

It should...

- proceed through a short process simulating a simple chat with test roles present
- halt the script on any failure

## 1. Create a test company

- `cat scripts/test-data/companies/simple-company.json` and pipe that into lcp-cli with verb `set-company`
  - fail if there's an error response with a helpful error message
  - capture the response json
  - store the company id in a variable for use later
- `list-companies`
  - pipe that into jq and fail if the new company isn't there (look for it by id)

## 2. Create the chicken assistant role

- `cat scripts/test-data/roles/chicken-assistant.json` and pipe that into lcp-cli with verb `set-role`
  - fail if there's an error response with a helpful error message
  - capture the response json
  - store the chicken assistant role id in a variable for use later
- `list-roles`
  - pipe that into jq, filter for the new role under the company id, and fail if the new role isn't there

## 3. Create the cat assistant role

- do the same for `scripts/test-data/roles/cat-assistant.json`
  - also store the cat assistant role id in a variable for use later

## 4. Submit prompts, present checks to the user

- for each prompt:
  - use the `chat` verb with `--role-id` for the selected role, `--prompt`, so showing the response to the user
  - for each check related to that prompt:
    - ask the user the check
    - each check is a yes/no, so fail on no, and proceed to the next prompt/check on yes

### Prompts

Some starting prompts and checks - please make this configurable in the script by setting a variable or reading some json.
