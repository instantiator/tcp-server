### Required tool call tracking

> - **Required tool call tracking** — `LcpAgent.requiredToolCalls?: string[]` set at creation (e.g. `['complete_task']` for consultation agents); `AgentLoopService` warns or retries if the stream ends without all required calls having fired; reduces silent fallback completions where the agent narrated a tool call instead of invoking it

We discussed adding a list of tool calls to `LcpAgent` that are required for the chat to be allowed to complete (with a count of retries explaining what's not done and what's expected of it, before giving up and failing the process). That way, for normal usage the LLM will be reminded to make calls for completion and summary; and when an agent-to-agent consultation takes place, we can be assured that the LLM will be instructed to call the appropriate tools to return its answer as well as completion and summary.

### Passing back failure information

Further, when an agent-to-agent process fails (eg. the agent fails complete its task successfully, or fails to call the appropriate interaction successfully after sufficient retries, or notes that for some reason it cannot or should not answer the question or complete a task) then that failure should be communicated back to the originating agent - which should then use its own judgement about how to proceed. (Perhaps the failure message could recommend escalating to a user if a response is absolutely necessary to be able to continue.)
