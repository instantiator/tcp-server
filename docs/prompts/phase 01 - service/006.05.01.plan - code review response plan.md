# 006.05.01 — Code Review Response Plan

Implementation plan in response to the structural code review in `006.05.00.prompt - code review comments.md`.
Phases are ordered so foundation work (shared library consolidation, entity changes, migrations) lands before the layers that depend on it.

## Phase 1 — Style: fix box-drawing section comments ✅

Replace all `// ─── Section name ─────` comments with plain `// Section name` in `apps/lcp-mcp-storage/src/mcp/storage-tools.service.ts`.

## Phase 2 — agent-loop.service.ts: comments and prompt strings ✅

### 2a — JSDoc/inline comments

JSDoc `/** … */` on every public and private method in `AgentLoopService`. Inline `//` comments for prompt parts 6 and 7 inside `buildInitialState`.

### 2b — Move baked strings to prompts.jsonc

`buildServiceMessage` and `buildRagMessage` inline prompt text moved to `apps/lcp-agent/src/prompts.jsonc`. Loaded via the existing `interpolate()` helper.

## Phase 3 — MCP server registry ✅

Hardcoded `['storage', 'memory', 'interactions']` list replaced with a typed registry in `apps/lcp-agent/src/mcp/mcp-registry.ts`. `resolveMcpServerUrls` moved there and imported from the registry file.

## Phase 4 — Agent run limit configuration ✅

- Renamed constants: `MAX_ITERATIONS` → `DEFAULT_AGENT_ITERATIONS`, `TIMEOUT_MS` → `DEFAULT_AGENT_LOOP_TIMEOUT_MS`
- `runConfig?: AgentRunConfig | null` JSONB column added to `LcpRole` and `LcpCompany`
- Migration `AddRunConfigToRoleAndCompany` generated and registered
- Optional `AGENT_ITERATIONS` / `AGENT_LOOP_TIMEOUT_MS` env vars added to lcp-agent config schema
- `resolveRunConfig` utility in `libs/lcp-shared/src/utils/resolve-run-config.ts`; precedence: role → company → env → default

## Phase 5 — LLM error handling in agent loop ✅

Summary generation now retries once (2 s delay) then falls back to a structured plaintext summary built from the agent's final state if the retry also fails.

## Phase 6 — DRY: shared library consolidation ✅

### 6a — Shared AuditClientService

Consolidated four identical `audit-client.service.ts` files to `libs/lcp-shared/src/audit/audit-client.service.ts`. Includes `notifyComplete()` (previously lcp-agent only). All four apps import from `@lcp/shared`.

### 6b — Shared BaseMcpController

Abstract base class in `libs/lcp-shared/src/mcp/base-mcp.controller.ts`. Each MCP app's controller extends it, applies `@Controller('mcp')`, and implements `createServer()`. `@Get()` and `@Delete()` are **separate methods** on the base (not stacked decorators — NestJS only registers the outermost when stacked).

### 6c — Shared TypeORM factory

`makeTypeOrmConfig(entities, migrations?)` in `libs/lcp-shared/src/db/typeorm-config.factory.ts`. Returns SQLite in-memory when `DATABASE_URL` is absent or starts with `sqlite`; Postgres otherwise. Used by lcp-server, lcp-agent, and lcp-mcp-memory.

## Phase 7 — MCP tool strings → tools.jsonc ✅

`tools.jsonc` created in each MCP app's `src/` root. Tool name, description, and parameter descriptions loaded from file instead of inline in `registerTool()` calls.

## Phase 8 — Health controllers review ✅

`lcp-mcp-interactions` has no direct infra dependencies (no DB, Redis, MinIO). Its static `{ status: 'ok' }` health response is correct by design. Explanatory comment added to the health controller.

Cross-service health call pattern documented in `docs/database.md`: each service's `/health` probes only its own infrastructure; startup ordering is handled by docker compose `depends_on`; cross-service validation belongs in smoke tests.

## Phase 9 — DB concurrency ✅

- `@VersionColumn() version!: number` added to `LcpAgent`, `Conversation`, `PendingConsultation`
- Migration `AddVersionToLcpAgentConversationAndConsultation` generated and registered
- `withOptimisticRetry<T>(fn, maxRetries?)` in `libs/lcp-shared/src/db/optimistic-retry.ts`; applied to all `save()` / `update()` calls on the three entities
- `docs/database.md` created covering: configuration, which services connect, SQLite fallback, concurrency strategy, migrations, manual querying

## Phase 10 — E2E test expansion ✅

Existing tests moved to `test/e2e/lcp-server/`:

- `app.e2e-spec.ts` → `lcp-server/company-role.e2e-spec.ts`
- `internal.e2e-spec.ts` → `lcp-server/internal-conversation.e2e-spec.ts`

New lcp-server specs: `agent.e2e-spec.ts`, `model.e2e-spec.ts`, `company-user.e2e-spec.ts`, `role-document.e2e-spec.ts`, `audit.e2e-spec.ts`.

New app-level specs:

- `test/e2e/lcp-agent/health.e2e-spec.ts`
- `test/e2e/lcp-mcp-interactions/health.e2e-spec.ts` + `mcp.e2e-spec.ts`
- `test/e2e/lcp-mcp-memory/health.e2e-spec.ts` + `mcp.e2e-spec.ts` (skipped without Postgres)
- `test/e2e/lcp-mcp-storage/health.e2e-spec.ts` + `mcp.e2e-spec.ts`

`test/jest-e2e.json` `testMatch` updated to `**/*.e2e-spec.ts` to pick up subdirectories.

Key implementation notes:

- `Accept: application/json, text/event-stream` header required for MCP POST requests (SDK returns 406 without it)
- `@Get()` and `@Delete()` must be **separate methods** on `BaseMcpController`, not stacked on one method (NestJS decorator application order means only the outermost method decorator wins)
- `process.env` stubs for MCP service URLs must live in `test/e2e/e2e-setup.ts` (`setupFiles`), not in test files — TypeScript `import` compiles to `require()` at the top of CJS output and runs before top-level code
