## Context

The project is renaming:

- `LCP` / `lcp` / `Little Computer People` → `TCP` / `tcp` / `Tiny Computer People`
- `mini-office` → `tiny-office`

This is a cosmetic rename with one genuinely destructive component: the database
tables are named `lcp_company`, `lcp_agent`, `lcp_role`, `lcp_task`,
`lcp_assignment`, and the user has chosen to **squash the 33 existing migrations
into a fresh `tcp_*` baseline** rather than add a rename migration.

Measured scope (excluding `node_modules`, `dist`, `.git`, `coverage`):

| `apps/lcp-server`                           | 123                               |

| `apps/lcp-cli`                              | 70                                |

| `libs/lcp-shared`                           | 46                                |

| Root config, `.github`, `docker`, `schemas` | ~18                               |

## Decisions already taken — do not relitigate

| Decision          | Choice                                                                       |
| ----------------- | ---------------------------------------------------------------------------- |
| DB tables         | **Squash 33 migrations to a `tcp_*` baseline.** Destructive to existing DBs. |
| `docs/prompts/**` | **Leave untouched.** Historical record.                                      |
| Sequencing        | This sub-plan lands **first**.                                               |

> [!WARNING]
>
> ## Erase existing dev volumes before you start
>
> The squash replaces every migration with a fresh `tcp_*` baseline. Any existing
> database will not match it and **cannot be migrated forward**. Before starting,
> destroy every dev Postgres volume:
>
> ```bash
> docker compose -p lcp-dev   down -v
> docker compose -p lcp-api   down -v   # if present
> docker compose -p lcp-smoke down -v   # if present
> docker volume ls | grep -Ei 'lcp|tcp'  # confirm nothing survives
> ```
>

> **Ask the user to confirm volumes are wiped before running Unit 2.**

## Non-goals — explicitly out of scope

- **`docs/prompts/**` (106 files).** These are records of what was written at the
  time; rewriting them would misrepresent the history for no navigational gain.
  `docs/index.md` already describes them as "records of how the project was
  designed, not active documentation".
- **The GitHub repository rename** (`instantiator/lcp-server` → `tcp-server`) and
  **the local clone path** (`~/src/mini-office/...` → `~/src/tiny-office/...`).
  Both are outside the repo and are manual steps for the user. Note them in your
  final report; do not attempt them.
- **`dev-environment/`** — a vendored copy of a separate repository. Leave it alone.
- Any behaviour change. This sub-plan renames things. Nothing else.

## Deliberate inconsistencies that must survive untouched

These look like mistakes and are not. Do not "tidy" them.

1. **`DynamicEmbeddingDimension` imports `defaults` by relative path**, not via the
   `@lcp/shared` alias. This is deliberate — the e2e tier's Jest globalSetup loads
   migrations without `tsconfig` paths or `moduleNameMapper`, so the alias would
   fail to resolve. The comment above the import explains it. Update the path
   text for the directory rename; keep it relative.
2. **Entity date columns are untyped** (`@Column({ nullable: true }) field?: Date`)
   so the same entities work against both Postgres and SQLite.
3. **`scripts/check-migrations.sh` is diagnostic-only**, not a gate — this repo has
   permanent phantom drift by design (uuid↔varchar, tz, pgvector, index names).
   **Do not validate the squash with `npm run migration:generate`** — it will
   always report drift and will mislead you.

# Units of development

Each unit ends with tests and a quality gate. **Do not begin a unit until the
previous one is green.** Commit at the end of each unit so a failure is bisectable.

## Unit 1 — Pre-flight

1. Branch from `main`: `git checkout -b 011.1.1_rename-to-tcp`.
2. Establish a green baseline **before changing anything**:
   ```bash
   ./dev-environment/scripts/check.sh
   ./scripts/run-all-tests.sh
   ```
   Record the pass counts per tier. These are your regression reference — the same
   counts must hold at Unit 9. If the baseline is not green, **stop and report**;
   do not rename on top of pre-existing failures.
3. Confirm with the user that dev volumes are wiped (see the warning above).

**Gate:** baseline recorded, volumes confirmed wiped.

## Unit 2 — Migration squash (33 → 2)

> [!WARNING]
> Destructive. Confirm dev volumes are wiped before running anything here.

The 33 files in `apps/lcp-server/src/migrations/` are registered through a single
`MIGRATIONS` array in `apps/lcp-server/src/migrations-list.ts`.

1. Read every existing migration and derive the **cumulative final schema**. Work
   from the migrations, not from a live database — the goal is a baseline that
   reproduces exactly what a fully-migrated DB looks like today.
2. Write **one** baseline migration creating every table with the `tcp_` prefix
   (`tcp_company`, `tcp_agent`, `tcp_role`, `tcp_task`, `tcp_assignment`) and all
   non-prefixed tables unchanged (`knowledge_chunk`, `episodic_memory`,
   `company_user`, `conversation`, `audit_event`, `knowledge_index_state`, …).
   Include: pgvector extension setup, all columns, FKs, indexes (including the
   IVFFlat index and the composite audit indexes), and `TIMESTAMPTZ` types.
   Vector columns use `DEFAULT_EMBEDDING_DIMENSION`.
3. **Retain `1784800000000-DynamicEmbeddingDimension.ts` unchanged** as the second
   and last migration. It is env-driven and idempotent — it reads
   `EMBEDDING_DIMENSION` and resizes vector columns when it differs, which is what
   lets the setup wizard and `set-embedding-model` change dimensions after
   deployment. Folding it into the static baseline would break that feature.
4. Delete the other 32 migration files and rewrite `migrations-list.ts` to the two
   remaining entries, in order.
5. Update `apps/lcp-server/src/app.module.ts` if it references migrations directly.

**Tests:**

- Bring up a **completely fresh** stack and confirm both migrations apply cleanly
  from empty.
- `./scripts/run-integration-tests.sh` and `./scripts/run-e2e-tests.sh` — these
  provision real Postgres via testcontainers and are the real proof the baseline
  is correct.
- Verify `EMBEDDING_DIMENSION` still takes effect: set a non-default value, start
  up, confirm the vector columns resize.

**Gate:** `./dev-environment/scripts/check.sh` + integration + e2e green from an
empty database. Do **not** run `migration:generate` to check your work.

## Code quality requirements

Route via `AGENTS.md` → `dev-environment/guidance/index.md`; read
`process/before-coding.md` first and `process/after-coding.md` when done. State the
filename of each guidance doc you read.

- **After every unit**, run `./dev-environment/scripts/check.sh` and fix what it
  reports before starting the next. Never bypass a hook with `--no-verify`.
- Zero compiler and linter **errors and warnings** — formatting counts as a warning.
- Never cast to `any`, especially in test mocks — type the mock instead.
- Comments state **intent**, not mechanics. Keep TSDoc on classes/functions/consts;
  `{@link}` for type references; no decorative separator comments.
- No unrequested abstractions, and **no opportunistic refactoring** — this sub-plan
  renames things and nothing else. Real improvements you spot belong in 011.1.2–011.1.5;
  note them in your report rather than fixing them here.
- No secrets in the codebase.
- Entity schema changes need a paired migration registered in `migrations-list.ts`.
- Generated artefacts (`schemas/schema.json`, `docs/licenses.md`) are regenerated
  via `npm run build`, never hand-edited.
- Full suite via `./scripts/run-all-tests.sh`; e2e via `./scripts/run-e2e-tests.sh`,
  never bare `npm run test:e2e`.
- aislop is opinionated and can disagree with these standards (notably on
  commenting). Where they conflict, **the documented standards win**.
