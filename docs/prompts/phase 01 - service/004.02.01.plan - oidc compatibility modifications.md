# 004.02.01 — OIDC compatibility modifications

## Context

During 004.02.00 we identified two changes made to support Keycloak that broke
general OIDC provider compatibility. This document records what was changed to
restore full compatibility.

## Problems found

### 1. Hardcoded Keycloak JWKS path

**File**: `apps/lcp-server/src/auth/jwt.strategy.ts`

**Before** (Keycloak-specific):

```typescript
jwksUri: `${internalUrl.replace(/\/$/, '')}/protocol/openid-connect/certs`,
```

`/protocol/openid-connect/certs` is Keycloak's non-standard JWKS path.
Standard providers (Auth0, Okta, Azure AD, Google) all use different paths;
there is no universal JWKS URI path. The OIDC specification mandates that the
correct URI be published as `jwks_uri` in the discovery document at
`{issuer}/.well-known/openid-configuration`.

### 2. Audience validation removed

**File**: `apps/lcp-server/src/auth/jwt.strategy.ts`

The audience check was removed entirely because Keycloak's ROPC tokens set
`aud: account` by default (not the client ID). This removes a security
constraint that providers like Auth0 and Okta rely on — they expect `aud` to
be validated against a known API identifier.

## Changes made

### 1. JWKS URI discovery (jwt.strategy.ts + auth.module.ts)

`JwtStrategy` constructor now takes `jwksUri` as an explicit parameter rather
than constructing it from the issuer URL.

`auth.module.ts` was converted to use an async factory provider that:

1. Checks `OIDC_JWKS_URI` env var for an explicit override (escape hatch for
   providers that don't support discovery).
2. Otherwise, fetches `{OIDC_INTERNAL_ISSUER_URL}/.well-known/openid-configuration`
   and reads the `jwks_uri` field from the discovery document.
3. Rebases the discovered `jwks_uri` onto the internal issuer URL using the
   same hostname-rebase logic as `AuthTokenService.resolveTokenEndpoint()`.
   This handles Keycloak's `KC_HOSTNAME` setting (and any equivalent provider
   behaviour) that causes the discovery doc to advertise external hostnames
   even when fetched via an internal Docker network URL.

This approach is compatible with every OIDC provider that publishes a
standards-compliant discovery document — which is all mainstream providers.

### 2. Opt-in audience validation (jwt.strategy.ts + config.schema.ts)

Audience validation is restored as optional. The factory reads `OIDC_AUDIENCE`
from config and, if set, passes `{ audience }` into the strategy options.

Two new optional env vars were added to `config/config.schema.ts`:

```
OIDC_JWKS_URI    — explicit JWKS URI override (skips discovery fetch)
OIDC_AUDIENCE    — audience claim value to validate (skipped if unset)
```

### 3. E2E test setup (test/e2e-setup.ts)

The async factory runs at module init and performs a fetch. E2E tests run
without Keycloak. Added `OIDC_JWKS_URI=http://localhost:8080/stub-jwks` to
the e2e stub env — this causes the factory to skip the discovery fetch. The
URI value is irrelevant because `jwks-rsa` is mocked in e2e tests.

## Compatibility matrix after changes

| Scenario                   | OIDC_JWKS_URI           | OIDC_AUDIENCE       | Behaviour                     |
| -------------------------- | ----------------------- | ------------------- | ----------------------------- |
| Keycloak (dev default)     | unset                   | unset               | Discovery fetch; no aud check |
| Keycloak + audience mapper | unset                   | `my-api`            | Discovery fetch; validate aud |
| Auth0                      | unset                   | `https://my-api`    | Discovery fetch; validate aud |
| Okta                       | unset                   | `api://default`     | Discovery fetch; validate aud |
| Azure AD                   | unset                   | `api://{client-id}` | Discovery fetch; validate aud |
| No-discovery provider      | `https://provider/keys` | as needed           | Skip fetch; use override      |
| E2E tests                  | stub (any)              | unset               | Skip fetch; mock signing key  |

## Files changed

- `apps/lcp-server/src/auth/jwt.strategy.ts` — constructor now takes `(config, jwksUri, audience?)`
- `apps/lcp-server/src/auth/auth.module.ts` — async factory with `resolveJwksUri` helper
- `apps/lcp-server/src/config/config.schema.ts` — `OIDC_JWKS_URI` + `OIDC_AUDIENCE` optional vars
- `apps/lcp-server/test/e2e-setup.ts` — stub `OIDC_JWKS_URI` to bypass discovery in e2e
- `docs/authentication.md` — new; documents OIDC setup for all provider types
