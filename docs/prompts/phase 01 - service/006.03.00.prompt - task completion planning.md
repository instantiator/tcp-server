Let's create a new plan to iterate on the completion conditions for an agent loop.

## Completion conditions

We've discussed in earlier conversations how the agent loop requires that the agent provides an output and checks for it when the LLM stops. When the agent uses MCP to provide an output, let's put a check in place to confirm that any files referenced in the output exist in shared storage: these files don't _need_ to have been created or modified in this agent loop, because its task might have been (eg.) to locate a particular file and comment on it.

If the named files don't exist, it should return a short templated/canned prompt that explains what's wrong, and instructs the agent to resolve it. It can include:

- which files are listed but missing
- files the agent has created or modified during the agent loop

If the agent has modified files during the agent loop, the prompt should ask if the agent meant to name one or more of those, or has made a typo in its submission. If it wants to make a correction it should submit an additional output.

If a subset of those files (and any other files it's aware of) wouldn't complete the output, it should continue working, and submit a new output when ready.

> [!NOTE]
> File tracking during an agent loop _could_ be extracted from the audit log, but I prefer that files be tracked separately, during the agent loop, as actions are taken, as part of the that completion summary (see below).

## Task completion summaries

After completing a task successfully, the agent should be prompted once more to provide text supporting short summary of everything it has done. This should be audit logged as a new kind of task completion summary audit event.

The `LcpTaskCompletionSummary` should be a structured event, something like this:

```ts
{
  summary: string,
  actions: string[],
  storage: {
    created: string[],
    modified: string[],
    deleted: string[],
    moved: { from: string, to: string }[],
  },
}
```

- `summary` - a short summary of what the agent did. It's an 'at a glance' confirmation of the top level changes. It could be 1 or a few sentences, but should avoid going into detail.
  - eg. "Created the new policy document for hiring."
  - eg. "Reorganised the shared design documents."
- `actions` - a short summry of each action taken through tools, in chronological order. ie. For each mcp tool, a short sentence is created (these can be templated/canned by the MCP service).
  - eg. `Created a new file: ${path}`
  - eg. `Consulted with ${user}: ${query}`
- `storage` - a structured object describing all changes to the shared storage

This means that:

- The agent loop should track actions taken, and changes to shared storage (this is more efficient than retrieving this data from audit logs)
- After the agent loop completes, the LLM should be presented with everything it needs to generate a short summary explaining what it did (eg. "Designed the login page.") which is also added to the task completion summary (this needn't be a full N-part prompt, just enough context to generate the summary)
