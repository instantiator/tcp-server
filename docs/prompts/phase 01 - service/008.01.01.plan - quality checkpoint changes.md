# 008.01.01 — Quality checkpoint: changes made

Light-touch code-quality pass run via the `quality-review` skill. Scope: changed
code plus the highest-signal findings from `check.sh` / `aislop scan` across the
important flows (chat orchestration, MCP tools, agent loop, CLI).

Result: `check.sh` passes (lint, typecheck, build, unit-tests, shellcheck,
aislop). aislop warnings dropped from **25 → 8** and high-confidence findings
from **13 → 0**. The remaining 8 are reviewed-and-accepted (see below).

## Changes

### Correctness / robustness

- **Undeclared direct dependencies** (`package.json`). `zod`, `json5`, and
  `js-tiktoken` were imported directly across several apps but only resolved
  transitively — a fragile setup that breaks silently if an upstream package
  drops them. Declared them as direct prod deps at their currently-installed
  versions (`zod ^4.4.3`, `json5 ^2.2.3`, `js-tiktoken ^1.0.21`, all MIT).
  Lockfile and `docs/licenses.md` regenerated.
- **Duplicate `lint:check` script** (`package.json`). The script key was defined
  twice, identically; the second silently shadowed the first. Removed the dupe.

### Simplification / de-duplication

- **`apps/lcp-mcp-interactions/.../interactions-tools.service.ts`** — the two
  near-identical tool registrations `registerListAvailableUsers` /
  `registerListAvailableRoles` (proxying `GET /internal/company/{id}/{users|roles}`)
  collapsed into one parameterised `registerCompanyListTool` helper. ~46 lines →
  ~34, behaviour unchanged (existing tests cover both endpoints and error paths).
- **`apps/lcp-agent/.../agent-loop.service.ts`** — removed a
  `as unknown as Record<string, unknown>` double type-assertion when recording the
  completion summary. Root cause: `AgentLoopCompletionSummary` was an `interface`
  (no index signature), so it wasn't assignable to the audit payload type.
  Changed it to a `type` alias in `libs/lcp-shared/.../AuditEvent.model.ts`, which
  is assignable with no cast. The "why type not interface" rationale is a plain
  `//` comment so it doesn't leak into the generated JSON schema description.
- **`apps/lcp-server/.../api/chat.service.ts`** — merged a duplicated `@lcp/shared`
  import (`DEFAULT_LLM_TIMEOUT_MS` was imported separately from the main block).

### Break long/complex functions into supporting files

- **`apps/lcp-cli/src/commands/chat.ts`** — the `registerChat` command handler was
  297 lines with depth-8 nesting, the worst offender being the inline SSE
  parsing + compaction-event formatting inside `observeEvents`. Extracted that
  pure logic into a new supporting module **`apps/lcp-cli/src/lib/sse.ts`**
  (`parseSseBuffer`, `formatCompactionEvent`), reducing nesting to ~4 and slimming
  the handler by ~35 lines. The logic is now unit-testable in isolation — added
  **`apps/lcp-cli/src/lib/sse.spec.ts`** (8 cases: buffer splitting with a trailing
  partial event, malformed-JSON skipping, non-data lines, both compaction event
  formats, `?` fallbacks for missing numeric fields, null for unrelated kinds).

### Documentation / comment accuracy

- **`apps/lcp-server/.../api/api.company.controller.ts`** — `getCompany`'s doc
  comment said "Returns an empty body when no match is found (see TODO below)" but
  there was no TODO below. Corrected to describe the actual behaviour: returns
  `null`, serialised as an empty body.

## Follow-up: e2e hang diagnosis (not a regression)

A subsequent run of the e2e tier hung and was halted. Diagnosis: the suite was
invoked as raw `npm run test:e2e` / `jest`, **without** the Docker services it
needs. With Redis down, the BullMQ enqueue/orchestration paths (consultation
pause, agent resume) block on the unreachable broker, so requests never return —
each test hits the jest timeout and `afterAll app.close()` hangs on the open
ioredis handles. Which tests time out is nondeterministic (offline-retry
timing), which is why the failing set varied between runs.

- **Confirmed not caused by this checkpoint's changes.** Run correctly via
  `./scripts/run-e2e-tests.sh` (starts Postgres/Redis/MinIO), the full tier is
  green: **15 suites, 64 tests, 6.5s**.
- Fixed the misleading comment in `test/e2e/e2e-setup.ts` that described the
  suite as running "without external services" — it does need Postgres/Redis; the
  comment now says so and warns that raw `jest` will hang.
