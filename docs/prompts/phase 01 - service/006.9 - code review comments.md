## Agent run limit configuration

The agent run limits are a little short.

It's entirely possible that an agent will have a complex task to complete, and that this will require plenty of interations. Local inference is slow - and we should allow a limit that doesn't penalise users with low powered machines.

Let's:

- rename `MAX_ITERATIONS` to `DEFAULT_AGENT_ITERATIONS`
- rename `TIMEOUT_MS` to `DEFAULT_AGENT_LOOP_TIMEOUT_MS`
- allow both to be overridden in the chosen `.env`
- add (and comment out) entries for these in `.env.example`, and `.env.testing`
- allow these values to be set in company config (optionally)
- allow these values to be set in role config (optionally)

In terms of precedence, draw the value from:

1. `LcpRole` (if defined)
2. `LcpCompany` (if defined)
3. Environment vars (if defined)
4. Default constants in the code

This is going to be a common order of precedence for a good amount of configuration in future, so if there's a good way to DRY it, that would be preferable.
