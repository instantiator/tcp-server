## New application CLI

The CLI is intended to interact with an LCP server through its exposed endpoints.

Ideally this would be written in typescript, able to share data structures with the rest of the project, and would be launchable from the cli.

For this plan, please review how everything works. Let me know if additional API endpoints are required. Ask questions to disambiguate where necessary, and let me know if there's a cleaner or more standard way to do things (eg. the parameters, etc.)

## Core parameters

- `-h` / `--help` if set, print usage information, and exit (negates any other required parameters, and doesn't execute any other actions)
- `-s` / `--lcp-server` (where to find the server API endpoints - default: assume a local instance), allow specification of a full base url, eg. `http://domain:port/and/perhaps/a/path`
- `-u` / `--username` and `-p` / `--password` (credentials to exchange for an access token), or `-t` / `--access-token` (the token itself) or `-e` / `--access-token-env-var` (env variable containing the access token)

If the username field is provided, but the password field is not, this then initiates an interactive password typing prompt (mask the characters typed) for the user.

## Getting a token

Verb: `get-token`

This makes the username field required.

- stdout: the token
- stderr: nothing, or a warning message if it fails

## Listing all companies

Verb: `list-companies`

- stdout = { id: uuid, name: string }[]
- stderr = progress, errors, warnings

## Listing all roles

Verb: `list-roles`

- stdout = { id: uuid, name: string, roles: { id: uuid, name: string }[] }[]
- stderr = progress, errors, warnings

### Parameters

- `c` / `--company-id` (uuid) - optional, if provided, filters to just that company

## Updating a company

Verb: `set-company`

Creates or updates an `LcpCompany`.

- stdout = the updated or created company (json)
- stderr = progress, errors, warnings

### Parameters

- `-i` / `--input` (a json `PartialOfPartials<LcpCompany>`)
  - If provided, sets the provided properties, unless validation fails
  - If not provided, assume the json will come from stdin
  - If the id of the object is provided, this is an update operation, and required fields are not required, and if not provided, the current values are left alone (although nulling a field by explicitly providing it with value `null` is still possible)
  - If the id of the object is not provided, this is a create operation: the required fields are required

## Updating a role

Verb: `set-role`

Creates or updates an `LcpRole` in the specified `LcpCompany`.

- stdout = the updated or created role (json)
- stderr = progress, errors, warnings

### Parameters

- `c` / `--company-id` (uuid) - required if the role is being created
- `-i` / `--input` (a json `PartialOfPartials<LcpRole>`)
  - If provided, sets the provided properties, unless validation fails
  - If not provided, assume the json will come from stdin
  - If the id of the object is provided, this is an update operation, and required fields are not required, and if not provided, the current values are left alone (although nulling a field by explicitly providing it with value `null` is still possible)
  - If the id of the object is not provided, this is a create operation: the required fields are required

`PartialOfPartials<T>` is shorthand... It's a `Partial<T>` but all object references inside it are also partials, too - is there an easy way to implement that?

## Communicating with an agent

Verb: `chat`

Initiates a conversation with an agent, using a given `LcpRole`. Triggers creation of an agent using the given role. Then enters an interactive prompt / response mode, where the user can issue messages to the agent which it may (in future) enact, or respond to. For this MVP, it'll just reply.

When the conversation closes (including when interrupted by a ctrl+c or other interruption), or when the user types `exit` or `quit`, the agent is removed.

Please describe what's involved with keeping a history of the current conversation (perhaps condensed?), so that the user and agent can hold meaningful discussions.

### Parameters

- `r` / `--role-id` (uuid) the role of the agent to initiate
- `q` / `--query` (string) a question to issue to the agent (if this is set, the stdout is the response, stderr for any status/process indicators, and the app should close the conversation, close the agent, and ezxit after the response instead of entering interactive mode)
