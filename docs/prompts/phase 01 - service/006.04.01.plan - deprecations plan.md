# 006.04.01 — Deprecated API Calls — Implementation Plan

## Context

`@typescript-eslint/no-deprecated` is enabled as `"error"` in `eslint.config.mjs` so that any future use of a deprecated API fails `npm run lint`. All existing violations are fixed in the same commit.

See `006.04.00.plan - deprecated calls planning.md` for the full investigation.

## Step 1 — Enable the lint rule

Add to the global `rules` block in `eslint.config.mjs`:

```ts
'@typescript-eslint/no-deprecated': 'error',
```

The rule is type-aware and works with the existing `recommendedTypeChecked` setup; no new packages are required.

## Step 2 — Fix existing violations

### `McpServer.tool` → `McpServer.registerTool` (26 call sites)

The new method wraps `description` and `inputSchema` in a config object:

```ts
// Before
server.tool('name', 'Description.', { param: z.string() }, handler);

// After
server.registerTool(
  'name',
  { description: 'Description.', inputSchema: { param: z.string() } },
  handler,
);
```

Zero-argument tools omit `inputSchema`:

```ts
// Before
server.tool('name', 'Description.', {}, handler);

// After
server.registerTool('name', { description: 'Description.' }, handler);
```

Files: `interactions-tools.service.ts` (6), `storage-tools.service.ts` (16), `memory-tools.service.ts` (4).

### `z.string().uuid()` → `z.uuid()` (15 call sites)

`z.uuid()` is a first-class Zod v4 string schema; `.describe()` and `.optional()` chain identically.

Files: `interactions-tools.service.ts` (8), `memory-tools.service.ts` (7, formatted as multi-line chains).

### `client.disconnect()` → `client.destroy()` (1 call site)

Redis `ioredis` client: `disconnect()` is deprecated in favour of `destroy()`, which is synchronous — remove `await`.

File: `apps/lcp-agent/src/health/health.controller.ts`.

### `z.ZodTypeAny` → `z.ZodType` (3 call sites)

Zod v4 deprecates the `ZodTypeAny` type alias; `z.ZodType` (without generics) is the replacement.

File: `apps/lcp-agent/src/mcp/mcp-client.service.ts`.
