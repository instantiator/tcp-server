# 006.04.00 — Deprecated API Calls — Planning

## User request

While reviewing the codebase, two deprecated API usages were spotted:

1. `McpServer.tool()` — the MCP SDK deprecation notice says "use `registerTool` instead."
2. `z.string().uuid()` — Zod's deprecation notice says "Use `z.uuid()` instead."

Both patterns appear across `lcp-mcp-interactions`, `lcp-mcp-storage`, and `lcp-mcp-memory`. The user asked: should these show as linting errors? And if so, please enable that across the codebase too.

## Investigation

### Installed versions

| Package                     | Version |
| --------------------------- | ------- |
| `@modelcontextprotocol/sdk` | 1.29.0  |
| `zod`                       | 4.4.3   |
| `typescript-eslint`         | 8.60.1  |

### `@typescript-eslint/no-deprecated`

The `typescript-eslint` v8 plugin ships a `no-deprecated` rule that catches usage of any symbol marked `@deprecated` in its JSDoc or TypeScript type declarations. It is type-aware (requires `recommendedTypeChecked`) and is not enabled by default.

Tested against `interactions-tools.service.ts` with `--rule '{"@typescript-eslint/no-deprecated": "error"}'`: it flagged every `server.tool()` and `z.string().uuid()` call with clear messages pointing to the replacement API.

### Full scope of violations

Running the rule project-wide revealed violations beyond the originally spotted ones:

| File                                                              | Deprecated symbol                               | Replacement                |
| ----------------------------------------------------------------- | ----------------------------------------------- | -------------------------- |
| `apps/lcp-mcp-interactions/src/mcp/interactions-tools.service.ts` | `McpServer.tool` (×6), `z.string().uuid()` (×8) | `registerTool`, `z.uuid()` |
| `apps/lcp-mcp-storage/src/mcp/storage-tools.service.ts`           | `McpServer.tool` (×16)                          | `registerTool`             |
| `apps/lcp-mcp-memory/src/mcp/memory-tools.service.ts`             | `McpServer.tool` (×4), `z.string().uuid()` (×7) | `registerTool`, `z.uuid()` |
| `apps/lcp-agent/src/health/health.controller.ts`                  | `client.disconnect()`                           | `client.destroy()`         |
| `apps/lcp-agent/src/mcp/mcp-client.service.ts`                    | `z.ZodTypeAny` (×3)                             | `z.ZodType`                |

### API signature change for `registerTool`

`McpServer.registerTool` has a different signature from the deprecated `tool`:

```ts
// Old (deprecated)
server.tool(name, description, inputSchema, handler);

// New
server.registerTool(name, { description, inputSchema }, handler);
```

For zero-argument tools the `inputSchema` key is omitted entirely from the config object.

## Decision

Enable `@typescript-eslint/no-deprecated` as `"error"` in `eslint.config.mjs`, then fix all existing violations so `npm run lint` passes. Future deprecated API usage will be caught automatically at lint time rather than requiring manual audits.

See `006.04.01.plan - deprecations plan.md` for the implementation plan.
