## Cancelling an in-flight prompt

In response to a query about implementation of aborting an LLM response during generation, you said:

> Currently: no. Ctrl+C triggers the SIGINT handler which calls `cleanup()` and `process.exit(0)` — it exits the whole session, it doesn't cancel-and-reprompt. The in-flight fetch also has no `AbortController`, so the server keeps processing even if the client disappears.
>
> **Cancel-and-reprompt (client side only):** achievable. The pattern is:
>
> - Wrap `sendMessage` with an `AbortController`; pass signal to fetch
> - Change the SIGINT handler to: first Ctrl+C aborts the current request and re-shows `> `, second Ctrl+C exits
> - Catch the abort error in the loop and continue rather than break
>
> **Halting the LLM server-side:** possible but more involved. LangChain's `ChatOpenAI` (and most LangChain chat models) accept an `AbortSignal` via `model.invoke(messages, { signal })`. The missing piece is the server detecting the client disconnect and propagating that signal. Node's `req.socket` emits a close event when the client drops, but NestJS doesn't surface this automatically — you'd need to thread an `AbortController` from the request context into `ChatService.sendMessage`. In practice this is the right thing to do (stops burning tokens and compute), but it's a non-trivial server change.
>
> Is this "normal"? For streaming UIs (SSE/WebSocket + a stop button), yes — it's standard. For a synchronous HTTP POST CLI like this one, it's less common but absolutely doable.

Let's plan an implementation for both client-side and server-side, allowing the user to halt generation for a prompt with Ctrl+C giving them a new prompt input.
