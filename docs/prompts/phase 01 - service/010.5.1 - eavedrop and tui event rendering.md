# 010.5.1 — Unified audit events and shared CLI rendering

**Recommended implementation model: Opus** — this is a cross-cutting refactor spanning lcp-server, lcp-agent, lcp-shared, and lcp-cli, with a DB migration, an SSE wire-format change, and a rendering rewrite. Implement the phases in order, one at a time, keeping the quality gate green after each phase (`./dev-environment/scripts/check.sh`; full suites at the checkpoints noted below).

## Context

The live-event system and the audit log have drifted into parallel, mirrored structures:

- Three live-event unions in `libs/lcp-shared/src/events/` (`agent-events.ts`, `task-events.ts`, `company-events.ts`) duplicate information that is (mostly) also written to the `AuditEvent` table — e.g. live `agent_status` vs persisted `state_change` carry the same fact in two schemas.
- The CLI reconstructs history through `mapAuditHistoryToEvents` (`apps/lcp-cli/src/lib/core/audit-to-agent-events.ts`), a drift-prone mirror of the live `mapStreamEvent` (`libs/lcp-shared/src/llm/stream-event-mapper.ts`).
- lcp-cli renders events through **three near-duplicate `switch` blocks**: `PaneEntryLog.append` (`lib/tui/tui-format.ts`), `createRenderer.render` (`lib/core/render.ts`), and `printAuditRow` (`lib/observability/eavesdrop.action.ts`) — each with different output formats.
- Eavesdrop's history mode dumps full LLM message-history JSON, which made it nearly useless.
- Audit rows cannot be filtered by task id (no `taskId` column), and orchestrator rows (agentId null) are missed by task history.

This plan makes **audit events the single source of truth** for both history and live streaming, and builds **one shared rendering library** used by the `tui`, `eavesdrop`, and `chat` modes, for both historical and live events. It also sweeps remaining stale Keycloak references (auth is Zitadel per ADR-017).

## Decisions already made (do not re-open)

1. **Chat input echo comes from SSE**: the CLI does not locally echo the user's typed message; it renders the `input` audit event when it arrives over the stream. Single rendering path; eavesdroppers see user inputs too.
2. **`llm_request` audit rows keep the full message history in their payload** (forensics per ADR-008). Only the _rendering_ changes: line-only in the CLI, never a JSON dump.
3. **Task SSE stays summary-level** (task/assignment state changes only, no per-agent detail or deltas). Task eavesdrop keeps the per-agent follower pattern.
4. **Streaming deltas are live-only** (not persisted per-chunk). The turn's final text is persisted in the `llm_response` row; history replays it as blocks.

## Part A — Unified audit-event model

### A.1 `AuditEvent` schema changes

`libs/lcp-shared/src/models/AuditEvent.model.ts`:

- Add one column:

  ```ts
  /** Denormalised task scope, derived server-side (never drifts). @format uuid */
  @Column({ nullable: true, type: 'varchar' })
  taskId!: UUID | null;
  ```

- Add a third composite index: `@Index(['companyId', 'taskId', 'timestamp'])`.
- Do **not** add kind/activity/tool columns — the required query filters are task/agent/assignment id only; kind/activity/tool are rendering concerns and live in `payload` (jsonb).

Two new `AuditEventType` values (varchar column — no DB change needed for the enum):

- `compaction` — payload `{ phase: 'started' | 'complete', strategies?, tokensBefore?, tokensAfter?, windowSize?, pct? }`
- `input` — user-submitted text (chat message, conversation answer): payload `{ text: string }`

Final set: `llm_request`, `llm_response`, `tool_call`, `tool_result`, `decision`, `state_change`, `agent_loop_completion`, `compaction`, `input`.

`state_change` payloads gain a **mandatory `entity` discriminator** written by all producers: `payload.entity: 'agent' | 'assignment' | 'task' | 'company'`. It renders as the `:kind` suffix (`state_change:task`) and drives channel routing. Legacy rows without it are inferred at render time (see B.2).

### A.2 Migration

New migration `AddAuditTaskId` in `apps/lcp-server/src/migrations/`, **manually registered in `apps/lcp-server/src/app.module.ts`** (import + migrations array — the CLI's data-source glob will silently mask a missing registration; this is a repo rule):

1. `ALTER TABLE audit_event ADD COLUMN "taskId" varchar NULL`
2. Backfill agent rows via the assignment join:
   `UPDATE audit_event ae SET "taskId" = a."taskId" FROM lcp_assignment a WHERE ae."assignmentId" = a.id AND a."taskId" IS NOT NULL`
3. Backfill orchestrator rows from jsonb: `UPDATE audit_event SET "taskId" = payload->>'taskId' WHERE "agentId" IS NULL AND payload ? 'taskId'`; likewise backfill `"assignmentId"` from `payload->>'assignmentId'` where currently null.
4. Create the `(companyId, taskId, timestamp)` index.

(Adjust SQL for the cross-DB situation the migration framework expects; follow the existing migration style in that directory.)

### A.3 Population rules

- `apps/lcp-server/src/audit/create-audit-event.dto.ts`: add optional `@IsOptional() @IsUUID() assignmentId?` and `taskId?`. **Every field must be decorated** — the pipe uses `whitelist: true` and silently strips undecorated fields (repo-documented failure mode).
- `AuditService.write` (`apps/lcp-server/src/audit/audit.service.ts`):
  - If `agentId` is present: derive `assignmentId` from the agent (as today), then derive `taskId` from that assignment. **Caller-supplied ids are ignored when agentId is set** — preserves the "never drifts" invariant.
  - If `agentId` is null (orchestrator/company rows): accept the DTO's explicit `assignmentId`/`taskId`.
- `task-orchestration.service.ts` `recordTaskState`/`recordAssignmentState`: pass `taskId`/`assignmentId` explicitly (keep them in the payload too, for legacy-row compat).
- `AuditService` gains `listByTask(companyId, taskId)`; `TaskService.getHistory` (`apps/lcp-server/src/api/task.service.ts`) becomes that single query — **this fixes the missing-orchestrator-rows gap** and drops the assignments→agents join.

### A.4 Mapping table: every current live-event kind → audit representation

| Current event | New representation |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `AgentEvent agent_status {status, reason, conversationSlug}` | `state_change` `{entity:'agent', newStatus, reason?, conversationSlug?}` — one write, no separate SSE emit |
| `AgentEvent llm request_started` | the `llm_request` row itself (already written), now also streamed live |
| `AgentEvent llm request_complete` | the `llm_response` row; payload **additionally** gains normalized `responseText` and `reasoningText` alongside the raw `output` |
| `AgentEvent llm tool_started {tool}` | `tool_call` row; payload `{tool: <name>, input}` — **fixes the missing tool name on tool_call** |
| `AgentEvent llm tool_complete {tool}` | `tool_result` row; payload `{tool: <name>, output}` |
| `AgentEvent reasoning {delta}` | **StreamDelta** (A.5) — not audited |
| `AgentEvent response {delta}` | **StreamDelta** (A.5) — not audited |
| `AgentEvent consultation_started {agentId, roleName}` | `state_change` `{entity:'agent', newStatus:'paused', reason:'consultation', consultedAgentId, consultedRoleName}` — CLI follower spawning keys on `consultedAgentId` |
| `AgentEvent completed {response}` | `state_change` `{entity:'agent', newStatus:'completed'                                                                                                               | 'idle', reason:'turn_complete', response}` |
| `AgentEvent failed {error}` | `state_change` `{entity:'agent', newStatus:'failed', reason: error}` |
| `AgentEvent compaction_started/complete` | `compaction` `{phase, ...metrics}` |
| `TaskEvent task_changed` | `state_change` `{entity:'task', newStatus, reason, summary: TaskChangeSummary}`, row `taskId` set, `agentId` null |
| `TaskEvent assignment_changed` | `state_change` `{entity:'assignment', newStatus, reason, summary: AssignmentChangeSummary}`, row `assignmentId`+`taskId` set |
| `CompanyEvent company_changed` | `state_change` `{entity:'company', reason}` |
| `CompanyEvent task_changed` | same row as TaskEvent `task_changed`, routed to the company channel too |
| chat's initial `LlmRequest {message}` audit | `input` `{text}` (also used for conversation answers in pause-and-resume) |

`decision` and `agent_loop_completion` are unchanged.

When implementing, cross-check this table against the actual unions in the three files being deleted — every `kind` must have a destination.

### A.5 Wire format

New file `libs/lcp-shared/src/events/wire-events.ts`. Delete `agent-events.ts`, `task-events.ts`, `company-events.ts`; `TaskChangeSummary`/`AssignmentChangeSummary` + their builders and the channel-name helpers move into `wire-events.ts` (they survive as payload types, not as an event family).

```ts
/** Serialized AuditEvent row as it crosses SSE/Redis. */
export interface AuditWireEvent {
  id?: string; // absent for synthesized replay/prime events
  timestamp: string; // ISO
  companyId: string;
  role: string;
  agentId: string | null;
  assignmentId: string | null;
  taskId: string | null;
  eventType: AuditEventType;
  payload: Record<string, unknown>;
}

export interface StreamDelta {
  type: 'stream';
  agentId: string;
  channel: 'reasoning' | 'response';
  delta: string;
  timestamp: string;
}

export type WireEvent = { type: 'audit'; event: AuditWireEvent } | StreamDelta;
```

`StreamDelta` is the **only** surviving non-audit structure. Justification: token deltas arrive in the hundreds–thousands per turn (persisting each would swamp the table and the hot path); there is zero information loss because the turn's full text persists in the `llm_response` row; and it is one 5-field interface with no mirrored family or mapper. The single sync invariant — "the concatenation of a turn's deltas equals `llm_response.responseText`" — holds because lcp-agent computes both from the same LangGraph stream.

### A.6 SSE endpoints: three scoped views over `WireEvent`

All three endpoints stay, now carrying the same payload type:

- `GET /api/agent/:id/events` — all audit events with that `agentId` + that agent's stream deltas.
- `GET /api/task/:id/events` — audit events with that `taskId` where `payload.entity ∈ {task, assignment}`. No deltas, no per-agent rows (decision 3).
- `GET /api/company/:id/events` — audit events where `payload.entity ∈ {company, task}` only (protects the roster TUI from volume).

`replayTerminal` priming survives (`api.agent.controller.ts`): on connect to an already-terminal agent, synthesize `{type:'audit', event: {eventType:'state_change', payload:{entity:'agent', newStatus: agent.status, response: agent.output, reason:'replay'}}}`. `primeTaskEvents`/`primeCompanyEvents` likewise synthesize `state_change` wire events with the same summaries they prime with today (`reason:'replay'`). No DB reads added.

### A.7 Single write path: persist → publish

`AuditService.write` becomes persist-then-publish:

1. `repo.save(event)` with derived ids (A.3).
2. Hand the saved row to a new `AuditEventPublisher` (`apps/lcp-server/src/events/`) that applies the A.6 routing rules and emits `{type:'audit', event}` on the relevant channel buses.

Every producer converges on this path:

- **lcp-agent + MCP servers**: contract unchanged — `POST /internal/audit` via `AuditClientService.record` (DTO now optionally carries assignmentId/taskId for agent-less rows). The server persists AND publishes. lcp-agent **stops** publishing `llm`/`agent_status` AgentEvents to Redis.
- **In-process lcp-server producers** (`chat.service.ts`, `pause-and-resume.service.ts`, `agent-orchestration.service.ts`, `task-orchestration.service.ts`): replace every `events.emit(...)` + separate `audit.record(...)` pair with a single `audit.record(...)`. The agent_status/state_change dual-schema drift disappears by construction.

**Bus consolidation**: delete `AgentEventService`; run three `KeyedEventBus<WireEvent>` instances (agent/task/company). Port `cleanup(key)` (called on agent deletion) and the ref-counted Redis subscription behaviour into `KeyedEventBus` (`apps/lcp-server/src/events/keyed-event-bus.ts`). The agent channel additionally receives messages published directly by lcp-agent (stream deltas); the relay parses them identically since both sides speak `WireEvent`.

**lcp-agent changes** (`agent-loop.service.ts`, `agent-event-publisher.service.ts`):

- The Redis publisher survives but publishes only `StreamDelta`s.
- `mapStreamEvent` (`libs/lcp-shared/src/llm/stream-event-mapper.ts`) shrinks to `mapStreamDeltas(event): StreamDelta[]` (the `on_chat_model_stream` branch only); the four lifecycle branches are deleted (redundant with the EVENT_TYPE_MAP audit writes).
- The `onEvent` hook enriches audit payloads: tool name+input on `tool_call`, tool name on `tool_result`, `responseText`/`reasoningText` on `llm_response`.
- The `updateStatus` live publish becomes an `auditClient.record` state_change (merge with the existing `recordStateChange` where duplicated).

**Terminal detection** (CLI + anything watching for turn end): keys on `eventType === 'state_change' && payload.entity === 'agent' && payload.newStatus ∈ {completed, failed, cancelled, idle}`. This replaces the `completed`/`failed` kinds.

## Part B — Shared CLI rendering library

New directory `apps/lcp-cli/src/lib/render/`:

```
render/
  style.ts            StyleBackend interface + ansiStyle, markupStyle, plainStyle
  line-format.ts      eventLabel(), header/indent/wrap/pretty-JSON helpers, legacy payload extractors
  entries.ts          LogEntry model + renderEntry(entry, width, style)
  audit-renderers.ts  AuditEventRenderer interface + concrete classes + registry
  heading.ts          HeadingBlockRenderer + ScopeTracker + HeadingInfoProvider
  event-log.ts        EventLogBuffer (implements LiveStreamRenderer semantics)
  stream-presenter.ts StreamPresenter (incremental writer for stdout/stderr surfaces)
```

### B.1 Style backend

```ts
export interface StyleBackend {
  paint(style: EntryStyle, text: string): string; // wraps in colour codes
  escape(text: string): string; // ^ -> ^^ for markup; identity otherwise
}
export type EntryStyle =
  'heading' | 'state' | 'llm' | 'json' | 'reasoning' | 'response' | 'user';
```

`markupStyle` (terminal-kit carets — reuse `escapeMarkup` + `statusColor` from `tui-format.ts`), `ansiStyle` (the `render.ts` ANSI constants), `plainStyle` (identity; used for non-TTY stdout and byte-exact tests). This is the **only** place colour codes live.

### B.2 Renderer interfaces and classes

```ts
export interface AuditEventRenderer {
  canRender(e: AuditWireEvent): boolean;
  /** Converts one audit event to zero or more entries; `state` carries turn-level dedupe flags. */
  toEntries(e: AuditWireEvent, state: TurnState): LogEntry[];
}
export interface LiveStreamRenderer {
  appendDelta(d: StreamDelta): void; // merge-or-create semantics
}
```

`LogEntry` generalises today's `PaneEntry`: `{ style: EntryStyle, time, label?, text, json?: boolean }`.

`renderEntry(entry, width, style)` produces exactly these formats:

- Line-only: `14:03:22 | state_change:agent | running (resumed)` — the trailing segment after the second `|` is the new state / short text.
- Content-bearing:

  ```
  14:03:22 | tool_call:web_search |

    {
      "tool": "web_search",
      "input": { ... }
    }

  ```

  Content always indented 2 spaces and wrapped (`wrapText`); JSON pretty-printed (`JSON.stringify(x, null, 2)`) then indented. Blank line between every entry (and around heading blocks) by construction in the buffer.

`eventLabel()` builds `<AuditEventType>[:kind[:activity[:tool]]]`: `state_change:<entity>`, `compaction:<phase>`, `tool_call:<tool>` / `tool_result:<tool>`, `llm_response:reasoning` / `llm_response:response` (history block rendering), bare `llm_request`, `input`, `decision`, `agent_loop_completion`.

Concrete classes (registry array, first `canRender` wins; fallback = bare `time | eventType` line):

- `StateChangeAuditEventRenderer` — all `state_change`; infers `entity` for legacy rows (payload.taskId → task; payload.assignmentId without agent → assignment; else agent); status coloured via `statusColor`.
- `TextContentAuditEventRenderer` — `input` (payload.text), `agent_loop_completion` (summary; keeps `ASSIGNMENT_COMPLETE_LABEL`), `llm_response` (reasoning entry then response entry from `responseText`/`reasoningText`, falling back to legacy `output.content` / `additional_kwargs.reasoning_content` extractors — moved from `audit-to-agent-events.ts` into `line-format.ts`, the one legacy-compat module).
- `JsonTextContentAuditEventRenderer` — `tool_call`/`tool_result`: pretty-printed `{tool, input|output}`. **Never renders `llm_request` bodies.**
- Line-only handling for `llm_request`, `decision` (payload.summary as trailing text), `compaction` (metrics summary — the single surviving compaction formatter).
- `HeadingBlockRenderer` — the scope heading block, e.g.:

  ```
  Task id:              <id>
  Task shortcode:       <shortcode>
  Assignment id:        <id>
  Assignment role:      <role name> (<role slug>)
  Assignment role id:   <id>
  Assignment mode:      <mode>
  Assignment shortcode: <shortcode>
  Agent id:             <id>
  ```

  Unknown fields render `—`; omit the task lines when there is no task scope (plain chat).

### B.3 Heading trigger

`ScopeTracker` (replaces `LogHeadingTracker`) keys on the `(taskId, assignmentId, agentId)` tuple read **from the wire event's own columns** — no client-side joins to decide _when_. A `HeadingInfoProvider` callback (`(scope) => HeadingInfo`) supplies shortcodes/role/mode; each surface backs it with data it already fetches (eavesdrop's `AgentContext` + role map, TUI pane info, chat session context). Blank lines before and after the block.

### B.4 `EventLogBuffer` — the shared state machine

One class used by every surface:

- `appendAudit(e)`: heading check via ScopeTracker → registry render → push entries.
- `appendDelta(d)`: merge into the trailing entry when same channel (today's `PaneEntryLog.appendDelta` semantics), else open a new `reasoning`/`response` entry; set a per-turn `deltasSeen` flag.
- **Dedupe rule**: when `deltasSeen` is set, `llm_response` and terminal `state_change` render **line-only** (their content already streamed); an `llm_request` resets the flag. History replay (no deltas) therefore renders full text blocks — this replaces both `responseSeen` and `mapAuditHistoryToEvents`.
- `render(width, style): string[]` — full re-render for the TUI (re-wraps on resize).
- `onAppend(listener)` — incremental notifications for streaming surfaces.

`StreamPresenter` subscribes to `onAppend` and writes styled lines immediately, routing `response` → `out` and everything else → `err` (preserves chat's stdout/stderr contract), plus the `(blank)` marker and open-block flushing from `render.ts`.

### B.5 Surface composition

- **TUI pane** (`tui.ts`): pane holds an `EventLogBuffer` (markupStyle); `appendEvent` dispatches to `appendAudit`/`appendDelta`; redraw calls `buffer.render(width, markupStyle)`. History priming: fetch `/api/agent/:id/history` and feed rows straight into `appendAudit` — the pane content becomes line-for-line identical to eavesdrop of the same assignment.
- **Eavesdrop assignment/agent** (`eavesdrop.action.ts`): one buffer + `StreamPresenter(out=stdout, err=stdout; ansiStyle when TTY else plainStyle)`. `--show-history` feeds audit rows and `--tail` feeds SSE `WireEvent`s into the _same_ buffer — history and live are one pipeline.
- **Eavesdrop task**: one shared buffer/presenter across agents (ScopeTracker inserts headings on agent/assignment change); history = `GET /api/task/:id/history` (now includes orchestrator rows, so `state_change:task` / `state_change:assignment` lines interleave with agent output — the "task events + headings" requirement); tail = task SSE (summary lines + follower spawning keyed on `entity:'assignment'` summaries and `consultedAgentId`) plus per-agent follows, all feeding the shared buffer.
- **Chat linear (piped) and one-shot (`--query`)**: `StreamPresenter` with `out=stdout, err=stderr`; `hideReasoning` drops reasoning deltas/entries; the typed message renders when its `input` event arrives over SSE (decision 1). `ChatSession` keeps its `Renderer`-shaped seam, but both implementations become thin adapters over `EventLogBuffer`/`StreamPresenter`.

### B.6 Deletions and reuse

Delete: `PaneEntryLog.append` switch (`tui-format.ts`), `createRenderer.render` switch (`render.ts`), `printAuditRow` (`eavesdrop.action.ts`), `audit-to-agent-events.ts` (+spec), both duplicate `AuditRow` interfaces, `JsonDeltaFormatter`, `SseEvent` (retarget `parseSseBuffer` to `WireEvent`), `formatCompactionEvent`, duplicate `str()` helpers, duplicate compaction formatter, `agentHeading` + `LogHeadingTracker`, server `AgentEventService` (+spec), the three event-union files, and chat's `pushUserPrompt` local echo.

Reuse as-is: `wrapText` (`text-wrap.ts`), `parseClockTime`, `shortId`, `isBlankText`, `statusColor`, `escapeMarkup`, `ASSIGNMENT_COMPLETE_LABEL`, `parseSseBuffer` (retargeted).

### B.7 Legacy-row compatibility

Old audit rows render best-effort via exactly one compat module (`line-format.ts` extractors + entity inference). Known, acceptable degradations: pre-migration `tool_call` rows have no tool name (label renders bare `tool_call`); old chat-input `llm_request {message}` rows render line-only. Both are strictly better than today's JSON dumps.

The wire format is a **hard break** between server and CLI. They ship together from one monorepo, so no dual-format support on the server; Phase 3 includes a small temporary CLI adapter (WireEvent → legacy SseEvent, ~20 lines) so old rendering keeps working until Phase 5 replaces it. Note the break in the changelog in case of any external SSE consumer (none known).

## Risks / likely regressions

1. **Terminal-detection drift** — chat turn end, eavesdrop `--tail` exit, and TUI pane teardown all move from `completed`/`failed` kinds to `state_change` payload inspection; the most likely functional regression (hung tails, never-ending turns). Cover with e2e.
2. **Live ordering wobble** — audit events ride HTTP→DB→Redis while deltas ride Redis directly; a `tool_call` line can appear after later deltas, and DB latency now precedes every discrete live line.
3. **Channel routing mistakes** — agent-level rows leaking to the company channel degrade the roster TUI; too-strict rules starve the task panel of assignment summaries. Publisher-routing spec is the guard.
4. **tui.spec churn** — every line-format change shows in ScreenBuffer dumps; large but mechanical.
5. **DTO whitelist trap** — a missing decorator on `taskId`/`assignmentId` silently strips them.
