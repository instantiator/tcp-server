## LLM configuration

Let's adjust the way `LlmConfig` is used.

On `LcpCompany`, have an (optional) `llmDefault` field of type `LlmConfig`

On `LcpRole` allow `llmConfig` to be optional, too.

If `LcpRole.llmConfig` is not present, then `lcp-agent` should fall back to `LcpCompany.llmDefault` and if that's not present then it should fail.

We should also guard against creating a role on a company if both the role and company do not have an LLM config.

We should update all tests to ensure this works correctly (check through unit tests, integration tests, e2e tests), and add any new tests to ensure we've thoroughly tested this.
