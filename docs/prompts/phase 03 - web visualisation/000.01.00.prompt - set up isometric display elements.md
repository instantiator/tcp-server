## Mapping agents and roles to a map

First, define the data structures that govern the visualisation, and the reducers required.

Apply rules in additional visualisation hooks or helper functions that are able to manipulate the reducers.

Ensure those rules run whenever the company visualisation is active.

Some rules for the data structures:

- Create a collection of rooms
  - Rooms can be added and removed as necessary
  - Rooms can be given purposes (eg. 1:1 room, task room, rec room, corridor, mail room)
- Create a dynamic map as a grid with walls, rooms, other office-style objects
  - The map should be dynamic - as rooms are added and removed, the map is updated
    - Represent it as a collection of objects, and provide a function that renders a rectangular section of the map (x1,y1,x2,y2)
      - Output would be: cells[][] (a rectangular grid of static items), and mobs[] an array of avatars and objects to render at given locations
  - Rooms can have different styles based on their purpose and that will adjust the furnishings
    - eg. rec room might have some sofas
    - eg. task room has a white board
    - eg. mail room has pigeon holes
    - eg. rooms will have different style floor and wall tiles
  - A special office door object is used as a location to show creation/removal of agent avatars
  - Agents and roles are represented as avatar MOBs (mobile objects)
  - When tasks are created, a task room is created
  - When tasks are finished, the task room is removed after all agents have left the room

### Rules for avatars

- Agent avatars can be given location and target location, when their state changes
  - The target is used to move the agent avatar through the map (using routing and object avoidance)
  - If blocked, the avatar should periodically re-route to find a way to its current target

#### When an agent avatar is created

- When first created agent avatars are mapped to just outside the office doors
- When first created, a desk is created for agent avatars in the their task's task room
  - Desk ownership is tracked: each desk may belong to 1 agent avatar
  - When creating an agent avatar, the first available desk is assigned, or a new desk created for them
  - When an agent avatar is removed from play, the desk is unassigned - and can be reassigned
- The new agent avatar is given a target of next to their desk in their task's 'task room'

#### Agent avatar working states

- When an agent is working, its avatar is given a target by the white board in the task room
- When an agent is reviewing another agent's assignment, their avatar stands next to the agent avatar they are reviewing
- When two agents are communicating, a 1:1 room is created, and their avatars are given targets next to each other
- When an agent is communicating a message to a user, their avatar is given a target next to the pigeon holes in the mail room

#### Agent assignment completion

- When an agent avatar finishes its assignment, it returns to its desk in the task room, and it is dissociated from the agent
- If another agent of the same role is created, an unassigned agent avatar of the same type is assigned to them

#### Task completion

- When the task finishes, all remaining avatars are given a target of the office doors (to exit)
  - When an agent avatar passes out of the office doors it is removed
- Roles are given locations in the rec room (they remain static for now)

### Starting condition

- 1 rec room
  - each role in the rec room
- a corridor outside it
- an office entry/exit door

## Rendering the view

- The map should be rendered as an isometric view
- Where the map extends beyond what's visible, it should be scrollable with some additional clickable buttons (but also keypresses)

### Clickable object effects

- Roles, agents, and tasks are clickable
  - The mouse cursor changes when hovered over them to indicate this
  - When hovered over them, a tooltip pops up indicating what they are, eg. "Agent: ${role}", or "Role: ${role}", or "Task: (${step}/${steps})<p>${text}</p>"
- Clicking a role, agent, or task opens a tray on the right hand side of the UI (outside the isometric view)
  - The tray contains some basics (for now): the role / agent's name
  - If an agent: the agent's current state, and its assignment
  - If a task: the task prompt, and the task's assignments listed below it
  - A button to toggle follow/stop following the target (ie. by centring the isometric view on it, and tracking it until the view moves away from it or the following is disabled)
  - The tray has a close button
  - Trays are linked to live data, so update automatically as the state of the object changes

### Full-screen mode

- If a non-clickable area of the visualisation is double clicked, the visualisation should toggle in and out of full-screen mode
