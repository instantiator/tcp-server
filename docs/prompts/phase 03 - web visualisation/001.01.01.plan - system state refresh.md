# 001.01.00 — System state refresh

## Context

Three problems block a clean first run:

- `npm audit` reports 20 advisories (13 high).
- `minio/minio` is gone from Docker Hub, so a machine without the cached image can't start the stack.
- `scripts/setup-wizard.sh` doesn't install packages. It even fails on a fresh clone: the wizard imports `inquirer`, which only arrives with `npm ci`.

Goal: a user can go from a clean clone to a running stack with only `scripts/setup-wizard.sh`, and the docs send them there.

Branch: `03/000-01_isometric-office` (confirmed current, tree clean). One commit per step below.

## Decisions taken before planning (user, 2026-09-26)

1. **Commits per direct root.** There are about 8 dependency commits, plus one for transitive-only lockfile bumps.
2. **Tiered testing.** Each step runs `check.sh` and unit tests. Runtime-facing bumps and the end of step 2 also run the full suite.
3. **The wizard offers to start the stack** once it has written the env file.
4. **Branch:** `03/000-01_isometric-office` (it already carries `start-dev.sh --reset`).

## Findings to raise (from preparing this plan)

1. **No `mc` usage anywhere.** Nothing needs the `mc`→`mcli` rename. The only MinIO-specific paths are the healthcheck (`/minio/health/live`), `health.controller.ts:50` and `minio.integration-spec.ts:10`. Silo keeps the MinIO API, so those should stay as they are. This gets verified in step 1.
2. **The root `overrides` pin vulnerable versions** (`js-yaml` 4.3.0 / 3.15.0, `multer ^2.2.0`, `brace-expansion ^5.0.8`). `npm audit fix` alone won't clear them, so each override moves with its bump.
3. **The setup wizard has no `package.json`.** It uses root and backend deps (`inquirer` is in `apps/backend`), and `tsx` isn't declared anywhere (the wrapper uses `npx --yes tsx`). Auditing it means auditing the root workspace. `apps/tcp-stub-llm` audits clean (0 vulnerabilities).
4. **The wizard's "instance name" is never used.** `start-dev.sh`/`stop-dev.sh` hardcode `-p tcp-dev`, and the Zitadel PAT path (`start-dev.sh:215`) hardcodes it too. The fresh-install test would therefore reuse your existing `tcp-dev_*` volumes and their Zitadel state. The fix is in step 3.
5. **All audit fixes are patch/minor.** There are no majors. The dry-run changes 33 packages.

## Order and why

1. **Silo first.** Every later test run then exercises the new image, and a fresh machine needs it.
2. **Dependency bumps.** Each one gets tested and committed on its own.
3. **Wizard: install and start.** This depends on steps 1 and 2 being in the lockfile and compose file.
4. **Fresh-checkout test.** This proves step 3 against the committed state.
5. **Docs.** They describe what step 4 proved.
