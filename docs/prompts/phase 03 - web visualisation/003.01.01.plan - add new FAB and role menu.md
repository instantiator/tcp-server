## Context

Prompt: `docs/prompts/phase 03 - web visualisation/003.01.00.prompt - add new FAB and role menu.md`.

- The company page has no way to start a task or a chat.
- `startChat` (`useChat.ts:63`) and `CreateTaskDialog` both exist, but nothing in the product calls them.
- The chat and task dialogs are React Aria modals, so while one is open the page behind it is inert.

FE = `apps/frontend/tcp-frontend/src`.

### Decisions (user, 2026-09-28)

| Item              | Choice                                                                                                                                                                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The modal problem | **Keep the dialogs modal**, so ADR-026 is unchanged. The same menu also appears inside the **chat dialog only**. The task dialog gets no menu: it holds nothing the user typed, so they close it to reach the floating button again (user, 2026-09-28). |
| Placement         | **A floating corner button**, fixed at the bottom-right.                                                                                                                                                                                                |

### Decisions I've taken (repeat at the end)

1. **One component, `AddNewMenu`, used in two places:** the page's floating button and the chat dialog's title bar. Each instance owns its own `CreateTaskDialog` mount and its own pending and error state.
2. **Inside the chat dialog:**
   - "New chat" adds a panel beside the open ones, through `startChat` → `openChat`. That's existing behaviour.
   - "Create a new task" opens the form as a nested modal on top of the chat. It's rendered inside the chat dialog's tree, which React Aria stacks correctly.
3. **Company id in the chat dialog:** `useMatch('/company/:companyId')`. The chat dialog lives in `AppShell` and persists across navigation. Away from a company route, its menu is omitted.
4. **Focus return comes from React Aria.** `MenuTrigger` returns focus to its button, and a dialog opened afterwards restores to that button. `Header.tsx:34-39` relies on the same thing.
   - Minimising a chat still moves focus to its dock entry (existing, deliberate).
5. **Floating button position:** it sits in the DOM right after the `h1`, so it comes early in the tab order, and is positioned fixed. It shares the dock's layer (`--tcp-layer-dock`) and is offset above the dock.
   - In the office view's full-screen mode it isn't visible, because full screen shows only the view's own section.
   - The role tray's chat button covers the chat half of it there. This is an unresolved note.
6. **Pending and error states:**
   - A role item uses `shouldCloseOnSelect={false}`, so the menu stays open while the chat starts. The chosen item shows "Starting chat with {role}…", and the other role items are disabled.
   - On success the menu closes. On failure the menu closes and the error shows beside the trigger, linked by `aria-describedby`, and is announced through the existing announcer.
   - Both the menu and the tray button get this from one hook, `useStartChatAction`.
7. **No roles:** the submenu's `Menu` uses `renderEmptyState` and says "This company has no roles yet".
8. **A long role list:** React Aria's `Popover` limits its own height, and a new `overflow: auto` rule on a menu inside a popover lets it scroll. React Aria scrolls the focused item into view. Roles are sorted by name, by a pure function `rolesForMenu`.

- Read ADR-026 and ADR-027 before any UI work.
- Every string goes through `t()`, with counted strings phrased to read at one.
- Use `--tcp-*` tokens only (`base.css:7`).
- Don't pass `className` to React Aria components that are styled by their defaults (memory: React Aria class names).
- Comments are `/** */` and state intent. Never change an assertion to make a test pass.
- Components import data only from `FE/api/hooks.ts`.
- Reuse:
  - `useCompanyRolesList` (`hooks.ts:117`);
  - `useChat().startChat` (`ChatProvider.tsx:105`);
  - `CreateTaskDialog` (`{companyId, onClose}`);
  - the account-menu pattern in `Header.tsx:63-76`;
  - the listen-in button in `AgentDetails.tsx:105-120`, as a model for the tray button;
  - `expectNoA11yViolations(document.body)` (`test-support/axe.ts`);
