## Context

Prompt: `docs/prompts/phase 03 - web visualisation/004.01.00.prompt - config and errors during setup.md`.

Running `scripts/setup-wizard.sh` from scratch worked, with some rough edges:

- The LLM questions don't explain what an application-level provider means. They default to "no" and make the user type a provider, URL and context size by hand.
- There's no way to re-test a configuration.
- A bare `jq` error appeared once and never came back.

### What exploration found

1. **The `jq` error is found.**
   - `start-dev.sh`'s seeding captures `tcp-cli.sh set-company`'s stdout and passes it to `jq` (`scripts/start-dev.sh:306-308`).
   - On a fresh machine `dist/` is missing, so `tcp-cli.sh:72-73` first runs `npm run build:tcp-cli`. npm prints its `> tcp-server@… build:tcp-cli` banner to **stdout**.
   - `jq` then sees `>` at line 2, column 2. The build output was captured along with the JSON.
   - The second run already had a built `dist/`, which is why it didn't recur.
2. **The wizard's probes hit `/v1/v1/…`.** `model-validator.ts:44` and `dimension-prober.ts:21` add `/v1/...` to a base URL whose default already ends in `/v1`. They also have no timeout.
3. **The server only speaks OpenAI-style.**
   - `buildChatModel` (`libs/tcp-shared/src/llm/llm-factory.ts:16-40`) accepts only `lm-studio` and `openai`.
   - `openai` **ignores `baseUrl`**.
   - Embeddings always use `OpenAIEmbeddings` with `baseUrl`, and ignore the provider.
4. **The application level is the env fallback.**
   - Chat is resolved role → company → env (`resolve-llm-config.ts`).
   - Embeddings are resolved company → env (`resolve-embedding-config.ts`). There's no role level for embeddings.
5. **`EMBEDDING_DIMENSION` never reaches the containers.** `docker-compose.yml` doesn't pass it through, so a dimension the wizard writes has no effect.
6. **`host.docker.internal` doesn't resolve on Linux** for tcp-server, tcp-agent or tcp-mcp-memory. Only `docker-compose.dev-web.yml` adds `extra_hosts: host-gateway`.
7. **Vector indexes are `ivfflat`**, which has a hard limit of 2000 dimensions. An embedding model wider than that (for example `text-embedding-3-large`, or Gemini's default 3072) breaks the migration.
8. **There's no shared provider data anywhere.**
   - models.dev (MIT, `https://models.dev/api.json`) has models and `limit.context` for every remote provider named in the prompt.
   - It has no base URLs for most providers, no embedding dimensions, and no local Ollama.
9. **The health checks already exist.**
   - tcp-server `/health` covers Postgres, Redis, MinIO and OIDC (`health.controller.ts:34-67`).
   - tcp-agent's covers Postgres and Redis. The MCP servers report static liveness.
   - Nothing checks the LLM or the embedding endpoint.
10. **Answers to the prompt's questions:**
    - **Is context size discoverable?** Partly.
      - Yes: Google (`inputTokenLimit`), OpenRouter, LM Studio (`/api/v0/models`) and Ollama (`/api/show`).
      - No: OpenAI's `/models`.
      - models.dev fills the gap for remote providers.
    - **Azure's service** is Azure OpenAI, part of Azure AI Foundry.
    - **Is nomic-embed-text-v2-moe a good choice?** It's good and multilingual, but its context is 512 tokens. Our chunks are 2000 characters, about 500 tokens (`rag-index.service.ts:10`), so dense text can be cut off.

### Decisions (user, 2026-09-30)

| Item                    | Choice                                                                                                                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Non-OpenAI providers    | **OpenAI-compatible endpoints.** Each template points at the provider's own compatible URL. The factory honours `baseUrl` for every known provider. No new dependencies.                     |
| Provider/model data     | **A hand-kept catalogue in `libs/tcp-shared`, plus live lookups.** Context size comes from models.dev, or from the local server's own API. The user is asked only when neither lookup works. |
| Starter embedding model | **nomic-embed-text v1.5**: 768 dimensions (the current default, so the DB doesn't change) and an 8192-token context.                                                                         |

### Decisions I've taken (repeat at the end)

1. **`provider` holds the catalogue id** (`openai`, `anthropic`, `google`, `azure`, `amazon-bedrock`, `mistral`, `openrouter`, `lm-studio`, `ollama`, `openai-compatible`).
   - Each id's `modelsDevId` points at the matching models.dev entry. The two differ only for LM Studio, whose models.dev id is `lmstudio`.
   - `buildChatModel` accepts every catalogue id and builds `ChatOpenAI` with `baseURL` whenever one is set.
   - `lm-studio` keeps its placeholder key, and `openai` with no `baseUrl` still goes to OpenAI, so existing configs behave the same.
   - Unknown ids still throw.
2. **The data and the code that fetches live data are kept apart.**
   - `libs/tcp-shared/src/llm/provider-catalogue.ts` is plain data with no imports, so the web client and TUI can use it later without a runtime import graph (memory: transcript-logic-shared).
   - The code that fetches from the network stays in the wizard (`scripts/setup-wizard/utils/`). Only the wizard needs it today.
3. **The catalogue includes these providers.**
   - Remote: OpenAI, Anthropic (no embeddings), Google Gemini, Azure OpenAI (needs a resource name, and the model is the deployment name), Amazon Bedrock (needs a region and a Bedrock API key; no embeddings), Mistral, OpenRouter (no embeddings).
   - Local: LM Studio, Ollama.
   - Custom: any other OpenAI-compatible server, such as llama.cpp, vLLM or Jan.
   - Every embedding model listed is ≤2000 dimensions. The wizard also rejects a probed dimension over 2000, and says why.
   - Before writing each compatible URL and starter model, the implementer checks it against the provider's docs and models.dev, and cites the source in a comment.
4. **Starter models.**
   - Local chat: a small Gemma instruct model with tool calling (check the LM Studio and Ollama catalogues at implementation for the current id).
   - Local embeddings: nomic-embed-text v1.5.
   - Remote: a cheap, current model from each provider, taken from models.dev.
5. **Localhost handling.**
   - Probes from the host use the URL as the user typed it.
   - If it points at `localhost` or `127.0.0.1`, the wizard explains why and offers to write the `host.docker.internal` form. The default is yes.
   - `extra_hosts: host.docker.internal:host-gateway` is added to tcp-server, tcp-agent and tcp-mcp-memory, so this also works on Linux.
6. **`--test-config` checks from where it matters.**
   - The LLM and embedding probes run **inside the tcp-agent container**, through `docker compose exec`, using the container's own env. That tests the address the agents actually use.
   - If the stack isn't running, those checks are skipped with a "start it with …" line, and the host-side checks still run.
   - The command exits non-zero if any check fails.
7. **One error pattern for the shell scripts** (`scripts/lib/errors.sh`):
   - `step "<what we're doing>" ["<what to try>"]` names the current step.
   - An `ERR` trap (with `set -E`) prints `✗ Failed while <step> (<file>:<line>)`, then the hint.
   - `json_field <what> <jq filter>` replaces bare `jq`. When its input isn't JSON, it prints what it was reading, the first 20 lines it got, and a hint.
   - `zit()` prints the method, path, HTTP status and the first 500 characters of the body to stderr when a call fails. Its exit status doesn't change, so the existing `|| true` and retry callers keep working.

### Stage 4: Wizard LLM flow (Sonnet → Opus review)

Files:

- `scripts/setup-wizard/prompts/llm.ts` (rewrite)

The flow, run once for chat and once for embeddings:

1. **Intro and confirm, defaulting to yes.**
   - Chat: "This will be the default model for every company you set up. A company, or a role within it, can override it later."
   - Embeddings: "…every company. A company can override it."
2. **Choose a provider** with `select`, in groups separated by `Separator`: Remote, Local, "Other OpenAI-compatible server".
   - For embeddings, providers without `embeddings` are hidden, with a one-line note that Anthropic, Bedrock and OpenRouter don't offer embedding models.
   - If the chat provider supports embeddings, it's the default choice.
3. **Remote:** ask only for the template's `fields`.
   - The API key uses `password` input, with a mask. When the embedding provider matches the chat one, ask "Use the same API key?".
   - `baseUrl` = `fillBaseUrl(...)`.
   - The model defaults to `starterModel` and stays editable.
4. **Local:** ask "Is <name> installed, running, and serving a model?" (default yes).
   - If not, print `localSetup` and the starter model, then "Press Enter when it's running (or type 'skip' to finish setup without testing it)".
   - Base URL: the template default, editable.
5. **Localhost check** (`docker-host.ts`):
   - `isHostLocal(url)` and `toDockerHost(url)` rewrite only the host part. The spec covers `localhost`, `127.0.0.1`, a port, a path, and a non-local URL.
   - If the URL is local, explain: "TCP's agents run inside Docker, where `localhost` means the container itself. `host.docker.internal` reaches your machine instead." Then "Use `http://host.docker.internal:1234/v1`?" (default yes).
   - Probe with the original URL; write the converted one.
6. **Test the connection:**
   - Both probes: base URL + `/chat/completions` or `/embeddings`. Never add `/v1`; the base URL includes it, the same as the backend.
   - `AbortSignal.timeout(15000)`.
   - `describeProbeError`: connection refused → "Nothing is answering at <url>. Is <provider> running?"; 401/403 → "The API key was rejected"; 404 → "Model '<m>' wasn't found. Check the name, or that it's loaded"; timeout → "No reply within 15s". Anything else shows the status and the first 300 characters of the body.
   - On failure: "Try again / Change settings / Keep these settings anyway".
7. **Context window (chat) and dimension (embeddings):**
   - `lookupContextWindow(template, model, probeUrl)`:
     - LM Studio: `GET <origin>/api/v0/models/<model>`, reading `loaded_context_length`, else `max_context_length`.
     - Ollama: `POST <origin>/api/show`, reading `model_info['*.context_length']`.
     - Otherwise: `models.dev/api.json` → `[modelsDevId].models[model].limit.context`.
     - A 5-second timeout; returns `undefined` on any failure.
   - Show "Context window: N tokens (from <source>). Use this?". The number prompt is the fallback.
   - The dimension comes from the probe. If it's over 2000, reject it with the ivfflat explanation.
   - The spec uses recorded JSON fixtures, with `fetch` passed in.
8. **Skipping embeddings** prints: "Without an embedding model, you won't be able to upload knowledge documents for roles. You can set one later in `<env file>` or per company."

`types.ts` stays as it is, apart from anything this needs.

## As built

- **Stages 0–7 are done.** Where this differs from the plan:
  - **Probe timeout is 60s, not 15s.** Against LM Studio, a cold `gemma-4-e4b` took 27.6s to answer its first request while the model loaded, and 0.4s after that. The timeout message now says a local server may still be loading.
  - **The `jq` bug's gate was checked directly.** Starting `.env.testing` beside the running `tcp-dev` stack isn't possible (see below). Instead, `apps/backend/dist/apps/tcp-cli` was deleted and `./tcp-cli.sh --version` run: stdout held only `0.0.1`, and npm's banner went to stderr.
  - **`--test-config`'s "dead port" gate doesn't work as written.** The model probe uses tcp-agent's own environment, so editing a copy of the env file changes nothing it sees. `describeProbeError`'s specs cover the failure messages instead.
  - **The shell error trap reports only from the top-level shell.** `set -E` also fires it inside `$(...)` guarded by `|| true`, and an unguarded failure would otherwise be reported twice. `errors.test.sh` pins down both cases.
  - **`check-ports.sh` names the likely cause** (another TCP stack) and how to stop it.
- **Found and left** (in `docs/outstanding-issues.md`):
