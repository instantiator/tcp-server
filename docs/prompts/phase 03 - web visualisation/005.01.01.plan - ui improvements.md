## Context

Prompt: `docs/prompts/phase 03 - web visualisation/005.01.00.prompt - ui improvements.md`.

This is a visual pass over the web client:

- thought bubbles on working agents;
- card-style companies list;
- a sticky top bar and horizontal breadcrumbs;
- floating office-view controls over a full-height canvas;
- an animated overlay tray and a round FAB;
- one tab per activity section, with count badges;
- drag-to-pan.

We want shared CSS classes so this can move into a design system later, with no loss of accessibility.

FE = `apps/frontend/tcp-frontend/src`, VC = `FE/visualisation/isometric/company`.

### Decisions (user, 2026-10-02)

| Item         | Choice                                                                                                                                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tabs         | **Top level.** The tabs are Company view, Active agents, Tasks, Consultations, Enquiries and Chats. The Activity tab goes away.                                                                          |
| Plurals      | **`Intl.PluralRules`** through a new `tCount(key, count)` that picks `key.one` or `key.other`. No library is added. The "read at one" rule still applies to every other string, including announcements. |
| Enquiry link | **Tabs follow the URL hash** (`#enquiries`, `#tasks`, …), so `NewEnquiryNotifications`' link opens the right tab. It also gives each tab a deep link.                                                    |
| Page `h1`    | **Visually hidden** (`.visually-hidden`). It stays as the focus target on route change (`useRouteChange.ts:45`) and keeps its heading role.                                                              |

### Decisions I've taken (repeat at the end)

1. **Icons:** use `lucide-react`, which is already a dependency (only `VisualisationToolbar.tsx` uses it today).
   - Move its `Icon` and `WithTooltip` helpers (`VisualisationToolbar.tsx:49-85`) to `FE/components/Icon/`. Every new icon-only control then has a visible tooltip, and an accessible name equal to that tooltip (WCAG 2.5.3).
2. **Shared classes and tokens for the future design system**, all in `base.css` and the theme files:
   - `.tcp-icon-button`: a circular icon button, applied alongside `react-aria-Button`, since `className` replaces the defaults.
   - `.tcp-icon-button--small` and `.tcp-icon-button--fab`.
   - `.tcp-badge`.
   - `.tcp-card`, plus `.tcp-card__link`, a stretched-link `::after` that makes the whole card clickable.
   - `.tcp-floating`, an absolute overlay surface with a background, border and padding.
   - New tokens:
     - `--tcp-color-highlight` and `--tcp-color-highlight-text`, in **both** theme files and all four light/dark blocks, checked to 4.5:1 (7:1 in high contrast);
     - `--tcp-layer-header`;
     - `--tcp-motion-duration`.
3. **Animation is CSS only.**
   - The tray slides in with `@starting-style` (a transform from 100%).
   - The FAB moves by transitioning `inset-inline-end`.
   - The existing global reduced-motion rule (`base.css:480`) already cancels transitions.
   - Exit animation is skipped, because the tray unmounts on close. That gets a `ponytail:` note.
4. **The tray becomes an overlay** on the canvas's right edge, not a flex sibling.
   - The canvas no longer resizes when the tray opens.
   - The FAB moves left via `body:has(.company-visualisation__tray) .company-page__add-new { inset-inline-end: calc(var(--tcp-visualisation-tray-width) + var(--tcp-space-lg)) }`.
   - The tray keeps `overflow: auto`, with its block size set to the stage's.
5. **DOM order doesn't change; only CSS moves the controls.** The toolbar and label toggles stay before the stage in the DOM, so tab order and landmarks are as now.
   - The stage fills from the tabs to the viewport bottom.
   - A `body:has(.dialog-dock)` rule subtracts `--tcp-dock-block-size`, so the bottom-left controls ride above the dock.
6. **Activity tabs:**
   - Each list moves into its own `TabPanel` with `shouldForceMount`. Hidden panels stay mounted (React Aria makes them `inert`), so filters survive a tab switch with no extra state.
   - Each list reports its filtered count through a new `onCount` prop. `CompanyPage` holds the counts for the badges.
   - The `ActivityList` `h2` becomes visually hidden. The tab is its visible title, and heading navigation and the `region` name still work.
   - `NewEnquiryNotifications` moves above the tab list.
   - Tab selection is controlled from `location.hash`, with `navigate({hash}, {replace: true})` on change.
7. **Thought bubble:**
   - It shows for agents whose activity is `working` or `reviewing` (`rules/companySnapshot.ts:46`).
   - React sends the thinking agent ids to the scene on a new bus event, `thinking-changed`. Today the scene doesn't know activities.
   - A new `scene/ThoughtBubbleLayer.ts` draws two small circles and a cloud, up and to the right of the head, so it doesn't cover the hat (`CARRIED_BOOK_Y = -44`). It follows the avatar the way `LabelLayer` does.
   - The animation is a phase index, `floor(time / 400) % 5`, set in `update()`; no tweens. Under `reducedMotion` the bubble is static and fully drawn.
   - Clicking it emits `listen-in {agentId}`. `CompanyVisualisation` then calls `openChat({…, readOnly: true})` through a hook extracted from `AgentDetails.tsx:105-119`, which both places share.
   - It's pointer-only by design. The keyboard path is the picker, then the tray, then "Listen in".
8. **Drag to pan:**
   - The scene pans the camera on pointer move while the button is down.
   - Hit zones select on `pointerup`, not `pointerdown` (`hitZone.ts:41-47`), and only when the pointer moved under 6px (`pointer.getDistance()`). That way a drag that starts on an avatar doesn't select it.
   - A drag stops a follow, the same as a manual pan.

### Constraints and reuse

- Read ADR-026 and ADR-027 before any UI work.
- Every string goes through `t()` (or `tCount()`).
- CSS uses `--tcp-*` tokens only. Component CSS files keep empty rule bodies (ADR-026); shared rules go in `base.css`.
- Don't pass `className` to a React Aria component without also repeating its default class (memory: React Aria class names).
- Comments are `/** */` and state intent. Never change an assertion to make a test pass, unless the plan says so.
- Reuse:
  - `Breadcrumbs.tsx`;
  - `useMatch('/company/:companyId/*')` (`ChatDialog.tsx:64`) and the company query hook for the header name;
  - `useCompanies()` stats (`CompaniesPage.tsx:73-98`);
  - `ACTIVE_TASK_STATUSES` (`api/statuses.ts:21`);
  - `ActivityList.tsx`'s `count`;
  - `useReducedMotion`;
  - `LabelLayer.follow`;
  - `createHitZone`;
  - `CameraController.pan` and the `follow-stopped` path;
  - `expectNoA11yViolations`.
- Sub-agent briefs carry the long-run rule: run tests in the foreground with a 600000 ms timeout, or in the background and end the turn. No poll loops.

The `CompanyPage` keyboard test was reworked on purpose for six tabs. The notification link is covered by the deep-link test (`#enquiries`), not by simulating an arriving enquiry.
- **Stages 5–8 share one commit**, for the same reason.
- **Stage 5.** `useStageTop` needed no change: it measures the stage itself, which now starts higher. The office view's section has `isolation: isolate`, so the floating controls and the tray (both on the dock's layer) can't paint over the sticky header. The picker keeps its `Label`, visually hidden: React Aria names the trigger from the label plus the selected value, and with no `SelectValue` only the label is left.
- **Stage 6.** Close stays last in the tray's markup and is moved to the top-right with CSS only, so the tray's tab order is unchanged except for Follow. One test was changed on purpose: the archive tray's tab order is now Follow, then the links, then Close, because Follow sits beside the heading.
- **Stage 7.** The drag rules are pure (`scene/dragPan.ts`). The scene adds its pointer listeners to its own input plugin, which drops them on shutdown. The cursor is `grab`, and `grabbing` while dragging. One hit-zone test was changed on purpose, from `pointerdown` to a click on `pointerup`.
- **Stage 8.** `ThoughtBubbleLayer` sits just under the labels. A bubble's hit area covers the whole bubble, so it can be clicked at any step, including the blank one. `useListenIn` is shared by the tray's button and the bubble. An agent label can overlap the cloud: this is the same as the existing label-overlap note.
- **For stage 10:** two assertions in `company-visualisation.spec.ts` expect the canvas to widen when the tray closes. The tray is an overlay now, so the canvas width no longer changes.
- **Stage 9.** The review found nothing to fix. One judgement was carried to phase 06's `001.02`: the floating controls keep their DOM order, so focus moves from the bottom-left controls to the top-left label checkboxes.
- **Stage 10.** The browser run found a real bug the component tier couldn't. The sign-in redirect saved and restored only `pathname + search`, so a fresh load of `/company/<id>#enquiries` lost the hash and opened the office view. Tokens are memory-only, so that affects every page load. Now `handleUnauthorized` saves the hash too, and `safeRedirectTarget` returns it once the origin and route checks have passed. The hash never reaches a server, so the open-redirect gate is unchanged. Unit tests cover both. The card-navigation spec makes the signed-in user a member of its company, because a company made with the machine token belongs only to the machine. Its click uses `force`, because the stretched link's `::after` is exactly what it's testing. Result: 54 passed.
- **Stage 11.** `check.sh --comprehensive`: every check passes except `audit:node`. It reports 4 advisories in existing dependencies (`@grpc/grpc-js`, `axios`, `undici`, `js-yaml`); this branch adds none, so they were reported to the user rather than fixed.
