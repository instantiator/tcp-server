## Context

The office view from 000.01 works. The user's feedback
(`002.01.00.feedback - isometric display elements.md`) asks for nine
improvements: fill the viewport, toggleable labels, shortened prompts, roles
drawn as books that agents pick up, fixed ring layering, tooltips on
furniture and doors, arrow-key-shaped icon pan buttons, and a read-only
"listen in" view of an agent's live thinking.

FE = `apps/frontend/tcp-frontend/src`. VIS = `FE/visualisation/isometric/company`.

### Decisions taken (user, 2026-09-27)

| Decision                                 | Choice                                                                                                                               |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Avatar pool scope (item 3)               | Per task room, as today. When a task closes, its avatars leave. New: a fresh avatar walks to its role's book before its real target. |
| Icon library (item 7)                    | `lucide-react` (ISC).                                                                                                                |
| Icon buttons and screen readers (item 7) | Keep them in the accessibility tree with their current names. Icons are `aria-hidden`. Each button gets a React Aria `Tooltip`.      |
| Commits                                  | One per stage.                                                                                                                       |

### Decisions I've taken (say so again at the end)

1. **Item 4 is fixed by item 3.** The only floor circle is the role avatar's ring (`scene/AvatarSprite.ts:66`), drawn after the body. Role avatars become books, so the ring goes. If any floor marker stays, it goes first in the container's `parts`.
2. **Labels are worked out in React, drawn by the scene.** A pure `ui/officeLabels.ts` builds `OfficeLabel[]` from world, snapshot and toggles. It sends them on a new `labels-changed` bus event, and the scene draws Phaser `Text`. That keeps the scene free of names and strings.
3. **Agent label status** is the agent's activity in words (for example "working" or "at desk"), not the raw DB status.
4. **Furniture and door tooltips are hover-only.** Their hit zones emit `hover` but not `select`. Whiteboards keep their task hover and select.
5. **The tooltip shows a shortened prompt with no "…" button**, because it has `pointer-events: none`. Clicking opens the tray, where the full text is one "…" away.
6. **Listening in reuses the chat dialog.** `Conversation` gains `readOnly`. A read-only panel has no Complete button and no message input. Opening read-only on a conversation that is already open and writable keeps it writable.
7. **Viewport fill uses a small hook plus CSS `max()`.** No page layout fills the viewport, so the hook measures the stage's page offset. CSS then takes `max(fixed height, space left)`, which covers both "content above is too tall" and "space left is too small".
8. **Pointer-only tooltip text isn't mirrored for screen readers.** The furniture descriptions explain the drawing, and the stage summary plus the picker already give the facts. Recorded in unresolved notes.
