I'm using the term 'run' to mean everything the agent does from an initial prompt until it finishes. Do we have terminology for that? When responding to a user request, the run would be everything the agent does to answer the user's request and complete any tasks given to it. When given a task by the orchestrator (this will be implemented in future), it means everything the agent does to complete the task given to it in the initial prompt.

## Completion conditions

We discussed how the agent loop requires that the agent provides an output and checks for it when the LLM stops. When the agent uses MCP to provide an output, let's put a check in place to confirm that any files referenced in the output exist in shared storage: these files don't _need_ to have been created or modified by the agent in this run, because its task might have been (eg.) to locate a particular file and comment on it.

If the named files don't exist, it should return a short templated prompt indicating:

- which files are listed but missing
- files the agent has created or modified during the run

If the agent has modified files during the run, the prompt should ask if the agent meant to name one or more of those, or has made a typo in its submission. If it wants to make a correction it should submit an additional output.

If a subset of those files (and any other files it's aware of) wouldn't complete the output, it should continue working, and submit a new output when ready.

## Completion summaries

After completing a task successfully, the agent should be prompted once more to provide a short summary of everything it has done. This should be audit logged as a new kind of task completion summary audit event. This should be a structured event that represents a series of bullet points, with a bullet point of a few sentences max, for each distinguishable action that agent has taken, and each decision taken (and the role or user that took the decision). It should also have a short paragraph summarising what it has done.
