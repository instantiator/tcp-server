> ## Company state reports
>
> **Today:** `CompanyStats` has `activeAgents`, `tasksByStatus` and
> `openEnquiries`. Nothing describes the business.
>
> **Recommend:**
>
> - Report definitions: a named set of [records](usage.gaps.md#structured-records) queries
>   and aggregates, plus an optional short LLM summary ("3 orders to post today,
>   1 enquiry waiting on you, income this month £212").
> - A company dashboard in the web UI: things needing the user first (approvals,
>   questions), then today's work, then trends.
> - Templates for a cottage business: orders to fulfil, enquiries awaiting a
>   reply, low stock, month and tax-year income and expenses.
> - A report can also run as a [recurring task](usage.gaps.md#recurring-tasks) that writes a
>   weekly summary into `resources/reports/`.

**Carried from 000.02 (spend tracking):** per-task token usage is already
available from `GET /api/company/:id/spend` (`tasks`, `series`) — show it on
the dashboard rather than adding a new query for it.

## Templates (from 002.03)

- Add report definitions to the template format (v2, planned in 005.04). A format change means bumping `formatVersion` (to 2 or higher). v1 refuses unknown keys, so an older server will refuse the new template with its "made by a newer version of TCP" message, which is the right result. The new code must still read version 1.
- Ship the cottage reports in `templates/cottage-industry`: orders to fulfil, enquiries awaiting a reply, low stock, and income (month and tax year).
- Reports depend on the template's record tables, so they must travel together (format v2).
- Export writes report definitions back. The format is documented in `templates/blank/README.md`, which travels inside every blank download. Update it in the same change, so it never lags behind the code.
