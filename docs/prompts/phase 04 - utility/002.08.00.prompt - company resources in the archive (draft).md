**Build this after 002.05.** 002.05 built the in-app storage browser. This prompt adds an entry point to it from the office, and should reuse what 002.05 made rather than build its own:

- `StorageBrowser` and `StorageBrowserDialog`, in `src/components/StorageBrowser/`. The dialog already opens from the task and archive trays, and portals into the office view.
- `GET /api/company/:companyId/storage/folder?path=`, which lists one level. Under `resources/` each folder comes back with its `purpose`; the browser also does history and restore for resources.

Company resources (001.02) are long-lived company documents — invoices, price lists, policies — kept in shared storage under `{slug}/resources/`.

Please create a plan to add a third piece of furniture to the office's archive, beside the bookshelf (task outputs) and the filing cabinet (record tables), for the company's resources.

- Clicking it, or choosing it in the details picker, opens a tray.
- The tray shows a navigable tree of directories, rooted at the company's resources directory, with each folder's purpose. Reuse 002.05's tree and listing route.
- Each directory opens that directory in 002.05's in-app storage browser. Where the storage console is configured, a link to it may be offered too, as the archive tray's task outputs are today (`taskOutputsUrl` in `src/api/storageLink.ts`, whose confirmed percent-encoded format works for any folder).

Notes for the plan:

- **The furniture is the easy part.** Since 001.03, the archive's selectable furniture comes from one map (`SELECTABLE_FURNITURE` in `scene/TcpCompanyScene.ts`). Follow how the filing cabinet was added: kind, tile (for example `(3, 1)`, the other side of the bookshelf), size, colour, description, `SelectionTarget` kind, picker entry, tray case.
- **Live resources only.** 002.05 works this way: a browser rooted at `resources/` shows live resources. Task drafts (`tasks/{id}/working/resources/…`) live under the task folders and aren't company resources until their task succeeds.
- **Files or folders?** Settled by 002.05: the browser lists both, folders first, then files.
- **If 002.05 changes shape,** revisit this prompt before planning it: the point is one way of browsing resources, reached from more than one place.

Accessibility is very important: the tree must work fully from the keyboard and with a screen reader, inside the office view's full screen too (portal into the view, as other trays do).
