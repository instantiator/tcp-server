## Context

Nothing backs up Postgres or MinIO today. Business records would be lost with the disk. The work must land before real records exist (usage.gaps.md#backup-and-restore).

Facts that shape the design:

- One Postgres server holds two databases: `tcp`, and `zitadel` (created by `docker/postgres-init/create-databases.sh`, used only under the `auth` profile). Company memberships are keyed by Zitadel user ids, so the two must be restored together.
- MinIO (`pgsty/silo` image) ships `mc` inside the container, so there is no new image or dependency. tcp-server uses one bucket (`tcp` by default, `MINIO_BUCKET_PREFIX`).
- tcp-server applies pending migrations at boot. So an older backup migrates forward, but a backup newer than the code must be refused.
- `start-deployment.sh` trusts the PAT already in `docker/zitadel-machinekey/<project>/pat.txt` when the Postgres volume already exists. A re-run regenerates every OIDC client secret into `<env-file>.local`. After restoring the `zitadel` DB, re-running it re-syncs the secrets, but only if `pat.txt` matches the restored instance.

Decisions agreed:

- **Secrets stay out of the archive by default.** `--include-pat` adds `pat.txt`. Env files are never included. The archive is created mode 600 with no encryption, and the guide tells operators to keep the env files (`ZITADEL_MASTERKEY`, the `.local` file) safe separately.
- **Redis is not backed up.** On restore it is flushed, so stale BullMQ jobs can't run against the restored DB.
- **CI restores onto a fresh stack** (`down -v`, then a fresh start) in its own job, in parallel with `api-test` and `e2e-test`.
- **Recurring backup is deferred** until 004.01 (recurring tasks) lands. It is recorded in `outstanding-issues.md`.

## Design

### Archive

`backups/<project>-<UTC yyyymmddTHHMMSSZ>.tar.gz` (add `backups/` to `.gitignore`); `--output <dir>` overrides the directory. Created under `umask 077`. Contents:

```text
manifest.env      FORMAT=1, CREATED, PROJECT, GIT_COMMIT, LATEST_MIGRATION, PG_VERSION
tcp.dump          pg_dump -Fc of the tcp DB
zitadel.dump      only if the zitadel DB exists
objects/<bucket>/ mc mirror of every bucket
pat.txt           only with --include-pat
```

`LATEST_MIGRATION` is `SELECT name FROM migrations ORDER BY timestamp DESC LIMIT 1`. That is TypeORM's class name, e.g. `ConversationRepliesDelivered1784820000000`.

### `scripts/backup.sh --project <name> (--env-file <f> | --env-files <a,b>) [--output <dir>] [--include-pat]`

Hot backup with the stack running: `pg_dump` per DB through `docker compose -p <project> exec -T postgres`. Objects come from `mc mirror` inside the `minio` container to a temp dir, then `docker compose cp` out, then the temp dir is removed. The DB is dumped before the objects, so every object a row refers to exists; an extra orphan object is harmless. Prints the archive path and size.

### `scripts/restore.sh --project <name> (--env-file … | --env-files …) --archive <path> [--yes] [-- <extra start-deployment args>]`

1. Unpack and validate first (steps 2–3), then stop the writers and bring up `postgres`, `redis` and `minio` itself (`up -d --wait`). So it works on a never-started project on a new machine without a wasted Zitadel bootstrap. _(Changed during implementation: the plan first required a running stack.)_ The manifest is parsed with `grep`, never sourced, because the archive is input. Refuse early if a zitadel dump has no matching PAT (none in the archive, none on disk).
2. Read `manifest.env`. Refuse if `FORMAT` isn't 1. Refuse if `LATEST_MIGRATION` matches no `class <name>` in `apps/backend/apps/tcp-server/src/migrations/`, because the backup is newer than this code.
3. Confirm by having the user type the project name, unless `--yes` is given. With no TTY and no `--yes`, refuse.
4. Stop `zitadel tcp-server tcp-agent tcp-web tcp-mcp-*`.
5. For each dump: `DROP DATABASE … WITH (FORCE)`, `CREATE DATABASE … OWNER $DB_USER`, then `pg_restore --no-owner -d`.
6. Run `redis-cli FLUSHALL`.
7. For each bucket: copy into the minio container, then `mc mirror --overwrite --remove`.
8. If the archive has `pat.txt`, write it to `docker/zitadel-machinekey/<project>/pat.txt`. If it doesn't and a zitadel dump was restored, warn that the original PAT must be in place.
9. Re-run `start-deployment.sh` with the same project, env files and any extra args. This regenerates the OIDC secrets and starts the services.

Both scripts reuse `scripts/lib/load-env.sh` and `scripts/lib/errors.sh` (`step` / `enable_error_report`), and copy the arg parsing and `$DC` setup from `scripts/start-deployment.sh`. They target bash 3.2 and must pass shellcheck.

### - [x] 2. `restore.sh` — Opus (destructive and lifecycle-sensitive: drops databases)

- **Brief:** as in Design → `restore.sh`.
- **Tests:** stage 3. Manual check: back up `tcp-dev`, create a company, restore, and confirm the company is gone and sign-in works.
- **Gate:** `check.sh --fast` plus the manual round trip.
- **As built:** before handing off to `start-deployment.sh`, restore stops `postgres`, `redis` and `minio` again, because that script's port check counts the project's own containers. Verified on 2026-10-04: seed, backup, `down -v`, restore, then company 200, object content intact, and sign-in working with re-synced secrets. A tampered manifest and a run with no TTY and no `--yes` are both refused.

### - [x] 3. Round-trip test tier — Sonnet

- **Brief:** create `scripts/run-backup-tests.sh --project <name> --env-file <f>`, modelled on `scripts/run-smoke-tests.sh` for its structure. Move `get_machine_token`, `resolve_issuer` and `read_env_var` from `scripts/start-dev.sh` into `scripts/lib/machine-token.sh`, and source it from both scripts. Steps:
  1. Run `start-deployment.sh` for the project.
  2. Seed: `POST /api/company` (slug `backup-roundtrip`) and `POST /api/storage` with one small text object. The body shape is in `storage-proxy.controller.ts:101` and its DTO.
  3. Take a snapshot: the row count of every table in `tcp`, plus `mc ls -r --json` for the object keys and sizes.
  4. Run `backup.sh --include-pat`.
  5. Run `docker compose -p <project> --profile auth down -v`.
  6. Run `restore.sh --yes` (it starts the data services itself).
  7. Take a second snapshot and `diff` it against the first.
  8. Using a new token: `GET /api/company/backup-roundtrip` returns 200, and `GET /api/storage` returns the seeded content.
  9. Negative case: copy the archive, set `LATEST_MIGRATION=NoSuchMigration9999999999999` in its manifest, and expect `restore.sh` to exit non-zero.
  10. On exit, take the stack down (the same trap as `run-all-tests.sh:55`).

  Add the tier as the last step of `scripts/run-all-tests.sh`, after browser tests, using its own project name `tcp-backup`.

- **Tests:** this stage _is_ the test.
- **Gate:** `./scripts/run-backup-tests.sh --project tcp-backup --env-file .env.testing` passes. `check.sh --fast` passes. `start-dev.sh --seed` still works.
