## Context

A company today is one JSON row (`scripts/test-data/companies/*.json`). Roles and knowledge are added one CLI call at a time. There is no way to share a working company, or to start from one. This plan adds a versioned zip format (company, roles, knowledge), import and export through the API, CLI and web UI, a gallery fed by several sources, and three templates: **Blank**, **Basic** and **Cottage industry**.

### Decisions agreed with you (2026-10-17)

- **Licence field here, LLM extras later.** Knowledge carries `license`, `source` and `attribution`; the API, CLI and web list show them. The LLM-written OKF summary and LLM licence detection move to 005.02, with the detail copied there.
- **The gallery and "New company starts from the gallery" land here.** 005.04 keeps v2, secrets and the first task.
- **One commit per stage.**

### Choices made in the design (say if you disagree)

1. **Import and export run on the server.** One implementation serves the API, CLI and web. The web client needs no zip library.
2. **Two stateless calls: preview, then import.** Each sends the zip (or a gallery template id) again. No server-side upload session to expire or clean up.
3. **Everything is validated before anything is written.** The template is parsed, every knowledge file converted and checked with `validateOkf`, and every LLM config checked against the URL policy first. Only then is the company created. If a later write fails, the new company is deleted. This matters for `replace`, which deletes the old company first.
4. **Knowledge licence lives in the OKF front matter, not a new table.** The document stays the one record, so edits in the MinIO console can't drift from a DB row. Listing reads each file's front matter. `// ponytail:` ceiling: one read per document per listing; move to a column if a scope's listing gets slow.
5. **Built-in templates are directories in the repo** (`templates/<name>/`), reviewable in git, copied into the tcp-server image and zipped on request.
6. **Directory sources come from config only.** A path only means something if it is mounted into the container, so the UI adds and removes GitHub sources. Config sources are listed in the UI as "set in server config" and can't be removed there.
7. **The import form is `CreateCompanyDialog` with a template.** It already has every company field and both pickers. A template adds a roles section and switches the submit to import.
8. **Template sources are managed from the admin system menu**, not from inside the gallery dialog, so no dialog opens over another.
9. **Cottage industry is UK-based**, matching 005.02's first pack. Its knowledge is gov.uk guidance under the Open Government Licence v3.0, converted to OKF with licence and attribution in the front matter. The template says plainly that it is not legal or tax advice.
10. **This plan builds the cottage roles; 005.03 refines them.** The roles here have prompts and knowledge but no email, approval or promises hook yet. 005.03's prompt is rewritten to extend these roles, not create them.
11. **The blank template's `README.md` is the format reference.** It travels inside every blank download, so it must stand alone. `docs/company-templates.md` covers using templates and links to it.
12. **`start-dev.sh --seed` is unchanged.** Converting the seeds to templates would dogfood the format, but the manual-verify and hook scripts depend on them. Recorded as an outstanding issue.

## Format v1

A zip whose root is the template directory (one top-level folder is also accepted and stripped):

```text
company.json          required: format version and company fields
context.md            optional: companyContext
README.md             optional: for people; not imported
LICENSES.md           optional: written on export from knowledge front matter
knowledge/            optional: company-wide (shared) knowledge, any accepted type
roles/<slug>/role.json      required per role
roles/<slug>/prompt.md      optional: rolePrompt
roles/<slug>/knowledge/     optional: that role's knowledge
```

`company.json`:

```json
{
  "formatVersion": 1,
  "slug": "cottage-industry",
  "name": "Cottage industry",
  "description": "…",
  "timezone": "Europe/London",
  "systemPromptTemplate": null,
  "plannerRole": "planner",
  "llmConfig": { "provider": "openai-compatible", "model": "…" },
  "embeddingConfig": null,
  "mcpServerToggles": { "records": true, "utilities": true }
}
```

`role.json`: `name`, `description`, and optional `llmConfig`, `systemPromptTemplate`, `mcpServerToggles`. The slug is the folder name.

Rules: `formatVersion` above 1 is refused ("made by a newer version of TCP"). Unknown keys are refused, so typos surface. Any `apiKey` in a template is dropped with a warning. Knowledge `.md` files must already be valid OKF; other types are converted as an upload is. `license`, `source` and `attribution` are optional front-matter keys (SPDX-style id where one exists, e.g. `OGL-UK-3.0`, `CC-BY-4.0`).

## API

| Route                                             | Scope                 | Does                                                                                                                                                                                                          |
| ------------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/company/import/preview`                | `@NoCompanyScope`     | Multipart: `file` (zip) or `template` (`<sourceId>/<name>`). Returns `CompanyTemplatePreview`.                                                                                                                |
| `POST /api/company/import`                        | `@NoCompanyScope`     | Multipart: `file` or `template`, plus `options` (JSON string). Returns the company (201). 409 on a taken slug unless `options.replace`; replace needs membership or admin (shared helper with `postCompany`). |
| `GET /api/company/:companyId/export?models=false` | `@CompanyScope` param | Streams `<slug>.zip`. `apiKey` always removed; `models=false` removes `llmConfig` and `embeddingConfig` everywhere.                                                                                           |
| `GET /api/template`                               | `@NoCompanyScope`     | Gallery: `{ sourceId, sourceName, name, title, description, roles, documents, formatVersion }[]`. One failing source is reported in `X-Tcp-Warnings`, not a 500.                                              |
| `GET /api/template/:sourceId/:name`               | `@NoCompanyScope`     | That template as a zip.                                                                                                                                                                                       |
| `GET /api/template-source`                        | `@NoCompanyScope`     | Lists sources, including the virtual `builtin`.                                                                                                                                                               |
| `POST /api/template-source`                       | `@AdminOnly`          | Adds a GitHub source `{ name, repo: "owner/repo", ref?: "main", path?: "" }`.                                                                                                                                 |
| `DELETE /api/template-source/:id`                 | `@AdminOnly`          | Removes a user source; 400 for `builtin` or a config source.                                                                                                                                                  |

`CompanyTemplatePreview`: `formatVersion`; `company` (slug, name, description, timezone, companyContext, llmConfig, embeddingConfig, all key-free); `plannerRole`; `roles` (`slug`, `name`, `description`, `llmConfig`, `documents`); `documents` (`scope` = `shared` or a role slug, `name`, `license?`, `source?`); `neededKeys` (providers in the template that need a key, from the provider catalogue `LlmConfigPicker` uses); `slugTaken`; `warnings`.

`ImportCompanyOptionsDto` (class-validator, parsed from `options`): `slug?`, `name?`, `description?`, `timezone?`, `companyContext?`, `llmConfig?: LlmConfigDto | null`, `embeddingConfig?: LlmConfigDto | null` (absent = the template's; `null` = none), `roleModels?: Record<string, boolean>` (false drops that role's `llmConfig`; absent keeps it), `replace?: boolean`.

Limits: new env `TEMPLATE_MAX_BYTES` (zip, default 50 MiB, multer limit on both import routes). Unzip refuses: more than 2,000 entries, total uncompressed size above 4 × the limit (checked from the central directory before inflating), absolute paths, `..` segments, and anything outside the layout above.

**Sources.** New entity `TemplateSource { id, name, kind: 'github' | 'directory', location, origin: 'config' | 'user', createdAt }` with a migration (registered by hand in each `app.module.ts` that lists migrations). New env `TEMPLATE_SOURCES`: comma-separated `github:owner/repo[@ref][/path]` and `dir:/abs/path`. Boot syncs config rows to match the env (adds, removes). `builtin` is virtual, read from `TEMPLATES_DIR` (default `/app/templates`). A directory source holds template folders and/or `.zip` files. A GitHub source is fetched from `https://codeload.github.com/<owner>/<repo>/zip/<ref>` (owner/repo checked against `^[A-Za-z0-9-]+/[A-Za-z0-9._-]+$`, ref against `^[A-Za-z0-9._/-]+$`), `redirect: 'error'`, 30 s timeout, size cap `TEMPLATE_MAX_BYTES`, cached in memory for 10 minutes. Templates are the one-level folders under `path` that hold a `company.json`.

## CLI

New commands in `apps/backend/apps/tcp-cli/src/commands/`, logic in `lib/templates/`:

- `import-company <zip-or-dir> | --template <sourceId/name>` with `--slug`, `--name`, `--llm-config <json>`, `--no-role-models`, `--replace`, `--preview` (print the preview, import nothing). A directory is zipped with `fflate` first.
- `export-company <company> [--no-models] [-o <file>]` (default `<slug>.zip`).
- `new-template <dir>`: downloads `builtin/blank` and unzips it into `<dir>` (refuses a non-empty dir).
- `list-templates`, and `template-source list|add|remove`.
- `list-knowledge` shows a licence column; `store-knowledge` gains `--license`, `--source`, `--attribution`.

## Web

- **New company opens the gallery** (`TemplateGalleryDialog`): "Start from scratch" (today's `CreateCompanyDialog`), "Import a zip file", then templates grouped by source, each with "Use this template" and "Download". Blank is the downloadable starting point.
- **Using a template or a file** previews it, then opens `CreateCompanyDialog` with `template` set: fields prefilled; a "You'll need a key for <provider>" notice per `neededKeys`; a Roles section listing each role, with a checkbox "Use its own model: <provider> · <model>" (checked) where it has one; a documents count and licences line. Submit calls import. A 409 opens a `ConfirmDialog`: "Replace <slug>? This deletes that company and everything in it." Replace resends with `replace: true`; Cancel focuses the slug field.
- **Admin → Company** gains "Export as template", with a checkbox "Include model settings" (default on).
- **System menu (admins)** gains "Template sources": list, add a GitHub source, remove a user source (`ConfirmDialog`).
- **Knowledge list** (`KnowledgePanel.tsx`) shows each document's licence, linked to its source when there is one.

## Security notes

- **Untrusted archives:** layout allow-list, traversal and size checks before inflating, entry cap.
- **No arbitrary outbound URLs.** GitHub sources reach one fixed host, with validated path parts, no redirects, a timeout and a size cap. Only admins add sources.
- **No keys travel.** Export strips `apiKey`; import drops any it finds; preview never echoes one.
- **Replace stays explicit and authorised:** 409 by default, membership or admin to replace, and a confirm in the web UI.
- **Licences:** shipped knowledge carries its licence and attribution, and exports write `LICENSES.md`, so a re-shared template keeps them.
