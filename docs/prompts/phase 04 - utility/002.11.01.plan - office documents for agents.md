## Context

Agents can't read Office or OpenDocument files (`.docx .xlsx .pptx .odt .ods .odp`), and people will give them price lists in Excel and policies in Word. Knowledge converts only `.docx` and `.pdf`. 002.05's storage browser shows "No preview" for Office files.

### The PDF check (prompt's first step): PDFs come back as noise

This was settled by reading the code, not by running it:

- Every agent read goes through one server path: `POST /internal/storage/read` (`storage-actions.controller.ts:89`) → `MinioStorageAdapter.readFile` (`minio-storage.adapter.ts:250`) → `S3ObjectStore.getText` (`s3-object-store.ts:150`). That covers `read_file`, `read_material_file`, and `read_resource` (once a format is allowed).
- `getText` decodes the bytes as UTF-8, with no branch for PDF.
- So 006.02's "storage tools handle text and PDFs" is wrong, and PDF is in scope here. Stage 0 corrects 006.02 and the Images section of `usage.gaps.md`.
- The only PDF extraction today is `convertPdf` in `knowledge-conversion.ts`, which knowledge uses and agent reads do not.

### Decisions

1. **One extractor: `officeparser` (yours).** Links: [npm](https://www.npmjs.com/package/officeparser), [GitHub](https://github.com/harshankur/officeParser), [homepage and docs](https://officeparser.harshankur.com).
   - **Why:** MIT licence, about 1.7M downloads a week, releases every few days. Version 8.9.0 is the latest; stage 1 checks it with `npm audit`, and it is pinned exactly because releases are so frequent.
   - **What it covers:** docx, xlsx, pptx, odt, ods, odp and pdf, with Markdown output, for both agent reads and knowledge.
   - **Removed:** `mammoth` and `pdf-parse`. `turndown` stays for `.html`.
   - **Not supported:** legacy `.doc`, `.xls` and `.ppt` stay binary, because officeparser doesn't read them.
   - **Turned off:** OCR, attachment extraction and passwords.
2. **The extraction lives in tcp-server, done on read** in `storage/document-text.ts`.
   - On read, rather than once on upload, so there are no derived files to keep in step. It also covers files that agents and the CLI write.
   - The MCP server stays a thin proxy.
   - `ponytail:` no cache. Add one, keyed by ETag, if reads get slow.
3. **Limits on every parse, because these files are untrusted:**

   | Limit         | Value                                                                                                                                   |
   | ------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
   | Input size    | 25 MB, checked with `head` before the file is fetched                                                                                   |
   | Unpacked size | 100 MB, through officeparser's own `decompressionLimits`, which stop the unzip at the cap (as built: simpler than a separate pre-check) |
   | Time          | 20 s                                                                                                                                    |
   | Output        | 1 MB of text, cut there with a note saying so                                                                                           |

   The parse runs in a `worker_threads` worker with `resourceLimits` (about 256 MB heap) and is terminated on timeout, so a bad file can't stall the request loop. The worker is inline (`eval: true`) and `require`s `officeparser` from `node_modules`. webpack externalises `node_modules`, so no second bundle entry is needed.

4. **No macros, links or embedded objects are ever run or fetched.**
   - officeparser only parses XML: it runs no VBA, loads no OLE objects, and with attachments off it touches no images.
   - `allowRemoteAssets: false` stops officeparser fetching pdf.js workers and decoders from a CDN (its default is `true`).
   - As a second guard, the worker replaces `fetch`, `http.request` and `https.request` with functions that throw.
   - A test uses a `.docx` with an external image link (`TargetMode="External"`) and checks that no request is made.
5. **What agents get:** a first line saying the text was extracted (for example "Text extracted from report.docx; layout and images are lost."), then Markdown.
   - The text is untrusted model input, like any file (see 003.04).
   - `BINARY_EXTENSIONS` in `resource-tools.service.ts` drops `pdf`, `docx`, `xlsx` and `pptx`, and keeps `doc`, `xls`, `ppt`, the images and `zip`.
6. **Resources: read only.** Writing an Office resource means generating Office files from an agent's text, which is a much bigger step, so it is left out.
7. **The preview is server-rendered Markdown (yours).**
   - A new `GET /api/company/:companyId/storage/text?path=` (`@CompanyScope`) returns `{ markdown, truncated }` from the same extractor.
   - The browser gets a new preview kind, `'office'`, and shows it with the existing `<Markdown>` renderer, plus a line: "Text only. Download for the original layout."
   - Nothing from the file runs in the app's origin, and the renderer is already accessible.
   - PDF keeps the browser's own viewer.

### - [x] Stage 1 — A bounded extractor (Opus)

- **The dependency:**
  - `npm view officeparser version`, then `npm install officeparser@<latest> --save-exact -w apps/backend`, then `npm audit`;
  - `npm install fflate` only if it isn't already a usable direct dependency;
  - remove `mammoth` and `pdf-parse` in stage 3, not here.
- **New** `apps/backend/apps/tcp-server/src/storage/document-text.ts`:
  - `EXTRACTABLE = ['docx','xlsx','pptx','odt','ods','odp','pdf']`;
  - `isExtractable(name)`;
  - `extractText(name, buffer, limits = DEFAULT_LIMITS): Promise<{ markdown, truncated }>`.
- **The parse:**
  - check the zip directory first (every format except pdf), then run the inline worker with timeout and terminate;
  - errors map to `UnprocessableEntityException` with plain reasons ("too large to read", "took too long to read", "isn't a readable … file");
  - read officeparser's README for its current API (AST → Markdown) and its config. Pass `ocr: false`, `extractAttachments: false`, and ignore notes off.
- **Tests:** `document-text.spec.ts`. Fixtures are small files in `src/storage/__fixtures__/`, made once with officeparser's own generator from a script kept beside them, so they can be remade.
  - one case per format: the heading or cell text appears, and Markdown tables survive for xlsx and ods;
  - a zip bomb (fflate-zipped 200 MB of zeros) is refused before parsing;
  - a tiny timeout gives "took too long";
  - the external-link `.docx` makes no request (spy on `http`, `https` and `fetch`);
  - output over the cap is truncated with `truncated: true`;
  - a corrupt file gives a clear 422.
- **Gate:** `check.sh --fast`, plus `npm test -w apps/backend -- document-text`.
