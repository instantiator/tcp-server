## The problem

Agents can't read Office or OpenDocument files (`.docx .xlsx .pptx .odt .ods .odp`) in company resources, task materials or shared storage. People will want to give them price lists in Excel and policies in Word.

What the code does today:

- **Knowledge** converts only `.docx` and `.pdf`. `apps/backend/apps/tcp-server/src/api/knowledge-conversion.ts` turns them into OKF Markdown with `mammoth` and `pdf-parse`, and **drops the original**. A knowledge folder never holds an Office file. `.xlsx`, `.pptx` and OpenDocument aren't accepted at all.
- **Resources** can't hold readable Office files. `resource-tools.service.ts` in `tcp-mcp-storage` lists `pdf doc docx xls xlsx ppt pptx` (and images and `zip`) in `BINARY_EXTENSIONS`, and `read_resource` refuses them: "can't be read as text".
- **Task materials and shared storage** keep the file as uploaded. `POST /api/task/:id/materials` stores the bytes unchanged. `read_file` and `read_material_file` read through `getText` in `S3ObjectStore`, which decodes the bytes as UTF-8, so an Office file comes back as noise.

## First step: check PDFs

[006.02](006.02.00.prompt%20-%20images%20%28draft%29.md) says "storage tools handle text and PDFs". The same `getText` path reads PDF materials, and decoding a PDF as UTF-8 gives noise too. Before planning anything else, **try it**: upload a PDF as a task material, and as a file in shared storage, and read it with `read_material_file` and `read_file`.

- If it comes back as noise, correct the claim in 006.02 and in `usage.gaps.md` (the Images section), and include PDF in this work.
- If it works, find out where the extraction happens and reuse it for the other formats.

## Scope

Please create a plan for:

1. **Text extraction for agents.** Extract text (Markdown where it can keep structure: headings, lists, tables) for `read_file`, `read_material_file` and `read_resource`. Lift the formats you can read off `BINARY_EXTENSIONS`. Decide where extraction lives (server-side in tcp-server, behind the internal storage routes, so the MCP server stays a thin proxy) and whether it is done on read or once on upload.
2. **Knowledge conversion for the same formats.** Widen `knowledge-conversion.ts` to `.xlsx`, `.pptx` and OpenDocument, as well as `.docx` and `.pdf`.
3. **The storage browser's Office preview.** A new `previewKind` (for example `'office'`) beside the existing ones in `src/components/StorageBrowser/previewKind.ts`, and a renderer in `FilePreview.tsx`. 002.05 shows "No preview" and a download button for these files.
4. **Resources.** Decide whether agents may read an Office resource only, or write one too. Writing is a much bigger step; say so in the plan and leave it out unless it is asked for.

## Libraries to vet

Vet each per `dev-qual/guidance/standards/dependencies.md` (licence, downloads, maintenance, audit) before choosing. Present options and trade-offs; don't pick one here.

- **A backend extractor** covering both Office and OpenDocument, for example `officeparser`.
- **A browser preview:** for example `docx-preview` for Word, and a sheet renderer for Excel and ODS. Previews run in the person's browser on a file an agent or a colleague may have written.
- **Whether to keep `mammoth`,** which is already installed and used for `.docx` knowledge. One library that covers everything may be better than several.

## Security

- **Parse untrusted files on the server with limits.** Cap the input size, the extracted text size and the time taken, and run the parse so a bad file can't stall the request loop. A zip-based format (all of these are) can be a zip bomb: cap the unpacked size too.
- **Office files can carry macros, external links and embedded objects.** Extraction and preview must never run macros, fetch an external link, or load an embedded object. State in the plan how each chosen library behaves, and test it with a file that has an external link.
- **Extracted text is untrusted input to a model.** It reaches an agent like any other file; see 003.04 (prompt security for untrusted inbound content).
- **The browser preview must not run the file's content as a document in the app's origin.** The same rule as 002.05's: HTML and SVG are never rendered as documents.

Accessibility is very important: the preview must work from the keyboard and with a screen reader, as the other previews do.
