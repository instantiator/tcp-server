## Context

Company resources (001.02) are long-lived company documents under `{slug}/resources/`: invoices, price lists and policies. Today they are reached only from Data → Documents. The office's archive already holds two pieces of furniture: the bookshelf (task outputs) and the filing cabinet (record tables). The prompt asks for a third, for resources:

- clicking it, or choosing it in the details picker, opens a tray;
- the tray shows a tree of the resources folders, with each folder's purpose;
- each folder opens 002.05's storage browser there;
- a storage-console link appears where the console is configured.

It must work fully from the keyboard and with a screen reader, including in the office view's full screen.

- **The tooltip needs reshaping.** `ui/VisualisationTooltip.tsx:75-85` maps the kind to an id with a binary ternary (`archive ? BOOKSHELF : CABINET`).

- **No reusable tree exists.** `StorageBrowser.tsx` holds a React Aria `Tree` whose row pieces are module-private:

  - `FileItem`;

- **`StorageBrowserDialog`** (`companyId, root, heading, onClose, portalContainer`) can open at any folder under `resources/`, with its write controls. Rooted inside `resources/`, though, the root folder's own purpose is never shown.
- **The route.** `useStorageFolder(companyId, path)` (`api/hooks.ts`) returns `{ path, writable, folders[{path,name,purpose}], files[...] }`:

- **The console link.** `storageFolderUrl(config, prefix)` in `src/api/storageLink.ts` builds a link for any folder, or `null` when unconfigured (`runtime-config` `storageConsoleUrl` and `storageBucket`).
- **Tray conventions:**
  - every tray uses `TrayPanel` (no icon inside the `h2`; actions are `RoundIconButton`s);
  - the tray is non-modal and opening it moves no focus;
  - dialogs portal into the view via `portalContainer`, and Escape returns focus to the trigger;
  - the details picker is the keyboard route.
- **ADR-026 and ADR-027 have no guidance for trees.** This plan decides it (see below) and stage 5 records it.

### Choices made — say if you disagree

You were away, so these are decided here rather than asked. Each is easy to change before stage 1.

1. **One tree, extracted:** a `FolderTree` component pulled out of `StorageBrowser`, which the tray and the browser both use. The tray's tree is not a second copy. It takes `foldersOnly` (the tray shows folders only) and `onOpen(folder)`.
2. **Opening a folder (confirmed by you, 2026-11-22):** a click on the row, or Enter, opens `StorageBrowserDialog` rooted at that folder. **There is a visual cue that a row opens:**
   - an "open" icon at the row's end (`aria-hidden`, since the row's role already says it acts);
   - a hover and focus highlight;
   - `cursor: pointer`.

   The rest of this choice, as before: The dialog's heading is the folder name, with its purpose as a description line. That closes the gap where a root folder's purpose was hidden. Arrows move through the tree and expand folders, as in the browser. Rows are action rows (`selectionMode="none"`), so Space does nothing surprising.

3. **"Browse all resources":** a `RoundIconButton` in the tray's actions opens the dialog at `resources/`. Files kept at the top of `resources/` (such as its `README.md`) stay reachable, though the folders-only tree hides them.
4. **One console link for the whole of `resources/` (confirmed by you),** in the tray's description area, like the bookshelf's link pattern (visible text plus a visually hidden suffix). There is none per folder: a second interactive control inside each tree row is hard to use from the keyboard, and the dialog is one Enter away.
5. **Refresh:** opening the tray fetches fresh data, and a refresh action (`useRefreshStorage`) sits beside "Browse all". Storage stays static, as decided in 002.05.
6. **The furniture (names confirmed by you):**
   - kind `resourcesChest`, a plan chest of wide, shallow drawers;
   - `SelectionTarget` kind `resources`;
   - room tile (3,1);
   - a muted green, distinct from the bookshelf and the cabinet.
   - Names: "Resources" in the picker; "Plan chest" with the description "Company resources: documents the company keeps." on the canvas; "Company resources" as the tray heading.
7. **Empty and error states:**
   - no subfolders: `EmptyState`, "No resource folders yet", with "Browse all" still offered;
   - a failed listing: an `ErrorState` row inside the tree, as the browser already shows.
8. **No CLI verb.** Reading resources from scripts is already covered by `download-shared-document` and its storage verbs, and the tray adds no new data.

### Security notes

- There are no new routes. The tray reads the existing `@CompanyScope`d storage folder route, and writes stay where 002.05 put them (`resources/` only, mirrored by `isWritablePath`).
- The console link is built from runtime config with the confirmed percent-encoding (`storageFolderUrl`).
- Purposes are text from `README.md`, rendered as text, never as HTML.
