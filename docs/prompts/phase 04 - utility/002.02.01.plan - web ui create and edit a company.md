## Context

A company can only be created, edited or deleted with `tcp-cli` (raw JSON). The web client's empty state says so. Since 002.00, deleting the default planner's role leaves nothing in the browser that can choose a new one. This plan adds a create dialog on the Companies page and an Admin → Company section for editing, choosing the planner, and deleting. It also closes a hole in `POST /api/company` that a web form would make easy to hit.

### What exploration found

- **Company fields** (`TcpCompany.model.ts`): `slug` (fixed after create), `name`, `description`, `timezone`, `companyContext`, `systemPromptTemplate`, `versionRetentionDays`, `plannerRoleId`, `llmConfig`, `embeddingConfig`, `mcpServerList`, `mcpServerToggles`. **There is no `region` field.** The prompt's "prompt template" is `systemPromptTemplate`.
- **`POST /api/company` is create-or-replace** (`company-db.service.ts:48`). It deletes any company with the same slug first. It is `@NoCompanyScope`, so **any signed-in user can wipe any company by posting its slug.** `start-dev.sh` (via `set-company`) and the e2e test "slug replacement" rely on the replace behaviour.
- **The creator becomes a member** (`memberType: 'creator'`, `company-db.service.ts:69-84`).
- **`plannerRoleId` can't be set on create**: a new company has no roles, so the ownership check fails (400). On update, `null` already clears it in practice, but the DTO doesn't declare it nullable, so `schema.d.ts` won't allow it. The same goes for `companyContext`, `systemPromptTemplate` and `timezone`. `versionRetentionDays` is already `| null` (1–3650).
- **Responses:** the bare company. Warnings travel in `X-Tcp-Warnings`; the client reads them with `readWarnings` (`api/warnings.ts:26`).
- **`DELETE /api/company/:id`** exists (204), any member may call it, and it cascades.
- **Frontend:**
  - `CompaniesPage.tsx` has no create button. Its empty state (`strings.ts:429-431`) says the web can't create one.
  - Admin sections are listed in `admin-sections.ts:4-10` (`roles, models, users, knowledge, data-protection`) and chosen by the ternary chain in `AdminPanel.tsx:57-70`.
  - Patterns to copy:
    - `LanguageModelsAdmin.tsx`: inline section, `ask()` + one `ConfirmDialog`, save → warnings → announce.
    - `RoleDialog.tsx`: create dialog, `slugify` until the slug is touched (`:60-65`), `focusFirstInvalid`, the 400-or-generic error rule.
    - `RetentionDialog.tsx:54-67`: days as a string field.
    - `RolesAdmin.tsx:253-268`: delete confirm.
  - Hooks: `useUpdateCompany` exists (`hooks.ts:427`). There is no create or delete hook. Copy `useCreateRoleMutation` (`endpoints.ts:611`) and `useUpdateCompanyMutation` (`:658-684`).
  - **`LlmConfigPicker` requires `companyId`** (live model listing posts to `/api/company/{id}/llm/models`). A company being created has no id yet.
- **Memory view (parity row 14) is out of scope.** It appears in this prompt's table, but it is 002.06's own prompt.

### Decisions agreed with you (2026-10-17)

- **Slug clash:** an existing slug returns **409**. `?replace=true` keeps today's replace, but only for a member of that company or an admin. `tcp-cli set-company` sends it. The web form never does.
- **Edit lives in Admin → Company**, a new first section (`#admin/company`). **Create is a dialog** opened from the Companies page.
- **Delete is included**, in Admin → Company, behind a `ConfirmDialog`. Any member may delete, as the API already allows.

### Choices made in the design (say if you disagree)

1. **No live model listing while creating.** `companyId` becomes optional on the picker. Without it, a local or custom provider shows the curated list plus free text, and the hint "The server's model list is available after the company is created." No new pre-company listing route, so no new place where the server fetches a URL the caller chose.
2. **The create dialog is kept short:** name, slug, description, timezone, company context, chat model, embedding model. Version retention and the system prompt template are edit-only (both have sensible defaults). The planner is edit-only (there are no roles yet).
3. **After create, go to `/company/:id#admin/roles`** and announce "Company created. Add roles next." The prompt's "list required secrets" waits for 003.00. "Offer a first task" needs roles and a planner first, so it is carried forward to 005.04 (create from template).
4. **Timezone is a RAC `ComboBox`** of `Intl.supportedValuesOf('timeZone')`, defaulting to the browser's zone on create. No custom values; the server validates anyway.
5. **Clearing a text field sends `null`.** Empty retention sends `null` (the app default, shown in the hint as "90 days"). Edit sends only changed fields, as `RoleDialog` does.
6. **Models stay in Admin → Language models.** Admin → Company doesn't show them a second way.
7. **Delete confirm** names the company and what goes with it: "Its roles, tasks, knowledge, records and files are deleted too. This can't be undone." Then it navigates to `/companies` and announces.

### Frontend

**Hooks** (`endpoints.ts`, re-exported from `hooks.ts`):

- `useCreateCompany()`: POST, returns `{ company, warnings }`, invalidates `['company']`. A 409 surfaces as `ApiError` with status 409.
- `useDeleteCompany()`: DELETE, invalidates `['company']` and removes `['company','detail',id]`.

**`LlmConfigPicker`:** `companyId?: string`. With none, `useLocalModels` gets `null` (sends nothing), the Refresh button is hidden, and the hint above shows.

**`CreateCompanyDialog`** (`pages/CompaniesPage/CreateCompanyDialog.tsx`):

- It opens from a "New company" button in the page header and from the empty state. The empty-state text changes to invite creating one.
- Fields, in order: name, slug, description (multiline), timezone, company context (multiline, optional), "Chat model" and "Embedding model" pickers (`fallback={{ from: 'app', config: defaults.chat / defaults.embedding }}`).
- `slugify` moves from `RoleDialog.tsx` to `components/Field/slugify.ts` (with the reserved-slug rule) so both dialogs use it.
- Save: validate (required name/slug/description; changed configs via `validate`), run `useLocalAddressCheck`, then POST. Send `patchOf(draft, null)` for each config and leave the key out when it is `null` or `undefined`.
- A 409 puts "That address is taken. Choose another." on the slug field. Other 400s and errors follow `RoleDialog.failed()`.
- On success: navigate as in choice 3.

**`admin/CompanyAdmin.tsx`** (section id `company`, label "Company", first in `admin-sections.ts`; `CompanyTabs` falls back to it instead of `roles`):

- Fields: name, description, timezone, company context, system prompt template (multiline; empty means the built-in default), version retention days (string field as in `RetentionDialog`, 1–3650, empty = app default), default planner.
- **Default planner:** a RAC `Select` of the company's roles plus "None: tasks must choose their own planner". Copy the provider `Select` in `LlmConfigPicker`.
- Save sends only changed fields through `useUpdateCompany`, then shows warnings and announces on channel `company`.
- **Delete company:** an outline danger button below the form, then the confirm from choice 7, then `useDeleteCompany`, then navigate to `/companies`.
- Wait for the company and roles to load before rendering the form (the 002.01 stage 9 race).

**Strings:** `companies.create.*`, `admin.company.*`, `admin.menu.company`; update `companies.empty.*`.

### Security notes

- **The 409 closes a real hole:** today a non-member can delete any company by POSTing its slug. With `replace=true`, replace is still possible, but only for members and admins.
- **No new route fetches a URL.** Live listing stays company-scoped, and create skips it.
- **Any member can edit or delete a company**, as the API already allows. Permission flags remain deferred (002.00 and 002.01 already record this).
- **Delete is irreversible.** The confirm says so. A backup (000.01) is the only way back.

### Changed while implementing stage 1 (2026-10-17)

- **`replace` reaches the database layer.** `CompanyDbService.create` deletes the old slug only when `replace` is set. Without it, the slug's unique index refuses a duplicate, so a race between the check and the save can't delete a company.
- **Only `?replace=true` widens the request.** `?replace` and `?replace=1` are plain creates (409 on an existing slug), the same rule as `?all`.
- **The API tier's `createTestCompany` sends `?replace=true`.** It reuses fixed slugs against a long-lived stack. The e2e and browser tiers use fresh or random slugs and needed no change. `run-backup-tests.sh` starts from an empty stack.
- **A 409 reveals that a slug exists.** That's unavoidable while slugs are globally unique, since a create form has to say "taken". The company's id is still never echoed.
- **`start-dev.sh` wasn't re-run.** Its seeds go through `set-company`, whose POST now carries `?replace=true` (unit-tested), and the machine token that seeds them is their creator, so it may replace them.
- Gates: unit 3,103 passed; e2e 469 passed; `schema.d.ts` regenerated from `tcp-testing` (only `UpdateCompanyDto` became nullable, and `replace` was added); `schemas/schema.json` unchanged.
