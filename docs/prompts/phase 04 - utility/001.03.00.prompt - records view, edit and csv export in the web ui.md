> | Records view, edit and CSV export in the web UI | Structured records | Users must be able to check and correct what agents record |

Please create a plan to implement the UI for record interactions.

We'll also need a CLI option to export the CSV of records and to obtain a list of tables.

Rather than implementing a CLI editing facility, we'll leave editing to the user's database tool of choice. Please also add CLI options to print the database connection string for:

- the tcp-server dataase
- the tables for a given company (as this may vary from the tcp-server db)

The visualisation for the records store should be a filing cabinet, next to the bookshelf in the archive. Its tray should show a table of tables for the current company (with the number of records), each clickable to open a dialog with a spreadsheet-like view of the data in the table. Columns:

- table
- records
- actions
  - download button
  - append CSV button
  - clear button (with a confirmation dialog)
  - delete button (with a confirmation dialog)

The tray should have a 'download all' small, round, download icon, control button. It should zip up all the table CSVs and initiate a download as `YYYY-MM-DD HH:mm:SS company-slug tables.zip`

The dialog should have a 'download' button, too - which retrieves the table currently on display as CSV.

The dialog sheet view should have the following features:

- Recognise and style the header row separately
- Rows can be filtered and sorted by any column
- By default, sorted most recently updated first
- Click in a cell, or navigate with arrow keys and enter to start editing, enter or click away to save
- Track changes and offer an undo feature

We ought to identify a spreadsheet library to use for this, rather than roll our own. Follow our code quality criteria for good libraries - remember accessibility though. Navigation and editing the sheet should follow common practices for accessible spreadsheets wherever possible. Explain the options and make a recommendation whilst preparing the plan. Plan should document the spreadsheet library decision as an ADR.

Similar to the tray, we'll also need a tab for 'Tables' as a part of the company view. Inside that tab should be a 'menu+main' view - menu down the left-hand side - with an entry for each table, and a download all control.

Selecting a table opens that table in the main portion of the view, using the same spreadsheet control as before, and with a small fixed title + download button.

Challenge me on the design if there's a clearer, more intuitive way to do this. Accessibility is very important.
