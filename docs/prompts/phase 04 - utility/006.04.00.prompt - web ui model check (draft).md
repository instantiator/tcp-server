> **Since 000.00:** the route is `@AdminOnly()`, `baseUrl` must pass `LlmDestinationPolicy` (the provider catalogue or `LLM_ALLOWED_HOSTS`), and each result carries an `errorCode` with an actionable `error`. So a web UI check is an administrator tool as it stands. For company owners, as model fit per job wants, add a company-scoped check **by reference** (`{ roleId }` or `{ companyId }`, probing the stored config) rather than reopening the raw-`baseUrl` route.

## Also: a Test button on the picker (from 002.01)

[002.01](002.01.01.plan%20-%20web%20ui%20llm%20provider%20picker.md)'s `LlmConfigPicker` can list a local server's models, but it can't test one. The by-reference check above (`{ roleId }` / `{ companyId }`, probing the stored config) should back a "Test" button on the picker. The browser never has a saved key (responses mask it), so the raw route can't be used from there. Remove the outstanding-issues entry "The model picker can't test a connection" when this lands.
