## Context

Agents work out sums, dates and unit conversions in their heads, and small models get them wrong. They also have nowhere structured to keep orders, customers or stock, so records end up as unchecked free text, and a retried run can create the same order twice. These two MCP servers fix both problems:

- `tcp-mcp-utilities`: stateless and deterministic. Decimal arithmetic, date maths and unit conversion.
- `tcp-mcp-records`: typed tables per company, stored as JSONB and checked by ajv. Unique keys make a repeated insert a no-op. Every read and write is audited.

### Decisions agreed with the user (2026-10-10)

- **Records may live in a fully separate database.** `RECORDS_DATABASE_URL`, falling back to `DATABASE_URL`.
- **Records logic is a shared service with direct DB access.** `RecordsService` lives in `libs/tcp-shared/src/records/`. `tcp-mcp-records` uses it now, and tcp-server reuses it in 001.03.
- **Agents create tables with a `create_table` tool.** Agents can't alter or drop tables. Schema changes wait for 001.03 (users) or templates (002.03).
- **`calculate` uses decimal.js 10.6.0** (MIT, no dependencies) and a small recursive-descent parser. It never calls `eval`.

### Decisions made in this plan (object at approval if wrong)

**Utilities**

- **Tools:** `describe_server`, `calculate`, `date_math` and `convert_units`. Every number goes in and comes out as a **decimal string**, so no float ever touches a value.
- **`calculate` grammar:**
  - Numbers: no thousands separators. A comma gets an error that says so.
  - Operators: `+ - * /`, `^` (integer exponents only, |n| ≤ 1000), parentheses, unary `±`, and **postfix `%` meaning ÷100** (`120 * 20%`). There is no modulo, because small models write `%` to mean percent.
  - Functions: `round(x, dp=0)` (half-up, the money convention), `round_even(x, dp)`, `floor`, `ceil`, `abs`, `min(...)`, `max(...)`.
  - Limits: 1000 characters, nesting depth 100. Precision: 40 significant digits. A non-terminating division is returned at 20 decimal places, and the description tells the agent to `round()` money.
  - Errors (`err()`) give the position and what was expected.
- **`date_math`** is one tool with an `operation` enum: `add`, `subtract`, `add_business_days`, `difference` (calendar days and business days), and `tax_year`. The `tax_year` start date is `MM-DD` and defaults to `04-06`, the UK. It returns start, end and a label like `2026/27`.
  - Dates are ISO `YYYY-MM-DD` (`Temporal.PlainDate`), with no times. Month arithmetic clamps to the end of the month (31 Jan + 1 month = 28 Feb), and the result says when it did.
  - Business days are Monday to Friday, minus an optional `holidays` date list. There is no built-in holiday calendar (ponytail: regional knowledge packs 005.02 can supply one).
- **`convert_units`** covers mass (`mg g kg t oz lb st`) and length (`mm cm m km in ft yd mi`). It uses exact factors (1 lb = 0.45359237 kg, 1 in = 0.0254 m). Converting between mass and length is an error.
- **No currency conversion.** No rates source exists, and `describe_server` says to use `calculate` with a stated rate. The outstanding issue says to add it when a rates source is chosen.
- **No server-side audit.** Every tool call is already audited on the client side as `tool_call` / `tool_result` (`stream-event-mapper.ts`). The server keeps no state, and its health check is the shared `StaticHealthModule`.
- **Every mode gets utilities.** Registry `usage`: "arithmetic on money and quantities, date calculations and unit conversion — use these instead of working figures out yourself."
