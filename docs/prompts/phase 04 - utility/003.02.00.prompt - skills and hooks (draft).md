> ## Skills and hooks
>
> **Today:** behaviour is shaped by the role prompt and checked after the fact
> by a QA agent of the same role (`assure_assignment`). `filterToolsForMode`
> filters tools by mode only. Nothing stops a tool call before it happens.
>
> **Recommend:**
>
> - **Hooks:** rules evaluated in tcp-agent around each tool call. They run
>   before the call (allow, deny with a reason the agent sees, or ask the user)
>   and after it (audit, redact). Rules are declared per company or role. Start
>   with simple matchers (tool name, argument patterns) and add an LLM-judged
>   rule type later.
> - **Skills:** named procedures (markdown plus optional records or tools) that a
>   role loads when it needs them, such as "handle a refund request" or "price a
>   custom order". This keeps the base prompt short, which matters on small
>   models.
> - Hooks are the enforcement layer behind
>   [no unauthorised promises](usage.gaps.md#no-unauthorised-promises) and
>   [action approval](usage.gaps.md#action-approval). Security-sensitive: plan with Opus.

## Templates (from 002.03)

[002.03](002.03.01.plan%20-%20company%20template%20format%20v1%20with%20import%20and%20export.md) built the format and the built-in templates (`templates/blank`, `basic`, `cottage-industry`). Skills and hooks should be part of both.

- **Format.** Add skills and hooks to the template format, per role and per company. Skills are markdown files in the role's folder. Hooks are declared where the plan decides (company or role). A format change means bumping `formatVersion` (to 2 or higher). v1 refuses unknown keys, so an older server will refuse the new template with its "made by a newer version of TCP" message, which is the right result. The new code must still read version 1. The format is documented in `templates/blank/README.md`, which travels inside every blank download. Update it in the same change, so it never lags behind the code.
- **`cottage-industry`: hooks** so the essential steps always happen:
  - every customer-facing draft passes the promises reviewer before it goes to the owner (wired to the real hook in 004.03);
  - the regulations adviser cites its source and the document's `retrieved` date in every answer;
  - the bookkeeper uses the calculator (utilities) for every sum.
- **`cottage-industry`: skills** for repeatable processes: "answer an enquiry", "record an order and work out postage", "prepare a tax-year summary", "write a listing". Move each from the matching role prompt into a skill, and keep the prompt short.
- **`basic`:** give the planner a planning skill if that suits better than its prompt. Move the prompt's planning guidance across only if a small model follows it better that way. Test both.
- Export must write hooks and skills back, and import must validate them. Import is a trust boundary: see 003.04.
