## Context

The TUI's last unique feature is following a chat agent into its consultations. The prompt asks for three things:

1. Show consultations in the web transcript of **both** agents. In the asking agent's view, show the consultation inline as a quote-style block (left border, small indent) with a waiting indicator. In the consulted agent's view, show it as a normal conversation.
2. Propose a way to keep the number of open streams low (`MAX_STREAMS = 12`).
3. Then remove the TUI completely: code, tests, libraries and docs.

### What exploration found

- **The consultation lifecycle** is in `apps/backend/apps/tcp-server/src/api/pause-and-resume.service.ts`:
  - **Start:** `pauseForConsultation` (:140-232) creates the consulted agent with the prompt `Context: …\nQuestion: …` (:175-180). It then records `state_change {reason:'consultation', consultedAgentId, consultedRoleName}` on the **asking** agent (:217-226). The question isn't in that event, only in the earlier `tool_call` row.
  - **Answer:** `completeAgent` (:242-290) and `failAgent` (:301-340) resolve the `PendingConsultation` row and resume the asking agent.
  - **No event on the asking agent's stream carries the answer.** It only appears inside the raw message list of the next `llm_request`.
- **The consulted agent's stream** has no `input` row for the question. Its transcript opens with LLM activity, with no question shown.
- **The web transcript** (`apps/frontend/tcp-frontend/src/components/Transcript/`: `useTranscript.ts`, `Transcript.tsx`, `Transcript.css`):
  - Entries come from the shared renderers in `libs/tcp-shared/src/transcript/` (`audit-renderers.ts`, `entries.ts`, `style.ts`, `line-format.ts`). `LogEntry` is a flat list, with no nested or quoted entry.
  - The pause shows as "paused (waiting for a consultation)" (`line-format.ts:114-151`), and `consultedRoleName` is ignored.
  - Nothing in the frontend reads `consultedAgentId`.
- **Opening another agent's transcript:** `openChat({ agentId, roleName, reference: null, readOnly: true })` from `useChat()` opens a read-only listen-in. `useListenIn.ts` (`visualisation/isometric/company/ui/`) is the pattern to copy.
- **Bug, which you asked to fix here:** a consulted agent inherits the task's `taskId` (`agent-db.service.ts:69`). So `AssignmentCompletionService.complete` (`assignment-completion.service.ts:101-110`) sends its answer through `handToQa`, and the asking agent waits a whole QA round. Task-less consultations take `completeOrphan` (:242-257).
- **The TUI footprint:**
  - Code and tests: `apps/backend/apps/tcp-cli/src/lib/tui/` (23 files, 5,789 lines), `commands/tui.ts` and its spec, and `chat/wiring.spec.ts`.
  - Chat code to slim down: `chat/action.ts`, `wiring.ts`, `turn-runner.ts`, `session.ts`, `session-api.ts`, `flags.ts`, `context.ts`, and `render/style.ts` (it imports `escapeMarkup` from `tui-format`).
  - Dependencies: `terminal-kit` and `@types/terminal-kit` in `apps/backend/package.json`. Removing them drops 9 transitive packages with them.
  - No config, script, CI or Docker entries mention the TUI.
  - Dead code to remove in the same sweep:
    - `core/agent-log-format.ts` and its spec. Nothing imports them.
    - `EventLogBuffer.render()` (`event-log.ts:118`).
    - `parseTaskChangeSummary` and `planIndexFromShortcode` (`events/wire-parse.ts`, exported from `client.ts:50-51` and `index.ts:33`). Only TUI session code uses them.
- **What stays:**
  - Linear `chat` keeps following consultations to stderr (`turn-runner.ts` `followConsultation`, the `createRenderer` branch).
  - Every TUI action has a CLI verb: `list-roles`, `chat --role`, `create-task`, `start-task`, `cancel-task`, `get-task`, and `eavesdrop --tail`.
  - The only loss is a live company-wide view in the terminal. The web UI covers it.

### Stream budget (the prompt asked for options)

The chosen design needs **no** extra stream: everything the asking agent's block shows arrives on its own stream. Options, for when the cap starts to bite:

1. **The chosen design:** compact answer events on the asking agent's stream. Uses 0 streams per consultation.
2. **Live follow on demand:** "Open Analyst's transcript" opens a stream only when someone asks for it, and closing it releases the stream (the existing 008.02 parking rules).
3. **Server-side merge:** the asking agent's SSE route `merge`s in `agentEvents.observe(consultedAgentId)` while a consultation is pending (`api.agent.controller.ts:206-216`; an extra Redis SUBSCRIBE on the shared connection, not a new connection). This gives live inline reasoning over 1 stream. Act when people ask to watch the consulted agent's reasoning inline.
4. **One company stream for all transcripts:** use the company channel plus client-side filtering. This is the biggest change. Act when a real view is refused under `MAX_STREAMS`.

### Design

**Events (stage 2):**

- **Asking agent, on pause:** add `question` (and `context`, when given) to the existing `consultation` pause payload (`pause-and-resume.service.ts:217-226`).
- **Consulted agent, at creation:** record an `input` row on the consulted agent, with payload `{ text: <question>, source: 'consultation', fromRoleName: <asking role's name>, context? }`. Its transcript then opens with the question, like a chat message.
- **Asking agent, on answer:** in `completeAgent` and `failAgent`, once a pending consultation resolves, record an `input` row on the **asking** agent. Payload: `{ text: <answer or failure reason>, source: 'consultation', consultedAgentId, consultedRoleName, failed: boolean }`.
  - It is an `input` row because it is exactly the text that gets injected into the asking agent, which today writes no row at all.
  - `input` rows aren't company-entity events, so they reach only that agent's stream.
- **Task consultations:** in `AssignmentCompletionService.complete`, a `consultee` assignment always takes `completeOrphan`. If it has a `taskId`, `recomputeTaskStatus` then runs after it.

**Shared renderers (stage 2):**

- Add a `'consultation'` `EntryStyle`, and an optional `consultation?: { agentId: string; roleName: string; kind: 'asked' | 'answered' | 'failed' }` field on `LogEntry`.
- `StateChangeAuditEventRenderer`: a `consultation` pause with a `question` becomes `{ style:'consultation', kind:'asked', text: question }`.
- `TextContentAuditEventRenderer`: an `input` with `source:'consultation'` and a `consultedAgentId` becomes `kind:'answered'` (or `'failed'`). With `fromRoleName` instead, it stays a `'user'` entry whose label names the asking role (the consulted agent's view).
- The CLI's linear renderer picks this up through `render/style.ts`. It prints `▌ Asked Analyst: …` and `▌ Analyst answered: …`, so `chat` and `eavesdrop` show the same thing as the web UI, with no new verb.

**Web transcript (stage 3):**

- **The block:** `Transcript.tsx` renders `consultation` entries as one quote-style block. The left border comes from tokens, copying `ChatDialog.css:66-68` (`border-inline-start: calc(var(--tcp-border-width) * 4) solid var(--tcp-color-accent)`).
  - Heading: "Asked {role}" / "{role} answered" / "{role} couldn't answer".
  - Body: the question or answer as `Markdown`.
  - A link button, "Open {role}'s transcript", calls `openChat({ agentId, roleName, reference: null, readOnly: true })`.
- **Waiting indicator:** shown under an `asked` entry until an `answered` or `failed` entry with the same `agentId` follows it. It reads "{role} is working on it" with a decorative animated ellipsis, which is still under `prefers-reduced-motion`.
- **Announcements:** follow the arrival-only policy (`ANNOUNCE_RESPONSE_BODY = false` in `useTranscript.ts`). Each block announces "Consulting {role}" and "{role} answered" (or "{role} couldn't answer"), with no body text.

### Security notes

- There are no new routes and no authorisation changes. The new rows are written server-side for agents in the same company. They reach the existing `@CompanyScope`d agent streams and history.
- The answer text is agent-written, so it gets the same trust as any response. It renders through the existing `Markdown` component, with no new HTML path.
- Removing `terminal-kit` drops 10 packages from the backend's dependency tree, a smaller attack surface.
