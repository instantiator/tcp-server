> ## Third-party MCP services
>
> > 📝 **In a draft, not implemented:** [unplanned.md](<../phase 05 - service quality/unplanned.md>) ("MCP tools are usable, but not easily configurable") asks for MCP configs on roles in a common format, and a searchable catalogue in the web UI and TUI.
>
> **Today:** `MCP_REGISTRY` (`libs/tcp-shared/src/mcp/mcp-registry.ts`) is a
> fixed list of four servers (storage, memory, interactions, tasks), and each
> URL comes from an environment variable. Companies and roles have
> `mcpServerList`, but `AgentRunEnvironmentService.assemble` resolves URLs only
> from that registry. So a name that isn't one of the four goes nowhere. There
> is no way to add a server without a code change and a restart.
>
> **Recommend:**
>
> - An `McpService` entity: name, transport (streamable HTTP first; stdio only
>   inside a container we run), URL, auth (a reference to a [secret](usage.gaps.md#secrets)),
>   a `usage` line for the prompt, and an optional tool allow-list.
> - Attach services to a company or a role. This keeps today's additive rule.
> - Per-role tool allow-lists, so an enquiry role can read email but not send it.
> - A catalogue of known services (from `unplanned.md`): a searchable list in the
>   web UI, and the same list in the API and CLI.
> - Each catalogue entry says which secrets it needs, and whether it acts on the
>   outside world. Anything that does gets [action approval](usage.gaps.md#action-approval)
>   by default.

## Templates (from 002.03)

- Add MCP service attachments to the template format, for the company and for each role. A template names the service (a catalogue entry) and any tool allow-list. It never carries a secret: the services' secrets are listed as "you'll need" (see 003.00).
- This is part of format v2, planned in 005.04. Coordinate the two plans: the service shape in `company.json` and `role.json` should be settled once. A format change means bumping `formatVersion` (to 2 or higher). v1 refuses unknown keys, so an older server will refuse the new template with its "made by a newer version of TCP" message, which is the right result. The new code must still read version 1.
- On import, an unknown catalogue entry must give a clear warning, not a failure, as the template may come from a source with a newer catalogue.
- The format is documented in `templates/blank/README.md`, which travels inside every blank download. Update it in the same change, so it never lags behind the code.
