## Revisits carried from earlier phase 04 work

Plan these in, and settle each one at the end of 000.05. Each is also an entry in [outstanding-issues.md](../../outstanding-issues.md). Update or remove that entry when it's done.

- **Supporting services fail a task rather than pause it** (from 000.04, and noted in its addendum). A run fails with `service_unavailable` when storage, Redis, the database or an MCP service is down, and so does its task. Once 000.05's health signal exists, pause the task instead, and resume it when the service reports healthy. Decide whether the resume is automatic or needs a user. See [the outstanding issue](../../outstanding-issues.md#supporting-services-fail-a-task-rather-than-pause-it).
- **An MCP server that's down at tool-load time is skipped quietly** (from 000.04). `McpClientService.loadTools` skips a server it can't reach, so the agent runs without those tools and no reason is recorded. If the health signal covers the MCP servers, use it to report this, or fail or pause the run. See [the outstanding issue](../../outstanding-issues.md#an-mcp-server-that-is-down-at-tool-load-time-is-skipped-quietly).
- **A `running` agent is stranded when the failure write itself fails** (from 000.04). The fix belongs in startup recovery: mark a `running` agent with no live job as failed. 000.05 works on shutdown and restart, so check whether it fits here. See [the outstanding issue](../../outstanding-issues.md#a-running-agent-is-stranded-when-the-failure-write-itself-fails).
- **Cancelling a drain has no surface** ([usage gaps](usage.gaps.md), and [006.05](<006.05.00.prompt - unused api routes (draft).md>)). `DELETE /api/system/shutdown` is unused. The system menu's shutdown entry is the natural place for a "Cancel shutdown" action, and the CLI may need a matching verb. If it's done here, take it off 006.05's list.

## Addendum — agreed in planning (2026-10-09)

Plan: [000.05.01.plan - system menu for health and shutdown.md](<000.05.01.plan - system menu for health and shutdown.md>).

- **Health is one admin route.** `GET /api/system/health` combines every service's `/health`, fetched by tcp-server on the internal network. The web dialog and the new `get-health` CLI verb both read it. Compose healthchecks are unchanged.
- **The web client learns admin status from `GET /api/system/access`** (`{ admin }`). The System menu shows only for admins. ADR-023 is amended, and there is still no general `/api/me`.
- **The web shutdown dialog drains and cancels, but never halts.** The host still stops the services (ADR-019). `cancel-shutdown` joins the CLI.
- **Supporting services still fail a task.** Exploring showed most outages never reach the `service_unavailable` code, so the pause is re-deferred with a sharper condition.
- **An MCP server the run needs that can't be reached at tool load fails the run** with a plain reason naming it.
- **Startup recovery fails `running` and `queued` agents that have no job**, with a new `interrupted` reason.
- **Commits:** one per stage.

**Added after review (2026-10-10):**

- **A shutdown banner for every signed-in user.** It reads `GET /api/system/status`, which replaces the planned access route.
- **A restart option.** It drains, then tcp-server and tcp-agent exit and Docker restarts them. Agents paused for the restart carry on by themselves on boot.
- **Startup recovery repairs before it fails.** A stranded agent is resumed from its checkpoint. It fails only if its task has ended, or it was already recovered once. Tasks stuck in `finalising` are repaired too.
