> ## Home hardware realities
>
> - The machine sleeps or reboots, so schedules need a catch-up rule (see
>   [recurring tasks](usage.gaps.md#recurring-tasks)).
> - A cold local model took 28s to load on first request, so probes and
>   scheduled runs need long timeouts.
> - One GPU means one model at a time. Scheduled work and interactive chat
>   compete for it. Make the agent queue aware of this (concurrency 1 per local
>   model endpoint), and show queued work in the UI so a wait doesn't look like
>   a hang.

## Additions

### Concurrency is configurable per endpoint

One at a time is the right default for a home GPU, but it must not be a fixed rule:

- **Local endpoints** default to 1, and an operator can raise it (for example, to test under higher load).
- **Remote endpoints** default to a higher number, so a remote model that can run work in parallel isn't held back by mistake. They also have a hard upper limit, to slow how fast spend builds up. This matters most for providers that bill from a usage bucket or quota.
- Choose the defaults and the limit in planning. Also decide where the setting lives (environment, per provider, or per endpoint).
- The per-model limit and the global `AGENT_WORKER_CONCURRENCY` both apply. An agent starts only when both allow it. When either changes (a run ends, a pause starts or lifts, a setting changes), check both again so waiting agents start as soon as they can.
- Both limits are optional. If one is not set, it does not limit anything. If neither is set, nothing limits how many agents run at once.

### Optional check and auto-resume after a rate limit

A spend cap already resumes on its own when its window resets (000.02, ADR-031: a 60-second sweep resumes agents paused with `spend_cap`). Nothing does the same for a provider's rate limit. Today only the model check recognises a 429. Find out what a rate-limited agent run does now (it probably fails once LangChain's retries are used up).

- When a provider rate-limits a run, pause the agent with its own pause reason, not a failure. Every new `PauseReason` needs a branch in `pauseResumePrompt()`.
- Resume on its own when the provider says to retry. Read the hints the response gives (`Retry-After`, `x-ratelimit-reset-*` and similar headers, or a reset time in the error body). Find out which hints each catalogue provider actually sends.
- The plan must include a research stage that reads each common provider's own rate-limit documentation: at least OpenAI, Anthropic, Google Gemini, Mistral, Groq and OpenRouter, plus any other provider in the 004.01 catalogue. For each one, record which headers or body fields it sends, their units (seconds, a date, or a duration like `6m0s`), and whether the error is a short-term rate limit or a used-up quota or credit balance. Use that table to decide how each hint is read. A used-up quota should not be retried every few seconds.
- If the response gives no hint, check again on a configurable cadence, with a sensible default and backoff.
- Make auto-resume optional (it can be turned off), so an operator can choose to resume rate-limited work by hand.
- Show why the agent is paused and when it will next try, in the same places as a `spend_cap` pause.

## Addendum — agreed in planning (2026-10-06)

Plan: [000.03.01.plan - one queue per local model and long timeouts.md](<000.03.01.plan - one queue per local model and long timeouts.md>).

- **Two global pools replace the single global limit.** A local pool (default 1) and a remote pool (default 4) each count every agent run of their kind. They ship set, and an operator can raise either or clear it (`null` means unlimited). `custom` endpoints count as local.
- **Per-endpoint limits are optional overrides** with no default. An agent starts only when its pool and its endpoint limit (if set) both allow it. Both are checked again whenever a slot frees.
- **`AGENT_WORKER_CONCURRENCY` is retired.** If it's set, tcp-agent logs a warning and ignores it.
- **Config is one environment variable**, `MODEL_CONCURRENCY` (JSON), validated at boot like `SPEND_CAPS`.
- **Limits apply per agent run**, not per LLM call. A paused agent frees its slot.
- **Long timeouts are already in place.** LLM calls, runs and model-check probes default to 30 minutes, and time spent queued doesn't count against a run. This prompt only confirms and documents that.
- **Cap auto-resume already exists** (000.02, ADR-031). Rate limits get the same treatment: a new `rate_limited` pause, resumed by the existing sweep at the provider's hinted time, or on a configurable backoff when there is no hint. A used-up quota waits longer (default 1 hour). Auto-resume can be turned off.
- **A research stage reads each provider's rate-limit documentation** before the hint parser is written.
- **Commits:** one per stage.
