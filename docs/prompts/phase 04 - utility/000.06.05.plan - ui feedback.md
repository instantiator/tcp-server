## Context

Feedback on 000.06.03 (`000.06.04.feedback - ui.md`) covers three areas:

- the tray's action buttons touch each other;
- the chat transcript shows markdown as raw text, loses line breaks, and dumps tool calls as JSON wide enough to widen the dialog;
- the chat list's states are wrong, and its rows are hard to tell apart.

## What's wrong with the chat list

I checked this against the dev instance (Test Company) by reading its database and the web logs. I made no changes.

**One cause explains most of it.** The chat list gets each agent's status from `GET /api/agent?companyId=…`. With no `status` filter, that route returns **only active agents** (`AgentDbService.list` defaults to `ACTIVE_AGENT_STATUSES`). Every agent in Test Company has finished, so the response is `[]` (the logs show 2-byte bodies). The list then can't find any status, and `isTerminalAgentStatus(undefined)` counts a missing status as "not finished". This explains:

- every chat showing as "Open";
- every eavesdrop sitting under "Listening in, running" and showing "Running";
- a completed chat staying in the list, because a chat counts as archived when it's finished, and it never looks finished;
- "Show archived" making no visible difference, because nothing ever counts as archived.

In the database, all three Cat assistant chats are `completed` and their assignments `succeeded`.

**The missing archive button for eavesdrops** comes from the dialog's width. The button exists (`ChatView.tsx`). The view's grid column is `1fr`, which won't shrink below its content's minimum width. A wide `<pre>` of tool JSON therefore pushes the whole view, including its header buttons, past the right edge. Your second screenshot shows this: even the reasoning menu button is gone. The same width problem caused the "accidentally wide" view.

**One smaller bug:** selecting an archived eavesdrop in the list (with "Show archived" ticked) un-archives it. That happens because the list's selection and "Listen in" share `select()`.

**Similar-looking rows.** Every row says "Cat assistant" and gives only a kind and a state. Chats have no shortcode at all, and the chats' assignments have no prompt to show either. Eavesdrops show only a raw shortcode like `002-000-plan`.

## Decisions (object at approval if wrong)

- **Markdown: yes, use a library.** `react-markdown` 10 with `remark-gfm` (tables, lists) and `remark-breaks` (a single newline becomes a line break, which keeps the agents' line breaks).
  - All three are MIT. `react-markdown` has 37M weekly downloads.
  - It builds React elements, not HTML strings, and ignores raw HTML by default. That matters because the text is LLM output.
  - I rejected `markdown-to-jsx`: it parses raw HTML unless you turn that off. I also rejected `marked` with DOMPurify, because it needs `dangerouslySetInnerHTML`. Writing our own parser is the wrong trade.
  - Run `npm audit` after installing, as usual.
- **Markdown safety and accessibility:**
  - **Images aren't rendered.** A remote image is the classic way a prompt injection leaks data through a URL. Each one is shown as its alt text.
  - Links get `rel="noopener noreferrer"` and `target="_blank"`. `react-markdown`'s default URL filter already drops `javascript:` links.
  - **Headings are moved down to `h4`.** The chat view's heading is an `h3`, so an agent's `# Title` would otherwise break the dialog's heading outline (ADR-027).
  - Tables scroll sideways inside their own box.
- **Streaming:** the markdown is re-parsed on every update, so it shows as markdown while it streams. Half-written markup, such as an unclosed `**`, shows as plain text until it closes. A `memo` component means only the entry being streamed is re-parsed. This applies to reasoning and response entries, and to user messages. The CLI is unchanged.
- **Tool calls:** a shared helper reads the key fields, and the full JSON goes in a disclosure.
  - `libs/tcp-shared/src/transcript/audit-renderers.ts` adds an optional `tool` field to `LogEntry`: `{ name, status?, content? }`. `name` comes from `payload.tool`. For a result, `status` and `content` come from the LangChain `ToolMessage` (`output.kwargs.status` and `.content`), or from `output` itself when it is a string. `text` stays the full JSON, so the CLI doesn't change.
  - The web transcript draws a small table for each tool entry:
    - **Request:** Tool name.
    - **Response:** Tool name, Status, Content.

    Row headers use `th scope="row"`, with a "Field | Value" header row as in your mock-up. Below it, a native `<details>` labelled "Full JSON" holds the existing `<pre>`.

  - I dropped the mock-up's "Input: See full JSON" row, because the "Full JSON" disclosure right below says the same thing.
- **The width fix is CSS:** use `minmax(0, 1fr)` for the view column, `min-inline-size: 0` on `.chat-view`, and `overflow-x: auto` on the `<pre>` and markdown tables. The new tool rendering makes wide content rare. This fix makes it harmless.
- **Chat list states come from assignments, not agents.** `ChatList` reads `useLiveAssignmentsList({ companyId })`, which returns every mode and every status (`AssignmentController.list` has no default status filter). It replaces `useLiveCompanyChatsList`.
  - Chat rows use their own assignment's status.
  - An eavesdrop's row looks up the assignment whose `agentId` matches.
  - "Finished" means the status isn't in `ACTIVE_ASSIGNMENT_STATUSES` (`api/statuses.ts`).
  - Activity ordering still uses `useActivityStamps` on the live agents list. That list only needs to see the changes, which it does. The fallback timestamp becomes the assignment's `updatedAt`.
  - The server route stays as it is. Its "active by default" behaviour is documented, and the office view relies on it.
- **Archive behaviour:** "Archive" on a chat completes it, so it moves under "Show archived". "Archive" on an eavesdrop hides it. Picking a row in the list no longer un-archives it; only "Listen in" from the office, the agent tray or the menu does. To do that, `ChatProvider` splits `select` (list) from `openChat` (opener).
- **Telling rows apart.** The first line stays the role. The second line becomes:
  - **Chat:** `Chat · started 10 Oct, 09:40 · Open`. The start time uses the assignment's `createdAt` and `Intl.DateTimeFormat`, and is the only thing that tells one chat from another.
  - **Listening in:** `Planning · Task 002 · Finished`. The mode label comes from the assignment, using the strings the task tray already uses. A third line, cut short with an ellipsis, gives the task title from `useLiveCompanyTasksList`. A consultee or other row without a task shows just the mode.
  - Each row's accessible name (`textValue`) becomes the role plus the second line, so arrowing through the list reads the difference out.
- **Tray spacing:** `.task-controls--icons` has no CSS, so its buttons sit flush, inside a `.tray-panel__actions` whose gap only spaces its direct children. The fix is `display: flex; flex-wrap: wrap; gap: var(--tcp-space-xs)`, plus `display: contents` so the Close-room extra joins the same row.
