# 000.00 — Model check SSRF fix

**Branch:** `04/000-00_model-check-ssrf-fix` off `phase-04`; PR targets `phase-04`.

## Context

`POST /api/model/check` connects to a `baseUrl` that the caller supplies. Any signed-in user can call it (`@NoCompanyScope`). That makes it a server-side request forgery (SSRF) route. The fix unblocks parity row 10 and model fit per job.

**Answering the prompt's question:** nothing calls this route today, apart from its e2e spec. It doesn't run before role, company or app config is changed, and LLM calls don't use it. The setup wizard's model test (`scripts/setup-wizard/test-config.ts`) runs its own probe inside tcp-agent, using env config.

**Wider risk found during planning:**

1. **Same SSRF through stored config.** Any signed-in user can `POST /api/company` and becomes its creator. They can then set `llmConfig.baseUrl` or `embeddingConfig.baseUrl`, on the company or on a role, to any address. tcp-server or tcp-agent calls that address on the next chat, agent run or knowledge upload.
2. **A stored API key can be leaked.** `CompanyDbService.setCompany` and `RoleDbService.setRole` deep-merge `llmConfig`. A PUT that changes only `baseUrl` keeps the stored `apiKey`, and the next call sends it as a Bearer header to the new host. Masking keys in responses doesn't stop this.
3. **Response as an oracle.** The probes swallow network errors today, so a real user can't tell a bad key from an incapable model. Step 4a makes errors actionable without reopening the oracle. Messages are fixed text, the destination is already allow-listed, and the route is admin-only.

Decisions confirmed with the user:

- Scope is the route **and** stored config.
- Policy is the provider catalogue plus an allow-list that the operator sets in env.
- Callers get errors that are generic but actionable. Each error is a fixed category with a hint that tells the user how to fix a genuine mistake, plus the HTTP status. The provider's response body and any resolved address are never echoed back. The raw error goes in the server log.

## Design

### 1. The `baseUrl` policy: a pure function in `@tcp/shared`

New file `libs/tcp-shared/src/llm/base-url-policy.ts`, next to `provider-catalogue.ts` (it uses `findProvider`). It is exported from the lib index.

```ts
/** Why `config` may not be used, or undefined when it may. */
export function refuseBaseUrl(
  config: Pick<LlmConfig, 'provider' | 'baseUrl'>,
  allowedHosts: readonly string[],
): string | undefined;
```

- The provider must be in the catalogue.
- With no `baseUrl`, the config passes. The catalogue default or the SDK default applies.
- A `baseUrl` must parse with `new URL`, use `http:` or `https:`, and carry no username or password.
- **`kind: 'remote'`:** the URL must match the template's `baseUrl` exactly. `{region}` and `{resource}` each match one DNS label (`[a-z0-9-]+`). A trailing `/` is allowed.
- **`kind: 'local' | 'custom'`:** `hostname`, lowercased, must be in `allowedHosts`.
- Refusal messages name the rule, never a resolved address.

There is deliberately no DNS or private-IP check. It would break local LM Studio, and DNS rebinding can get round it. The host allow-list is the control.

Spec: `base-url-policy.spec.ts`, a table of allowed and refused cases, including region and resource templates, userinfo, `file:` and an unlisted host.

### 2. Allow-list config (tcp-server)

- `config.schema.ts` gets `LLM_ALLOWED_HOSTS: Joi.string().allow('').default('')`, a comma-separated list.
- The effective list is that env list plus the hostnames of `LLM_BASE_URL` and `EMBEDDING_BASE_URL`. So `.env.dev` (`host.docker.internal`) works without any change.
- There are no other built-in defaults. `localhost` inside the container would reach tcp-server's own ports.
- Document it in `.env.example` next to `LLM_BASE_URL`. Add test hosts (stub-llm, `example.com` or similar) to `.env.testing`.

### 3. Enforce where configs are written: an injectable policy

`apps/backend/apps/tcp-server/src/db/llm-destination-policy.ts` (`LlmDestinationPolicy`, provided and exported by `DbModule`, with `mergeLlmConfig` beside it):

- It reads the list once from `ConfigService`.
- `assertAllowed(config, field: 'llmConfig' | 'embeddingConfig')` throws `BadRequestException` with the refusal reason.

It is called at the choke points, so every writer is covered, including template import:

- **`CompanyDbService.setCompany`:** check the **merged** `llmConfig` and `embeddingConfig`. Checking the merged result stops a PUT that changes only `provider` from slipping past.
- **`RoleDbService.setRole`:** check the merged `llmConfig`.
- **The key-leak fix**, in both merges: if the partial changes `baseUrl` or `provider` and carries no `apiKey`, drop the stored `apiKey`.

Rows already in the database are not re-checked. That only matters for dev data; note it in the PR.

### 4. The model check route

`apps/backend/apps/tcp-server/src/api/api.model.controller.ts`:

- Replace `@NoCompanyScope(...)` with `@AdminOnly()`.
- Before probing, run the policy on each model. A refused model returns `{ compatible: false, error: '<policy reason>' }` rather than a 400 for the whole batch, which keeps the per-model result shape.
- Error reporting is described in step 4a.

### 4a. Actionable errors in the model check

Today both probes `catch { return false }`, so a wrong key looks the same as "model can't call tools". The probes will return the error they caught, and `checkOne` will classify the first one.

New pure function `classifyProbeError(err, config)` in `src/model-check/probe-error.ts`, with a table spec. It returns `{ code, message }`. `ModelCompatibilityResult` gains `errorCode?: ProbeErrorCode`, and `error` keeps the message. The DTO changes too, so the web client schema is regenerated (006.04 will want `errorCode`).

It classifies by `status`, `name` and `constructor.name`. Those survive `@langchain/openai`'s `wrapOpenAIClientError`, which maps a timeout to `name: 'TimeoutError'` and sets `lc_error_code` on 401, 404 and 429.

| code                   | Signal                    | Message the caller sees (fixed text; `<host>`/`<model>` are the caller's own input)                                                                                                         |
| ---------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `unsupported_provider` | `findProvider` miss       | Unknown provider `<id>`. Use one of: `<catalogue ids>`.                                                                                                                                     |
| `destination_refused`  | policy refusal            | Policy reason. Local or custom: "ask an operator to add `<host>` to LLM_ALLOWED_HOSTS". Remote: "remote providers must use their catalogue URL; leave baseUrl empty".                       |
| `unreachable`          | `APIConnectionError`      | Couldn't connect to `<host>`. Check the server is running and that the base URL is right, including `/v1`. From inside Docker, the host machine is `host.docker.internal`, not `localhost`. |
| `timeout`              | `name === 'TimeoutError'` | `<host>` didn't answer within `<timeoutMs>` ms. A local model may still be loading, so try again or raise `timeoutMs`.                                                                      |
| `auth_rejected`        | 401                       | The provider rejected the API key. Check it's set and belongs to this provider (`<keysPageUrl>` if the catalogue has one).                                                                  |
| `forbidden`            | 403                       | The key isn't allowed to use this model or API. Check the key's permissions, project or region.                                                                                             |
| `model_not_found`      | 404                       | Model `<model>` wasn't found. Check the name (on Azure it is the deployment name), that the model is loaded (local), and that the base URL ends in `/v1`.                                   |
| `rate_limited`         | 429                       | Rate-limited or out of quota. Check the account's billing or credits, then retry.                                                                                                           |
| `provider_error`       | 5xx                       | The provider returned HTTP `<status>`. It's a provider-side fault, so retry later.                                                                                                          |
| `failed`               | anything else             | The check failed (HTTP `<status>` if present). Details are in the server log.                                                                                                               |

- **A 400 or 422 from a probe, or an `OutputParserException`, is a capability "no", not an error.** The model rejected `tools` or `response_format`, or answered in the wrong shape. That probe's flag is false and no `errorCode` is set, so an incapable model is not reported as broken.
- Each classified error is logged with `logger.warn`, including the raw message.
- Response bodies are never echoed. They would turn the route back into a reader of internal services.

## Tests

- **Shared:** the policy spec from step 1.
- **`probe-error.spec.ts`:** one row per code. Fake errors carry `status`, `name` and `constructor.name` as the wrapped SDK produces them. Assert that the message never contains a body string planted in the fake error.
- **`model-compatibility.service.spec.ts`:** a 400 on the tools probe gives `supportsTools: false` and no `errorCode`. A 401 gives `auth_rejected`.
- **`model.e2e-spec.ts`:**
  - Without a token: 401.
  - Non-admin: 403.
  - Admin (the identifier from `.env.testing`'s `TCP_ADMIN_IDENTIFIERS`): 201 with an empty list.
  - Admin with an unlisted host: the policy error appears per model.
  - The existing no-network test stays, run as admin.
- **Company and role e2e (or API tier):**
  - Refused `baseUrl`: 400.
  - Allowed host: 201.
  - A PUT changing only `baseUrl` clears the stored `apiKey`.
  - A PUT changing only `model` keeps it.
- **Fixtures:** `test/api/helpers/ApiHelper.ts:201` uses `http://example.com` with `lm-studio`, so add that host to the testing allow-list or change the fixture. Fixtures that pair `provider: 'openai'` with `STUB_LLM_URL` must switch to `openai-compatible`, because a remote provider is held to its catalogue URL. Grep `test/integration` and `test/e2e` for `baseUrl` that goes through HTTP routes; the `STUB_LLM_URL` host must be allowed.
