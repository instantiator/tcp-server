Company resources (001.02) are long-lived company documents — invoices, price lists, policies — kept in shared storage under `{slug}/resources/`. Agents read and change them; people can't see them in the web UI yet.

Please create a plan to add a third piece of furniture to the office's archive, beside the bookshelf (task outputs) and the filing cabinet (record tables), for the company's resources.

- Clicking it, or choosing it in the details picker, opens a tray.
- The tray shows a navigable tree of directories, rooted at the company's resources directory.
- Each directory links to that directory in the shared storage service, as the archive tray's task outputs do now (`taskOutputsUrl` in `src/api/storageLink.ts`).

What's there already, and what isn't:

- **The furniture is the easy part.** Since 001.03, the archive's selectable furniture comes from one map (`SELECTABLE_FURNITURE` in `scene/TcpCompanyScene.ts`). Follow how the filing cabinet was added: kind, tile, size, colour, description, `SelectionTarget` kind, picker entry, tray case.
- **The storage link only needs widening.** `taskOutputsUrl` builds a console link for one task's folder. The same confirmed format (a percent-encoded prefix) works for any folder. Without `storageConsoleUrl` and `storageBucket` configured, show the tree as plain text, as the archive tray does.
- **People have no route to list folders.** The only list route (`POST /internal/storage/list`) is internal, for agents. A company-scoped route for people is needed. It must list everything (`listAll`), not stop at the first 1,000 keys.
- **There is no tree component yet.** React Aria Components 1.20, already installed, has an accessible `Tree` whose items can be links.

Things the plan should consider:

- **Folder purposes.** A folder's purpose is the first line of its `README.md` (see `docs/shared-storage.md#folder-purposes`), as `list_resources` shows agents. Showing it beside each folder would help people too.
- **Live resources only.** Show live resources, not task drafts (`tasks/{id}/working/resources/…`), which aren't company resources until their task succeeds.
- **Files or folders only?** The tree is of directories. Decide whether files are listed too, or counted.
- **Restoring old versions.** Linking to the console also gives people version history and restore, since the bucket is versioned (001.02).
- **The later storage browser.** 002.05 plans a full in-app storage browser, including `resources/`. This is a small step towards it, not a replacement: keep the tree and the listing route reusable.

Accessibility is very important: the tree must work fully from the keyboard and with a screen reader, inside the office view's full screen too (portal into the view, as other trays do).
