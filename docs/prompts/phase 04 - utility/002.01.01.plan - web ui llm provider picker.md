## Context

A role's or company's model can only be set through the CLI as raw JSON. The role dialog shows it read-only. This plan adds one picker component, used in the role dialog and a new Admin → Language models section, for the company's chat model, the company's embedding model and each role's model. App-level defaults stay in env files for now.

### What exploration found

- **Catalogue:** `libs/tcp-shared/src/llm/provider-catalogue.ts` has no imports. It holds 10 providers (7 remote, LM Studio, Ollama, `openai-compatible`), each with `kind`, a `baseUrl` (which may contain `{region}`/`{resource}`), `fields`, a `keysPageUrl`, `chat.starterModel` and `embeddings.{starterModel,dimension}`. It also exports `findProvider` and `fillBaseUrl`. It is **not** exported from `@tcp/shared/client`, the only shared surface the frontend may import (ADR-022).
- **The setup wizard** is `scripts/setup-wizard/prompts/llm.ts`. It asks for the model as free text and lists no models. It does have three things the picker needs:
  - `isHostLocal`/`toDockerHost` (`scripts/setup-wizard/utils/docker-host.ts`, no imports);
  - the 32k advice for local models (`RECOMMENDED_LOCAL_CONTEXT_WINDOW`, `libs/tcp-shared/src/config/defaults.ts:205`, which has no imports);
  - the embedding-width rules (`MAX_EMBEDDING_DIMENSION`).
- **Live model listing** happens only at run time, on the agent (`libs/tcp-shared/src/llm/model-readiness.ts:34`, `GET {baseUrl}/models`).
- **DTOs:** `LlmConfigDto` is `{provider, model, baseUrl?, apiKey?, contextWindow?, timeoutMs?}`, and the same class is used for embeddings.
  - `UpdateRoleDto.llmConfig` accepts `null`.
  - `UpdateCompanyDto.llmConfig` and `.embeddingConfig` do not.
- **Merging (`llm-destination-policy.ts:62`):** `mergeLlmConfig` keeps the stored key unless the provider or base URL changes. **Company `embeddingConfig` is replaced whole and not merged**, so saving it without `apiKey` would drop the key.
- **The base URL policy:** a remote provider's URL must match its template. A local or custom host must be in `LLM_ALLOWED_HOSTS` or be the host of the env `LLM_BASE_URL`/`EMBEDDING_BASE_URL`.
- **Fallback:** role, then company, then env, and the whole object is taken from the first level that has one (`resolve-llm-config.ts`). Embeddings go company, then env.
- **App default:** env only, and **no route exposes it**.
- **No model anywhere:** the agent fails the run (`no_llm_config`) and chat answers 404. Nothing warns when the role is saved. Embeddings already have a warning (`computeEmbeddingConfigWarning`, `validation-warnings.ts:80`).
- **The embedding width is fixed per deployment:** `EMBEDDING_DIMENSION` sizes the pgvector columns.
- **Changing a company's embedding model does not reindex.** Old vectors and new queries then come from different models, and search quietly returns junk.
- **Frontend:**
  - `RoleDialog.tsx:262-285,406-419` is the read-only model section.
  - `admin-sections.ts` plus the ternary chain in `AdminPanel.tsx:56-67`: a new section needs its own branch.
  - `TextField` has no `type`, so there is no password field.
  - There is no `ComboBox` in the app. RAC `^1.20` has one. The only `Select` is `DetailsPicker.tsx:131-160`.
  - There is no company-update hook, though `PUT /api/company/{id}` exists.
  - Tool footprint has a route (`GET /api/company/{companyId}/roles/by-slug/{slug}/tool-footprint`, one mode per call) and no hook.

### Decisions agreed with you (2026-10-16)

- **Model suggestions:**
  - a short curated list per provider, kept in the catalogue;
  - for local and custom providers, a live list from that server through a new route behind the base URL policy;
  - the model field always takes free text.
- **App default:** a read-only `GET /api/system/llm-defaults` with no key and no base URL. Editing stays in the env files and goes to outstanding work.
- **Embedding change:** the server reindexes the company when its embedding provider, model or base URL changes. The picker says so before saving.
- **Embedded, not a dialog:** the picker is a form section that its host saves. That lets the role dialog save model and details in one action.

### Challenges to the prompt (UX), adopted in the design

1. **"(none)" says where it falls back to.** The first option reads "Use the company's model (LM Studio · gemma)", "Use the app default (OpenAI · gpt-5-mini)", or "None: no app default is set". A bare "(none)" hides what will actually run.
2. **A remote provider's base URL is shown, not edited.** The server refuses any URL that doesn't match the template, so an edit box could only produce a 400. Region and resource get their own fields, and the URL is built from them (`fillBaseUrl`). Local and custom URLs stay editable. That still allows "modify all details" wherever the server allows it.
3. **The API key is never shown.** It is a password field with one of these hints:
   - "A key is saved. Leave blank to keep it."
   - "Changing the provider or address drops the saved key. Enter a new one." (the merge rule, said up front)
   - "Optional for local servers."
   - There is also a "Get a key" link to `keysPageUrl`.
4. **Embedding suggestions are filtered to the deployment's width.** If the model's known width differs, an inline error blocks saving, since that model can't be indexed.
5. **Context advice is a budget, not just a number.** In the role dialog it reads "Tools take about 5,800 tokens a turn; 8,192 leaves about 2,400 for the conversation", using the role's tool footprint. Below 32k for a local model, it repeats the wizard's advice.
6. **A local address is caught on Save, not on blur.** The `ConfirmDialog` offers "Use host.docker.internal" or "Keep as typed", as the prompt asks.
7. **No "Test connection" button yet.** `POST /api/model/check` is admin-only and needs the raw key. A by-reference check belongs to 006.04, so it is carried forward there.

  - `embeddings.models: readonly { id: string; dimension: number; note?: string }[]`;

### Frontend

**Hooks** (`endpoints.ts`, re-exported from `hooks.ts`):

- `useUpdateCompany()`, which invalidates `['company']` and returns warnings, as `useUpdateRole` does;
- `useLlmDefaults()`;
- `useLocalModels(companyId, { provider, baseUrl, apiKey?, keyFrom? } | null)`, a query that is disabled when the argument is null, has `retry: false`, and whose key holds no `apiKey`;
- `useToolFootprint(companyId, slug, mode)`.

**`components/LlmConfigPicker/`** (one folder):

- **`llmDraft.ts`: pure logic, unit-tested.**
  - `type LlmDraft = { choice: 'inherit' | string /* provider id */; region; resource; baseUrl; model; apiKey /* typed only */; contextWindow; timeoutSeconds }`.
  - `draftOf(saved: LlmConfig | null)`.
  - `patchOf(draft, saved): LlmConfig | null | undefined`:
    - `undefined` means unchanged;
    - `null` means inherit;
    - otherwise it returns the **whole** config;
    - `apiKey` is included only when typed;
    - it never includes `'***'`.
  - `keyState(draft, saved): 'saved' | 'dropped' | 'none'`.
  - `validate(draft, purpose, dimension)` returns field errors.
- **`LlmConfigPicker.tsx` props:**
  - `purpose: 'chat' | 'embedding'`;
  - `draft` and `onChange`;
  - `saved` (masked, for `keyState`);
  - `fallback: { label: string; config: { provider; model } | null }`;
  - `companyId`;
  - `keyFrom` (for live listing);
  - `footprint?: number`;
  - `embeddingDimension?: number`;
  - `errors`.
  - The host owns save, so the picker has no Save button.
- **`LlmConfigPicker.tsx` fields:**
  1. **Provider:** a RAC `Select` with sections Remote / Local / Custom. The first item is the inherit option, labelled as in challenge 1. For `purpose: 'embedding'`, the list shows only providers that have `embeddings`, plus custom.
  2. **Region / Resource:** text fields, shown when `fields` asks for them.
  3. **Base URL:** read-only text for remote providers, and a `TextField` for local and custom ones (prefilled from the template).
  4. **Model:** a RAC `ComboBox` with `allowsCustomValue`. Its items are the curated list plus the live list, deduplicated, with each item's note as its description. A "Refresh models" button sits beside it for local and custom providers. A listing failure is a hint ("Couldn't list models from this server: …"), not an error.
  5. **API key:** `TextField` gains a `type` prop, used here as `type="password"`, with the hints from challenge 3.
  6. **Context window (chat only)** and **Timeout (seconds)**: numeric `TextField`s, as `RetentionDialog` handles days. The hint gives the budget from challenge 5.
  7. **Embedding:** a read-only line "This deployment stores N-wide vectors", and the width error from challenge 4.
  - Choosing a provider fills the model with its starter (unless the model was typed), the base URL, and the context window (from the curated entry, if known).
- **`useLocalAddressCheck()`:** a small hook plus a `ConfirmDialog`, used by both hosts on Save. If `isHostLocal(baseUrl)`, it asks; "Use host.docker.internal" rewrites with `toDockerHost` and then saves.

**Role dialog** (`RoleDialog.tsx`):

- The read-only section and `admin.role.llm.later` are replaced by the picker.
- The fallback label comes from the company's model, else `useLlmDefaults().chat`, else "None".
- `patchOf` feeds `changes`, so one Save covers both details and model.
- The footprint is the largest total across modes for a saved role. For a new role there is no footprint, and the hint says it appears after saving.
- The "Use the company's model" button goes: choosing the inherit option does the same thing.

**Admin → Language models** (`admin/LanguageModelsAdmin.tsx`, section id `models`, inserted after Roles):

- It has two headed pickers, "Chat model" and "Embedding model". Their fallback is the app default from `useLlmDefaults()`.
- One Save sends `{ llmConfig?, embeddingConfig? }` through `useUpdateCompany`. Before sending, it goes through these checks in order:
  1. the local-address check;
  2. **no-model confirm:** if the chat patch is `null`, the app has no default, and some roles have no own model, a `ConfirmDialog` asks "N roles will have no model: a, b. Their tasks will fail. Save anyway?";
  3. **reindex confirm:** if the embedding patch changes provider, model or base URL, a `ConfirmDialog` asks "Knowledge will be re-indexed with the new model. Search may be incomplete until it finishes."
- Server warnings appear as plain text, as in the role dialog, and success is announced on a new `models` channel.

**Roles table** (`RolesAdmin.tsx`): a text marker "No model" beside a role that resolves no model, as "Default planner" is shown. This makes the error case visible after the fact.

**Strings:** all of the above go in `strings.ts` under `llm.*` and `admin.models.*`. Remove `admin.role.llm.later`.

### Security notes

- **The live-listing route makes the server fetch a caller-chosen URL.** It is held to the same `LlmDestinationPolicy` as saving, limited to local and custom providers, company-scoped, and has a 5 s timeout. It returns model ids only. The stored key is used only for the same provider and URL it was saved with, so the route can't send a key to a new host.
- **The defaults route** returns provider and model names only, with no key and no URL. It needs a signed-in user.
- **`apiKey`** is sent only when typed, and `'***'` never leaves the browser. The embedding merge fix closes a silent key-loss bug.
- **Any company member can still change the company's models.** Permission flags are deferred, as in 002.00.
