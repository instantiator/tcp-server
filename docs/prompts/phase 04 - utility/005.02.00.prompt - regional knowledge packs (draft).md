## Templates (from 002.03)

- The 14 GOV.UK documents in `templates/cottage-industry` (3 shared, 4 for the bookkeeper, 7 for the regulations adviser) become the first UK pack. Each already has `source`, `license`, `attribution` and `retrieved` in its front matter. `templates/cottage-industry/SOURCES.md` lists them.
- Add a review-by date to each document's front matter. Check that the OKF validator accepts the new key.
- Settle how a pack relates to a template. Either the template contains a copy, as now, or it names the pack and the importer fetches it. If a pack is separate, add it to the format (v2, planned in 005.04). A format change means bumping `formatVersion` (to 2 or higher). v1 refuses unknown keys, so an older server will refuse the new template with its "made by a newer version of TCP" message, which is the right result. The new code must still read version 1.
- Cover the gaps `SOURCES.md` lists. Candles and wax melts have no open-licence labelling checklist. Postage prices are not knowledge, so they belong in a `postage` records table. The unfair commercial practices guidance (CMA207, drip pricing and fake reviews) was left out of v1 and is worth a look here.
- The format is documented in `templates/blank/README.md`, which travels inside every blank download. Update it in the same change, so it never lags behind the code.

## Document handling (deferred from 002.03)

[002.03](002.03.01.plan%20-%20company%20template%20format%20v1%20with%20import%20and%20export.md) deferred two improvements to how knowledge documents are handled. They belong here.

- When creating the OKF version of a document, generate the OKF's summary information with an LLM if an application, company or role default model is available. (At the time of 002.03 none is.)
- When a document's licence is unknown and an LLM is available, use it to search the document for information about its licence.

**What 002.03 already did.**

- `license`, `source` and `attribution` are stored in the document's OKF front matter.
- They are set on upload: API fields, and CLI `--license`, `--source-url` and `--attribution`.
- The knowledge list returns them, and the CLI and web lists show them.
- Export writes them to `LICENSES.md`.
- Knowledge has no database table, so the licence lives in front matter, and a recorded ceiling applies: one read per document per listing. Move to a column if a listing gets slow.
