At current time, the web UI doesn't have comprehensive ways to manage roles, knowledge, or company users.

Create a plan to implement the missing functionality outlined here.

Challenge any part of the plan before starting to ensure we develop the best user experience.

## Roles

Key aspects of a role are: its role prompt, the LLM configuration (optional - if not provided, falls back on the company config, if not provided falls back on the app-level config), the MCP server list for the role.

- Create a role
- Edit a role
- Delete a role

## Knowledge

Roles and companies can hold knowledge. Company knowledge is shared between all roles, and then roles have their own specialist knowledge. So, for both company role, we'll need to implement:

- List knowledge
- Upload knowledge
- Delete knowlege
- Reindex knowledge
- Get knowledge status
- Query knowledge (this is a means for the user to test the knowledge contained by the company / role - it should retrieve chunks, and render them as words, but shouldn't pass through an LLM (so as to avoid accidental injection of outside knowledge))

## Company users

For now:

- List company users
- Show user companies (within the user's personal information)

At a future date, we'll explore add/remove users to and from companies.

## UI

The above should be implemented as components with launching points in a company administration tab, labelled 'Admin'.

Admin should use a menu (left) / main layout - with options in the menu:

- Roles
  - Shows a filterable/sortable table of roles, with an 'Add role' button, and selectable rows (and a delete button)
    - Delete button has a confirmation dialog before permitting a delete
      - Deletion of a role also deletes role knowledge
      - If the company default planner role is being deleted, warn the user about this in the dialog, too
    - Opening a role / adding a role opens a dialog showing details of the current role (or defaults)
      - There's an open button in the row, or clicking the role name will do it
    - Dialog has a tab for knowledge
      - There's a table of all knowledge entries
      - Files can be uploaded / deleted
      - There's a re-index button (disabled until the role exists / all knowledge has been uploaded)
      - A refresh button updates an indicator of the current knowledge status
      - Query knowledge - there's a query box below the knowledge table
        - Input for the query, and query button
        - Below that is a table of all findings from the query
- Users
  - Shows a table of users associated with the company
- Knowledge
  - Re-use the same component as created for the role knowledge management in the dialog described above
- Data protection
  - Shift data protection into here - it's a part of company admin

Use small round buttons with appropriate icons, and tooltips with accessibility features wherever possible.
