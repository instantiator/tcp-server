## Context

Every MCP server reaches every role, and the six servers' tool schemas cost about 5,600 tokens a turn. That fills an 8k window. Nothing lets a company or role leave a server out, and `estimate-context-window` ignores tool schemas, so it can't warn anyone.

### What exists (from exploration)

- `resolveMcpServerList(registryNames, company, role)` (`libs/tcp-shared/src/mcp/resolve-mcp-server-list.ts`) returns the union of the configured servers and the company's and role's `mcpServerList` extras. It's used by tcp-agent's `RunEnvironmentService.serverNames` and tcp-server's `ChatTurnEnvironmentService`.
- `ContextBudgetService.countTools(tools)` already counts bound tool schemas the way the model sees them (`convertToOpenAITool`). The run-time budget uses it; the CLI estimator (`tcp-cli/src/lib/context/estimate-context-window.action.ts`) doesn't.
- The CLI runs on the host and can't reach MCP servers, which are internal-only. tcp-server can: it already loads tools for chat turns with `McpClientService`.
- Soft warnings go in the `X-Tcp-Warnings` header (`computeCompanyWarnings`/`computeRoleWarnings` in `api/validation-warnings.ts`), and the CLI prints them.
- Done outside the code: gemma-4-e4b reloaded in LM Studio with a 32,768-token window (`lms load -c 32768`), and `.env.dev` now has `LLM_CONTEXT_WINDOW=32768`. The user still needs to set LM Studio's saved default for the model, or a reload on demand falls back to 8,192.

### Decisions agreed with the user (2026-10-11)

- Every server can be switched off. Servers are on unless switched off.
- A toggle map on company and role: role over company, company over default.

### Decisions made in this plan (object if wrong)

- **Field:** `mcpServerToggles: Record<string, boolean> | null` (jsonb, nullable) on `tcp_company` and `tcp_role`. One tcp-server migration.
- **Validation:** keys must be names in `MCP_REGISTRY` and values must be booleans. Anything else is a 400 that lists the server names.
- **Resolution happens inside `resolveMcpServerList`**, after the union, so tcp-agent, chat turns and the estimator all agree: `role?.[name] ?? company?.[name] ?? true`.
- **Switching off `tasks` warns but isn't refused.** The warning says a role can't finish an assignment without the tasks server. It applies wherever the switch-off takes effect (a company toggle, or a role toggle).
- **Tool footprint route:** `GET /api/company/:id/roles/:roleId/tool-footprint?mode=<mode>` (default `implement`), scoped with `@CompanyScope`. It resolves the servers exactly as tcp-agent does (`resolveMcpServerList` → `serverNamesForMode`), loads their tools (an unreachable server is reported, not fatal), drops what `filterToolsForMode` drops, and counts with `countTools`. It returns `{ mode, servers: [{ name, tools, tokens } | { name, error }], total }`.
  - ponytail: it counts `memory` even when the role has no knowledge, while tcp-agent drops it then. So the estimate is a worst case; say so in the output.
- **CLI:** `estimate-context-window` gets a `tools` line from that route in live mode, plus `--mode <mode>`. With `--from-file` it takes `--tool-tokens <n>`, and prints that tools weren't counted when none is given.
