## Context

Feedback on 000.06 (`000.06.02.feedback - ui.md`):

1. A task room goes dark between assignments, because a room is lit only while a running agent's avatar stands in it. It should stay lit while the task is active.
2. The office tray needs a new layout, shared by every tray: a title bar with the close button, a fixed section of icon actions and a description that can be expanded, a scrolling body, and Follow at the bottom right. The task tray's body becomes a compact list of assignments, each with a status icon and a button to listen in.

Frontend paths below are under `apps/frontend/tcp-frontend/src/visualisation/isometric/company/` unless they start with `components/`.

## Decisions (object at approval if wrong)

- **Lighting.** A task room is lit when its whiteboard is: the task is `planning`, `in-progress` or `finalising`, and not paused. This reuses `litBoards` in `rules/roomLighting.ts`. A paused task's room goes dark, the same as its board. One-to-one rooms keep the avatar rule.
- **One shared tray layout, `ui/TrayPanel.tsx`, replacing `TrayHeading.tsx`.** Props: `headingId`, `heading`, `icon?`, `actions?`, `description?` and `children` (the body). It renders:
  - a title bar: `h2` (with the icon), with room left for the close button;
  - a fixed section: the action buttons, then the description;
  - the body, which scrolls.

  The tray keeps Close and Follow and positions them with CSS. Close sits in the title bar. Follow moves to the bottom right, as a floating round button (same `Crosshair` ToggleButton). The `headingAction` prop is removed from all four `*Details`. The DOM order stays heading → actions → description → body → Follow → Close.

- **Layout with plain CSS, no JS.** The `aside` becomes a flex column with `overflow: hidden`. The description is `flex: 0 1 auto; min-block-size: 0; overflow: auto`. The body is `flex: 1 1 0; overflow: auto`, so it gets whatever space is left. An expanded description can take all the space and then scrolls, as asked.
- **Description control: a new `variant="icon"` on `components/ExpandableText`.** Collapsed, it shows the excerpt followed by a small `ChevronDown` icon button. Expanded, it shows the full text with a `ChevronUp` button that is `position: sticky; inset-block-end: 0`, so it stays visible. It keeps the existing `aria-expanded`/`aria-controls`, and its labels say what it reveals.
- **Task actions as icons: an `icons` prop on `components/TaskDialog/TaskControls.tsx`.** The five controls become one list of `{ id, icon, label, onPress, isDisabled, outline }`, drawn as text `Button`s (the task dialog, unchanged) or as `RoundIconButton`s (the tray).
  - Icons: Start `Play`, Resume `Play`, Pause `Pause`, Cancel `Square` (outline), Edit `Pencil`.
  - Icon labels name the task ("Pause task 002"), per WCAG 2.4.6.
  - **"Retry" isn't a separate action.** There's no retry route for a failed task. Resume already covers the waiting kinds that are retries: rate-limited, spend cap, restart.
  - The focus fallback stays as it is.
  - "Close room" becomes a `DoorClosed` icon action in the same row. The outputs link goes at the top of the body.
- **Status icons: a new `ui/statusIcon.ts` map.** Task and assignment statuses map to lucide icons:
  - ready: `Hourglass`
  - planning, in-progress, in-qa, finalising: `CirclePlay`
  - paused: `CirclePause`
  - succeeded: `CircleCheck`
  - failed: `CircleX`
  - cancelled: `Ban`

  The icon is `role="img"` with the status label as its name. In the heading it reads as "In progress, Task 002". The visible status text is dropped, as in the mock-up.

- **Assignment list.** It replaces the "In progress"/"Completed" sections with one `h3` "Assignments" and one `<ol>` in creation order (`value` keeps the numbers). Each `li` is a three-column CSS grid:
  1. The status icon, aligned to the top.
  2. The mode (e.g. "Planning") in bold on the first line. On the second line, a native `<details>`: its `<summary>` is the role name followed by a `ChevronRight` icon (rotated when open), plus visually hidden text "— description of assignment {n}". The body is the assignment's prompt. This is the same `<details>` pattern as the transcript's reasoning entries.
  3. **Listen in:** a `RoundIconButton` with the `Ear` icon, the same icon the chat list uses for listening in. It is filled while the assignment is `in-progress` or `in-qa`, outlined once it is finished and has an agent, and absent when the assignment is `ready` or has no agent. It calls `useListenIn` with `{ id: agentId, roleId, assignmentId }`. Its label is "Listen in to {role}, assignment {n}".

  The `AssignmentInfo` tooltip button is removed.

- **The other trays move to `TrayPanel`**, keeping what they show:
  - **Role:** "Chat with" becomes a `MessageCircle` icon action. `RoundIconButton` gains `isPending` for this, passed through to RAC. The description is the role's description.
  - **Agent:** "Listen in" becomes an `Ear` icon action. The description is the assignment's prompt (`variant="icon"`). The body is the status `dl`.
  - **Archive:** no actions and no description. The body is its list.
  - The loading and gone states render through `TrayPanel` with the generic heading.
