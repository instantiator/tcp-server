Prepare a plan to implement simple memory management features, and improve how memory is used by agents:

- Users should be able to view the memories stored for a role.
- Users should be able to delete individual memories stored for a role.
- Users should be able to modify memories stored for a role.

The plan should include web UI (ie. when editing role) and CLI tools to list and manage memories for a role.

Show the items as a table, with an indicator if the data has changed so the user can choose to refresh the table. This pattern is already in the code base for other tables.

For roles with no memories, show an empty state indicator, eg. "This role has no memories yet"

We noted that an agent only gets access to the memory server if it also has indexed knowledge (see: `run-environment.service.ts`:190). The plan should include modifications to make memory available to all agents.

Add a succinct prompt nudge to ensure that agents decide to use the memory system. Something like these. Devise wording that's most likely to ensure the agent will choose to record memories for relevant, useful, information.

Assignments:

> If you learn anything that would help you perform the same task in future, or make a mistake and learn the correction, store it as a succinct memory with the `remember` tool.

Chat:

> If the user gives you new information, and it's relevant to your role, store it as a succinct memory with the `remember` tool.

Propose an approach to ensuring that memories surface when the agent is tasked with or has reasoned about things that are relevant to them:

- eg. indicate to the agent "You have N related memories. Retrieve them using the `remember` tool."
- eg. inject whole, relevant memories into the prompt when appropriate

Challenge any part of this prompt while planning.
