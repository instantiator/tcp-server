## Context

The chat dialog stacks one block per conversation, and each block has its own controls. It's hard to read and it opens one stream per block. The prompt asks for a conventional chat layout instead: a fixed title bar, a searchable list of views on the left, and one transcript on the right with its own fixed heading, a follow button and a send bar. Reasoning entries become accordions, under a rule the user chooses. Every non-confirmation dialog can be minimised or closed, through one shared dialog component.

### What the code does today (from exploration)

Frontend paths are under `apps/frontend/tcp-frontend/src/`.

- **Shared dialog.** One shared dialog already exists: `components/Dialog/Dialog.tsx`, built on RAC `ModalOverlay > Modal > Dialog`. It has a `heading`, `onMinimise?`, `hideClose`, and `actions`. Minimising unmounts the dialog. Only the chat dialog minimises. There is no confirmation component: `TaskDialog/TaskControls.tsx:174-200` builds one by hand.
- **Dock.** `components/Dialog/DockProvider.tsx` and `useDock.ts` provide `minimise`, `restore`, `remove` and `focusEntry`. Only `ChatProvider.tsx:115-138` uses them, with one entry per conversation.
- **Chat state.** `ChatProvider` holds `conversations[]` in React state. Nothing is in the URL or in storage. The openers are Activity → Chats (`pages/CompanyPage/activity/ChatsList.tsx`), `useListenIn.ts` (`readOnly: true`), and `AddNewMenu` (`inChat`).
- **What "archive" means today.** The archive button is **Complete** (`useCompleteChat` → `POST /api/agent/:id/complete`, 409 mid-turn). No archived flag exists anywhere.
- **Delete.** `DELETE /api/agent/:id` exists, but it only deletes the agent row. The assignment's FK is `SET NULL` and audit rows are `SET NULL`, so the chat assignment and its transcript would be orphaned. No frontend hook calls it.
- **Search.** Nothing searches transcript text. `AuditEvent.payload` is jsonb with no text index (`audit/audit.service.ts`).
- **Transcript.** `components/Transcript/Transcript.tsx` renders an `<ol>`, and `useTranscript.ts` primes from history and then streams. It doesn't auto-scroll. Reasoning is a plain `<li>`, not collapsible. Announcements happen on arrival only (`ANNOUNCE_RESPONSE_BODY = false`). `TaskDialog` uses the same `Transcript`.
- **Ordering signal.** List rows have `updatedAt`, but live cache patches don't update it (`events/cache.ts` has no `updatedAt` handling and no delete handling; see memory "Live agent rows carry no summary").
- **Icons and storage.** Icons come from `lucide-react` (`Archive`, `Minus`, `Plus`, `X` are already used), wrapped by `RoundIconButton` and `WithTooltip`. The only use of `localStorage` is `theme/storage.ts`, which is the pattern to copy (every access in a try/catch, validate on read).

### Decisions agreed with the user (2026-10-10)

- **Eavesdrops are kept in browser storage**, keyed by user and company. Role chats come from the server. A role chat counts as archived once it's completed.
- **Search uses a backend route** over audit payload text.
- **Every non-confirmation dialog gets Minimise and Close.** This reverses 008.03's decision that the task dialog never docks, so ADR-026 gets an amendment and the memory note is retired.
- **The list has three groups:** Chats, Running, Finished (eavesdrops split by agent state). Each group is newest first.
- **Escape closes the chat dialog**, as it does every other dialog.

### Decisions made in this plan (object at approval if wrong)

- **Keep the name `Dialog`; don't introduce `TcpDialog`.** It is already the single shared component, and the prompt allows adapting it. Renaming nine call sites gains nothing.
- **Minimise works the same way everywhere, through `useMinimisable`.** The new hook `components/Dialog/useMinimisable.ts` takes `{ id, label }` and returns `{ isOpen, minimise, restore }`. The dialog's owner stays mounted and passes `isOpen` to `Dialog`. The RAC modal unmounts its children, so streams are still released, and any state held by the owner (a create-task draft, say) survives. Where a dialog keeps its form state _inside_ the modal body, that state moves up into the owner component.
- **`ConfirmDialog` is a new component**, `components/Dialog/ConfirmDialog.tsx`.
  - It is RAC `role="alertdialog"`, with a heading, a message, and **Yes/No** buttons whose labels the caller can change. It has no minimise or close button.
  - Escape means No, which is the WAI-ARIA alertdialog convention.
  - Focus starts on **No** for a destructive action.
  - `TaskControls`' cancel confirmation and the chat delete both use it.
- **Archive (role chat) = Complete.** For an eavesdrop, archive only sets the stored flag; it never stops the agent. Selecting an archived eavesdrop un-archives it, as the sketch asks. Archived items are hidden unless "Show archived" is ticked; it is unticked by default.
- **Delete is a new route: `DELETE /api/agent/:id/chat`.** It refuses a non-chat with 400, and refuses with 409 while a turn is running, matching Complete. Otherwise it deletes the agent's and the assignment's audit rows and then the assignment, which cascades to the agent, and closes the agent's SSE subject. It returns 204. The existing `DELETE /api/agent/:id` is left alone, because the CLI uses it.
- **Search is a new route: `GET /api/agent/search?companyId&q`**, returning `{ agentIds: string[] }`.
  - It is `@CompanyScope` from the query.
  - `q` is 2–200 characters (class-validator).
  - It runs `LOWER(CAST(payload AS TEXT)) LIKE :pattern ESCAPE '\'`, with `%`, `_` and `\` escaped, scoped to the company, and returns at most 200 distinct agentIds. The SQL is portable across Postgres and SQLite.
  - The client debounces it by 300 ms. A row matches when its title matches **or** its agentId is in the result.
  - **Ceiling:** it's a full scan per company. A `pg_trgm`/tsvector index can be added when a search takes more than about 500 ms.
- **Order without jumps.** Each view's activity time is `max(row.updatedAt, local stamp)`. The local stamp is set when the cache applies a status change for that agent: a user message moves it to running, and a finished turn moves it to idle. That is exactly the cadence the prompt asks for. Reasoning deltas and tool steps inside a turn never re-sort the list. `ponytail:` a tool call finishing mid-turn doesn't bump it; add that if users ask.
- **Only the selected view's transcript is mounted**, so the dialog uses one stream instead of N. This sits within the 008.02 stream-budget rules.
- **A single dock entry** labelled "Chats". The `ChatDockLabel` per conversation is removed.
- **The `useChat` API stays the same shape.** `openChat(conversation)` now selects that view: an eavesdrop (`readOnly`) is added to the stored list, and a role chat is just selected. `closeChat` is removed. Its callers (the per-panel X) disappear, and "forget an eavesdrop" becomes archive. `startChat` creates a chat and selects it, as now.
- **The dialog can open with nothing selected.** The right pane then shows an empty state: "Choose a chat, or start one with +".
- **Reasoning rule:** `all | none | latest`. The default is `latest`. It is a per-viewer setting in `localStorage` (`tcp.transcript.reasoning`, the `theme/storage.ts` pattern) and is shared by every transcript, including the task dialog's.
  - The control is a small `Brain` icon `MenuTrigger` in the transcript heading, with a single-selection menu of the three rules ("Show all reasoning", "Hide all reasoning", "Show latest reasoning only").
  - Each reasoning entry is a native `<details>/<summary>` ("Reasoning, 10:42:31"), controlled through `open` and `onToggle`. The user's per-entry choices are held in a map that is cleared whenever the rule changes.
  - The task dialog's transcript gets the same control.
- **Follow:** a `RoundIconButton` with a toggle (`aria-pressed`) and the `ArrowDownToLine` icon, labelled "Follow latest". It is on by default.
  - On a new entry while following, scroll to the bottom.
  - A `scroll` event that leaves the view more than 24 px from the bottom turns it off. The programmatic scroll always lands at the bottom, so it never turns itself off.
  - Turning it on scrolls to the bottom.
- **Layout.** The dialog grows to `min(64rem, 100vw - 2rem)` and to the viewport's full height minus the gutters. The title bar, the list's search box and footer, the transcript heading and the send bar are fixed, and the list and the transcript scroll. Below `40rem` wide, the panes stack: the list sits above, capped at `30vh`.
- **Accessibility order and semantics.** The DOM order is the order of reading and tabbing:
  1. The title bar.
  2. The list pane, a `<section>` labelled "Chats list": a RAC `SearchField`, then a RAC `ListBox` with single selection and three `Section`s with `Header`s (Chats, Running, Finished), then the "Show archived" `Checkbox`, then the `+` menu.
  3. The transcript pane, a `<section aria-labelledby>` its `h3`: the heading row (archive, delete and reasoning controls), then the transcript `ol`, then Follow, then the message form.

  Each row's accessible name is its text: role, kind and reference, and state, e.g. "Cat assistant, Listening in, Task 001 assignment 004, Running". The icon is `aria-hidden`.

  Selecting a row (Enter or click) keeps focus in the list, so the user can browse. A list change re-sorts without moving focus, because RAC keeps focus by key. Announcements stay arrival-only, and only the selected transcript announces. Search results are announced through `useListChangeAnnouncement` ("{n} chats match"). Delete and archive move focus to the list.

- **`+` menu** (`AddNewMenu` `inChat`): it gains two submenus, **Chat with a role** (the current role list; always starts a new chat) and **Listen in on an assignment** (the company's running assignments that have an agent, from `useLiveAssignmentsList`). Each submenu selects the view it creates.
