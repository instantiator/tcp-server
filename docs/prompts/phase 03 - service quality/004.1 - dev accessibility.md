## Prompt history rationalisation

The prompt history is a pretty good record of everything we composed, however...

The prompts are in chronological order (good) and should remain so. Renumber the prompts and use three-part numbering for every prompt, as `xxx.xx.xx`:

- increment the first digit (eg. `001.*.*`) when the the major theme of work changes
- increment the second digit (eg. `*.1.*`) when a sub theme or related topic or a small unrelated side-mission changes
- use the third digit (eg. `*.*.x`) to show progress over time (eg. prompts and plans, in the order they were implemented)

Where a digit wasn't provided before, that can be `0`, eg. `001.1` becomes `001.01.00`

This will leave the docs numbered chronologically (good), but not clearly as "prompt" / "plan" - it would be good to be able to see which are which at a glance (ie. by filename).

Please iterated through each doc, determine its origin/purpose and rename as:

- `xxx.x.x.prompt` for user prompts
- `xxx.x.x.plan` for implementation plans

Where a prompt exists without a related plan, this is very likely because the prompt was used directly for an implementation (and likely wasn't considered sufficiently complex to warrant a planning phase). That's ok. Add a short note near the top of the prompt, something like:

```md
> [!NOTE]
> Implemented without a planning phase.
```
