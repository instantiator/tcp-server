[Strands](https://strandsagents.com/) is posited as an alternative to [LangGraph](https://www.langchain.com/langgraph).

There are some fundamental differences in their approach to the agent loop. It's not yet clear how well Strands works with local agents, and small models or models with small contexts. (In fairness, there's only limited information about how well LangGraph does - but it seems sufficient for the basic tests we've been running with 'chicken assistant' and 'cat assistant'.)

We've built lcp-agent to use LangGraph, but there may be some advantages to working with Strands.

Please evaluate the differences in the light of how we currently work with LLMs, and what the agent loop does, in the lcp-agent application. Please make a recommendation between these options:

1. continue with LangGraph
2. switch to Strands
3. offer both by configuration (by precedence: role, company, config, defaults)
4. use both, identifying different uses that play to their strengths in the application
5. your recommendation, if not covered by the above

For each option, present:

- a comparative level of complexity
- how well the option meets our criteria
- what the top level changes would be (bullet points)
- what the top level impact would be (bullet points)

Criteria to consider:

- **Correctness.** ie. the agents that run are likely to do as expected, able to reason about their tasks, able to select appropriate courses of action (eg. can consult with each other, make user queries, review and request information from their role-based and company-based RAG stores, read and write shared storage) to complete their task.
- **Efficiency.** ie. the agents are likely to work sufficiently well with smaller models and smaller contexts.
- **Simplicity.** ie. the code should be easily readable for new developers, the right parts of the code should be easily discoverable. The code should be DRY, and kept small where possible.
- **Flexibility.** ie. if we determine we need to alter the behaviour of the system we can do it.
- **Testability.** ie. the agent loops can be tested (whether that's automated tests or manual tests, eg. with a script like `manual-verify.sh`)

Make a recommendation and explain why your recommendation is stronger than the other options. Please draft a new ADR in `docs/ADRs/` describing the context, options, recommendation, and potential impact of the proposed change (if any).
