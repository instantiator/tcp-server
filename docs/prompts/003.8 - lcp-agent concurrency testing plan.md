# lcp-agent — Concurrency Testing Plan (003.8)

Follows the query in `003.7`. Implements BullMQ concurrency and fills audit record test gaps.

---

## What was built

### 1 — Enable concurrent job processing

Added `concurrency: 5` to the `Worker` constructor options in `apps/lcp-agent/src/worker/agent-worker.service.ts`.

Hardcoded for now; move to config when per-role resource limits are addressed (see `003.3`). 5 is a safe default — very high concurrency exhausts PostgreSQL connections because each agent opens its own `PostgresSaver` pool.

### 2 — Unit tests: deduplication guard

Created `apps/lcp-agent/src/worker/agent-worker.service.spec.ts`.

Approach: `jest.mock('bullmq')` at the file level captures the `Worker` constructor. After `module.init()` triggers `onModuleInit()`, the processor callback is extracted from `Worker.mock.calls[0][1]` and called directly in tests — no Redis connection required.

Tests:
- Skips `loop.run` when the agent is already registered in `AgentRegistryService`
- Calls `loop.run(agentId)` when the agent is not registered

### 3 — Integration test: two concurrent agents

Added a second `it` block to `apps/lcp-agent/test/integration/agent-worker.integration-spec.ts`.

Seeds two `LcpAgent` rows, enqueues both jobs before either can be picked up, polls until both reach `Completed`, then asserts each agent's `threadId` equals its own `id` (not the other's). This is the key correctness check: LangGraph checkpoint threads must not be shared between agents.

### 4 — Audit record test coverage

**Unit tests** (`apps/lcp-agent/src/agent/agent-loop.service.spec.ts`):
- Added `on_chat_model_start` event to `SUCCESS_EVENTS` so that `LlmRequest` audit events are written in unit tests (previously the stub stream only emitted `on_chat_model_end`)
- Added test: `'writes both LlmRequest and LlmResponse audit events with correct metadata'` — asserts both event types exist and that `companyId`, `agentId`, and `role` fields are correctly populated

**Integration tests** (`apps/lcp-agent/test/integration/agent-loop.integration-spec.ts`):
- Extended `'runs to Completed and writes an LlmResponse audit event'` to also assert the `LlmRequest` event and verify `companyId`, `agentId`, `role` on both events
