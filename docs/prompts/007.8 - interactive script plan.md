# Plan: Interactive Manual Verification Script

## Context

The test suite covers unit/integration/e2e behaviour but doesn't cover the
end-to-end conversational quality of agent responses — e.g. "does the chicken
assistant actually sound like a chicken?" That judgement requires a human in the
loop. This plan adds a shell script that:

1. Spins up fresh test data (company + roles) against a running server
2. Runs each prompt with `lcp-cli.sh chat -q`
3. Presents yes/no checks to the operator after each response
4. Halts immediately on any failure

The script replaces ad-hoc manual testing steps that currently require knowing
the right lcp-cli incantations.

---

## Findings

- **MCP servers**: all registry entries (`storage`, `memory`, `interactions`) are
  always available to every agent at runtime when their env vars are set — the
  `mcpServerList` field only adds *extras*. No test-data changes needed.
- **`set-role` company-id**: must be passed via `--company-id` CLI flag, not
  embedded in the JSON (the command merges it on creation).
- **`chat` query flag**: `-q / --query`, not `--prompt` (as the 007.7 doc says).
- **`list-roles --company-id`** returns a single-element array
  `[{ id, name, roles: [{id, name}] }]`.

## Files

### `scripts/manual-verify.sh`

Bash script that:

1. Parses `--username`, `--password`, `--lcp-server` (default
   `http://localhost:3000`), `--scenarios` (default
   `scripts/test-data/manual-verify-scenarios.json`).
2. Wraps `lcp-cli.sh` with auth/server flags pre-filled (`cli()` helper).
3. Creates a test company from `scripts/test-data/simple-company.json`,
   verifying it round-trips through `list-companies`.
4. Creates the chicken and cat assistant roles from
   `scripts/test-data/chicken-assistant.json` /
   `scripts/test-data/cat-assistant.json`, each verified through `list-roles`.
5. Iterates the scenarios file, running each prompt with `chat --role-id
   <id> --query <prompt>` and asking the operator a yes/no check after each
   one (`ask_yn()` helper) — a "n" answer halts the script immediately, as
   does any failed API call (`set -euo pipefail` plus explicit `|| fail`
   checks on every command substitution).

### `scripts/test-data/manual-verify-scenarios.json`

Array of `{ role, prompt, checks[] }` objects — the four prompts and their
checks from the original spec, made configurable independent of the script.

### `docs/scripts.md`

Added `manual-verify.sh` to the summary table and documented its flags and
prerequisites.

### `docs/index.md`

Reviewed ADR implementation states against the `007_swagger` branch's recent
work (`ReasoningContentRecovery` nudge-and-retry redesign, MCP identity context
auto-injection via `McpToolContext`) and updated ADR-002 / ADR-010 notes.

## Verification

```bash
./scripts/manual-verify.sh \
  --username test \
  --password test \
  --lcp-server http://localhost:3000
```

Confirmed: company and both roles appear in list output, all four prompts
produce responses, the script halts on a "n" answer, and exits 0 when every
check passes.
