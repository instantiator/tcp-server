## Implementation notes

- review the relevant ADRs where related decisions have been planned
- implement `LcpRole` in `libs/lcp-shared/src/models` (template for an agent)
- implement `LcpAgent` in `libs/lcp-shared/src/models` (instance of an agent)
- accept an `LcpCompany`, `LcpRole`, and prompt to initiate a separately running agent loop backed by an `LcpAgent` instance in the database `LcpCompany`, `LcpRole`, `LcpAgent` to resume an agent (if not currently running)
- maintain awareness of all currently running agents
- implement a basic agent loop
  - use configuration from `LcpRole` to connect to an LLM service for inference
  - validate the model before starting:
    - can it use tools?
    - can it create structured output?
    - reject the request to start if not (although, for structured output, it might be possible to manage this with prompt engineering)
    - provide that check as a more general model-compatibility check service and endpoint in the lcp-server (accept a list of models, report on their compatibility)
  - connect to postgresql to keep the agent's state/checkpoints
  - grant access to the common LCP MCP servers
    - shared storage for all agents in the same company
    - knowledge base
    - episodic memory
    - decision logging
  - provide the initial system and task prompts to the LLM
    - include expected outputs
    - describe the environment
      - MCP servers available
    - use the role's RAG memory to complement the prompts
  - capture auditing information

Please review this list as a part of planning the work, check with me if anything doesn't sit right or doesn't agree with previous planning, and amend any parts of this if needed.
