When the lcp-cli initiates a chat session, it should be able to monitor:

- changes in state of the agent (eg. when it starts, when it pauses, resumes, and finishes)
- activities that the LLM undertakes: tool use, encoding/decoding, reasoning, response generation
- reasoning as it happens (ie. token by token) (where this is available from the LLM service)

To do this, we're likely to need

- an SSE endpoint for each agent that the client can connect to, and then interpret events from
- a way to determine the endpoint to retrieve reasoning and tool use events

The lcp-cli should:

- show reasoning only if the `--debug` flag is set when it is launched
- show reasoning as grey text, and slightly indented, to distinguish it from real response content
- show changes to the agent state on their own line, in a bright colour
- show changes to the LLM state on their own line, in a different bright colour
- show response content in white, as before
- separate each of these with a blank line to make them easier to distinguish
- prefix each with the text that's indicated by the colour, eg. "Reasoning: " / "LLM state: " / "Agent state: " / "Response: " etc.

Occasionally the lcp-cli still shows an extra, unwanted `>` while the LLM is still working. This doesn't always happen, so something odd causes the loop to do this. Please test for it again after implementing the monitoring described above - as the new changes may be substantial enough to remove this issue anyway.
