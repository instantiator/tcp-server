## Context

`.env.testing` is committed (its header says "safe to commit — only test credentials"), but it also holds four **Zitadel-generated** values — `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `TEST_CLIENT_ID`, `TEST_CLIENT_SECRET`. These are wrong for everyone else: [start-deployment.sh](../../scripts/start-deployment.sh) regenerates both client **secrets** on _every_ run (drift-avoidance), and the client **IDs** change whenever Postgres is wiped (Zitadel stores everything in the `zitadel` DB; there is no Zitadel volume). Committing them produces spurious diffs every run and hands new users credentials their own Zitadel doesn't recognise.

External OIDC providers (Auth0/Keycloak/Okta) are the opposite: an admin issues a _fixed_ client id/secret that must not be committed either.

**Outcome:** adopt the conventional dotenv-layering split — a committed base file for static/shared config, and a gitignored `<file>.local` sibling for generated-or-provider-issued secrets. Loaders apply `<file>` then `<file>.local` (local wins). Decisions taken with the user: **per-instance pairing** (`.env.testing.local`, `.env.dev.local`, `.env.<instance>.local`); **only the four generated values move** — static test placeholders (`DB_PASSWORD`, `MINIO_*`, `ZITADEL_MASTERKEY`, `ZITADEL_ADMIN_PASSWORD`, `INTERNAL_API_KEY`, `TEST_USERNAME/PASSWORD`) stay committed.

## The model

- **Local-only keys** (single source of truth): `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `TEST_CLIENT_ID`, `TEST_CLIENT_SECRET` — `LOCAL_ONLY_ENV_KEYS` in `libs/lcp-shared/src/config`; shell references it by comment.
- **Load order everywhere:** base file → `<base>.local` (last wins). The app runtime is unaffected — it reads `process.env`; layering happens only in the scripts/test-harness/wizard that populate it.

## Changes

### Unit 1 — `.gitignore`

Add `.env*.local` (covers `.env.local`, `.env.testing.local`, `.env.dev.local`, `.env.<instance>.local`; supersedes the three specific `.env.*.local` lines) and `.env.run` (temp file from `run-api-tests.sh`, currently un-ignored).

### Unit 2 — `LOCAL_ONLY_ENV_KEYS`

`libs/lcp-shared/src/config/local-env-keys.ts` (exported from the barrel): the four keys, re-used by the wizard and the TS layering helper.

### Unit 3 — `start-deployment.sh`

- `LOCAL_ENV_FILE="${ENV_FILE}.local"`.
- The four `set_env_var` writes for generated values → `$LOCAL_ENV_FILE`, created if absent.
- After sourcing the base file, source `$LOCAL_ENV_FILE` if present (local overrides). Pass both to Compose: `--env-file "$ENV_FILE" --env-file "$LOCAL_ENV_FILE"` (repeated flag, last wins; the script also `export`s the regenerated values so current-run interpolation is covered regardless).
- Fix [load-env.sh](../../scripts/lib/load-env.sh)'s stale "first wins" comment — plain `source` makes **last win**, which is what layering needs.

### Unit 4 — `run-api-tests.sh`

When resolving `TEST_CLIENT_ID/SECRET` from the env file, also read `${ENV_FILE}.local` (local wins). Keeps standalone runs working after the split.

### Unit 5 — TS test harness

Add `loadEnvFileWithLocal(basePath)` to `test/support/env-file-parser.ts`: `loadEnvFile(base)` then `loadEnvFile(base + '.local', { overwrite: true })`. Use in `testcontainers-env.ts` (`startComposeTier`) and `test/api/api-setup.ts`.

### Unit 6 — Setup wizard

`writeEnvFile` writes **two** files: base `.env.<instance>` (non-secret config incl. `OIDC_ISSUER_URL`) and `.env.<instance>.local` (the `LOCAL_ONLY_ENV_KEYS`). External-OIDC path writes user creds to `.local`; local-Zitadel path leaves them to the bootstrap. `index.ts` summary/next-steps mention the gitignored `.local` file.

### Unit 7 — `ci.yml` (api-test job)

- Base URL must track `EXPOSE_PORT_API` (3001), not hardcoded 3000.
- `start-deployment.sh` call needs `--dev-ports` (smoke hits MCP host ports).
- `.env.testing.local` is generated in-runner by the bootstrap; `run-api-tests.sh` reads it. No secret checkout.

### Unit 8 — Staging hygiene

Rewrite committed `.env.testing` to omit the four generated keys (keep static config + a pointer comment). Move the current working-tree generated values into gitignored `.env.testing.local`. Confirm nothing secret is staged.
