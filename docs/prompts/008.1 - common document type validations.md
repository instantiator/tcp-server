Let's plan in some common document type validation.

When agents write to or update files in the shared document store, the files should be validated to ensure they're in good condition.

Types of files to validate:

- JSON
- Markdown
- OKF
- YAML
- XML
- CSV

There may be other formats in future, so let's plan this to be modular in the lcp-mcp-storage service.

Please plan in clean business logic that's called during the storage process and can reject the file. If rejected, the response from the service should contain a clear indicating that the operation failed, with a clear explanation that an LLM could attempt to resolve.

Please include tests including

- Unit tests for the different operations
- Integration tests showing that the process runs correctly
