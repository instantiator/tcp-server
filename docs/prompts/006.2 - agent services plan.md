# Plan: Agent Services (RAG + MCP) — 006.2

## Context

Agents run with LLM + conversation history (LangGraph checkpoint). Six prompt parts are marked TODO in `agent-loop.service.ts` and `chat.service.ts` (parts 1, 2, 3, 5, 6, 8). This plan fills them in by implementing RAG and MCP services, following ADRs 006, 007, 010, 012, 013.

**Current state:**

- pgvector: provisioned, unused (no vector columns or queries)
- MinIO: running in Docker Compose, no application code touches it
- `LcpRole.knowledgeDomains` and `mcpServerList` fields: exist, unused
- Context management (compaction): implemented; has a TODO where MinIO storage should be used

**ADR deviations to flag:**

- **ADR-009** says MCP servers as child processes. This plan proposes Docker Compose services (better networking, restart resilience). ADR-009 should be superseded/updated.
- **Anthropic embeddings gap**: Anthropic Claude has no embeddings API. Resolved: add a separate `embeddingConfig` field to `LcpCompany` (same JSONB shape as `LlmConfig`). Operators set it independently — e.g. Anthropic for chat, LM Studio for embeddings.

---

## ADR-007 Addition: `finished/` folder

Add to the per-company bucket structure:

```
{company_slug}/
  tasks/{task_id}/
    materials/           ← user-submitted task inputs
    output/              ← files created during task execution
  knowledge/{role_name}/ ← OKF source files for RAG indexing
  finished/              ← NEW: stable outputs accessible to all agents
    {category}/          ← reports | specifications | designs | code | other
      {task_id}/
        {filename}
  audit/{task_id}/
    {step_id}.jsonl
```

Agents write to `tasks/{task_id}/output/` during execution. When a task reaches `completed`, the reviewing agent (or orchestrator) copies finalised artefacts to `finished/{category}/{task_id}/`. This keeps in-progress work isolated from stable outputs.

## Phases

### Phase 1 — Prompt restructure (prerequisite)

_No external services required._

1. Add `rolePrompt TEXT NULL` to `LcpRole`, `companyContext TEXT NULL` to `LcpCompany`.
2. TypeORM migration — generated via `npm run migration:generate -- apps/lcp-server/src/migrations/AddRolePromptCompanyContext`, then reviewed and registered in `apps/lcp-server/src/data-source.ts`.
3. Rebuild schema: `npm run build`.
4. Wire prompt parts 1, 2, 8 in `agent-loop.service.ts` and `chat.service.ts`:
   - Part 1: inject `role.rolePrompt` as HumanMessage (skip if null).
   - Part 2: inject `company.companyContext` as HumanMessage (skip if null).
   - Part 8: append a fixed final-instruction HumanMessage (constant text, not a DB field).
5. Update unit tests for both services.
6. Verify: `npm run build && npm run lint && npm test`.

### Phase 2 — RAG infrastructure

_Depends on Phase 1. Requires pgvector (already running)._

#### 2a — Embedding service

- Add `embeddingConfig` (JSONB, nullable) to `LcpCompany` — same shape as `LlmConfig` (provider, model, baseUrl, apiKey) but points to an embeddings model.
- Migration — generated via `npm run migration:generate -- apps/lcp-server/src/migrations/AddCompanyEmbeddingConfig`, reviewed, registered.
- `EmbeddingService` in `apps/lcp-server/src/rag/`: wraps OpenAI-compatible `/v1/embeddings` endpoint (works for LM Studio, OpenAI, and any compatible provider). Falls back to `llmDefault` provider with an embeddings model override if `embeddingConfig` is null.

#### 2b — KnowledgeChunk entity + migration

New entity in `libs/lcp-shared/src/models/KnowledgeChunk.model.ts`:

```typescript
@Entity()
class KnowledgeChunk {
  id: UUID;
  companyId: UUID;
  roleId: UUID;
  documentPath: string; // MinIO path to OKF source file
  chunkIndex: number;
  content: string;
  embedding: number[]; // stored as VECTOR(N) — dimension from embeddingConfig
  createdAt: Date;
}
```

Migration — generated via `npm run migration:generate -- apps/lcp-server/src/migrations/AddKnowledgeChunk`, then hand-edited to add the vector column (`ALTER TABLE knowledge_chunk ADD COLUMN embedding vector(1536)`) and IVFFlat index, since TypeORM does not generate pgvector DDL automatically. Register in `data-source.ts`.

#### 2c — RAG index service

`RagIndexService` in `apps/lcp-server/src/rag/`:

- `ingestDocument(roleId, path, markdownContent)`: chunk → embed → upsert (delete old chunks for same path first).
- `removeDocument(roleId, path)`: delete chunks for that path.

#### 2d — RAG retrieval service

`RagRetrievalService`:

- `retrieve(roleId, query, topK=5, threshold=0.7)`: embed query → pgvector cosine similarity search → return chunks above threshold only.
- Returns empty array when nothing exceeds threshold (no forced injection).

#### 2e — Wire RAG into agent loop

Fill in TODO part 5 in both `agent-loop.service.ts` and `chat.service.ts`:

- On first message: call `RagRetrievalService.retrieve(role.id, initialPrompt)`.
- If results returned: build RAG HumanMessage, inject as part 5.
- If empty: skip entirely.

`lcp-agent` accesses RAG via the shared DB connection (TypeORM + pgvector) — no HTTP call needed.

#### 2f — Tests

Unit tests for `EmbeddingService`, `RagIndexService`, `RagRetrievalService` (mock DB and embedding API).
Verify: `npm run build && npm run lint && npm test`.

### Phase 3 — CLI RAG management

_Depends on Phase 2._

New commands in `apps/lcp-cli/src/commands/`:

**`store-role-documents`**

- `--role-id <uuid> --src <glob> [--overwrite]`
- Expand glob (`node:fs` glob matching via built-in `fs.glob` in Node 22, or `fast-glob` if already present — check first).
- Validate each file: must be `.md`, must have valid YAML front-matter (`gray-matter` — MIT, 50k weekly downloads, no transitive deps — check license before adding).
- Reject all if any file fails OKF validation; report failures.
- Upload to MinIO via `POST /api/roles/:roleId/documents` (new lcp-server endpoint).
- Server runs `RagIndexService.ingestDocument` for each.

**`list-role-documents`**

- `--role-id <uuid>`
- Calls `GET /api/roles/:roleId/documents` and prints the list of documents (path, size, last modified) currently stored for this role.

**`remove-role-documents`**

- `--role-id <uuid> --src <glob>`
- Calls `DELETE /api/roles/:roleId/documents`.

**`open-document-store`** _(bonus — MinIO has a web console at port 9001)_

- Prints MinIO console URL from config (`MINIO_CONSOLE_URL`, default `http://localhost:9001`).
- Opens in browser via `child_process.exec('open <url>')` on macOS, `xdg-open` on Linux — no new dependency.

**MinIO access controls and Keycloak integration:**

MinIO supports OIDC for **console SSO** — when configured, users log in via Keycloak instead of root credentials. Programmatic S3 API calls (lcp-server, lcp-agent, MCP servers) continue to use static access keys regardless.

- Add OIDC federation env vars to the MinIO service **under the `auth` Docker Compose profile only** (optional alongside Keycloak):

  ```yaml
  MINIO_IDENTITY_OIDC_CONFIG_URL: http://keycloak:8080/realms/lcp/.well-known/openid-configuration
  MINIO_IDENTITY_OIDC_CLIENT_ID: ${OIDC_CLIENT_ID}
  MINIO_IDENTITY_OIDC_CLIENT_SECRET: ${OIDC_CLIENT_SECRET}
  MINIO_IDENTITY_OIDC_REDIRECT_URI: http://localhost:9001/oauth_callback
  MINIO_IDENTITY_OIDC_CLAIM_NAME: preferred_username
  MINIO_IDENTITY_OIDC_SCOPES: openid,profile,email
  ```

  Requires a second Keycloak client (e.g. `lcp-minio`) with the callback redirect URI above, or the existing client updated with that redirect URI.

- **Per-company bucket ACL**: Bucket structure provides logical isolation (ADR-007). Hard IAM policies scoped per Keycloak user would require provisioning MinIO users matched to Keycloak identities — non-trivial to automate and deferred to a later phase. Consistent with ADR-007's existing "no hard per-agent ACL" stance.

New lcp-server endpoints:

- `GET /api/roles/:roleId/documents`
- `POST /api/roles/:roleId/documents`
- `DELETE /api/roles/:roleId/documents`

E2E and API tests for all three endpoints.

### Phase 4 — MCP servers

_Depends on Phases 2–3._

**Deployment**: New NestJS apps under `apps/`, running as Docker Compose services on the internal network using MCP streamable HTTP transport. This supersedes ADR-009's child-process approach.

**Agent MCP client** in `lcp-agent`:

- `@modelcontextprotocol/sdk` client.
- `langchain-mcp-adapters` to convert MCP tools to LangChain tools (check license/downloads).
- Tools loaded per-agent-run from `role.mcpServerList`.
- Conditional `tools` node added to LangGraph graph (fills the `ponytail:` comment in `buildGraph`).

#### 4a — Storage MCP server

**MinIO does not ship its own MCP server.** Since MinIO is S3-compatible, the AWS-provided S3 MCP server (`awslabs/amazon-mcp-servers` → `awslabs/s3-mcp-server`) may work with a custom endpoint override (`AWS_ENDPOINT_URL=http://minio:9000`).

**Implementation decision (evaluate at Phase 4 start):**

1. Test `awslabs/s3-mcp-server` against the running MinIO instance with endpoint override.
2. If it covers the required tools below and works cleanly: use it directly as a Docker Compose sidecar (no custom code).
3. If it is missing tools (e.g. `summarise_file`, `search_files`) or has AWS-specific assumptions that break: build `apps/lcp-mcp-storage/` as a custom NestJS MCP server using `@modelcontextprotocol/sdk` + `@aws-sdk/client-s3` pointed at MinIO.

Either way, port 3002 (internal). Scoped to company bucket. Required tools:

| Tool                           | Description                                      |
| ------------------------------ | ------------------------------------------------ |
| `list_files(prefix?)`          | List files under prefix                          |
| `search_files(query, prefix?)` | Pattern-match file names/paths                   |
| `get_file_properties(path)`    | Size, modified, content type                     |
| `read_file(path)`              | Raw text content                                 |
| `summarise_file(path)`         | LLM summary (uses company llmDefault)            |
| `write_file(path, content)`    | Overwrite (soft confirmation check in tool desc) |
| `create_file(path, content)`   | Create new (error if exists)                     |
| `copy_file(src, dst)`          | Copy within bucket                               |
| `move_file(src, dst)`          | Copy + delete                                    |
| `delete_file(path)`            | Soft delete (MinIO versioning = recoverable)     |

All tools write audit events to the `audit_event` table.

#### 4b — Memory/RAG MCP server (`apps/lcp-mcp-memory/`)

Port 3003 (internal). Tools per ADR-006:

| Tool                                            | Description                                |
| ----------------------------------------------- | ------------------------------------------ |
| `recall(query, top_k?)`                         | Semantic search: episodic + knowledge base |
| `remember(content, tags?)`                      | Write episodic memory entry                |
| `search_knowledge(query, top_k?)`               | Knowledge base only                        |
| `search_rag(query, top_k?)`                     | Ad-hoc RAG retrieval mid-conversation      |
| `remove_rag_context(context_id)`                | Signal to remove a RAG section from prompt |
| `condense_rag_context(context_id, instruction)` | Summarise a RAG section                    |

#### 4c — Interactions MCP server (`apps/lcp-mcp-interactions/`)

Port 3004 (internal). Stubs:

| Tool                                                        | Behaviour                                                                                                                                                       |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `request_agent_consultation(role_name, question, context?)` | Returns `"Agent consultation is not yet implemented."`                                                                                                          |
| `request_user_input(question, context?)`                    | Creates `Conversation` record (ADR-012 data model), emits `user_input_requested` SSE event, suspends agent via LangGraph `interrupt()`. Returns pending status. |

#### 4d — Prompt part 3 (services available)

Generate services description dynamically from `role.mcpServerList`. Inject as part 3 HumanMessage in both agent-loop and chat service.

#### 4e — Docker Compose

Add `lcp-mcp-storage`, `lcp-mcp-memory`, `lcp-mcp-interactions` to `docker-compose.yml`. Internal network; no external port exposure.

Validate: `docker compose config`.

Integration tests for each MCP server (new test files under `test/integration/`).
